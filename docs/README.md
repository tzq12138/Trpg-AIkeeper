## 目录说明

| 目录 | 用途 |
|------|------|
| `00-产品规范/` | M0 唯一规范入口：产品宪法、角色权限、生命周期、权威矩阵、范围、安全和 ADR。 |
| `00-路线图/` | 从完整平台清单中压缩出短中长期路线、MVP 边界和优先级。 |
| `10-现状盘点/` | 记录当前代码、测试、已有文档、近期更新索引和工作区风险，避免脱离现状执行。 |
| `20-核心链路/` | 固化 AI-KP 区别于普通网团工具的核心架构。含 soul、KP MCP 设计、规则导入、数据流和玩家行动协议。 |
| `25-深挖优势与设计原则/` | 战略设计笔记：AI 长期记忆、自然语义理解、线索自动整理、战斗运行时等核心差异点。 |
| `30-DeepSeek任务包/` | 面向 DeepSeek 的可执行批次，每批都有范围、文件方向、验收命令和禁止事项。 |
| `40-平台补全/` | 收纳核心链路之外的平台能力、后续阶段路线、工程安全运营护栏。 |
| `50-AI-Keeper-Platform/` | 按 24 个平台模块拆分功能列表、PRD 初版和 DeepSeek 模块计划。 |
| `60-验收与测试报告/` | 所有验收报告、审计报告、E2E 测试报告、loop 运行报告和测试覆盖文档。 |
| `90-归档/` | 归档内容，包含历史计划、外部审查、方向性问题头脑风暴、早期模块设计（host/player/compose/superpowers）、前端设计备份。 |
| `PRDs/` | 最终版本产品需求文档，PRD-00 到 PRD-30。 |
| `开发文档/` | 将 PRD 转成工程开发说明。 |
| `设计前端/` | Host/Player 前端设计稿、截图和静态原型。 |

## 当前执行口径

- 所有新设计和实现任务先引用 `00-产品规范/`；旧文档若冲突，以其中的 ADR 和裁决映射为准。
- DeepSeek 负责后续实际实现，Codex 负责拆方向、定边界、整理文档和复核验收口径。
- 第一轮只围绕核心链路补文档和任务包，不实现语音视频、社区、付费、动态光照、完整插件市场等外围功能。
- 核心链路之外的完整平台能力统一沉淀在 `docs/40-平台补全/`，等 Batch 5 验收后再拆新的 DeepSeek 批次。
- 具体平台模块的长期施工图写入 `docs/50-AI-Keeper-Platform/`；其中的 `DeepSeek计划.md` 是模块级初版，不替代 `docs/30-DeepSeek任务包/` 的当前执行批次。
- 当前工作区已有大量未提交改动，任何实现任务开始前必须先确认 `git status --short`，并且不得覆盖无关改动。
- 所有新计划和任务说明都应写入 `docs/`，不要重新在仓库根目录创建 `plan/`。
