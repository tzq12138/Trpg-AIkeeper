# 工程安全运营护栏

## 为什么单独成文

AI-Keeper 不是只存聊天记录的工具。它会保存玩家身份、角色私密信息、未公开线索、剧本真相、AI 调用记录和长团档案。平台化前必须把工程、安全、运营边界写清楚，否则后续功能越多，越容易把数据、权限和成本搅在一起。

## 工程护栏

| 护栏      | 要求                                         | 验收方式                                                |
| ------- | ------------------------------------------ | --------------------------------------------------- |
| 单一权威状态源 | Engine 是唯一权威写入者，Host/Player/AI 都不能直接改世界状态。 | 核心链路测试覆盖越权写入拒绝。                                     |
| 测试库隔离   | 自动测试不得清空开发库或真实房间数据。                        | `tests/server/conftest.py` 明确测试数据库配置。               |
| 可重复构建   | 前端 build 和后端测试不依赖未提交本地文件。                  | `python -m pytest tests/server -q`、`npm run build`。 |
| 事件可追溯   | 状态变化必须能追到 action、transaction、event。        | 抽样检查日志和数据库记录。                                       |
| 快照和恢复   | 房间状态、Session、投影进度能从检查点恢复。                  | 断线重连和 checkpoint 测试。                                |
| 幂等与去重   | 玩家重复提交、WS 重连、刷新页面不会重复结算。                   | 重复 actionId、lastEventId、stateVersion 测试。            |
| 后台任务可诊断 | AI、RAG、剧本结构化和导入任务必须记录状态与错误摘要。              | 管理端或日志可查到任务失败原因。                                    |

## 权限和隐私护栏

| 数据 | 默认可见 | 禁止事项 |
|---|---|---|
| 玩家账号资料 | 玩家本人、平台必要后台 | 不给其他玩家暴露真实账号信息。 |
| 角色公开信息 | 同房间玩家、Host 公共舞台 | 不包含私密背景、暗线和未公开状态。 |
| 角色私密信息 | 角色拥有者、Engine 必要处理上下文 | Host 不默认拥有完整 KP 视角。 |
| 模组真相 | Engine、受控 AI 上下文 | 不进入 Player 可见上下文，不写入公共日志。 |
| 未发现线索 | Engine、受控 AI 上下文 | 不投影给 Player，不被 AI 当作已知事实讲出。 |
| 私密线索 | 拥有者、Engine | 未分享前不进入团队线索板。 |
| AI 调用日志 | 开发/运维必要人员 | 不记录 API Key，不长期保存完整 prompt。 |
| 安全边界设置 | 玩家本人、必要的 KP/平台调解 | 不用于公开展示或社区评价。 |

## AI 安全护栏

这些要求和核心链路相连，但在平台化能力里也必须持续执行：

| 护栏 | 要求 |
|---|---|
| 生成不等于事实 | AI 生成 NPC、地点、线索、Handout 后，必须经过确认或 Engine 入库流程。 |
| 证据优先 | 玩家猜测不能因为 AI 复述而变成真相。 |
| 输出校验 | AI 输出必须经过 schema 校验、权限校验和状态边界校验。 |
| 上下文最小化 | 每次 AI 调用只注入当前任务必要的真相、已知信息和角色状态。 |
| 模型失败可降级 | DeepSeek/MCP 不可用时，返回可解释 fallback，不破坏房间状态。 |
| 成本可观测 | 每次 AI 调用记录 provider、任务类型、耗时、token 或估算成本。 |

## 跑团安全护栏

| 能力 | 最小要求 | 推进阶段 |
|---|---|---:|
| 内容分级 | 房间或模组声明恐怖、血腥、成人、暴力强度。 | 阶段 5 |
| 禁区标签 | 玩家可在 Session 0 设置不希望触碰的内容。 | 阶段 5 |
| X-Card / 暂停卡 | 玩家可一键暂停当前演出并通知 Host/AI。 | 阶段 5 |
| 私密反馈 | 玩家能向 Host 或平台提交不公开反馈。 | 阶段 5 |
| 剧情淡出 | AI 和 Host 能把不适内容改为非细节描述。 | 阶段 5 |
| AI 内容限制 | AI prompt 和输出校验尊重房间安全设置。 | 阶段 5 |

## 运营护栏

| 护栏 | 要求 | 不上线风险 |
|---|---|---|
| 数据备份 | 房间、Session、角色、线索、日志、模组定期备份。 | 长团资料丢失。 |
| 房间快照 | 每个关键事务后可以生成或恢复快照。 | 崩溃后无法继续。 |
| 限流 | 登录、加入房间、AI 请求、上传资源均有限流。 | 被刷爆成本或服务不可用。 |
| 错误报警 | AI 失败率、WS 断连率、任务队列积压、数据库错误可报警。 | 故障无人发现。 |
| 日志脱敏 | 日志不暴露 token、API key、玩家私密线索和模组真相。 | 隐私泄露。 |
| 数据删除 | 用户可删除账号资料或申请删除个人数据。 | 隐私合规风险。 |
| 导入导出 | 房间、模组、日志支持开放格式导出。 | 用户数据被锁死。 |

## 成本护栏

| 成本项 | 控制方式 |
|---|---|
| LLM 调用 | provider 顺序、超时、重试上限、房间级模型配置。 |
| Token 消耗 | 上下文压缩、RAG 引用裁剪、摘要替代长日志。 |
| 存储 | 资源配额、旧 debug 日志过期、压缩图片和 Handout。 |
| 带宽 | Host/Player 投影分层，避免给所有客户端广播私密或无关数据。 |
| 前端资源 | 素材预加载清单和失败兜底，避免演出时卡死。 |

## 上线前最低门槛

公开测试前至少满足：

1. 后端全量测试和前端 build 可重复通过。
2. Host/Player/AI/Engine 权限边界有测试或手动验收记录。
3. 房间快照、断线重连、事件日志可用。
4. AI 调用失败不会破坏权威状态。
5. 日志不记录 API Key、房间 token、完整私密 prompt。
6. 有基础限流和错误报警口径。
7. 有数据备份和导出路径。
