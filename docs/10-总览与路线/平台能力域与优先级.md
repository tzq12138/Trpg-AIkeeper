# 平台能力域与优先级

## 总体分层

完整 AI-Keeper 平台可以分成四类能力：

| 层级 | 能力域 | 当前口径 |
|---|---|---|
| 跑团基础层 | 房间、用户、频道、骰子、角色、NPC、世界书、线索、日志、玩家动作、Host/Player 端 | 第一轮只保证 AI-KP 主链路可跑；其余作为 P0/P1 补齐项。 |
| VTT 与沉浸层 | 地图、场景、Token、素材、媒体、Host 大屏演出 | 先做轻量公共舞台和场景展示，不追 Roll20/Foundry 的完整动态光照。 |
| 内容生产层 | 模组编辑器、剧本结构化、AI 内容生成、资源库、导入导出 | 第二阶段重点，服务 KP 降低备团成本。 |
| 平台运营层 | 安全边界、日程招募、社区生态、插件 API、后台运维、成本控制 | 上线前逐步补齐，商业化和生态能力后置。 |

## 能力域矩阵

| 能力域 | 附件来源范围 | 建议优先级 | 与当前项目关系 | 第一轮处理 |
|---|---|---:|---|---|
| 房间 / 团管理 | 房间、邀请码、Session、席位、旁观者、归档 | P0/P1 | 已有房间和加入流程，需要补 Session、公告、旁观者、归档口径。 | 只修创建、加入、ready、start 主链路。 |
| 用户 / 身份 / 权限 | 账号、KP、玩家、旁观者、助理 KP、审计 | P0/P1 | 当前以房间 token 和角色绑定为主，正式账号体系未展开。 | 只保证 Host/Player 权限分离。 |
| 聊天 / 频道 / 信息流 | 公共剧情、OOC、系统、私聊、线索、日志、引用、搜索 | P0/P1 | 现有主链路偏行动和投影，频道模型还需要独立设计。 | 只保留公共/私密/系统事件投影。 |
| 骰子 / 判定 / 规则 | 骰子表达式、暗骰、技能检定、SAN、规则插件 | P0/P1 | COC 检定、规则执行已有基础，完整多规则插件后置。 | 只稳定 COC 主检定和 Engine 权威裁决。 |
| 角色卡 | 创建、导入、属性、技能、HP/SAN、物品、状态、成长 | P0/P1 | 已有 xlsx 导入和 Player 角色页，创建器和成长记录进入阶段 2。 | 只保证角色导入、查看、技能检定。 |
| NPC / 怪物 / 势力 | NPC 档案、性格、目标、秘密、关系网、怪物、势力时钟 | P0/P2 | 剧本结构化会产出 NPC，但 NPC 运行时状态还需建模。 | 只把 NPC 当 AI 上下文和剧本资产。 |
| 世界书 / 知识库 | 世界设定、真相、地点、事件、玩家已知、RAG、版本 | P0/P1 | RAG、剧本知识图谱已有基础，版本和编辑器进入阶段 3。 | 只服务防剧透上下文和 AI 检索。 |
| 线索 / 道具 / 情报 | 发现状态、归属、分享、来源、证据链、Handout | P0/P1 | 这是核心链路后最靠前的内容层能力。 | Batch 4 只补线索证据链和防剧透。 |
| 地图 / 场景 / Token | 地图上传、场景切换、网格、Token、迷雾、光照 | P0/P2 | 当前 Host 舞台和地图面板可承接轻量场景，完整 VTT 后置。 | 只保证场景/地图不会破坏投影链路。 |
| 时间轴 / 世界推进 | 游戏内时间、事件轴、未来事件、倒计时、触发事件 | P0/P2 | 事件日志已有基础，世界时钟未形成独立服务。 | 只记录行动和事件顺序。 |
| Journal / 回放 | 自动摘要、Session 总结、行动/骰子/状态/线索日志、导出 | P0/P1 | 事件日志与档案已有基础，摘要和导出可后续增强。 | 只保证日志可查、可追溯。 |
| 玩家动作 / 交互 | 自由文本、快捷行动、目标/地点/物品选择、投票、准备状态 | P0/P2 | Player 行动页已有入口，结构化 Actions 还可细化。 | 只保证行动提交、锁定、回执。 |
| Host 公共舞台 | 旁白、场景、字幕、NPC 立绘、HUD、演出队列、恢复 | P0/P2 | HostStage 已是首版体验重点。 | 只修实时投影、队列和死锁风险。 |
| Player 私人端 | 角色卡、私密通知、个人线索、笔记、私聊、重连 | P0/P1 | Player 端已有页面雏形，笔记和私聊进入阶段 2。 | 只修手机主链路和重连恢复。 |
| 资源 / 素材 / 媒体库 | 图片、地图、Token、音乐、Handout、模组包、标签、权限 | P1/P2 | 当前素材以本地测试资产和前端设计稿为主。 | 不进入第一轮。 |
| 模组 / 剧本编辑器 | 真相、开场、NPC、地点、线索、事件、多结局、测试模式 | P0/P2 | PDF 导入和结构化已有基础，编辑器是第二阶段重点。 | 只保证导入、质量报告、一键开局链路。 |
| AI 内容生成工具 | NPC、地点、线索、Handout、随机事件、前情提要、审核入库 | P1/P2 | 必须遵守“生成不等于事实”。 | 不直接落库，不进入第一轮。 |
| 语音 / 视频 / 实时协作 | 语音、视频、录制、STT、TTS、BGM 同步、禁麦 | P2 | PRD-08 有语音意图，但实时音视频复杂度高。 | 仅保留语音意图占位和文字兜底。 |
| 跑团安全边界 | 内容分级、禁区标签、X-Card、私密反馈、Session 0 | P1/P2 | AI 自动生成内容使安全边界更重要。 | 不进入第一轮实现，但上线前必须补。 |
| 通知 / 日程 / 招募 | 开团提醒、时间投票、缺席、招募大厅、评价、跑团历史 | P1/P2 | 平台化能力，不影响本地 AI-KP 主链路验证。 | 不进入第一轮。 |
| 社区 / 内容生态 | 模组广场、角色卡广场、战报、评论、收藏、付费模组 | P2/P3 | 商业和增长能力。 | 后置。 |
| 开发者 / 插件系统 | 规则插件 API、角色卡插件、Webhook、Bot API、协议文档 | P1/P3 | 双层规则引擎已给未来插件留入口。 | 只保留协议稳定性和导出自由。 |
| 后台 / 运维 / 成本 | 管理后台、AI 调用日志、Token 统计、限流、备份、隐私合规 | P0/P3 | 崩溃恢复、备份、日志脱敏是上线前硬门槛。 | 只保证开发态稳定和测试隔离。 |

## 优先级解释

- **P0**：直接影响能否完成一场 AI-KP 跑团或避免状态/权限事故。
- **P1**：能明显提升长期跑团可用性，应在核心主链路稳定后拆批。
- **P2**：平台化增强，适合 Beta 或公开测试前后推进。
- **P3**：商业化、生态化能力，等产品留存和内容供给被验证后再做。

## 第一轮不吸收的能力

以下能力应保留在平台补全 backlog，不允许混入当前核心链路 Batch：

```text
实时语音视频
社区广场和内容市场
付费模组与订阅
高级动态光照和复杂战争迷雾
完整多规则插件市场
AI 地图/立绘/BGM 生成
OBS/直播适配
复杂日程招募和评价体系
CDN/对象存储资源平台
```

## 进入实现前的准入条件

任一能力从本目录进入实现前，必须满足：

| 条件 | 说明 |
|---|---|
| 主链路已验收 | 创建房间、加入、ready、提交行动、AI/规则裁决、投影、日志均通过。 |
| 权限边界明确 | 明确 Host、Player、AI、Engine 谁能看、谁能写、谁只能建议。 |
| 数据归属明确 | 明确数据属于房间、角色、玩家、Session、模组还是平台全局。 |
| 可测试 | 至少有后端单测、前端类型检查或手动验收脚本中的一种明确验证方式。 |
| 可回滚 | 对状态、权限、日志、资源相关能力，必须有失败恢复或检查点策略。 |
