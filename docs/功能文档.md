## 1. 核心系统架构

### 1.1 技术栈

| 层级 | 技术 | 说明 |
|------|------|------|
| 后端 | Python FastAPI | REST + WebSocket 双协议 |
| 前端 | React 18 + TypeScript + Vite | 移动端竖屏优先 + Host 大屏 |
| 数据库 | PostgreSQL 16 (pgvector) | 关系数据 + 向量检索 |
| 缓存 | Redis 7 (可选) | 事件缓存 + HUD 数据 |
| AI | DeepSeek API / MCP / OpenAI-compatible | 多 Provider 链式调用 |
| KP MCP | 独立 ASGI 服务 | Prompt 契约 + 工具注册 |

### 1.2 核心架构原则

1. **Engine 是唯一权威写入口**：AI、Host、Player 均不能直接写数据库。所有状态变更必须经过 Engine → StateService。
2. **AI 不写状态**：AI 只输出建议，Director 的 `state_patch` 标记为 `advisory_only`，必须经 Engine 校验后写入。
3. **Player 不越权**：所有写操作走 `POST /api/player/intent`，不接受前端传入 characterId 作为身份。
4. **Host 不判定**：Host 只消费事件播放公共演出，不承载规则逻辑。
5. **REST 负责写入，WebSocket 负责推送**：服务器→客户端事件通过 WebSocket 实时推送。

### 1.3 应用启动流程（11 步）

```
Database → Auth → Embedding → RAG → Engine → MechanicCompiler
→ Redis(可选) → SpoilerGuard → ResolutionPipeline → StateService
→ GameAgent+GameLoop(可选) → AiGateway → TurnTimeoutWorker
```

### 1.4 状态管理双路径

- **旧路径（Engine 直写）**：`Engine.submit_intent()` → `ResolutionPipeline` → 直接 INSERT/UPDATE
- **新路径（StateService）**：`StateService.apply_change()` 接收 JSON Patch 风格的 mutations，通过 `MUTATION_PATH_HANDLERS` 映射到具体列，含钳制（HP/SAN/MP 夹在 `[0, max]`）、版本递增和 no-op 检测

### 1.5 事件可见性模型

| audience | 可见性规则 |
|----------|-----------|
| `host` | 始终不可见（返回 False） |
| `party` | 始终可见 |
| `player` | 仅当 `payload.characterId` 匹配请求者 |
| `system` | 仅当 `event_type` 在白名单中（`s2c_turn_resolved`、`s2c_checkpoint_created`） |

## 2. 房间管理

### 2.1 创建房间

`POST /api/rooms`

- 支持指定剧本、场景版本、运行时包
- 可选回合制模式（`turn_based: true`）
- 可选动作 timing 预设（`fast/standard/slow`）
- 返回房主 token（`owner_token`）
- 自动初始化运行时场景状态
- 支持角色预设导入（`character_presets`）
- 生成房间邀请码（`invite_code`）
- 动作时序预设参数：

| 预设 | 输入提示 | 回执 | 预览 | 结算 |
|------|---------|------|------|------|
| fast | 30s | 3s | 15s | 90s |
| standard | 60s | 5s | 30s | 180s |
| slow | 120s | 10s | 60s | 300s |

### 2.2 加入房间

`POST /api/rooms/join`

- 通过邀请码加入
- 速率限制（5 次/60s/IP）
- 支持账号绑定（`account_id`）
- 返回玩家 token（`player_token`）
- 可选角色预设选择
- 支持 `X-Idempotency-Key` 幂等重试

### 2.3 房间配置

`GET/PUT /api/rooms/{room_id}`

- 查看/修改房间设置
- 包含 `draft_analysis_enabled`（AI 动作分析开关）
- 包含 `absent_policy`（缺勤策略：`idle` / `maintain_existing`）
- `turn_based` 回合制开关
- 房间状态：`active` / `archived` / `finalized`

### 2.4 房间生命周期

- `room_lifecycle_guard` 确保删除竞态安全
- 规则源版本检查（`ensure_room_rule_source_available`）
- 战役归档只读保护（`CampaignReadOnlyError`）

### 2.5 房间迁移

`POST /api/admin/migrate`

- 房间 V2 迁移器（`room_migration.py`）
- `build_room_package()` 打包房间数据
- `import_room_package()` 导入到目标环境
- `inspect_room_package()` 检查包内容
- V2 切换管理器（`v2_cutover.py`）

## 3. 玩家功能

### 3.1 动作提交

`POST /api/player/intent`

玩家动作提交流程：

```
1. 前端幂等检查（action_id 已存在 → 直接返回）
2. Engine.submit_intent()：版本冲突检测(state_version)
3. INSERT actions(status='queued') → INSERT events(s2c_action_queued)
4. 等待 Host 手动触发 OR 自动批次收集 OR GameLoop.process_turn()
5. TurnManager.mark_resolving()（条件 UPDATE，幂等）
6. ResolutionPipeline.resolve_action() → 完整结算流水线
```

**动作类型（intent_type）：**

| 类型 | 说明 | 示例 |
|------|------|------|
| `voice_command` | 语音命令 | "我想调查书架" |
| `dialogue` | 对话 | "我是来调查案件的" |
| `skill_check` | 技能检定 | "侦查检定" |
| `move` | 移动 | "前往大厅" |
| `use_item` | 使用物品 | "使用急救包" |
| `show_item` | 展示物品 | "拿出怀表给NPC看" |
| `combat_action` | 战斗动作 | "用手枪射击" |
| `chase_action` | 追逐动作 | "追赶逃跑的嫌疑人" |
| `prepared_action` | 准备动作 | "如果敌人靠近就开枪" |
| `retroactive_item_claim` | 追溯物品声明 | "我本来就带了手电筒" |

### 3.2 动作草稿系统

`POST /api/player/actions/draft`

- AI 分析动作草稿（`analyze_action_draft`）
- 引擎安全策略检查（`apply_engine_action_policy`）
- 运行时策略检查（`apply_room_runtime_policy`）
- 草稿确认（`confirm_action_draft`）
- 草稿取消（`cancel_action_draft`）
- 复合动作延续（`choose_composite_action_continuation`）
- 动作暗示/提示（`build_manual_action_hints`）
- 版本冲突检测（`base_state_version`）

### 3.3 动作状态机

14 个状态，严格跃迁校验：

```
analyzing → awaiting_confirmation → queued → batched → resolving
   │              │                    │         │           │
   ├─canceled     ├─sync_required      ├─sync    ├─await     ├─await_player_choice
   └─timeout      └─canceled           └─rejected│  host_ex  ├─sync_required
                                                  │  ception  └─await_host_exception
                                                  └─canceled
```

**终端态：** `completed` / `rejected` / `canceled` / `timeout`

### 3.4 动作后续决策

`POST /api/player/actions/{action_id}/follow-up`

- CoC 后续决策提交（`submit_coc_followup_decision`）
- 自动触发后台结算（`_resolve_action_background`）
- 包含 Idempotency-Key 幂等控制

### 3.5 动作审查请求

`POST /api/player/actions/{action_id}/review-requests`

- 玩家对已结算动作提交审查请求
- 包含 `original_intent` 和 `objection`
- 审查状态：`pending` → `accepted` / `modified` / `rejected`
- 仅对特定状态的动作可发起（`resolving`、`completed` 等）

### 3.6 动作同意

`GET /api/player/action-consents`
`POST /api/player/action-consents/{consent_id}/respond`

- PVP 效果同意（damage/resource_take/restrict_action/status_change）
- 组决策类型：

| 类型 | 决策规则 |
|------|---------|
| `reversible_route` | 简单多数 |
| `shared_resource` | 全票通过 |
| `ending` | 全票通过 |
| `abandon_ally` | 全票通过 |
| `risk_expansion` | 全票通过 |

- **默认沉默即拒绝（fail-closed）**
- 过期自动失效（`expire_pending_action_consents`）

### 3.7 线索管理

`GET /api/player/clues`
`POST /api/player/clues/{clue_id}/share`

- 列出玩家私人和公开线索
- 线索分享机制：
  - `share_full_text=true` 需 `confirm_share_full_text=true`
  - 经过 SpoilerGuard 检查
  - 未提供 `public_version` 时使用安全占位符
  - 写入 `clue_shares` 表并广播 `s2c_clue_shared` 事件（party 可见）

### 3.8 目标管理

`GET /api/player/objectives`
`POST /api/player/objectives`

- 团队目标（`type: team`）
- 个人目标（`type: personal`）
- 目标状态：`active` / `completed`

### 3.9 澄清请求

`POST /api/player/clarification`

- 玩家对模糊意图的澄清
- 目标动作 ID + 澄清文本 + 可选证据
- 5 分钟窗口期
- 60 秒冷却限制

### 3.10 协作契约

`POST /api/player/contracts`
`POST /api/player/contracts/{contract_id}/respond`
`GET /api/player/contracts`

- 多玩家协作动作契约
- 参与者决策记录
- 契约状态：`pending` / `accepted` / `rejected` / `expired`

### 3.11 玩家设置

`GET /api/player/settings`
`PUT /api/player/settings`

- `draft_analysis_enabled`：AI 动作分析开关
- `absent_policy`：缺勤策略（`idle` / `maintain_existing`）
- 房间级默认值覆盖

### 3.12 角色管理

`GET /api/player/character`
`PUT /api/player/character/note`

- 查看角色卡（HP/SAN/MP/Luck，技能，属性）
- 个人笔记创建/分享
- 角色图片上传
- 装备/物品清单（`GET /api/player/inventory`）

### 3.13 重连

`GET /api/player/sync`
`GET /api/player/ws-connection`

- 断线重连 catch-up
- 状态快照同步（`_scene_snapshot`）
- 待处理动作列表
- 客户端状态版本屏障（Client-side State Version Barrier）

### 3.14 档案

`GET /api/player/archive`

- 按类型筛选事件档案
- 类型：`narrative` / `clues` / `actions` / `skill_checks` / `citations` / `state_changes` / `messages`

### 3.15 队伍消息

`POST /api/player/team-messages`

- 玩家间 OOC 文本/语音消息
- 速率限制（3 msg/s/character）
- 来源：`text` / `voice`
- 最大长度：2000 字符
- 广播 `s2c_team_message` 事件（party 可见）

### 3.16 设备会话

`POST /api/player/device-session`

- 设备 ID 声明
- `takeover` 选项（接管已有会话）
- 设备 ID 格式校验：`^[A-Za-z0-9._:-]+$`

## 4. 房主（Host）功能

### 4.1 房间管理

`GET /api/host/{room_id}`
`PUT /api/host/{room_id}`

- 查看房间完整状态
- 更新房间设置
- 验证身份：`X-Owner-Token` 或账号 Bearer Token

### 4.2 HUD（Head-Up Display）

`GET /api/host/{room_id}/hud`

- 实时 HUD 数据
- 包含：所有角色状态、场景信息、回合状态、事件概览
- 缓存策略：Redis TTL 60s

### 4.3 动作审查

`GET /api/host/{room_id}/action-reviews`
`POST /api/host/action-reviews/{review_id}/resolve`
`POST /api/host/action-reviews/{review_id}/recalculate`

- 列出待处理审查请求
- 审查决议：`accepted` / `modified` / `rejected`
- 状态补偿：通过 `StateService.apply_change()` 应用补偿变更
- 骰值重算：更换难度等级（`regular` / `hard` / `extreme`），不改变世界状态
- 验证 roll receipt 完整性

### 4.4 异常处理

`POST /api/host/{room_id}/exception`

- 处理需要 Host 裁决的异常动作
- 路由到 `request_player_choice` 或 `rejected`

### 4.5 公共舞台

`GET /api/host/{room_id}/stage`

- 公共舞台投影
- 基于 `build_public_stage_projection()` 构建
- 包含：当前场景、公开事件、角色位置

### 4.6 Host 存储

`GET /api/host/{room_id}/store`
`PUT /api/host/{room_id}/store`

- 内存状态存储（`HostStore`）
- 可见事件类型白名单（`HOST_VISIBLE_EVENTS`）
- 私密事件过滤（`PRIVATE_EVENTS`）

### 4.7 WebSocket 端点

`/ws?room={room_id}&role=host&ownerToken={token}`

- 实时事件推送
- 指数退避重连
- 断线后自动清理

### 4.8 回合控制

`POST /api/host/{room_id}/turn/resolve`
`POST /api/host/{room_id}/turn/skip`

- 手动触发回合结算
- 跳过当前回合
- 查看回合状态

### 4.9 战役管理

`GET /api/host/{room_id}/campaign`
`POST /api/host/{room_id}/campaign/finalize`

- 战役概览
- 战役终结（`finalize_campaign`）
- 只读/终结状态机

## 5. AI 守秘人系统

### 5.1 AI Gateway

`AiGateway`（`ai/gateway.py`）——统一 AI 调用入口

**Provider 链路**（按优先级）：

```
MCP → DeepSeek → 管理员配置的 OpenAI-compatible → 本地回退
```

**支持的 task type：**

| task type | 说明 | 校验 schema |
|-----------|------|-------------|
| `analyze_director_action` | 分析玩家意图 | DirectorPlanDTO |
| `narrate_action` | 生成叙事 | NarrationResultDTO |
| `resolve_turn` | 回合结算 | KpResponse |
| `generate_map` | 地图生成 | MapData |
| `extract_structure` | 剧本结构提取 | ScenarioKnowledgeGraph |
| `suggest_combat` | 战斗建议 | CombatRoundSuggestion |
| `answer_knowledge` | 知识问答 | KnowledgeAnswer |
| `generate_scene_image` | 场景图片生成 | SceneImageData |

### 5.2 Director

`Director`（`ai/director.py`）——玩家意图理解

```
输入：玩家自然语言意图 + 上下文（角色、场景、runtime package、recent events）
输出：DirectorPlanDTO
  - interpreted_intent：解读后意图
  - intent_type：意图类型
  - intent_contract：意图契约（target/method/object/constraints/resources/conditions/visibility/ambiguities）
  - mechanic_plan：机制计划
  - state_patch：状态变更建议（advisory_only）
  - citations：引用
  - confidence：置信度
  - semantic_progression：语义推进信息
  - action_steps：复合动作步骤
```

**路由逻辑：**
- `confidence < 0.6` 或模糊意图 → `player_clarification_required` → `host_exception`
- `confidence >= 0.6` → `director_plan_validated` → 继续结算

### 5.3 Narrator

`Narrator`（`ai/narrator.py`）——叙事生成

- 基于已验证 Director plan + 确定性规则结果生成公开叙事
- 严格 fact-ref 校验：叙事只能引用 runtime package 中声明的 `allowed_facts`
- 校验失败 → `build_verified_narration()` 本地回退（直接从场景文本渲染，不调用 AI）
- 支持风格包（`style_pack_version`）

### 5.4 Mechanic Compiler

`MechanicCompiler`（`ai/mechanic_compiler.py`）——自然语言→游戏机制

- DeepSeek API 模式（配置 API key 时）
- 本地正则兜底模式（无 API key 时）
- 输出：`MechanicCompileResult`（triggers + mechanics + explanations）

### 5.5 Rule Policy Compiler

`RulePolicyCompiler`（`ai/rule_policy_compiler.py`）——规则策略编译

- 从规则源元数据编译运行策略
- 输出：`policy` 对象（含 `max_bonus_dice`、`allow_luck_spend`、`allow_pushed_roll`、`low_skill_fumble_min`）
- 来源签名验证（`rule_policy_sources_signature`）

### 5.6 RAG 检索

`RAGStore`（`ai/rag.py`）——规则书检索

- 基于 pgvector 的语义检索
- 分块存储（`document_chunks` 表，`vector(768)` 列）
- 检索端点：`POST /api/rag/search`、`GET /api/rag/chunks/{chunk_id}`

### 5.7 Hybrid Embedding

`HybridEmbedding`（`ai/embedding.py`）——混合嵌入

- 优先：`text2vec-base-chinese`（sentence_transformers）
- 回退：确定性 SHA-256 哈希向量（768 维）
- 保证无外部依赖也能运行

### 5.8 AI Provider 配置

`AiProviderConfigStore`（`ai/provider_config.py`）——外部 AI Provider 管理

- CRUD 操作
- 单活跃 Provider
- 连通性测试（`test_status = 'passed'` 才能激活）
- API 密钥加密存储（Fernet + HKDF）
- SSRF 防护
- 审计日志（`ai_provider_config_audits` 表）

### 5.9 KP MCP Server

独立服务（`kp_mcp_server/`，端口 9100）

- ASGI 应用（`server.py`）
- 核心逻辑（`kp_brain.py`）
- Prompt 契约：

| 文件 | 说明 |
|------|------|
| `prompts/soul.md` | KP 人格设定 |
| `prompts/rules.md` | 规则说明 |
| `prompts/contract.md` | 调用契约 |

### 5.10 Provider Health

`ProviderHealth`（`ai/provider_health.py`）——Provider 健康监控

- 健康检查
- 失败计数
- 自动降级

### 5.11 决策审计

`DecisionAudit`（`ai/decision_audit.py`）——AI 决策审计

- 按 task type 声明允许字段白名单
- 禁止字段自动删除（token/密码/私人笔记等）
- 审计日志持久化

## 13. 安全机制

### 13.1 鉴权体系

| 角色 | 凭据 | 传递方式 |
|------|------|---------|
| 房主 | `owner_token` | `X-Owner-Token` Header |
| 玩家 | `player_token` | `X-Room-Token` Header |
| 管理员 | JWT | `Authorization: Bearer` Header |
| 账号 | JWT | `Authorization: Bearer` Header |

### 13.2 反剧透（SpoilerGuard）

`SpoilerGuard`（`engine/spoiler_guard.py`）

- 构建敏感项索引（真相/结局/隐藏 NPC/隐藏线索）
- 确定性匹配
- 发现违规时生成重试 prompt
- 二次违规回退到模板化安全叙述
- 被 Pipeline、ProjectionDispatcher、clue share 等多处调用

### 13.3 动作安全层

**ActionPolicy**（`engine/action_policy.py`）：

- 分析意图文本中的事实声明模式（"已经拿到"、"自动成功"）
- 检测 unsafe candidate markers
- 分类：`allow` / `clarify` / `reject` / `timeout_safe_effect`

**RiskContract**（`engine/risk_contract.py`）：

- 伤害风险声明契约
- `categories`：伤害类型与最大等级（`low/medium/high`）
- `excluded_tags`：排除标签
- `default_harm`：NPC/场景默认伤害等级
- `irreversible_controls`：不可逆后果清单
- `hidden_checks`：隐藏检定声明来源

**HostAutonomy**（`engine/host_autonomy.py`）：

| 策略 | 说明 |
|------|------|
| `host_required` | 等待 Host 上线 |
| `conservative` | 仅安全动作自动路由 |
| `delegated` | 信任 AI 处理大部分场景 |

**RevealLedger**（`engine/reveal_ledger.py`）：

- 知识授权的权威、只增账本
- `validate_proposals()`：检查事实揭示条件
- 映射到 `s2c_fact_revealed` / `s2c_fact_corrected` / `s2c_fact_safety_event`
- `RevealPolicyError`：玩家安全的错误码

### 13.4 素材上传安全

- 扩展名白名单（`ALLOWED_EXTENSIONS`）
- 危险扩展名拦截（`BLOCKED_EXTENSIONS`）
- MIME 类型校验（`ALLOWED_MIME_TYPES`）
- 魔术字节文件头检查（`MAGIC_BYTES`）
- 大小限制 50MB

### 13.5 AI Provider 安全

- API 密钥加密存储（Fernet + HKDF）
- SSRF 防护（阻止云 metadata 地址）
- 连通性测试要求
- 审计日志

### 13.6 加入速率限制

- 5 次/60s/IP
- 内存计数器
- 账号级别速率限制

### 13.7 XML 安全

- `defusedxml.defuse_stdlib()` 防御 XXE / billion-laughs

## 附录：关键设计约束

1. **AI 不写状态**：AI 只输出建议，HP/SAN/物品/线索/场景进度必须 Engine 校验后写入。
2. **Player 不越权**：所有写操作走 `POST /api/player/intent`，不接受前端传入 characterId 作为身份。
3. **Host 不判定**：Host 只消费事件播放公共演出，不承载规则逻辑。
4. **房主不剧透**：房主可开房/暂停/急救，但不能看到完整真相或未发现线索。
5. **PDF 本地优先**：剧本原文本地存储，云端 AI 只接收处理所需片段。
6. **MVP 不做网络流式叙事**：`narrative_text` 完整文本下发，客户端本地打字机播放。
7. **不做任意事件回滚**：只有检查点恢复，无分支时间线。
8. **Embedding 本地优先**：优先 `text2vec-base-chinese`，回退确定性 SHA-256 哈希向量。
9. **Redis 可选**：`REDIS_URL` 为空时缓存层透明 no-op。
10. **Agent 可选**：`AGENT_ENABLED` 控制 GameAgent + GameLoop。
11. **state_version 仅世界状态变更递增**：动作入队、ready_toggle、空变更不递增。
12. **character_runtime_state 是权威来源**：HP/SAN/MP/Luck 以此为准。
13. **事件按 audience 严格过滤**：`_can_player_see_event()` 是唯一可见性判定入口。
14. **AI 叙事必须通过 fact-ref 验证**：未声明的 fact_ref 触发本地回退。
15. **AI Provider 配置加密存储**：Fernet 加密 + 连通性测试要求。
16. **Director 不写状态**：`state_patch` 为 `advisory_only`，必须 Engine 验证。
17. **动作状态机严格校验**：非法跃迁直接抛异常。
18. **组决策默认沉默即拒绝**：超时未响应视为拒绝（fail-closed）。
19. **单人冒险节点完整性校验**：运行时拒绝无效跳转。
20. **审计日志字段白名单**：敏感字段在审计前自动删除。
