对。既然产品定位已经改成：

> **AI 是正式 KP，所有人类都是玩家；房主只负责房间管理和无剧透应急。**

那么页面也必须彻底摆脱传统 VTT 的“玩家端 + KP 后台”结构。

最关键的页面原则是：

# **所有人使用同一套玩家界面，房主只多一个“桌务抽屉”**

房主不能拥有另一套能够查看完整地图、幕后真相、隐藏线索、NPC 动机的 KP 页面。否则产品仍然会退回“人类 KP + AI 助手”。

---

# 一、先把三个身份名称固定

建议产品内不再把人类房主称为“主持人”。

| 身份 | 页面名称 | 权限 |
|---|---|---|
| `Player` | 玩家 | 操作自己的角色、推理、交流 |
| `RoomOwner` | 房主 | 创建房间、邀请、成员管理、结束房间 |
| `TableSteward` | 桌务 | 暂停、恢复、处理系统故障、发起无剧透裁定 |
| `AIKeeper` | AI-KP | 掌握完整模组、扮演 NPC、推进剧情、组织裁决 |

同一个人可以同时是：

```text
Player
+ RoomOwner
+ TableSteward
```

但不会因此获得：

```text
隐藏模组
完整地图
未发现线索
NPC 真实动机
其他玩家私人笔记
其他玩家私密结果
```

更严格地说：

> **桌务权限是一组操作能力，不是一种内容可见性。**

---

# 二、页面权限必须分成“内容权限”和“操作权限”

这是产品架构的底线。

| 能力 | 普通玩家 | 房主 / 桌务玩家 |
|---|---:|---:|
| 查看自己的角色状态 | 是 | 是 |
| 查看 Party 公开内容 | 是 | 是 |
| 查看自己的私密线索 | 是 | 是，仅自己的 |
| 查看其他玩家私密线索 | 否 | 否 |
| 查看其他玩家私人笔记 | 否 | 否 |
| 查看完整模组真相 | 否 | 否 |
| 查看隐藏地图 | 否 | 否 |
| 查看 NPC 真实动机 | 否 | 否 |
| 创建房间、邀请成员 | 否 | 房主可以 |
| 暂停、恢复 Session | 否或投票 | 桌务可以 |
| 处理系统异常 | 否 | 桌务可以 |
| 选择无剧透恢复方案 | 可参与投票 | 桌务可以提交 |
| 直接修改 HP、物品、剧情状态 | 否 | 否 |
| 查看完整 AI 隐藏上下文 | 否 | 否 |

真正拥有 `keeper_internal` 内容权限的是 AI-KP 运行时，而不是人类房主。

# 三、整个用户页面只需要七个主要入口

```text
1. 大厅 Lobby
2. 继续战役 Continue
3. 游戏主页面 Play
4. 调查工作台 Investigation
5. 角色与物品 Character
6. 地图 Map
7. 本局总结 Session Handoff
```

房主不增加一套独立 KP 导航。

只在右上角增加：

```text
[桌务中心]
```

它是一个抽屉或侧边面板，不是幕后控制台。

另外可以提供一个可选的：

```text
公共舞台 Public Stage
```

用于电视、投影仪或 Discord 直播共享。

# 四、全局页面外壳

所有活跃游戏页面共用一个顶部状态栏。

```text
┌──────────────────────────────────────────────────────────────┐
│ 圣玛丽医院 · Session 4   游戏时间 23:20   AI-KP 正常   在线 4/4 │
│ [继续战役] [游戏] [调查] [角色] [地图]                 [桌务] │
└──────────────────────────────────────────────────────────────┘
```

顶部至少显示：

| 信息 | 作用 |
|---|---|
| 战役公开名称 | 确认所在房间 |
| Session 编号 | 长团连续性 |
| 游戏内时间 | 区别于现实时间 |
| AI-KP 状态 | 正常、较慢、降级、恢复中 |
| 网络状态 | 在线、重连、离线 |
| 房间状态 | active、paused、recovery |
| 未处理事项数字 | Luck、复核、协同行动等 |
| 桌务入口 | 只有具备桌务能力的人可见 |

AI 状态不能只有“正在输入”。

应区分：

```text
正常主持
正在结算
等待玩家决策
服务降级
一致性恢复中
房间已暂停
```

不能把所有内容都显示成相同的聊天气泡。

```text
空气中有纸张受潮后的霉味。
```

```text

不会触发行动
```

```text

等待确认

正在裁决
```

```text
仅你可见
```

不显示它是否符合原模组。

# 八、固定输入区要明确输入行为

输入框上方使用模式按钮：

```text
[行动]
[角色发言]
[队伍讨论]
[规则提问]
[私人笔记]
```

这是降低自然语义误执行的第一层保障。

---

## 行动

进入语义理解、确认、规则和状态链。

```text
我假装整理书桌，观察院长听到失踪病人时的反应。
```

---

## 角色发言

作为角色说话，AI-KP 控制 NPC 回应。

它可能引出检定，但不会把语言本身直接写成成功结果。

---

## 队伍讨论

只发送给队伍：

```text
我们是不是应该先检查 B-17？
```

不会创建行动。

---

## 规则提问

例如：

```text
Luck 可以在这次检定后使用吗？
```

不消耗行动，不推进剧情。

---

## 私人笔记

默认：

```text
仅本人可见
不发送给队伍
不发送给桌务
不进入 AI 上下文
```

玩家可以主动打开：

```text
允许个人 AI 帮助整理
```

# 九、玩家行动页面表现

玩家输入：

> 我假装整理书桌，看看院长听到“失踪病人”时有没有异常，但不碰他的私人信件。

```text
[目标：院长]
[方式：观察反应]

[限制：不碰私人信件]
```

然后弹出意图确认卡：

```text

├──────────────────────────────────────┤
│ 你会以整理书桌为掩饰，提到“失踪病人”， │
│ 同时观察院长的反应。                  │
│                                      │
│ 不会做：                             │

│ · 不触碰私人信件                     │
│                                      │
│ 可能检定：心理学                     │
│                                      │
│ 公开影响：                           │
│ 院长会听到你提及“失踪病人”。          │
├──────────────────────────────────────┤
│ [确认行动] [修改理解] [取消]          │
└──────────────────────────────────────┘
```

玩家确认后，输入框区域变成：

```text

```

不能让玩家不确定是否需要再点一次。

```text
│ B. 撤回之前描述：铁门实际锁着          │
│    影响：系统会向全桌说明前一句为口误   │
│                                      │
│ C. 保持不确定                         │
│    影响：需要玩家现场检查              │
│                                      │
│ [选择 A] [选择 B] [选择 C]            │
│ [发起全桌投票]                        │
└──────────────────────────────────────┘
```

不能显示：

```text
原模组正确答案是 B
门后存在最终线索
选择 A 会绕过第三幕
```

桌务选择之后，页面显示：

> 该选择将成为本桌当前事实。  
> AI-KP 会调整后续场景，不判断该决定是否符合原模组。

这正好落实：

> 人类即使做了“错误决定”也没有关系。

# 十八、桌务动作流

## 正常游戏时

桌务和其他人完全一样：

```text
输入行动
确认语义
查看裁决
整理线索
使用角色和物品
```

不会每回合审批 AI。

---

## 出现事故时

```text
系统自动重试
→ 一致性验证器尝试修复
→ 保守降级
→ 必要时暂停相关事务
→ 桌务收到 Blind Recovery Card
→ 桌务选择安全继续方式或发起投票
→ 生成 TableRuling
→ 系统生成 CanonPatch
→ AI-KP 继续主持
```

---

## Session 结束时

桌务可以点击：

```text
结束本局
```

系统生成：

```text
Session Handoff
本局状态变化
调查变化
角色与物品变化
未完成决定
队伍下次计划候选
```

玩家共同确认：

```text
下次先调查 B-17
```

然后生成每个玩家的 Continuity Packet。

桌务不需要写完整总结。

# 最终页面设计原则

整套页面应该让用户明确感受到：

> **AI-KP 在主持游戏，所有人类都在玩游戏。**

玩家主页面负责：

```text
理解情境
表达行动
看懂裁决
整理调查
管理角色
继续战役
```

房主只额外负责：

```text
管理房间
保障流程
处理异常
```

但永远不需要打开幕后剧本。

最终页面定位可以收敛为：

> **同一张玩家桌面承载所有人的游戏体验；房主只多一个无剧透桌务层。AI-KP 掌握真相，人类只处理自己看得见、能够共同接受的桌面现实。**
