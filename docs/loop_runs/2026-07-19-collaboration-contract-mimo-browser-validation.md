## 浏览器协同复验与场景调度修复（2026-07-20）

1. 旧验收标签已变为浏览器“无法访问此站点”错误页；在同一浏览器新建 `http://127.0.0.1:5180/player/d1790320` 后，P1 正常恢复自然语言行动、协同行动、AI 阶段和资料侧栏。P2--P4 与 Host 公共舞台分别从 `:5181`--`:5184` 载入。
2. P1 邀请 P2、P3 共同执行“检查门锁、警戒走廊”。P2、P3 可见接受/拒绝入口；P4 不含共同意图；Host 公共舞台只保留公开场景和角色状态，不含共同意图或合同 ID。
3. P2、P3 均接受后，P1--P3 分别获得高风险确认卡。刷新/实时连接恢复后，三张卡均展示“确认后才会进入裁决”；此阶段没有 `actions` 自动执行，P4 仍无合同内容。
4. 仅 P1 点击“确认并提交”。P2、P3 的确认卡保持不变，公共舞台没有提前投影；P1 显示“已进入队列 / 正在裁决”。等待一个 AI 周期后仍未完成，且没有出现伪叙事或隐私泄露。
5. 根因已追溯为：活跃场景也把行动写入 `scene` 回合，而调度器只会在全员提交时结算；超时工作器又只扫描 `combat` 回合。因此场景中的单人确认会永久排队。修复后，只有活跃战斗才绑定 `combat` 回合；场景行动保持单人非终态互斥并直接调度结算。新增回归覆盖“场景不等待全员”和“战斗不复用旧场景回合”。
6. 当前隔离服务 `:3006` 为无热重载进程，环境策略禁止本轮替换或新增后台进程，因此上述浏览器实例仍运行旧后端。修复后的浏览器结算、MIMO 供应商调用和公共舞台投影必须在用户重新启动当前工作区服务后复验；在此之前不得把第 4 步标记为通过。
