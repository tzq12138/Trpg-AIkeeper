# 02：核心用户旅程与生命周期

## 术语

```text
ScenarioPackage / ScenarioVersion
    -> Campaign
        -> Room
            -> Session
                -> Scene
                    -> PlayerAction
                        -> ResolutionTransaction
                            -> RuleResult + StateChange + Event + Projection
```

- `ScenarioPackage`：可准备、可发布的模组内容集合；`ScenarioVersion` 不可变。
- `Campaign`：一组玩家对固定模组版本的实际游玩实例；M0 可以由单个 Room 承载，但语义不得混同。
- `Room`：成员、凭证、实时连接和当前访问边界。
- `Session`：一次开始到结束或暂停恢复的游玩过程。
- `Scene`：当前可交互情境及其玩家可见投影。
- `PlayerAction`：玩家声明、理解、确认和状态机记录。
- `ResolutionTransaction`：一次可审计的权威裁决，关联输入、规则、状态差异、事件和回执。

## 黄金路径

1. ScenarioPreparer 发布一份经人工校验的 `ScenarioVersion`。
2. RoomOwner 建房并绑定版本；玩家使用独立凭证加入、选择或绑定角色。
3. 开局前完成 Session 0：内容提示、边界确认、AI/Host 方式说明、隐私与设备说明。
4. Engine 创建 Session 和开场 Scene；Shared Stage 若存在，只接收 party-safe 投影。
5. 玩家以自然语言提交 `PlayerAction`。低风险明确行动可直接进入解析；模糊或高影响行动必须显示 Intent Contract。
6. 玩家确认后，Engine 验证身份、版本、前置条件、规则和状态版本；生成权威 `RuleResult` 与 `StateChange`。
7. AIKeeper 只能依据已验证结果生成叙事；Engine 写入 Event、Projection 和 `Resolution Receipt`。
8. 私密线索先归属获得者；分享产生新的队伍可见摘要，不复制未授权原文。
9. 断线客户端以检查点、事件序号和状态版本恢复；不得依赖 Shared Stage 或重新执行已提交事务。
10. Session 正常结束或从暂停安全结束，生成 party-safe 与 player-private 摘要，并保留只读回顾与追加式纠错链。

## 行动状态与失败分支

`analyzing -> awaiting_confirmation -> queued -> batched -> resolving -> completed` 是正常路径。行动可在适用状态下进入 `canceled`、`rejected`、`timeout`、`awaiting_player_choice`、`awaiting_host_exception` 或 `sync_required`。

- 模糊意图：给出 2–3 个理解候选；玩家未确认前不得写状态。
- 高影响意图：必须说明技能、难度、可见影响和脱敏依据；幸运、孤注一掷等额外消耗需二次确认。
- AI 或网络故障：保留权威状态；明确低风险动作可由本地规则链处理，其余进入可恢复状态或异常队列。
- 结算后争议：不静默重写历史；玩家提交原意与异议，系统产生追加式审查和补偿记录。
- 安全暂停：立即停止继续叙事和交互推进；恢复时从最后权威检查点继续。

## 生命周期不变量

1. 已提交事务必须可用幂等键、事件序号和状态版本唯一识别。
2. 任何投影都只是状态的可见切片，不能反过来证明或决定状态完成。
3. 叙事和摘要只能使用对应受众可见事实；它们不是新事实的写入口。
4. 回滚不得覆盖已见历史；纠错、补偿和认知修正均以追加事件表达。
