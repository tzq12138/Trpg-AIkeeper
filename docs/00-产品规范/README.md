# AI-Keeper M0 产品规范

这里是 AI-Keeper 的唯一 M0 产品定义入口。工程实现、测试计划、模块 PRD 和验收报告必须优先引用本目录；历史分析和旧设计只可作为 [证据档案](../90-归档/方向性问题头脑风暴/README.md)。

## 阅读顺序

1. [产品宪法](./00-产品宪法.md)：产品为何存在、为谁服务，以及 M0 不做什么。
2. [运行模式、角色与权限总表](./01-运行模式、角色与权限总表.md)：人、设备与服务的边界。
3. [核心用户旅程与生命周期](./02-核心用户旅程与生命周期.md)：从备团到结束与恢复的唯一语义。
4. [领域对象与唯一权威矩阵](./03-领域对象与唯一权威矩阵.md)：谁可以写什么、谁只能提出建议。
5. [M0 范围、里程碑与指标](./04-M0范围、里程碑与指标.md)：范围、Gate、验收与学习指标。
6. [跨域安全与非功能基线](./05-跨域安全与非功能基线.md)：安全、隐私、可访问性、性能和恢复下限。
7. [决策记录 ADR](./06-决策记录 ADR.md)：重大取舍、失效关系和裁决追溯。

## 规范优先级

出现冲突时，按以下顺序处理：

1. 本目录中的 ADR；
2. 本目录其余 `normative` 文档；
3. 被 ADR 明确接纳的模块 PRD；
4. 工程实现、测试和验收报告（实现证据，不改变产品定义）；
5. `candidate`、`exploratory`、`deprecated` 和 `archived` 文档。

任何改变 M0 主命题、运行模式、状态权威或 Shared Stage 边界的提案必须新建 ADR，不能只在模块文档或代码中改写。

## 快速不变量

- M0 只支持 `ai_only`：没有真人 KP 的剧情裁决职责。
- Engine 是唯一权威状态写入者；AI、玩家和投影端都只能提出输入或接收结果。
- 权威规则结果先于叙事；叙事不能回写骰点、状态、真相或结局条件。
- Shared Stage 是 party-safe 的可选只读镜像；其断线、关闭或未连接不得阻塞行动完成。
- 每项高影响或模糊行动必须能够被解释、确认、回执、恢复和追加纠错。
