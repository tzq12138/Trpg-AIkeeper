# 01：运行模式、角色与权限总表

## M0 运行模式

M0 的唯一运行模式为 `ai_only`。AIKeeper 负责受证据约束的理解、建议和叙事；Engine 执行规则、权限和状态提交。`Host` 不是规范概念：旧代码中的 Host 名称只能作为兼容别名，不能据此推导角色权限。

## 人、设备与服务

| 名称 | 类型 | 可见信息 | 允许操作 | 明确禁止 |
|---|---|---|---|---|
| ScenarioPreparer | 开局前的人 | 模组原件、结构化包、质量报告 | 准备、校验、发布固定版本 | 进入已开局房间裁决剧情 |
| RoomOwner | 人 | 房间成员、party-safe 运行信息、脱敏操作审计 | 建房、邀请、成员管理、开始/结束 Session | 阅读幕后真相、玩家私密原文、裁决隐藏事实 |
| TableSteward | 人，可与 Owner 同人 | 操作状态与脱敏安全信号 | 暂停、恢复、X-card、故障恢复、提出纠错请求 | 按幕后真相修改剧情结果 |
| Player | 人 | 本角色已知信息、获授权队伍信息、自己的私密内容 | 输入行动、确认、撤回、申诉、管理/分享自己的线索 | 读取其他角色私密信息或内部秘密 |
| SharedStage | 公共设备 | party-safe 公共投影 | 只读展示、重连、播放本地表现 | 写业务状态、确认行动、读取私密内容 |
| AIKeeper | 服务 | 经过策略筛选的事实、角色认知、规则输入和公开上下文 | 解析意图、提出计划、生成叙事和澄清 | 掷权威骰、直接写状态、创造运行时 Canon |
| Engine | 服务 | 完成权限与规则所需的受控数据 | 身份校验、规则结算、状态提交、事件和投影生成 | 用自由叙事越过模组和规则约束 |

## 权限原则

1. 同一人可持有多个“人”角色，但凭证和审计主体必须分离。
2. 真相访问权不从房间所有权、设备接入权或管理员 UI 自动推导。
3. 所有权威写入都通过 Engine 产生 `ResolutionTransaction`；没有“房主直接修正世界”的隐式通道。
4. Player 的取消权只适用于尚未进入不可逆结算窗口的自身行动；结算后只能追加纠错请求。
5. 安全暂停不要求说明理由，不依赖 RoomOwner 在线，也不暴露触发者身份。

## Shared Stage 规则

Shared Stage 只维护本地视觉播放状态。业务事实、行动完成、骰子、线索获得、暂停和恢复均以 Engine 事件与状态版本为准。Stage 延迟、断线、关闭、拒绝显示或重播失败都不得阻塞 Engine 提交或玩家终端的恢复。

## Human Keeper 边界

Human Keeper 是 Later 模式的独立产品选择，不是把 RoomOwner 或 TableSteward 临时升级为剧情裁判。引入该模式前必须新增运行模式、真相访问、审计、争议处理和状态写入边界的 ADR。
