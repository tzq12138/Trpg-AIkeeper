# 03：领域对象与唯一权威矩阵

“AI 不直接写状态”不是指 AI 没有作用，而是任何 AI 建议都必须经由 Engine 验证、提交并留下事务证据。每个对象只有一个权威写入者；其他组件最多拥有受控读取、建议或投影责任。

| 对象/事实 | 唯一权威 | 允许输入者 | 可见输出 | 禁止路径 |
|---|---|---|---|---|
| 模组定义、来源、版本与素材绑定 | ScenarioPackage / 发布流程 | ScenarioPreparer、受审计编译器 | 质量报告、已发布版本 | 运行时 AI 改写已发布 Canon |
| Campaign 运行事实与检查点 | Engine State | 已验证的 ResolutionTransaction | 授权状态快照 | Stage、AI、Owner 直接写入 |
| 骰子、技能、SAN 与规则结果 | Rule Executor（由 Engine 调用） | 已确认行动与规则版本 | RuleResult、脱敏解释 | AI 或玩家口述骰点成为权威 |
| PlayerAction 生命周期 | Transaction 服务 | Player、系统恢复逻辑 | 个人回执、队列状态 | 前端本地状态替代服务器终态 |
| 状态变化 | Engine State | 经过验证的 RuleResult / 批准补偿 | StateChange、版本号 | 叙事文本直接修改 HP、SAN、位置或库存 |
| 线索归属、分享和认知版本 | Clue / Knowledge 服务 | Engine 事件、拥有者授权分享 | 私密、队伍或公共摘要 | 其他玩家读取原线索；AI 擅自升格猜测 |
| 事件事实与审计 | Journal / Event Log | Engine、受控安全操作、补偿服务 | 按受众投影的事件流 | 静默覆盖或删除已见事实 |
| 可见投影 | Projection 服务 | Engine 事件、受众策略 | player / party / stage-safe 视图 | Projection 回写业务事实 |
| 叙事文本 | AIKeeper | 已验证 Director/Rule/State 上下文 | 受众安全叙事 | 叙事创造新 Canon 或改写 RuleResult |
| Shared Stage 播放状态 | SharedStage 客户端 | party-safe Projection | 本地画面和播放进度 | ACK 阻塞 Action 或 StateChange |
| 安全边界与私密反馈 | Safety 服务 | Player、TableSteward | 最小必要操作信号 | 将私密原文默认交给 Owner、AI 或 Stage |

## 权威提交顺序

```text
Player input
  -> Intent analysis / player confirmation
  -> Engine authorization and precondition check
  -> Rule Executor
  -> Engine State commit
  -> Event Log
  -> Projection
  -> AI narration from committed result
```

AIKeeper 可以在“Intent analysis”产生候选理解或在最后生成叙事，但不能跳过 Engine。若 AI 输出与模组证据、权限或规则冲突，Engine 拒绝该计划并进入澄清、降级或异常恢复；不得用更流畅的叙事掩盖冲突。

## 可见性层

| 层级 | 含义 | 典型对象 |
|---|---|---|
| `internal` | 仅系统和受控编译流程可读 | 原始模组、隐藏前置条件、密钥 |
| `player_private` | 单个角色/玩家可读 | 私密线索、个人笔记、个人回执 |
| `party` | 已获授权的队伍成员可读 | 分享摘要、公共目标、共同状态 |
| `stage_safe` | 可以公开展示且不依赖观众身份 | 队伍安全叙事、公共场景投影 |

共享信息的提升必须产生新的授权事件；删除、纠错和认知变化同样以追加事件表示。
