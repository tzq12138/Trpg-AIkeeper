# 平台能力分层与 MVP 边界

## 核心判断

AI-Keeper 不应先做成 Roll20 或 Foundry 的完整替代品。普通网团平台的核心是聊天、地图、骰子和角色卡；AI-KP 平台的核心是有状态世界引擎：玩家提交意图后，系统能防越权、防剧透、防 AI 幻觉，并把权威结果分别投影给 Host 和 Player。

第一轮路线锁定：

```text
玩家意图 -> AI 裁决建议 -> Engine 事务 -> 权威状态变更 -> 分层投影 -> 事件日志/复盘
```

## 能力分层

| 层级 | 模块 | 优先级 | 第一轮口径 |
|---|---|---:|---|
| 核心链路 | 权限、意图网关、事务、状态、投影、日志 | P0 | 必须稳定，所有后续能力都依赖它。 |
| AI 安全 | 真相锁定、反幻觉、可见上下文过滤、AI 输出校验 | P0 | AI 只给建议，不直接写状态。 |
| 跑团基础 | 房间、玩家加入、角色卡、骰子、公共/私密频道 | P0 | 保持可跑一条文字团主链路。 |
| COC 内容层 | 世界书、NPC、线索、道具、日志、档案 | P0/P1 | 先服务 COC，不追求多规则完整生态。 |
| Host/Player 体验 | Host 公共舞台、Player 手机端、等待室、回执 | P0/P1 | 体验服从核心链路，不做过度视觉扩展。 |
| 工程稳定性 | 断线重连、快照恢复、测试库隔离、日志落盘 | P0 | 开发态稳定优先于新功能。 |
| 剧本准备 | PDF 导入、质量报告、一键开房、原文引用 | P1 | 当前已有实现，后续补稳定和校验。 |
| 素材与模组 | 资源库、模组编辑器、导入导出、版本管理 | P1/P2 | 第二阶段后再做。 |
| 平台外围 | 日程招募、安全边界工具、Admin/Ops、成本控制 | P1/P2 | 上线前逐步补齐。 |
| 生态商业 | 社区广场、付费市场、插件市场、直播适配 | P2/P3 | 不进入第一轮。 |

## MVP 必做

| 能力 | 验收标准 |
|---|---|
| 房间与身份 | 房主能创建房间，玩家能加入，Host/Player 权限分离。 |
| Player 意图入口 | 玩家所有写操作只走 `POST /api/player/intent` 或明确的 Player 受控接口。 |
| Engine 权威写入 | AI、Host、Player 都不能直接修改权威状态。 |
| 事务与投影 | 一次裁决能同时生成 Host 公共演出、Player 私密反馈和事件日志。 |
| AI 裁决安全 | AI 输出必须结构化校验，越权状态变更和未授权真相不能落库。 |
| 线索与防剧透 | 私密线索默认只给拥有者，主动分享后才产生团队可见版本。 |
| 断线重连 | Player 刷新或断线后能恢复快照、pending action 和私密信息。 |
| 日志与复盘 | 行动、骰子、状态变化、线索获得都能追溯。 |

## 第一轮不做

以下能力有价值，但不进入当前 DeepSeek 第一轮：

```text
语音视频
社区广场
付费市场
高级动态光照
复杂插件市场
完整多规则支持
AI 地图生成
OBS/直播适配
复杂日程招募
完整素材 CDN
```

这些能力不是丢弃，而是统一沉淀到 [平台补全文档索引](../40-平台补全/README.md)。核心主链路通过 Batch 5 验收后，再从该目录拆第二阶段及以后任务。

## 优先级解释

- **P0**：没有它就不能稳定跑完一条 AI-KP 主链路。
- **P1**：能显著提升可用性，但可以在主链路稳定后实现。
- **P2**：平台化或商业化增强，不影响第一版验证。
- **P3**：生态和商业闭环，等核心产品被验证后再考虑。
