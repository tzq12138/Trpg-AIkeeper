# 核心链路之后的阶段路线

## 路线原则

核心链路稳定前，不扩平台外围。核心链路稳定后，也不一次性做完整 Roll20 或 Foundry 替代品，而是按“可跑团、可长团、可备团、可上线、可生态化”的顺序推进。

```text
第一轮：有状态 AI-KP 主链路
第二轮：文字网团基础体验
第三轮：内容生产和模组准备
第四轮：轻量 VTT 与素材管理
第五轮：上线前安全、运营和成本控制
第六轮：社区、插件、商业生态
```

## 阶段 1：核心主链路验收

**目标**：保证 AI-Keeper 不是聊天机器人，而是可验证的有状态世界引擎。

| 能力 | 验收结果 |
|---|---|
| 房间创建与玩家加入 | 房主开房、玩家扫码或房间码加入、ready 同步。 |
| 玩家行动入口 | 文本、按钮、语音转写后的行动都走统一意图网关。 |
| AI/规则裁决 | AI 只给建议，Engine 执行权威规则和状态写入。 |
| 投影与日志 | Host 公共演出、Player 私密反馈、事件日志一致且可追溯。 |
| 重连与状态版本 | 断线恢复不会乱序覆盖或泄露私密 patch。 |

本阶段由 `docs/30-DeepSeek任务包/` Batch 0 到 Batch 5 承接。

## 阶段 2：文字网团基础体验

**目标**：让平台即使不依赖高级地图和语音视频，也能稳定跑文字团和半语音团。

| 批次候选 | 范围 | 不做 |
|---|---|---|
| Batch 6：房间与 Session 管理 | 房间状态、Session 开始/暂停/完结、公告、席位、旁观者只读。 | 招募大厅、评价系统。 |
| Batch 7：频道与信息流 | 公共剧情、OOC、系统、骰子、私聊、消息引用、固定消息、基础搜索。 | 论坛、复杂 Thread、Reaction 体系。 |
| Batch 8：角色与 NPC 运行态 | 角色创建器最小版、角色公开/私密信息、NPC 已知信息、NPC 状态。 | 势力资源经济和完整怪物图鉴。 |
| Batch 9：世界时钟与日志摘要 | 游戏内时间、事件时间轴、Session 总结、前情提要。 | 多地点并行时间模拟。 |

**验收主线**：一个纯文字 COC 团可以连续跑多个 Session，玩家能查前情、查线索、查自己的私密信息。

## 阶段 3：内容生产和模组准备

**目标**：降低 KP 备团成本，让 AI-Keeper 能稳定从剧本资料变成可主持房间。

| 批次候选 | 范围 | 不做 |
|---|---|---|
| Batch 10：世界书编辑器 | 真相、地点、NPC、物品、事件、玩家已知层的编辑与版本记录。 | 多人协作编辑。 |
| Batch 11：模组编辑器最小闭环 | 剧本基础信息、开场场景、关键 NPC、地点、线索、结局、隐藏信息。 | 模组发布市场。 |
| Batch 12：AI 内容生成入库闸门 | NPC/地点/线索/前情提要生成后必须人工确认或 Engine 入库。 | 生成内容直接成为世界事实。 |
| Batch 13：Handout 与资源绑定 | 图片、信件、报纸、文件和线索/地点/NPC 的绑定。 | CDN、版权交易。 |

**验收主线**：上传或手工创建一个 COC 短模组后，可以通过质量报告发现缺口，并一键生成可开局房间。

## 阶段 4：轻量 VTT 与素材管理

**目标**：补齐场景、地图、Token、素材库，但保持轻量，不抢 AI-KP 主链路复杂度。

| 批次候选 | 范围 | 不做 |
|---|---|---|
| Batch 14：场景与地图轻量版 | 地图上传、场景切换、缩放拖拽、地图标记、隐藏区域。 | 动态光照。 |
| Batch 15：Token 与状态展示 | 玩家/NPC Token、可见权限、血条、状态标签。 | 完整战棋规则。 |
| Batch 16：素材库 | 图片、地图、Token、Handout、标签、权限、导入导出。 | 对象存储、CDN、素材市场。 |
| Batch 17：Host 演出增强 | NPC 立绘、阻塞字幕、演出恢复、紧急清屏、音频解锁。 | 直播和 OBS 适配。 |

**验收主线**：Host 可以用场景图、Token 和 Handout 支撑一场调查团，不需要外部 VTT 辅助。

## 阶段 5：上线前安全、运营和成本控制

**目标**：从本地可用走向多人稳定使用，避免隐私、成本和数据丢失事故。

| 批次候选 | 范围 | 不做 |
|---|---|---|
| Batch 18：跑团安全边界 | 内容分级、禁区标签、X-Card、私密反馈、Session 0 设置。 | 平台举报仲裁流程。 |
| Batch 19：后台和审计 | 管理后台、房间监控、权限审计、AI 调用日志、错误报警。 | 财务报表。 |
| Batch 20：备份与隐私 | 房间快照、数据备份、数据删除、日志脱敏、导出。 | 跨地区合规自动化。 |
| Batch 21：成本与限流 | Token 统计、模型配置、请求队列、限流、配额。 | 付费套餐。 |

**验收主线**：公开测试时，平台能限制滥用、追踪错误、恢复房间、控制 AI 成本，并尊重玩家隐私。

## 阶段 6：社区、插件和商业生态

**目标**：在核心产品留存成立后，再做规模化供给和第三方扩展。

| 批次候选 | 范围 | 不做 |
|---|---|---|
| Batch 22：日程与招募 | 开团时间、玩家可用时间投票、提醒、跑团历史、新手教程团。 | 复杂声誉系统。 |
| Batch 23：社区内容 | 模组广场、战报、收藏、评论、创作者主页。 | 付费分成。 |
| Batch 24：开放 API 与 Webhook | WebSocket 协议文档、事件 Webhook、Bot API、导出 JSON/Markdown。 | 插件市场沙箱。 |
| Batch 25：规则/角色卡插件 | 规则插件 API、角色卡插件、Prompt 插件。 | 任意代码执行插件。 |
| Batch 26：商业化 | 付费模组、订阅 KP/作者、存储配额、套餐。 | 在留存未验证前提前收费。 |

**验收主线**：第三方可以创建内容、集成外部社群工具，平台能围绕模组和跑团记录形成内容循环。

## 阶段切换门槛

| 从阶段 | 到阶段 | 必须满足 |
|---|---|---|
| 1 | 2 | 主链路回归通过，权限和投影没有 P0 漏洞。 |
| 2 | 3 | 多 Session 文字团能稳定运行并复盘。 |
| 3 | 4 | 至少一个短模组能从资料准备到一键开局完整跑通。 |
| 4 | 5 | Host/Player 基础体验不依赖外部 VTT 才能跑。 |
| 5 | 6 | 数据备份、审计、限流、隐私删除和成本统计可用。 |

## 拆批模板

后续从本路线拆 DeepSeek 任务时，每批都用同一结构：

```text
目标：一句话说明该批解决什么真实跑团问题。
范围：列出允许修改的模块和文件方向。
不做：列出明确禁止顺手扩展的能力。
数据边界：说明房间、角色、玩家、Session、模组、平台全局的归属。
权限边界：说明 Host/Player/AI/Engine 的读写权限。
验收命令：至少包含后端测试、前端类型检查或 build。
手动验收：给出一条从用户视角可走通的流程。
```
