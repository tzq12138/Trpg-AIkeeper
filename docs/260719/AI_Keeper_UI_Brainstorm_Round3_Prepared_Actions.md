# AI-Keeper UI 头脑风暴第三轮总结：预备动作

**日期：2026-07-19**  
**承接文档：`AI_Keeper_UI_Brainstorm_Round2_Combat.md`**  
**范围：预备动作的声明、锁定、触发、感知依据、目标绑定、同时触发排序、连续动作中断、失败处理、审计，以及公共大屏与玩家手机表现。**

---

# 1. 最终定义

> **预备动作是玩家放弃本轮普通主动行动，预先锁定一个完整动作；当本轮内一个明确、具体、可观察且尚未发生的条件首次有效满足时，系统按照规则时序自动执行该动作。**

预备动作不是：

- 免费反应；
- 普通行动之外的额外动作；
- 看到结果后再决定是否执行的期权；
- 由 AI-KP 自动寻找最佳时机、最佳目标或最佳感知方式的战术托管；
- 对已经完成的事件进行追溯补救；
- 跨轮自动延续的永久待机动作。

基础流程：

```text
玩家自然语言声明条件式动作
→ 系统识别为预备动作候选
→ 补齐必要信息
→ 校验触发条件、阈值与感知依据
→ 校验目标、武器、技能和未触发处理
→ 玩家确认
→ 占用本轮主动行动
→ 声明锁定
→ 等待本轮首次有效触发
→ 自动执行或因不合法而失效
→ 本轮结束后终止
```

---

# 2. 功能启用边界

只有规则包明确支持以下机制时，界面才提供预备动作：

```text
预备
延迟行动
待机动作
触发式行动
规则定义的类似机制
```

产品层不能为了 UI 顺滑自行发明预备机制。

若规则包不支持，玩家输入：

```text
如果敌人进门，我就开枪。
```

系统只能将其作为普通条件式意图交给 AI-KP 理解，不能自动授予中断时序。

---

# 3. 自然语言声明方式

玩家仍使用自然语言：

```text
如果人影越过翻倒的推车，我就用左轮向它开枪。
```

系统识别后转为确认卡，而不是直接提交：

```text
系统理解为预备动作

触发条件
走廊中的人影越过翻倒的推车

执行动作
使用左轮手枪向该人影射击

本轮未触发
动作不执行，本轮主动行动仍然消耗

[确认预备]
[改为普通行动]
[修改]
```

若信息不完整，只询问缺少的必要内容。

例如：

```text
如果门开了，我就行动。
```

系统只追问：

```text
门打开后，你准备执行什么动作？
```

不要求玩家填写复杂表单，但后台结构必须完整。

---

# 4. 预备动作消耗本轮主动行动

这是硬规则：

```text
声明预备动作
→ 本轮普通主动行动被占用
→ 角色本轮不再进行另一项普通主动行动
```

禁止：

```text
我先搜索房间；
如果怪物冲进来，我再开枪。
```

否则预备动作会变成免费反应。

手机确认卡必须明确提示：

```text
预备动作将占用你的本轮主动行动。

触发前：
你不会执行其他普通主动行动。
```

内部字段：

```text
consumesRoundAction = true
```

---

# 5. 触发条件必须具体、可观察

## 5.1 允许的条件

```text
人影越过翻倒的推车
北侧铁门开始打开
邪教徒进入安娜的近距离范围
怪物越过房间门槛
护士从口袋中拿出一件物品
目标离开公开掩体区域
```

这些条件必须具备：

- 明确对象；
- 明确事件或状态变化；
- 明确边界或阈值；
- 能够被权威事件系统判断；
- 角色能够通过锁定的感知依据确认。

## 5.2 不允许的条件

```text
如果它有敌意
如果它想攻击我
如果它是神话生物
如果它准备背叛我们
如果这是最危险的目标
如果现在是最佳射击时机
如果情况不对
```

这些条件依赖隐藏意图、未公开身份、战术最优判断或模糊主观感受。

系统提示：

```text
无法锁定该触发条件

“如果它有敌意”不能直接观察。

请改为可以实际看到或听到的事件，例如：
· 如果它举枪指向我们
· 如果它向安娜冲过去
```

---

# 6. 准备动作必须完整

锁定前必须明确：

```text
触发事件
触发阈值
触发依据
执行什么动作
具体目标或区域
使用什么武器、物品、技能或方式
本轮未触发时如何处理
有效时间
```

建议结构：

```text
PreparedActionDeclaration
├─ triggerEvent
├─ triggerThreshold
├─ perceptionBasis
├─ actionType
├─ targetBinding
├─ method
├─ toolOrSkill
├─ noTriggerOutcome
├─ validRoundId
└─ consumesRoundAction
```

完整确认卡：

```text
确认预备动作

触发条件
走廊中的人影越过翻倒的推车

触发依据
直接看见该人影越过推车

执行动作
使用左轮手枪向目标射击

目标
触发该条件的单位

可能消耗
弹药 1

本轮未触发
动作不执行，本轮主动行动仍然消耗

有效时间
仅当前战斗轮

[确认预备]
[修改]
[改为普通行动]
```

缺少关键内容时不能锁定。

---

# 7. 声明锁定后不可修改

以下内容在锁定后固定：

```text
触发事件
触发阈值
感知依据
目标或目标选择器
动作内容
武器、物品或技能
有效轮次
未触发处理
```

触发时不能：

```text
改打后面的目标
更换武器
改成其他动作
改变触发条件
改用另一种感知方式
```

系统也不能自动换目标、换武器、优化行动或使用隐藏信息修正声明。

---

# 8. 禁止追溯触发

预备动作只能响应声明锁定之后发生的新事件。

合法：

```text
门开始打开
→ 检查预备条件
→ 满足后插入预备动作
→ 结算预备动作
→ 继续后续事件
```

非法：

```text
门已经撞开
→ 敌人已经进入
→ 攻击已经完成
→ 伤害已经结算
→ 玩家提出“刚才应该触发”
```

一旦相关事实和后续动作已提交：

```text
不能倒带
不能补触发
不能局部重算
不能事后更换条件
```

---

# 9. 本轮未触发时

```text
本轮结束
→ 触发条件未发生
→ 预备动作失效
→ 本轮主动行动不返还
→ 下一轮如需继续必须重新声明
```

手机记录：

```text
预备动作未触发

触发条件：
走廊中的人影越过翻倒的推车

本轮结果：
条件未发生，预备动作未执行。
本轮主动行动已经消耗。
```

不允许备用动作、退还行动、自动跨轮保留或自动改写条件。

---

# 10. 触发后自动执行

```text
触发事件提交
→ 匹配锁定条件
→ 校验动作当前合法性
→ 自动进入规则结算
```

不再次询问：

```text
是否执行
是否放弃
是否换目标
是否换武器
```

玩家在声明锁定时已经完成最终授权。

手机：

```text
预备动作已触发

人影已经越过翻倒的推车。
正在结算射击……
```

公共大屏：

```text
人影刚越过推车，
陈默已经扣下扳机。
```

---

# 11. 触发成立但动作无法执行

若触发发生时动作已经不合法：

```text
触发条件满足
→ 动作合法性校验失败
→ 不执行
→ 不换目标
→ 不换武器
→ 不生成替代动作
→ 本轮行动仍然消耗
```

示例：

```text
预备：
人影越过推车时用左轮射击。

触发时：
左轮此前已经被打落。
```

手机记录：

```text
预备动作无法执行

触发条件已经满足：
人影越过了翻倒的推车。

无法执行原因：
左轮手枪当前不在你手中。

结果：
预备动作未执行；
本轮主动行动不返还。
```

---

# 12. 同一事件触发多个预备动作

```text
触发事件发生
→ 找出全部匹配动作
→ 校验每项当前合法性
→ 按规则优先级排序
→ 按敏捷、速度或规则指定属性排序
→ 使用规则包既有平手规则
→ 仍完全相同时使用本场稳定平手顺序
→ 逐项结算并提交状态
```

禁止按声明提交时间、网络到达时间、点击确认时间、大屏顺序或 AI-KP 叙事偏好排序。

---

# 13. 每项预备动作独立提交事务

正确链路：

```text
PreparedActionTrigger
→ RuleResolution
→ ResourceTransaction
→ StateCommit
→ RevalidateRemainingPreparedActions
```

不能先完成所有骰点再统一写入状态。

前一个动作可能导致后续动作目标倒地、离开、失效或被遮挡，因此剩余动作必须基于最新状态重新校验。

---

# 14. 本场稳定平手顺序

若规则优先级、敏捷及规则包平手条件全部相同，使用战斗开始时生成的固定顺序。

```text
战斗开始
→ 根据战斗实例与随机种子生成 stableTieBreakerRank
→ 写入 CombatOrderSnapshot
→ 整场战斗保持稳定
```

不能依据提交顺序、网络延迟、每轮重新随机或 AI-KP 判断。

新单位加入时：

- 已有单位相对顺序不变；
- 新实体获得独立 Rank；
- 离场后重回保留原 Rank；
- 断线不改变 Rank；
- 名称变化不生成新 Rank。

---

# 15. 平手顺序的 UI 可见性

默认不主动占用公共界面。

实际发生平手时，手机规则依据显示：

```text
结算顺序依据

· 动作优先级相同
· 敏捷相同
· 规则包没有其他平手条件

使用本场固定平手顺序：
陈默先于林海
```

玩家可在“更多 → 规则依据 → 本场平手顺序”查看公开参与者的安全版本。

不能泄露隐藏敌人、隐藏单位空缺、未公开 NPC 或隐藏参与者数量。

---

# 16. 同一条件一轮内出现多次

预备动作只响应本轮内第一次有效触发：

```text
进入等待
→ 第一次有效满足
→ 消费预备动作
→ 自动执行或因不合法失效
→ 后续相同事件不再触发
```

即使第一次触发时无法执行，也不能等待第二次更有利机会。

若第一次事件无法通过锁定感知依据确认，则不算有效触发，预备动作可以继续等待本轮后续有效事件。

---

# 17. 锁定时条件已经成立

若锁定时条件已经成立，不能作为预备动作。

例如人影已经在房间内：

```text
无效：
如果人影进入房间，我就开枪。
```

系统提示：

```text
该条件当前已经成立，
不能作为未来的预备触发条件。

你可以：
· 改为本轮普通射击行动
· 改为“如果人影越过北侧门槛”
· 改为“如果人影继续靠近安娜”
```

系统不能自动理解成“再次进入”。

---

# 18. 状态与事件必须区分

```text
当前状态：门已经打开
未来事件：门从关闭变为打开

当前状态：敌人在房间内
未来事件：敌人越过门槛

当前状态：邪教徒正在靠近
未来事件：邪教徒进入明确距离范围
```

预备动作必须绑定未来事件或状态跃迁，而不是当前已成立的静态状态。

---

# 19. 触发阈值必须明确

模糊条件需要规范化为明确节点。

“门被打开”需要明确为：

```text
门开始移动
门打开到足以看见门后
门完全打开
```

“邪教徒靠近安娜”需要明确为：

```text
开始朝安娜移动
进入安娜近距离范围
到达安娜身边
```

通用阈值类型：

```text
状态开始变化
越过明确边界
进入明确范围
动作完成
```

锁定后不能修改阈值，AI-KP 不能为了故事效果提前或延后触发。

---

# 20. 连续动作在触发节点暂停

若预备条件是“怪物越过门槛时开枪”：

```text
怪物从走廊开始移动
→ 到达门槛
→ 提交门槛中间位置
→ 暂停剩余移动
→ 触发预备射击
→ 提交射击结果
→ 重新校验怪物剩余移动
```

不能先把怪物移动到房间中央，再补算门槛射击。

连续动作需支持中间状态：

```text
MovementStep
├─ startPosition
├─ triggerBoundary
├─ intermediatePosition
├─ remainingPath
└─ continuationStatus
```

---

# 21. 预备动作后原连续动作自动继续

预备动作完成后：

```text
提交预备动作结果
→ 重新校验被暂停的原连续动作
```

若仍合法，从触发节点继续剩余部分。

不能重新从起点执行、再次询问行动者、由 AI-KP 改变目标，或把剩余动作视为新行动。

若角色失能、路径封闭、目标不存在或规则条件失效，则按新状态终止或改变。

---

# 22. 目标绑定方式

允许两类目标绑定。

## 22.1 具体实体

```text
目标：邪教徒 A
```

底层绑定 `entityId`，名称变化不视为换目标。

## 22.2 可观察的确定性选择器

```text
第一个越过北侧门槛的可见单位
第一个进入安娜近距离范围的公开敌对单位
第一个从门后出现并举起武器的人
```

建议结构：

```text
TargetSelector
├─ eventType
├─ areaOrBoundary
├─ observableFilters
├─ ordinal
├─ visibilityRequirement
└─ resolveOnce
```

---

# 23. 允许与禁止的选择器

允许：

```text
越过指定门槛
进入公开区域
进入明确距离
从指定方向出现
拿出可见武器
打开指定的门
第一个满足条件的单位
```

若使用“敌对单位”，敌对关系必须已经公开成立。

禁止：

```text
最危险的敌人
最适合攻击的目标
幕后主使
HP 最低的敌人
准备攻击我的人
对安娜威胁最大的人
神话生物
隐藏身份为邪教徒的人
```

这些依赖隐藏属性、战术优化或未公开身份。

---

# 24. 选择器只解析一次

触发时：

```text
匹配触发事件
→ 按锁定选择器解析唯一目标
→ 绑定具体 entityId
→ 消费预备动作
→ 不再重新选择
```

后续出现更危险或更适合的单位，也不能换目标。

---

# 25. 触发条件与目标解析必须区分

例如：

```text
门打开时，射击门后第一个可见单位。
```

门打开但门后无人：

```text
触发条件已满足
目标选择器解析失败
预备动作被消费
动作无法执行
本轮行动不返还
```

若声明是：

```text
第一个单位越过门槛时射击该单位。
```

则没有单位越过时，触发条件尚未满足。

---

# 26. 同时多个候选满足选择器

```text
匹配全部候选
→ 先比较权威事件顺序
→ 若规则上完全同时
→ 使用 stableTieBreakerRank
→ 解析唯一目标
```

不能由 AI-KP 选更危险、更近或 HP 更低的目标，也不能在触发后让玩家选择，或同时攻击多个目标。

---

# 27. 触发时无法感知

若事件发生，但角色无法通过锁定依据感知：

```text
事件发生
→ 感知校验失败
→ 不构成有效触发
→ 预备动作继续等待
```

不消耗预备动作，也不事后补触发。

角色后来看到目标已在房间内，也不能倒带触发。

---

# 28. 本轮后续仍可等待下一次有效触发

第一次相关事件不可观察时，不算有效触发。

若本轮稍后再次出现符合全部条件、并能通过锁定依据感知的事件，可以正常触发。

若声明绑定具体实体，则其他实体不能替代。

---

# 29. 感知判断使用触发时点状态

必须在事件实际发生的规则时点判断：

```text
视线
照明
遮挡
距离
听觉条件
触觉条件
有效感知能力
设备状态
角色当前状态
```

例如：

```text
触发前能看见，触发时灯熄灭 → 不触发
触发时看不见，随后灯亮 → 不补触发
触发时通过有效设备看见 → 可以触发
触发时角色昏迷 → 不触发
```

AI-KP 不能事后认定角色“应该注意到了”。

---

# 30. 安全记录不能泄露隐藏事件

若角色无权知道事件发生过，记录不能写：

```text
邪教徒曾越过门槛，但你没有看见。
```

只能写：

```text
本轮没有出现你能够观察到的有效触发事件。
```

只有角色之后合法得知相关事件时，才可以显示具体未触发原因。

---

# 31. 触发依据必须锁定

触发事件描述外部发生了什么；触发依据描述角色凭什么确认事件发生。

例如：

```text
触发事件：
北侧铁门开始向内移动

触发依据：
听见北侧铁门门轴转动的声音
```

或：

```text
触发事件：
邪教徒越过北侧门槛

触发依据：
通过走廊尽头的镜面观察
```

两者必须分开保存。

---

# 32. 允许的触发依据

只允许声明锁定时已经成立、且能够具体描述的感知渠道：

```text
直接视觉
直接听觉
直接触觉
已启用设备
明确的反射或观察媒介
事先约定的公开信号
```

示例：

```text
看见门开始移动
听见门轴转动声
感觉手中的绳索被拉紧
通过已开启的摄像头看到门口
通过镜面看到目标越过门槛
听见安娜喊出约定口令
```

---

# 33. 不允许的触发依据

```text
感觉情况不对
察觉到敌意
AI-KP 判断我应该发现
队友可能会提醒我
任何可用感官
如果有人注意到了
系统认为时机合适
```

系统应要求玩家说明具体感知方式。

---

# 34. 触发时严格使用锁定依据

例如锁定依据是门轴声音，但爆炸声完全掩盖门轴声：

```text
门开始移动
→ 听觉依据无效
→ 不触发
```

即使角色能看见门，也不能自动改用视觉，除非视觉已作为第二依据锁定。

若摄像设备断电，也不能改成“角色碰巧听见”。

---

# 35. 设备感知必须已经成立

合法：

```text
已经开启并对准北侧门的摄像机
```

不合法：

```text
我身上带着摄像机
```

设备依据至少要明确：

```text
设备是什么
是否已经启用
正在观察哪个区域
角色如何接收信息
```

若设备需要本轮拿出、启动或部署，这本身可能需要行动，不能默认与预备动作同时完成。

---

# 36. 约定信号的边界

例如：

```text
触发事件：
安娜喊出约定口令“灯灭了”

触发依据：
直接听见安娜的喊声
```

它只能证明角色听见了约定口令，不能自动证明门后有敌人、安娜看见了神话生物或当前目标有敌意。

信号可能基于误判、欺骗或错误信息。

---

# 37. 最多两个明确触发依据，使用 OR

最终采用：

> **一份预备动作最多锁定两个明确、具体的触发依据，并使用 OR 关系。任一依据在触发时点有效，即满足感知条件。**

例如：

```text
触发事件
北侧铁门开始移动

触发依据之一
直接看见铁门开始向内移动

或

触发依据之二
听见北侧铁门门轴转动的声音
```

内部表达：

```text
perceptionLogic = OR
perceptionBases = [
  direct_vision:north_door,
  direct_hearing:north_door_hinge
]
```

---

# 38. 两个触发依据的硬边界

允许：

```text
直接看见门开始移动
或
听见门轴转动声
```

允许：

```text
通过已开启摄像机看到门口
或
听见约定口令
```

不允许：

```text
任何一种我能察觉的方式
视觉、听觉、直觉或其他感官
系统找到任何可用渠道
队友或设备可能通知我
```

两个依据必须：

- 在锁定时完整列出；
- 各自具体；
- 各自已经成立或准备完成；
- 不依赖隐藏信息；
- 触发时不能增加第三种依据；
- 不能从 OR 改成 AND；
- 不能事后替换失效依据。

---

# 39. 两个依据的触发判定

```text
检查依据 A
→ 有效则触发

否则检查依据 B
→ 有效则触发

两者均无效
→ 本次不构成有效触发
→ 预备动作继续等待
```

只触发一次。

若两个依据同时有效，也只生成一次触发事务。

建议统一去重键：

```text
prepared:{preparedActionId}:trigger:{sourceEventId}
```

```text
预备动作不消耗本轮行动
触发条件依赖隐藏意图

事件完成后事后补触发
未触发时退还行动
未触发时执行备用动作
自动保留到下一轮
触发时再次询问是否执行
动作失效时自动换武器或目标
同时触发时按提交时间排序
完全平手时由 AI-KP 决定
锁定时条件已成立仍立即触发
模糊条件默认采用最早或最晚时点
连续动作完成后再补算触发

```

# 46. 最终设计原则

| 主题 | 最终决定 |
|---|---|
| 行动成本 | 消耗本轮普通主动行动 |
| 有效时间 | 仅当前战斗轮 |
| 未触发 | 失效且不返还行动 |
| 触发后 | 自动执行，不二次确认 |
| 条件 | 具体、可观察、可结构化判断 |
| 阈值 | 有歧义必须明确 |
| 当前已成立条件 | 不能锁定 |
| 修改 | 锁定后不可修改 |
| 追溯 | 禁止 |
| 多次事件 | 第一次有效触发后消费 |
| 动作失效 | 不自动换目标、武器或动作 |
| 同时触发 | 规则顺序、规则平手、稳定 Rank |
| 连续动作 | 在触发节点暂停，结算后重新校验并继续 |
| 目标 | 具体实体或确定性选择器 |
| 多候选 | 事件顺序 + stableTieBreakerRank |
| 感知 | 必须在触发时点有效 |
| 感知依据 | 锁定时明确 |
| 多感知 | 最多两个，OR |
| 隐藏信息 | 不通过条件、记录或 UI 泄露 |
| 公共大屏 | 只显示可观察姿态与结果 |
| 手机 | 显示完整声明、触发来源和规则依据 |

---

# 47. 本轮最终产品表达

> **玩家用自然语言声明预备动作，系统负责将其规范化为一份完整、可观察、可审计且只在本轮有效的条件式行动。玩家在锁定时一次性决定触发条件、一个或两个感知依据、目标和执行方式；条件首次有效满足后，规则系统按权威时序自动执行，AI-KP 只负责将已经确定的触发、中断和后续行动编排成连贯叙事。**
