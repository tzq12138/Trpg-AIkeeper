# Diceframe《玻璃雨夜》可用候选版目标

用户已确认以减少开发维护量为优先，接受 Diceframe 底座，并要求建立目标、开始执行。

## 目标与成功标准

交付朋友能独立加入、完整玩完《玻璃雨夜》、中断后能够续玩的候选版。独立房主不占玩家身份；分别完成双人和四人短团。只有以下证据齐全才算完成：

1. 固定上游提交，保留现有试点和存档作为回退；候选环境独立运行。
2. 每名普通玩家拥有独立会话，不能通过 URL、入座请求或实时连接冒用另一玩家或 GM；私人钩子和私信仅发给所属玩家。
3. 两人、四人各完成一场真实模型短团，留存开局、行动、至少一次检定、结局回顾的证据。浏览器验证与独立 HTTP 客户端验证分别记录。
4. 刷新或掉线后能回到原席位；服务重启后存档、私信和角色状态保留，可从原生暂停状态恢复。模型错误可重试，不得重复执行状态更新。
5. 使用原生暂停/结束及保存、导出能力形成可找回的结团记录；不复刻旧系统的档案中心。
6. 提交启动说明、验收报告和可复现测试，将通过审查的改动同步 GitHub 主线。

## 范围与维护约束

- 上游基线：`297da1f06d1e177ade2324eb35d9eb8e1dff89cb`，禁止自动跟随 main。
- 旧试点继续使用 `127.0.0.1:19876` 和 `.runtime/diceframe-pilot/`；候选版使用 `127.0.0.1:19877` 和 `.runtime/diceframe-candidate/`。
- 只迁移原创内容包与四张预设卡；原世界 ID、规则 ID、公开/私有边界与私用许可不变。旧状态机的严格剧情条件仍不视为已迁移。
- 优先用原生界面与流程，先完善开局、入座、私人钩子投递和结团操作说明。没有真实缺口时不增设界面或框架。
- 密钥由用户在设置页填写；不从环境变量提取，不提交运行数据。
- 2026-10-03 对主分支的合成 HTTP 测试已复现普通玩家跨席位读取私信和切换身份。用户已选择“维护一份最小权限补丁，继续候选版”。
- 若选择补丁，保存可审核的补丁文件和适用提交，补丁无法干净应用时停止升级；不静默扩展为长期核心分叉。

## 验证矩阵

| 范围 | 方法 | 通过标准 |
| --- | --- | --- |
| 内容包 | 本地生成 + 真实插件宿主加载 | 四张卡数值保真；公开内容无私人钩子 |
| 玩家权限 | 合成数据真实 HTTP / 会话 / SSE | 本人可用，他人和 GM 拒绝，无失败请求副作用 |
| 双人、四人短团 | 独立会话 + 浏览器抽验 + 真实模型 | 两次叙事收束，检定与人物状态可追溯 |
| 重连与重启 | 同会话重连、重启前后状态比较 | 身份、私信、存档保留，可继续 |
| 模型异常 | 定向故障注入与原生恢复测试 | 明确失败、可恢复、状态不重复结算 |
| 结团 | 原生结束/暂停、保存、导出或记录 | 回顾明确，重载后找得到 |

本阶段不承诺公网部署、生产可用性、弱网长时间压测或全量旧系统等价迁移。
