# CoC7 权威规则库、房间失效与分页管理设计

日期：2026-08-13

状态：已完成方案评审，待书面规格确认

## 1. 目标与边界

本设计将 CoC7 规则检索从当前的本地测试语料替换为一份经管理员确认的完整来源，并将“有原文依据的规则裁定”与“AI-KP 为推进剧情作出的临时裁定”严格区分。

同时，管理员房间列表增加分页、每页数量选择、当前页全选和当前页批量删除。该功能只改变房间管理，不改变剧本、角色、账号的列表行为。

本轮已确认的产品决定：

1. 唯一正式来源为 `COC7th核心规则书v1.2.1.pdf`，共 380 页；当前原始文件指纹为 `22F5F56B7A0989CBDED695D39C7D5EDDDDD809CFC9D2C47E4CF4C5D7EDEA6815`。
2. 旧 25 页本地测试规则不能再参与任何运行时检索或规则绑定；在正式版通过发布门槛前，规则问题不得用旧资料兜底。
3. 旧房间若依赖该旧规则版本，允许直接失效、不可打开；不做旧房间规则迁移或兼容。
4. AI-KP 在没有充分规则证据时继续自然推进剧情，但不得把临时裁定伪装成规则书结论或伪造页码。
5. 剧本明确的特殊规则在该剧本版本内优先于通用 CoC7；之后才是当前房间的临时裁定。
6. 原文、页码、来源指纹、检索置信度和临时裁定审计只对管理员可见。房主与玩家只看到正常的剧情结果；房主不具备规则原文查看权限。
7. 当前不物理删除旧测试规则数据或测试素材。先隔离会导致异常的旧运行时记录，完整清理另行确认。

本设计不声称语言模型可以做出绝对无误的自由文本判断。准确性契约是：系统不会把无证据的内容标成规则书结论；所有标为规则依据的裁定均可由管理员追溯到固定版本和真实页码；资料不足时只会留下“AI-KP 临时裁定”的内部审计记录。

## 2. 现状问题

当前已发布的基础 CoC7 规则版本是本地受限测试资料：

- 来源仅有 25 页，不能覆盖完整规则体系。
- 文本由双栏 PDF 的通用提取产生，阅读顺序可能交错。
- 固定字符长度分块可跨页，引用中的序号并非真实页码。
- 中文自然语言查询的词法得分常为零；低相关向量结果仍会被返回。
- 直接指定规则版本的查询路径没有统一的正式发布资格校验。

因此，替换文本本身不足以解决问题；来源、提取、分块、检索、发布、房间访问和审计必须共同收口。

## 3. 方案比较与采用方案

### A. 在现有版本化 RAG 上增量加固（采用）

保留 `rule_sets`、`rule_set_versions`、`source_documents`、`source_parts`、`rule_documents`、`document_chunks` 与现有房间规则绑定。补齐来源清单、页级分块、资格门槛、中文混合检索、房间失效保护和管理员审计。

优点是兼容现有数据模型和运行时调用，改动集中；缺点是需要严格覆盖所有旧的检索旁路。

### B. 重建独立规则知识库和后台

隔离最强，但会重复已有版本、绑定与审计能力，造成两套规则运行机制。超出当前需求。

### C. 只替换为 380 页文本

最快，但不能解决错误引用、中文召回、错误兜底和旧房间问题，不满足目标。

## 4. 权威来源与导入流程

### 4.1 来源档案

正式文件从当前测试素材目录迁出或以正式来源登记，不再让运行时把它识别为测试语料。每次导入创建一份不可变的来源档案，至少记录：

- 原始文件名、文件指纹、页数、语言、规则系统、管理员确认的授权类型与导入时间；
- 380 个按物理页编号的来源页记录；
- 每页提取方式、文本哈希、提取质量、人工复核状态和是否可检索；
- 版本标签及来源指纹。

文件指纹或页数不匹配时，导入任务失败，不创建可发布版本。

### 4.2 页级提取与核验

导入器逐页处理原始 PDF，保留每页的页码与文本范围。双栏或表格页采用按版面坐标的阅读顺序提取；无法可靠提取的页进入 OCR 或人工复核队列，不以空文本或交错文本继续发布。

每页必须处于以下一种明确状态：

- `indexable`：经提取和质量检查后参与规则检索；
- `archived_non_retrieval`：版权、目录、索引、角色卡、空白表单等保存在来源档案中，但不作为答案候选；
- `needs_review`：文本缺失、版面异常或提取置信度不足，阻止版本发布。

规则分块不跨物理页。每一块保存 `source_document_id`、`source_part_id`、真实 `page_number`、页内起止位置、标题/锚点和摘录。不存在“第 N 块即第 N 页”的推断引用。

### 4.3 发布门槛

新版本只能从 `draft` 发布为 `published`，且须同时满足：

1. 原始文件指纹和页数与来源档案一致；
2. 380 页均已入档，没有未分类页面；
3. 所有应检索规则页均有有效文本和页级引用；
4. 没有 `needs_review` 页面；
5. 所有规则分块属于该版本、带真实页码、且不可被房主或玩家直接读取；
6. 中文规则查询、剧本规则覆盖、低相关拒答、页码追溯和旧版本隔离的自动验收全部通过；
7. 管理员在审计界面完成来源及异常页复核确认。

发布动作必须在事务中完成，并记录门槛结果。任何管理员直接指定 `rule_set_version_id` 的查询也只能读取满足上述门槛且为已发布状态的版本。

## 5. 运行时规则决策

### 5.1 优先级

每次 AI-KP 需要机械规则依据时，按下列顺序构造候选：

1. 当前已发布剧本版本中明确的特殊规则；
2. 已发布且通过门槛的 CoC7 基础规则版本；
3. 当前房间已存在的匹配临时裁定；
4. 新的 AI-KP 临时裁定。

剧本特殊规则只覆盖其明确冲突的范围，不改变通用 CoC7 的其他条款。

### 5.2 检索与拒绝规则

规则候选采用中文归一化后的混合检索：语义向量召回与中文字词/连续字符词法召回分别取候选，再由标题、页内锚点、词法命中与向量相似度统一排序。该实现不依赖把中文交给 PostgreSQL 的 `simple` 词法器。

仅当最高候选满足阈值、来自合格正式版本、页码完整且与查询主题一致时，才允许标记为规则依据。低相关、未知概念、缺页或来源不合格时不返回伪相关规则内容。

规则分块的可见性为 `internal`：AI 运行时和管理员审计可读取；房主、玩家和普通 RAG API 投影不可读取原文、页码或完整摘录。

### 5.3 AI-KP 临时裁定

当没有合格的规则候选，或规则条件不足以确定唯一裁定时，AI-KP 自行随机应变，正常推进剧情。它不向房主或玩家显示“临时裁定”标签，也不宣称该结果来自规则书。

为保证同一战役的一致性，系统为当前房间保存最小临时裁定记录：规范化问题键、裁定摘要、所需最小场景状态、适用范围、使用的规则版本、审计类别、创建/更新时间。后续遇到同一问题优先复用该记录。

临时裁定不写回通用规则库、不影响其他房间，也不保存账号身份、令牌、原始安全边界文本或与当前决定无关的未揭示秘密。

## 6. 旧测试规则隔离与房间失效

### 6.1 隔离方式

当前 25 页本地测试版本及其规则文档、分块、向量和伪引用保留为可审计的隔离记录，但：

- 不再是基础规则默认版本；
- 不得通过房间绑定、剧本绑定、直接指定版本或无版本回退进入检索；
- 管理员也不能把它重新发布为正式规则，除非走一次明确的恢复/审计操作；
- 运行时没有合格规则版本时，只能触发 AI-KP 临时裁定，不能回退到该资料。

物理删除将作为后续独立操作，先展示受影响记录与删除范围，再由管理员确认。

### 6.2 旧房间不可打开

切换时，所有有效规则链包含旧测试版本的既有房间都标记为 `rule_source_retired`。该状态独立于“大厅/进行中/归档”等游戏状态，保留删除、管理员详情和审计能力，但阻止玩家、房主和 AI-KP 进入或执行房间运行时接口。

受影响入口统一返回稳定的“该房间使用的规则版本已失效，无法继续打开”结果；前端显示静态失效页，不显示空白、通用 500 或错误的游戏界面。管理员房间列表明确标识此状态，仍可批量删除这些房间。

新建房间仅可使用通过发布门槛的最新正式 CoC7 基础版本。若正式版尚未发布，创建房间应明确失败，而不是创建一个没有可靠规则来源的房间。

## 7. 管理员审计能力

管理员拥有专用规则审计视图/接口，可查询：

- 正式规则版本、文件指纹、页数、导入状态和发布门槛；
- 页级提取状态、非检索页分类和需要人工复核的页；
- 某次检索的候选、得分、使用版本、真实页码、页内锚点和原文摘录；
- 某房间的临时裁定及其最小必要场景状态；
- 旧测试版本的隔离原因和受影响房间数。

该能力复用管理员认证；不向房主或玩家暴露对应 API、原文或引用字段。

## 8. 房间管理分页与当前页删除

### 8.1 列表协议

房间管理列表改为服务端分页，支持 `page` 和 `page_size`。`page_size` 仅允许 `10`、`30`、`50`，无效值返回明确的参数错误。响应包含当前页条目、总条数、当前页、每页数量和总页数。

已有无分页参数的管理 API 调用保持兼容；管理员前端始终使用分页参数。

### 8.2 界面行为

- 默认每页 10 条，可选择 10、30、50；切换每页数量回到第 1 页；
- 显示上一页/下一页、页码、总条数与当前范围；
- “全选本页”只选中当前页面实际显示的房间；再次点击取消全选；
- 逐项复选框只用于选择，点击卡片仍只查看详情；
- 切换页面或每页数量时清空选择，避免跨页误删；
- 批量删除走现有前后端确认链，确认区域必须包含可见的“确认删除”和“取消”；
- 删除请求只携带当前已选 ID。服务端逐项执行并返回成功、未找到、受保护/受依赖阻止、系统失败；前端只移除真正成功的 ID；
- 删除后重新加载当前页；若最后一页被删空，自动回退到最后一个有效页；失效房间与普通房间遵循同一删除确认机制。

## 9. 错误处理与安全边界

- 来源指纹、页数、提取状态、版本资格或引文不完整时，发布失败且保持草稿；
- 任何查询路径均再次检查版本资格，不能因传入 ID 绕过；
- 旧房间被运行时访问时返回确定的失效结果，不执行 AI、规则、状态写入或游戏事件；
- 规则书原文仅在管理员审计结果中返回，且只返回完成当前审计所需的页内摘录；
- 批量删除没有隐式删除：未勾选时按钮禁用，第一次点击只展开确认，确认才发出带 `confirm: true` 的请求；
- 所有隔离、发布、房间失效与临时裁定操作写入管理员审计，不记录凭据或无关敏感内容。

## 10. 验收标准

### 10.1 规则库

- 380 页文件哈希与来源档案一致，380 页全部有明确分类；
- 任意正式规则分块可回溯到单一真实页码，且不跨页；
- 旧 25 页版本无法经任何运行时或管理员检索参数返回；
- 中文自然语言问法能召回对应规则页；不存在概念不会返回无关规则作为依据；
- 规则证据不足时，AI-KP 可继续游戏，但管理员审计记录为临时裁定而非规则引用；
- 房主与玩家无法通过接口取得规则原文、页码或临时裁定标记；管理员可以取得必要审计信息；
- 剧本特殊规则优先于通用规则，房间临时裁定仅在该房间复用；
- 旧测试规则依赖房间无法打开，新建房间没有合格正式版时不能创建。

### 10.2 房间管理

- 管理员可选择 10、30、50 条每页，分页总数和边界正确；
- “全选本页”不影响其他页，切页清空选择；
- 当前页全选后能看到准确计数、可见确认按钮并完成批量删除；
- 批量删除部分失败时，成功项消失，失败项保留并逐项说明原因；
- 删除当前页最后一项后，列表回到有效页且详情不会指向已删除房间；
- 桌面与窄屏均能使用分页、选择、确认删除和房间详情。

## 11. 非目标与后续工作

- 本次不物理删除旧测试数据、测试脚本或测试素材；清理需要独立确认和影响预览。
- 本次不将整本规则书或页码展示给房主、玩家。
- 本次不迁移旧房间到新版规则，也不恢复旧房间。
- 本次不新增对其他三类管理列表的分页需求。

后续若需要清理旧测试内容，先生成受影响对象清单并由管理员确认，再在独立事务中删除；不允许以清理操作替代来源验证或发布门槛。
