# M0 权威运行时与多人治理设计

日期：2026-08-02

状态：已完成方案评审，待书面规格确认

适用范围：AI-only CoC7 M0、多人房间、`《玻璃雨夜》`黄金样本

## 1. 背景与目标

当前 V2 已具备 Engine 状态写入、action 幂等、状态版本、玩家投影、掷骰回执、结局判定和归档，但仍存在若干互相矛盾的路径：

- `runtime_policy.session_mode=ai_only` 的剧本创建房间后，房间仍默认使用 `host_required`，黄金测试需要手工改为 `delegated`。
- Director、Narrator、状态服务或规则建议异常时，部分路径仍进入 `awaiting_host_exception`。
- 私密文本可以被解析成私密机械行动；PvP 缺少逐次受影响玩家确认。
- 推骰在一次规则调用中同时完成初骰和重骰，没有独立锁定风险边界。
- checkpoint 没有状态版本、事件边界、哈希和恢复前不变量验证。
- Session Zero 没有绑定被冻结的风险契约版本。
- 剧情推进已有语义边和结局条件，但没有完整表达关键推进、替代路径和恢复节点。

本设计在现有 V2 运行时上增量实现决策 33–60，并收口决策 1–32 中仍标记为“部分落实”或“待实现”的项目，使以下目标同时成立：

1. Engine 的结构化状态是唯一运行时权威，AI 仅提出受约束建议。
2. AI-only 房间不以真人 Host 在线或裁决为运行依赖。
3. 多人行动、可见性、风险、同意、随机性和剧情推进均可审计、可重放、可验证。
4. 不进行完整 Event Sourcing 重写，也不迁移或恢复旧房间运行态。
5. `《玻璃雨夜》`以 1 个房主和 4 名玩家从浏览器完成至可刷新验证的结局。

## 2. 采用方案

采用“现有 V2 增量加固”方案：

- 保留 `StateService`、`ResolutionPipeline`、`action_drafts/actions`、`resolution_bundles`、`EventLog`、剧本编译器和 campaign archive。
- 在现有表上补充风险契约、完整性和审计字段。
- 只为现有结构无法表达的逐次同意与事实揭示新增最小表。
- 将原有 Host 例外分支按原因改成玩家澄清、确定性降级或房间只读暂停。
- 继续使用状态快照作为当前状态；event 用于审计、恢复边界和验证，不改造成全量事件溯源。

明确不采用：

- 只修 AI-only、私密行动和推骰的缩减方案，因为它会遗漏已确认的风险契约、知识投影和恢复要求。
- 完整 Event Sourcing 重写，因为它超出 M0 且违背“版本化状态为权威”的既定决定。

## 3. 权威状态与事务边界

### 3.1 当前状态

- `rooms.state_version` 与各结构化运行态表组成房间当前状态。
- AI 输出、Narrator 文本、摘要和记忆均是可丢弃、可重建的派生数据。
- 任意 AI `state_patch` 只能作为建议输入；只有 Engine 验证后的 `StateChangeSet` 可以写状态。
- action 的状态变更、结构化 state delta、状态版本递增、决定回执和对应审计 event 必须在同一数据库事务中提交。

### 3.2 并发与幂等

- 每个需要改变状态的 action 必须绑定：`room_id`、`character_id`、`base_state_version`、`idempotency_key`。
- 相同幂等键重试必须返回原 action 和原随机结果。
- 不同角色的非冲突行动可以并行；同一资源、同一目标或存在因果依赖的行动串行执行。
- 基础版本过期时，不使用最后写入覆盖。Engine 重新验证；如果输入语义可能改变，返回新的澄清或确认要求。

### 3.3 完整性状态

房间增加运行时完整性状态：

- `healthy`：允许正常行动。
- `read_only_recovery`：状态不一致或 checkpoint 校验失败，只允许读取、导出、恢复检查和管理员修复操作。
- `paused_provider`：固定模型持续不可用；不接收新的机械行动，可恢复或通过显式版本化切换解除。

进入暂停必须记录原因、检测来源、当前状态版本并通知参与者；AI 不得自行解除。

## 4. Checkpoint 与恢复

checkpoint 继续保存结构化快照，但增加：

- `schema_version`
- `state_version`
- `event_sequence`
- `snapshot_sha256`
- `invariant_report`
- `verification_status`

快照只包含恢复当前游戏所需的运行态，不包含账号身份、登录令牌、原始安全边界文本或无关私人数据。

恢复流程：

1. 读取 checkpoint 并验证规范化 JSON 哈希。
2. 验证房间、角色、场景、资源和引用完整性。
3. 在隔离事务中进行 dry-run 重建，生成差异和不变量报告。
4. 自动恢复只允许使用验证通过的 checkpoint，并重放其后可验证的结构化变更。
5. 自动恢复失败时保持 `read_only_recovery`。
6. 人工修复必须提交结构化提案，执行 dry-run，经过双确认后原子应用；全程审计并通知参与者。

旧的直接删除表数据并忽略逐行恢复错误的行为将被移除。

## 5. 冻结风险契约

### 5.1 编译与锁定

剧本运行包增加规范化 `risk_contract`，至少包含：

- 允许的风险类别与等级。
- 明确排除的内容标签。
- NPC/场景伤害的默认风险范围。
- 需要逐次确认的不可逆控制变更。
- 是否允许隐藏检定及其声明来源。
- 安全替代与安全中止规则。

编译器生成稳定规范化 JSON 和 SHA-256。房间启动时把契约版本与哈希固定到房间；运行中不能静默变化。

### 5.2 玩家确认

- Session Zero 的风险步骤绑定具体契约版本和哈希，而不是只记录一个布尔值。
- 新加入、迟到或重新加入的玩家必须先读取当前契约和无剧透变更说明，再确认该版本。
- 契约未确认或确认的是旧哈希时，只允许读取、退出和安全操作，不能提交机械行动。
- 超出契约的内容必须在揭示前暂停，只显示无剧透风险标签，并征求所有可能受影响玩家的明确同意。
- 任一受影响玩家拒绝时，Engine 使用剧本提供的等价安全替代；不存在安全替代则保持无效果。

## 6. 行动解释、澄清与超时

### 6.1 玩家文本不是世界事实

玩家自由文本只表达意图或主张：

- 对话、情绪和不改变规则状态的外观描述可以直接进入叙事。
- 位置、物品、伤害、结果、NPC 状态、线索发现及其他世界事实必须由 Engine 验证。
- 客户端选择的 intent type 只是提示，服务端仍需分类并验证。

### 6.2 歧义处理

以下任一差异都会触发玩家澄清：目标、风险、资源、检定类型、安全边界或不可逆后果。

- 返回 2–3 个经过 Engine 过滤的选项。
- 澄清期间不产生骰子、不消耗资源、不写共享状态。
- 可逆的纯装饰歧义可以保守推断，但必须在预览中说明。
- 等待某玩家澄清不得阻塞其他玩家不冲突的行动。

### 6.3 超时

- 调查和一般行动：取消未提交意图，不消耗资源。
- 战斗：只执行 Engine 固定的最低风险防御、保持或安全撤退。
- 群体决策：超时记为弃权；未达到阈值或平票时无效果或选择更安全结果。
- 超时原因和结果必须写入审计，AI 不得替玩家选择。

## 7. 私密频道、PvP 与离线保护

### 7.1 私密频道

M0 私密频道只允许：私人笔记、内心活动、规则问题和不改变世界状态的内容。

任何改变共享状态、消耗资源、移动角色、获得线索或影响其他角色的行动必须公开提交。秘密机械行动返回明确拒绝和“公开重新提交”选项，不进入 Host 例外。

### 7.2 PvP

- 默认拒绝非自愿 PvP。
- 伤害、夺取资源、限制行动或改变其他角色状态，需要受影响玩家针对该 action 明确确认。
- 房间级开关、历史同意或房主身份不能替代逐次确认。
- 无回应或拒绝时不产生机械效果。
- NPC 和剧本风险在已接受风险契约内正常解析，不要求每次确认。

### 7.3 离线与移除

- 长时间离线角色进入 `protected_inactive`。
- 只允许确定性防御、跟随队伍或安全撤退；不得消耗稀缺资源、作不可逆选择、获得私密揭示或交给 AI 完全控制。
- 玩家返回后恢复控制。
- 房主移除玩家只终止访问，不删除或接管角色和私人数据；角色保持受保护，公共归档匿名化。
- 永久退场或角色转移必须由所属玩家显式确认。

## 8. 群体决策与房主权限

- 可逆路线选择由当前活跃玩家多数决定。
- 结局选择、放弃队友、销毁唯一物品、消耗重大共享资源和扩大风险契约，需要所有受影响的活跃玩家同意。
- 房主只负责邀请、移除访问、暂停、结束和申请归档。
- 房主不能查看未揭示真相、他人私人数据，不能修改骰子、角色状态或故事决定。
- 高影响生命周期操作必须审计并通知房间参与者。

## 9. 事实揭示与受众知识

### 9.1 Engine 揭示账本

新增最小揭示记录，包含：

- 稳定事实或内容节点 ID。
- 来源 citation。
- 目标受众或角色。
- 触发条件和来源 action。
- 揭示时状态版本和 event 序号。
- 状态：已揭示、已更正或被安全事件标记。

AI 只能提出揭示。Engine 验证来源、条件和受众后，在提交 narration 前原子写入揭示记录；未写入账本的秘密不得进入玩家投影。

### 9.2 真相、知识与信念

- 世界真相来自已编译剧本和 Engine 状态。
- 玩家知识由公共揭示、本角色私密揭示和本人输入组成。
- 玩家假说仍是 belief，除非 Engine 依据来源事实明确标记为 confirmed。
- Director 可读取必要的隐藏真相；玩家 AI 上下文只能读取该角色有权知道的投影。
- 更正采用追加记录，不抹除“玩家曾看到什么”。错误揭示作为安全事件处理。

## 10. 可验证随机性与 CoC 推骰

### 10.1 随机决定

所有机械随机性由 Engine 产生，并绑定：

- 房间和状态版本。
- action 和随机用途。
- 规则版本。
- 锁定的难度、奖励/惩罚骰和其他修正。
- 幂等键。

相同 action 重试必须返回相同随机结果。AI 和客户端不能自行重投或请求一个新的随机结果来替换已提交结果。

掷骰回执向玩家提供脱敏的：规则版本、允许输入、修正、随机来源、验证结果、最终 delta、actor 和稳定回执 ID。隐藏来源只显示“存在已验证隐藏修正”，不泄露剧本秘密。

### 10.2 隐藏检定

- 只有被冻结的规则或剧本运行包明确声明时才允许隐藏检定。
- AI 不能临时把检定改为隐藏。
- Engine 立即锁定随机承诺；房间结束后可在不泄露其他私密信息的范围内验证。

### 10.3 幸运与推骰

初次技能检定先独立完成。失败且规则允许时，Engine 返回可用后续选择：

- 幸运：显示精确消费值，只能由角色所属玩家确认。
- 推骰：显示定性风险警告、锁定风险等级、允许影响范围和支撑事实，只能由所属玩家确认。
- 超时不消费幸运，也不自动推骰。

推骰是关联原始 action 的第二个规则步骤，不在初次规则调用中自动重投。若推骰失败：

1. AI 可以在已锁定边界内提出具体后果。
2. Engine 校验风险等级、影响对象、状态路径和剧本事实。
3. 不合规提议最多进行一次受限重试，随后使用 Engine 确定性后果。
4. 后果与状态变更原子提交，并写入同一决定链和玩家回执。

该行为遵循 CoC7 规则书：守秘人可以在推骰前预示失败风险，但无需提前锁死精确后果。

## 11. 剧情推进与恢复节点

剧本编译产物扩展：

- `critical_progression`：关键推进事实或节点。
- `alternative_paths`：每个关键推进至少一个替代路径。
- `recovery_nodes`：当当前合法路线耗尽时可启用的已编译恢复节点。
- `true_failure_conditions`：唯一允许真正锁死或结束的显式条件。

编译器拒绝以下发布产物：

- 关键推进只有一个可能被普通检定失败永久关闭的入口。
- 恢复节点没有可追溯 citation。
- 恢复节点凭空生成新事实或新线索。
- 失败条件不能由 Engine 的结构化事实判定。

运行时发现当前路径耗尽时：

1. Engine 先检查合法的已编译恢复节点。
2. 没有可用恢复节点时，只能提示已经公开但尚未解决的信息。
3. 两者都没有时保持当前状态并明确告知没有合法推进，不调用 AI 创造新线索。

恢复节点可以产生已声明的时间、风险或资源代价，但必须追溯到已编译剧本事实。

## 12. AI-only 故障处理

对 `session_mode=ai_only`：

- 低置信意图：返回玩家澄清，不进入 `awaiting_host_exception`。
- Director 输出无效：使用本地解析候选；仍不安全时拒绝或澄清。
- Narrator 失败：若状态尚未提交则使用确定性预览；状态已提交则使用模板叙事描述已提交结果。
- 规则建议需要人工确认：改为玩家确认、Engine 固定规则或拒绝，不转交 Host。
- 状态服务不可用或完整性失败：进入只读暂停，绝不继续猜测。
- 固定模型持续故障：达到阈值后进入 `paused_provider`，记录并通知；切换模型必须显式生成新绑定版本和审计记录。

黄金样本中 `awaiting_host_exception` 必须保持为零。

## 13. 决策 1–32 的遗留收口

决策 1–32 已有大量实现，本轮不重写已通过验收的路径，只处理落实矩阵中的明确缺口：

- 高风险疯狂表现：持久化 AI 提议、Engine 验证、一次受限重试和确定性安全替代的两阶段决定链。
- 安全偏好：以此前确认的“外部 AI 只接收规范化标签”为边界；审计现有加密存储与保留时间，不擅自扩展为删除玩家提交所必需的受控原文。
- SAN 归零：退出玩家控制并转为受限 NPC；只在 Engine 验证的安全场景向玩家提供替补调查员。
- 背景变化：AI 提议、玩家确认；拒绝后 Engine 给出安全替代，该玩家的等待不阻塞他人。
- 不定疯狂恢复：只接受已编译且已验证的治疗或恢复节点；永久疯狂在 M0 不恢复。
- 结局编译：增加优先级、互斥与 safe-abort 最高优先级验证；拒绝无法确定唯一结果的产物。
- 结束事务：在同一事务中完成结局、房间状态、归档和取消全部未提交行动；结语路径为只读，不能再写游戏状态。
- 归档治理：数据库级保护最小不可变归档；统一公共摘要、本角色私密 arc 和管理员运维元数据的分层读取；彻底清除继续使用双确认与审计。
- AI 决策审计：保留模型、模板/规则版本、最小上下文哈希、引用、结构化提议、Engine 验证结果和最终 delta，不保存令牌、原始安全文本或无关秘密。
- 保留策略：诊断数据 24 小时、AI 决策 90 天、账号/清除审计 1 年、归档直到显式清除；实现可重复、可审计的清理执行器。
- 敏感审计访问：管理员默认只能查看运维元数据；查看敏感内容需要事件单、原因、限时提权并记录访问日志。
- 固定模型持续故障：区分单次失败和连续故障；达到阈值后暂停房间，恢复或显式版本化切换均审计并通知参与者。

落实矩阵中某项若经代码与行为测试证明已经满足用户确认的精确边界，应更新证据并标记完成，不为追求“新增代码”而扩大需求。

## 14. 前端体验

玩家端增加或调整以下状态：

- Session Zero 显示风险契约摘要、版本和确认状态。
- 迟到或契约更新时显示无剧透重新确认页。
- 行动预览显示 Engine 解释、风险、资源影响和 2–3 个澄清选项。
- 私密机械行动显示不可执行原因和公开重提入口。
- PvP 目标玩家显示逐次同意卡；拒绝或超时明确显示无机械效果。
- 初骰失败后独立显示幸运消费和推骰选择。
- 推骰确认显示锁定的定性风险边界。
- 行动完成显示脱敏决定回执和稳定回执 ID。
- 房间完整性或 provider 暂停时显示只读原因和允许操作。
- 结局页在刷新后仍从 campaign archive 显示结局摘要和角色允许范围内的内容。

## 15. 最小数据模型改动

优先扩展现有表：

- `rooms`：风险契约版本/哈希、完整性状态、暂停原因。
- `events`：状态版本、action ID、payload 哈希。
- `checkpoints`：结构版本、状态版本、事件序号、快照哈希、验证报告和状态。
- `session_zero_confirmations`：契约版本和哈希。
- `actions` / `action_drafts` / `resolution_bundles`：继续承载锁定输入、后续决定链、随机回执和玩家投影。
- `ai_call_logs`：结构化决定审计、上下文哈希、引用、验证和最终 delta，以及分层到期时间。
- `campaign_archives`：不可变状态和公共/本人私密/运维分层投影所需元数据。

只新增两类无法由现有结构安全表达的记录：

- action 逐次同意记录。
- Engine 事实揭示记录。

所有 schema 改动同时维护 PostgreSQL 初始化和兼容升级 SQL；不引入另一套迁移框架。

### 16.3 浏览器验收

使用当前本地服务进行一次全新、可观察的浏览器流程：

2. 房主邀请，4 个玩家分别使用 4 个预设角色加入并确认风险契约。
3. 通过玩家页面完成公开调查、一次需要澄清的行动、一次多人并发行动和安全暂停/恢复。
4. 完成合法线索与场景推进，抵达 Engine 验证的结局。
5. 截图并验证结局卡；刷新页面后结局和归档仍可见。
6. 检查数据库中 `campaign_archives`、决定回执和揭示记录。
