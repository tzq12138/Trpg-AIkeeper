# AIKP 主持运行时阶段测试报告（2026-07-19）

## 本轮范围

- 固化玩家行动信封、非状态输入与玩家可见 AI 上下文。
- 将裁决结果分为权威结果、玩家投影、舞台投影与 Host 导演台投影。
- 为同房间非回合制行动增加短窗口批处理，并保留数据库状态机作为跨进程竞争裁判。
- 收紧 AI 润色：后台 PostgreSQL worker 继承动态 AI、剧透守卫和连接隔离的状态服务；Narrator 只接收已验证公开结果。
- 修复回合结算广播，禁止把原行动文本、状态补丁或完整结果广播给全队。
- 补齐玩家高风险确认卡、Host 导演台和遭遇快捷行动的安全交互。

## 已验证结果

| 能力 | 验证结论 | 证据 |
| --- | --- | --- |
| 玩家动作与隐私输入 | 通过 | 私人笔记审计正文脱敏；非状态输入不能创建权威行动。 |
| 玩家可见 AI 上下文 | 通过 | 网关仅序列化已知线索、目标、背包和证据，排除注入的幕后真相。 |
| Narrator 约束 | 通过 | 所有已结算行动仅白名单序列化已验证公开结果；剧透守卫异常时返回安全占位。 |
| 投影隔离与恢复 | 通过 | `ResolutionBundle` 持久化后再发布；待发布投影可重放而不重结算。 |
| 多人动作窗口 | 通过 | 同房间只建立一个短窗口任务；V2 行动能走 `queued → batched → resolving`。 |
| 回合投影 | 通过 | 全队仅收到回合数量和中性摘要，个体原行动与结果不再广播。 |
| 遭遇快捷动作 | 通过 | 每个按钮必须携带服务器事件中的 `encounterId`；缺失 ID 时不生成按钮。 |
| 前端构建 | 通过 | TypeScript 检查和 Vite 生产构建成功。 |

## 运行环境说明

- 数据库、RAG、Embedding 和编译器健康检查可用。
- 当前 MCP URL `http://127.0.0.1:9100/mcp` 未连通；现有 DeepSeek 链与本地回退可用。
- 因此本报告只确认自动化和运行健康，不把真实供应商的浏览器叙事质量、延迟或多玩家互动称为已验收。

## 待浏览器验收

1. 单人：自然语言调查、追问、战斗、理智/伤害、结局与刷新恢复。
2. 四人：两名玩家在批次窗口内确认行动，检查 `batched` 状态、公开叙事和私密行动隔离。
3. Host：导演台仅显示裁决摘要/规则依据，使用“恢复待发布裁决”不重复应用状态。
4. 遭遇：从 `s2c_encounter_started` 进入快捷动作，确认请求携带正确 `encounterId`。
5. 真实图文供应商与文本备用供应商各跑一轮，记录阶段事件、citation 和故障恢复。
