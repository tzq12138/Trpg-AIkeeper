# AI-Keeper UI 头脑风暴第一轮总结

**日期：2026-07-18**  
**范围：公共实时舞台（Shared Stage Live）与玩家手机端（Player Companion）**  
**目标：让玩家无需学习复杂系统，也能一眼看懂当前局面，并立即知道自己该做什么。**

---

## 1. 核心产品原则

### 1.1 公共大屏与玩家手机分工

| 终端 | 核心职责 |
|---|---|
| 公共大屏 | 展示全桌共同看到的场景、叙事、行动焦点、公开结果与队伍概况 |
| 玩家手机 | 处理个人行动、确认、私密信息、角色、物品、调查资料与待处理事项 |
| 桌务端 | 后续单独设计，只负责流程、安全和无剧透异常处理 |

公共大屏负责“看懂现在”；玩家手机负责“我现在要做什么”。

### 1.2 每个主页面只回答一个问题

- 公共大屏：**现在发生了什么？**
- 玩家手机首页：**现在需要我处理什么？**
- 调查页：**刚获得了什么、还在调查什么？**
- 角色页：**我现在状态如何、还能使用什么？**

### 1.3 公共大屏不是控制台

公共大屏不常驻：

- 系统设置和管理菜单；
- 主动掷骰、推进剧情、添加单位；
- 完整角色卡和精确资源；
- 完整日志和后台状态；
- 玩家私人信息；
- AI-KP 幕后信息。

# 2. 公共实时舞台

## 2.1 默认焦点

默认采用：

> **场景氛围 + AI-KP 公共叙事。**

场景视觉占据主要区域；行动、骰点、线索、决定等内容只在发生时临时进入焦点，结束后回到场景。

## 2.2 基础结构

```text
┌────────────────────────────────────────────────────┐
│ 场景名称 · 游戏时间                   AI-KP 状态   │
├─────────────────────────────────┬──────────────────┤
│                                 │ 当前目标         │
│                                 │ 公开时钟         │
│          场景主视觉             ├──────────────────┤
│                                 │ 队伍成员         │
│                                 │ 简化 HP / SAN    │
│                                 │ 当前行动状态     │
├─────────────────────────────────┴──────────────────┤
│ 当前叙事                                           │
│ 最近 3—5 条公共事件                                │
└────────────────────────────────────────────────────┘
```

建议比例：

- 顶部状态栏：7%—9%；
- 中部舞台：66%—70%；
- 底部叙事栏：22%—25%；
- 右侧栏：中部宽度的 20%—24%。

## 2.3 右侧信息栏

固定顺序：

1. 当前队伍目标；
2. 公开游戏时钟或倒计时；
3. 所有玩家角色。

队伍目标只能来自玩家已经确认的计划，不能由 AI 根据模组真相推荐。

没有明确目标时显示“自由调查”；没有时间压力时显示游戏内时间，不制造虚假倒计时。

## 2.4 角色状态显示

公共大屏显示简化状态条，不显示精确数值。

```text
[头像] 陈默           轻伤
HP   ███████░░░
SAN  █████░░░░░
```

规则：

- 不显示 `8/12`、`54/70` 等精确值；
- 必须同时显示文字状态，不能只依赖颜色；
- Luck、MP、弹药和私人状态不常驻；
- 已公开的重伤、疯狂、昏迷等可以突出；
- 状态变化仅使用短暂轻量动画。

## 2.5 成员排列

- 所有队伍成员始终显示；
- 按固定座位顺序排列；
- 当前在场、离场、断线、行动中等只改变样式，不改变位置；
- 当前行动角色只高亮对应角色卡；
- 3—4 人使用中型卡；
- 5—6 人使用紧凑卡；
- P0 最多支持 6 名玩家；
- 不使用分页、轮播或滚动角色列表。

## 2.6 底部叙事记录

采用固定底部叙事栏，显示当前叙事和最近 3—5 条公共事件。

规则：

- 最新内容最大、最醒目；
- 历史内容逐级缩小和降低对比度；
- 超出数量后最旧内容淡出；
- 不使用聊天气泡；
- 不显示完整玩家原始输入；
- 不显示私密行动；
- 不显示复杂规则过程；
- 不使用逐字打字效果。

## 2.7 当前行动表现

公开行动在以下流程完成后才进入大屏：

```text
玩家输入
→ 确认或撤销窗口
→ 服务端验证
→ 正式接收行动
→ 生成公共安全摘要
```

大屏显示：

```text
陈默正在观察教授的反应……
```

同时高亮陈默的角色卡并标记“行动中”。

该摘要一直保留到裁决结果产生。

以下内容不会进入大屏：

- 行动草稿；
- 尚未消除的歧义；
- 已撤销行动；
- 无效目标；
- 未通过权限验证的行动；
- 秘密行动；
- 玩家完整原话和私人限制。

## 2.8 等待玩家决定

行动进入 Luck、Push、反击等阶段时，根据可见范围显示。

公开决定：

```text
陈默可以花费 Luck 修改这次结果
等待陈默决定……
```

私人决定：

```text
等待陈默完成一项个人决定……
```

完成后显示安全摘要：

- 公开资源或公开动作：显示“陈默决定花费 Luck 修改结果”；
- 私密机制：显示“陈默完成了一项个人决定”。

不显示精确剩余资源、隐藏风险或未选择的选项。

## 2.9 公共骰点和重要结果

采用两级展示。

### 普通结果

- 高亮对应角色卡；
- 写入底部叙事记录；
- 不遮挡主场景。

### 重要结果

以下内容可以进入中央结果卡：

- 大成功、大失败；
- 重伤、昏迷、临时疯狂；
- 关键公开线索；
- 敌对单位被击败；
- 重大桌面裁定。

展示时场景保留并轻微压暗，不完全切走。

## 2.10 瞬时结果与持续内容

### 瞬时结果

大成功、大失败、受伤、疯狂、击败等：

- 约 4 秒自动收起；
- 随后写入底部记录；
- 返回场景。

### 持续内容

新线索、Handout、全桌决定、桌面裁定、安全提示等：

- 按内容类型决定何时收起；
- 右侧角色栏继续保留；
- 底部叙事栏临时收缩成一行；
- 主视觉扩大用于资料展示。

| 内容 | 结束条件 |
|---|---|
| 线索、Handout | 满足最低展示时间，AI-KP 继续叙事时收起 |
| 全桌决定 | 投票或决定完成 |
| 桌面裁定 | 在线玩家确认，桌务必要时可继续 |
| 安全提示 | 必须明确确认 |

# 3. 公共大屏与手机联动

## 3.1 新线索通知

大屏展示线索时，玩家手机收到非打断式通知：

```text
队伍获得新线索
旧建筑平面图

[查看]
```

规则：

- 不自动跳转；
- 不覆盖正在编辑的行动；
- 通知收起后进入待处理入口；
- 私密线索只通知有权限的玩家；
- 其他玩家不知道私密线索是否存在。

## 3.2 线索详情打开方式

根据内容类型自适应：

- 简短线索、人物摘要、地点信息：底部抽屉；
- 地图、照片、信件、长文档：全屏查看器；
- 关闭后返回原页面；
- 行动草稿、滚动位置和当前事项不丢失。

## 3.3 分享内容的公共展示

普通文字发现：

- 进入底部公共记录；
- 分享者角色卡短暂高亮；
- 不抢占主视觉。

图片、地图、信件、证物等内容：

- 系统可以根据公开形式建议“重点展示”；
- 玩家最终确认；
- 重点展示进入公共主视觉；
- 所有玩家手机收到通知。

系统不能依据“是否接近真相”判断重要程度。

# 4. 玩家手机首页：当前事项优先

## 4.1 默认入口

玩家拿起手机后首先看到当前最需要处理的一件事。

```text
当前需要你处理

是否花费 3 点 Luck，
将失败改为普通成功？

[花费 Luck]
[接受失败]
[查看依据]
```

无特殊事项时显示：

```text
当前可以自由行动

所在位置：地下档案室
队伍目标：调查 B-17

[描述你的行动]
```

## 4.2 事项优先级

```text
安全确认
> 必须立即处理的规则窗口
> 轮到玩家行动
> 协同行动邀请
> 新私密结果
> 新公共线索
> 自由行动
```

## 4.3 一件主事项 + 待处理数量

首页一次只展开最高优先级的一项，下面显示：

```text
接下来还有 2 项
协同行动邀请 ×1
新线索 ×1
```

不把首页做成任务列表。

## 4.4 统一底部抽屉

点击摘要后打开：

```text
[待处理] [最近发生]
```

### 待处理

- Luck、Push；
- 协同行动；
- 物品接收；
- 安全确认；
- 需要玩家确认的状态变化。

### 最近发生

- 公共裁决；
- 私人结果；
- 线索；
- 状态变化；
- 物品变化；
- 桌面裁定。

抽屉最多占屏幕约 70%，保留当前页面上下文。

# 5. 玩家行动输入

## 5.1 一个输入框 + 明确模式

```text
[行动 ▾]  描述你想做什么……  [发送]
```

模式：

- 行动；
- 角色发言；
- 队伍讨论；
- 规则提问；
- 私人笔记。

规则：

- 当前模式始终可见；
- 切换模式不清空输入；
- 不依赖 AI 猜测输入类型；
- 进入新场景或处理完强制事项后默认回到“行动”；
- 非行动模式不会自动执行角色行动。

## 5.2 渐进式确认

### 低风险且理解明确

```text
将执行：查看北侧铁门是否能够打开
[撤销]
```

显示约 2 秒后自动提交。

### 高影响行动

必须完整确认目标、方式、资源消耗和公开影响。

### 关键歧义

不提交，只追问一个必要问题。

## 5.3 行动等待状态

```text
你的行动

观察教授听到“B-17”时的反应

正在裁决……
```

此时：

- 不能再提交新的正式行动；
- 可以继续角色发言、队伍讨论、规则提问和私人笔记；
- AI 响应较慢时显示“行动已保存”；
- Luck、Push 等决定自动成为首页主事项。

# 6. 玩家结果与历史

## 6.1 分层结果卡

```text
结果：普通成功

[全桌可见]
教授听到“B-17”时短暂停顿。

[仅你可见]
教授随后看向了北侧书架。

[加入笔记]
[分享给队伍]
[查看判定依据]
```

规则：

- 公共结果与大屏一致；
- 私人结果明确标记；
- 其他玩家不知道私人补充是否存在；
- 规则过程默认折叠；
- 没有私人结果时不显示空区域。

## 6.2 结果收起规则

### 普通结果

普通成功、失败、常规伤害：

- 满足最低阅读时间后自动收起；
- 玩家开始下一行动或切换页面时收起；
- 永久进入“最近发生”。

### 重要结果

私密线索、重伤、疯狂、关键物品变化：

- 持续停留；
- 玩家阅读、确认或完成后续操作后收起。

### 后续决定

直接转为新的最高优先级事项。

## 6.3 最近发生

公共和私人内容按真实时间混合排列：

```text
23:20 [仅你] 教授看向北侧书架
23:19 [全桌] 心理学普通成功
23:18 [队伍] 获得旧建筑平面图
```

同一次行动合并成一张卡，不拆成碎片事件。

展开后显示：

- 行动；
- 最终裁决；
- 公共结果；
- 私人结果；
- 资源变化；
- 复核或桌面裁定。

# 7. 私密发现分享

点击“分享给队伍”后先生成可编辑摘要：

```text
准备分享

教授听到“B-17”后，
下意识看向北侧书架。

公开范围：全体队伍

[确认分享]
[修改内容]
[取消]
```

规则：

- 不默认分享原始完整内容；
- 不附带私人笔记、假说和判定依据；
- 分享后生成队伍版本；
- 私人原始记录继续保留；
- 队伍版本标记“由某玩家分享”；
- 玩家观察不会自动升级为系统确认事实。

# 8. 手机底部导航

固定四个入口：

```text
[当前] [调查] [角色] [更多]
```

| 入口 | 职责 |
|---|---|
| 当前 | 当前事项、行动输入、待处理、最近发生 |
| 调查 | 线索、人物、地点、地图、开放问题、假说 |
| 角色 | 状态、技能、物品、成长、更多数值 |
| 更多 | 规则帮助、设置、连接、安全工具；有权限时显示桌务控制 |

地图不单独占底部入口，通过当前地点或调查页进入。

# 9. 调查首页

## 9.1 调查总览

```text
调查

[搜索线索、人物、地点……]

当前调查目标
最近新增
开放问题
队伍置顶

[线索] [人物] [地点] [时间线] [假说]
```

## 9.2 动态排序

- 有未读资料：最近新增置顶；
- 全部读完：开放问题置顶；
- 不在玩家阅读过程中突然重排；
- 重新进入或主动刷新时更新顺序。

## 9.3 队伍资料与私人资料

默认主体为队伍公开资料。

存在新的私人发现时，在顶部单独提醒：

```text
仅你可见的新发现 1

教授看向了北侧书架。

[查看]
[分享给队伍]
```

读完后进入对应资料分类，并保留“仅你可见”标签。

# 10. 调查资料详情

## 10.1 统一四段式

人物、地点、物品和线索全部使用：

1. 摘要；
2. 当前已知；
3. 相关资料；
4. 玩家笔记。

摘要默认展开，其余折叠，并显示数量。

```text
摘要                         已展开
当前已知                     3 条
相关资料                     4 项
玩家笔记                     2 条
```

“当前已知”必须使用认知标签：

- 亲眼观察；
- NPC 证词；
- 玩家推测；
- 存在争议；
- 已确认；
- 已证伪。

不显示关键程度、完成度和隐藏线索数量。

## 10.2 底部操作

最多显示两个主要操作和一个更多菜单。

示例：

- 私人发现：加入笔记、分享给队伍；
- 队伍资料：加入笔记、置顶；
- 开放问题：补充发现、提出假说；
- 玩家假说：关联资料、更新状态。

# 11. 玩家假说

## 11.1 创建方式

采用“一句话假说 + 可选关联资料”。

```text
我认为：
陈教授知道 B-17 的真实用途。

可能相关：
☑ 教授听到 B-17 时停顿
☑ 护士关于教授行踪的证词

[保存假说]
```

规则：

- 只要求一句话；
- 关联资料可跳过；
- 从资料详情创建时自动关联当前资料；
- 系统只能推荐近期公开资料，不能推荐“正确证据”；
- 假说明确标记为玩家推测。

## 11.2 默认可见范围

默认仅自己可见。

分享后生成独立的队伍版本；之后修改私人原稿不会偷偷修改队伍版本。

## 11.3 共享假说协作

其他玩家不投票，只能：

- 补充支持资料；
- 补充矛盾资料；
- 补充相关资料；
- 写评论。

## 11.4 状态

只保留：

- 讨论中；
- 已证伪；
- 已搁置。

AI 可以依据新的已确认事实提出“可能证伪”建议，但不能自动修改状态。

任意玩家确认后立即生效，并提供 10 秒撤销。

状态变化只进入公共大屏底部记录，不抢占场景。

---

# 12. 开放问题

## 12.1 状态

- 待调查；
- 已有解释；
- 已关闭。

规则：

- 关联队伍假说后可建议改为“已有解释”；
- 已有解释被证伪后可建议恢复“待调查”；
- AI 不能自动关闭；
- 已关闭不代表答案绝对正确；
- 可以重新打开。

## 12.2 关闭流程

任意玩家可以发起关闭。

确认时显示仍有关联的假说和争议资料，并说明关闭不会删除资料。

关闭后提供 10 秒撤销。

## 12.3 首页展示数量

调查首页最多显示 3 条开放问题。

排序：

```text
队伍置顶
→ 最近更新
```

AI 不按幕后重要程度排序。

# 13. 角色页

## 13.1 页面结构

正常时显示精简总览；存在异常时，顶部增加当前状态卡。

```text
陈默 · 私家侦探

当前状态
轻伤 · 右手活动受限
[查看影响] [使用急救包]

HP      8 / 12
SAN     54 / 70
Luck    31

技能
常用 3 项 · 全部 24 项

物品
装备 2 · 背包 6 · 重要物品 1

成长
待处理 1 项

更多数值
```

## 13.2 常驻核心数值

只常驻：

- HP；
- SAN；
- Luck。

MP、MOV、体格、伤害加值等进入“更多数值”。

## 13.3 异常卡

- 只显示当前实际影响；
- 最紧急的一项展开，其余折叠；
- 可处理时显示一个主要操作；
- 私密异常不会公开到大屏；
- 解除后自动消失，但保留历史。

# 14. 技能页

## 14.1 页面组织

- 顶部搜索；
- 常用技能；
- 完整技能按调查、社交、战斗、知识、其他分类。

常用技能来源：

```text
玩家手动置顶
+
最近使用补足
```

AI 不能根据隐藏场景推荐正确技能。

## 14.2 技能使用

点击技能不会直接掷骰，而是将技能作为辅助标签带入行动输入：

```text
[行动 · 侦查]

描述你想怎样使用侦查……
```

玩家仍需描述目标和方法。

技能标签是玩家建议，不强制 AI-KP 使用该技能。

# 15. 物品页

## 15.1 页面组织

```text
当前装备
随身携带
容器内
不在身上
```

提供统一搜索。

规则：

- 物品位置必须真实；
- 容器默认只展开一层；
- 搜索结果仍显示当前位置；
- 当前无法使用时显示原因；
- 私人物品不会公开。

## 15.2 简洁物品卡

```text
急救包
随身携带 · 剩余 1 次
[仅你持有]

已知用途
可以处理常规外伤。

[使用物品]
[转交]
[…]
```

点击“使用物品”后，将物品标签带入行动输入，而不是直接消耗。

# 16. 物品转交

## 16.1 接收确认

转交采用请求—确认流程。

```text
发送者发起
→ 接收者确认
→ 服务端原子更新持有人和位置
```

接收前物品仍属于发送者。

请求期间同一物品不能再次转交或消耗。

## 16.2 公开与私下递交

发起时选择：

- 公开递交；
- 私下递交。

公开递交成功后进入公共记录。

私下递交只通知双方；其他玩家不知道该事务存在。

## 16.3 私下递交风险

如果环境不适合隐蔽，不禁止，也不自动改为公开，而是作为隐蔽行动裁决。

风险只显示定性等级：

- 较低；
- 一般；
- 较高；
- 无法判断。

风险提示只能依据玩家已知的公开环境，不能泄露隐藏观察者和隐藏警觉数值。

## 16.4 接收者信息

接收者看到：

- 发送者；
- 物品；
- 递交方式；
- 定性风险；
- 是否可能占用行动。

不显示发送者私人备注和隐藏难度。

## 16.5 是否占用行动

由当前情境和规则决定。

自由调查中通常是轻量互动；战斗、追逐、潜行或高压场景中可能占用动作、反应或注意力。

如果会占用行动，必须提前明确确认。

## 16.6 接收者正在行动

新递交请求不会打断当前正式行动，而是排入待处理队列。

当前行动结束后重新验证：

- 双方是否仍在同一场景；
- 物品是否仍由发送者持有；
- 当前行动阶段是否允许；
- 风险和行动成本是否变化。

## 16.7 条件暂时不满足

转成“暂存意图”，不继续占据待处理队列，也不锁定物品。

```text
暂存请求

准备将“旧钥匙”交给安娜
当前无法完成：双方不在同一场景

[条件满足时提醒]
[取消]
```

发送者仍可以正常使用、丢弃或转交物品。

条件重新满足后，不自动执行，只提醒发送者：

```text
你现在可以把“旧钥匙”交给安娜了。

[重新发起]
[忽略]
```

只有重新发起后，接收者才会收到请求。

# 17. 本轮简化策略汇总

| 复杂问题 | 采用的简化方式 |
|---|---|
| 公共大屏信息过载 | 场景为主，右侧轻量概况，底部有限历史 |
| 玩家不知道该做什么 | 手机首页始终突出一个当前事项 |
| 多个通知同时出现 | 一件主事项 + 待处理数量 |
| 行动误执行 | 渐进式确认 |
| AI 裁决等待 | 正式行动锁定，讨论与笔记继续 |
| 私密与公共混淆 | 明确文字标签，不只靠颜色 |
| 历史事件碎片化 | 同一次行动合并为一张记录 |
| 调查页面过于复杂 | 总览首页 + 统一四段式详情 |
| 玩家不敢提出猜测 | 假说默认私人 |
| 推理变成投票 | 只补充支持、矛盾和评论 |
| 角色卡数字太多 | 首页只显示 HP、SAN、Luck |
| 技能按钮变成自动过关 | 技能只作为行动标签 |
| 物品误消耗 | 使用物品必须进入行动确认 |
| 转交状态不一致 | 接收确认 + 原子事务 |
| 暂时无法递交 | 保存意图、不锁物品、不自动执行 |

# 19. 本轮最终表达

> 公共大屏负责让所有人看懂“现在发生了什么”；玩家手机负责让每个人看懂“现在需要我做什么”。  
> 大屏以场景和叙事为核心，手机以当前事项和行动为核心；调查、角色、技能和物品都围绕同一套低学习成本结构展开。
