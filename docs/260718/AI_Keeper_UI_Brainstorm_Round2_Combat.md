# AI-Keeper UI 头脑风暴第二轮总结

**日期：2026-07-18**  
**承接：`AI_Keeper_UI_Brainstorm_Round1.md`**  
**范围：战斗整轮声明、AI-KP 综合排序与结算、公共战斗舞台、手机端声明、角色喊话、缺席与重连、离线重大结果、行动限制提示。**

---

## 1. 战斗主模型

本轮最终否决“轮到某人后再输入并立即结算”的传统电子游戏式流程。

最终模型：

```text
公开本轮局势
→ 全体玩家分别声明
→ 处理未声明或缺席玩家
→ 锁定全部声明
→ 公开可观察的准备动作
→ AI-KP 生成整轮结算计划
→ 按规则顺序逐步提交结果
→ 将相关结果编排成连贯场景
→ 生成轮末局势总结
→ 开放下一轮声明
```

核心原则：

- 玩家负责声明自己的意图；
- 规则系统负责顺序、检定、资源和状态；
- AI-KP 负责综合所有行动、处理相互影响并组织叙事；
- 公共大屏负责共同理解；
- 玩家手机负责个人声明、结果和规则决定。

---

## 2. 手机端不建立独立战斗控制台

继续使用：

```text
[当前] [调查] [角色] [更多]
```

“当前”页根据阶段变化：

```text
声明阶段 → 声明本轮行动
已提交未锁定 → 修改或撤回声明
声明锁定 → 查看整轮结算
规则真实要求决定 → 处理该决定
轮末总结 → 填写下一轮声明
```

不常驻“攻击、闪避、反击、移动、使用物品、奖励骰”等按钮。目标、技能、武器和物品只作为辅助标签。

---

## 3. 公共战斗舞台

战斗时可以切换为只读战斗舞台，但不能成为控制台。

大屏只回答：

```text
第几轮？
当前是声明还是结算？
哪些公开单位参与？
当前正在发生哪个冲突？
本轮已经产生哪些公开结果？
```

禁止：

```text
发起攻击
选择反应
修改顺序
手动掷骰
添加单位
调整 HP
代替玩家声明
推进结算
```

---

## 4. 单位状态与敌人可见性

玩家和已公开敌人显示简化生命条与状态词：

```text
陈默
HP  ███████░░░
轻伤
```

规则：

- 不显示精确 HP 和最大 HP；
- 必须显示文字状态；
- SAN 不常驻；
- 已公开重伤、昏迷、疯狂可以显示；
- 无法观察伤势时，不显示生命条。

敌人只有在玩家明确感知后才进入公共舞台。禁止显示隐藏敌人、未知回合、隐藏占位或未发现数量。

安全名称示例：

```text
走廊中的人影
黑暗中的枪手
戴面具的陌生人
```

失去踪迹后保留原单位：

```text
黑暗中的枪手
失去踪迹
最后发现：走廊北侧
```

不显示当前位置、生命条、伤势变化和具体行动。轮到其结算时可显示：

```text
当前行动 · 具体情况未知
```

公开后果发生后再叙述可观察结果。

## 5. 声明阶段

手机页面：

```text
第 4 轮 · 声明行动

当前可见
· 走廊中的人影 · 近距离
· 北侧铁门 · 约 5 米
· 安娜 · 重伤
· 翻倒的推车 · 身旁

[描述你的行动]
```

提交后：

```text
你的本轮声明

向走廊中的人影开枪，
并掩护安娜退向北侧铁门。

状态：已声明 · 尚未锁定

[修改声明]
[撤回声明]
```

声明锁定前：

- 不掷骰；
- 不扣弹药或资源；
- 不改变位置；
- 不造成伤害；
- 不写入状态事务；
- 玩家可以修改或撤回。

公共大屏只显示：

```text
陈默    已声明
安娜    已声明
林海    思考中
顾云    已声明
```

不显示声明内容、提交顺序、NPC/敌人计划、秘密行动或私人限制。

“本轮暂不主动行动”也是正式声明，但锁定前只显示“已声明”。

---

## 6. 可观察对象与目标标签

手机只显示角色当前确实能感知的对象，不推荐行动、不按幕后重要性排序。

点击对象只添加目标标签：

```text
[本轮行动 · 目标：走廊中的人影]

描述你想怎么做……
```

不弹“攻击、观察、交谈”等预设操作。

P0 最多两个目标标签。超过两个时要求选择主要目标，其他内容可作为行动目的保留。不会因三个名词自动生成三次行动。

---

## 7. 组合行动确认

组合行动采用简短步骤确认：

```text
你的行动

1. 朝走廊中的人影开枪
2. 掩护安娜退向北侧铁门

主要目标
· 走廊中的人影
· 安娜

可能消耗
· 左轮手枪弹药 1

[确认行动]
[调整顺序]
[修改描述]
```

P0 最多整理为两个主要步骤，但仍是一份本轮声明，不重复扣行动次数。

---

## 8. 多阶段行动

明确撤销：

```text
第一步失败 → 自动取消第二步
第一步失败 → 固定询问是否继续
第一步成功 → 固定进入第二阶段
```

最终原则：

> 组合行动可以拆为多个结算阶段，但后续阶段如何发生，由 AI-KP 根据前面已提交事实、规则与整体故事继续编排。

例如：

```text
射击结算
→ 局势变化
→ 掩护与撤退结算
→ 统一叙事
```

公共大屏以整体冲突卡追加结果，不显示固定阶段总数或百分比。

手机显示紧凑阶段进度：

```text
✓ 射击
  弹药 -1 · 未命中

✓ 局势变化
  人影注意力转向你

● 掩护撤退
  正在结算……
```

已完成阶段可展开规则依据、资源、状态和公开/私人结果。

---

## 9. 声明锁定后的可观察准备动作

锁定后才统一公开本轮可观察动作：

```text
陈默举起左轮，瞄向走廊中的人影。
安娜开始向北侧铁门后退。
林海俯身检查卡住的门轴。
```

它不是完整意图，也不是最终顺序。

秘密复合行动只公开表面部分，不显示秘密动作占位。

NPC 与敌人也只显示观察性动作：

```text
走廊中的人影压低身体，重心向前。
陈教授正向北侧铁门移动。
护士把手伸进外套口袋。
```

不能直接断言“准备攻击、逃跑或拔枪”。

## 10. AI-KP 整轮结算计划

AI-KP 综合：

```text
全部玩家声明
NPC 与敌对单位意图
锁定前已发生的角色喊话
当前场景状态
位置、距离、遮挡
敏捷与规则顺序
预备动作和触发条件
持续行为
上一轮遗留影响
```

建议结构：

```text
RoundResolutionPlan
├─ ResolutionStep
│  ├─ globalOrder
│  ├─ clusterId
│  ├─ involvedEntities
│  ├─ dependsOn
│  ├─ ruleBinding
│  ├─ visibility
│  └─ stateTransaction
└─ PresentationCluster
   ├─ publicTitle
   ├─ publicParticipants
   ├─ completedPublicFacts
   └─ currentNarration
```

顺序不能按提交先后，必须综合规则、敏捷、预备动作、触发条件、位置和行动依赖。

---

## 11. 以冲突为焦点

公共大屏不显示“正在结算陈默、下一位安娜”，而显示：

```text
走廊入口的争夺

涉及：
陈默 · 安娜 · 走廊中的人影
```

一轮可有多个 `ResolutionCluster`：

```text
走廊入口的争夺
北侧铁门的开启
暗中的物品递交
```

私密冲突不显示标题、占位或存在提示；只有产生公开后果后才显示可观察结果。

---

## 12. 多冲突与全局顺序

采用：

> 规则层保持全局正确顺序；展示层在不改变事实先后的前提下，尽量合并为连贯场景。

内部顺序可能跨多个冲突。公共叙事可以自然切镜头，但不能颠倒已经提交的事实。

每个关键状态必须逐步提交，不能先生成整轮故事再一次性修改世界状态。

---

## 13. 正式结算阶段

大屏只显示当前冲突和已经完成的公开结果：

```text
第 4 轮 · 正在结算

走廊入口的争夺

当前发生
人影越过翻倒的推车扑向安娜，
陈默同时举枪试图阻止它。

已发生
✓ 顾云试图关门，但门轴卡住
✓ 陈教授退到了北侧墙边

本轮仍在继续……
```

不提前显示完整后续顺序、NPC 计划、隐藏行动、步骤总数或进度百分比。

---

## 14. 结算期间的输入边界

声明锁定后，玩家不能：

```text
补交新行动
修改或撤销声明
插入新的角色喊话
根据前面结果改目标
要求 AI-KP 重新排序
```

仍可：

```text
队伍讨论
规则提问
私人笔记
```

产品不能发明规则系统中不存在的中途反应、自由打断或“是否继续第二步”窗口。

只有规则包真实要求的决定，才生成待处理事项。

---

## 15. 多人规则决定与结果

若规则真实要求多人选择：

```text
相互独立 → 并行收集
存在依赖 → 按规则顺序开放
```

大屏只显示总体进度，不公开谁未提交。

收齐后先播放统一场景叙事，再在底部补个人结果摘要。具体伤害、资源和私人效果进入对应玩家手机。

---

## 16. 队伍讨论与角色喊话

### 队伍讨论

属于桌外协调：

- NPC 和敌人听不见；
- 不进入游戏世界；
- 不自动变成行动；
- 不消耗角色行动；
- 不覆盖正式声明；
- 默认不上大屏。

### 角色喊话

仅声明阶段开放：

```text
短促喊话 → 立即进入场景
长篇说服、欺骗、威胁、演说、仪式语言 → 进入正式行动声明
```

声明锁定后不再接受新的角色喊话，也不因喊话创造规则外反应窗口。

---

## 17. 未提交声明与缺席处理

公共大屏不显示倒计时和具体未提交者，只显示：

```text
已完成声明：3 / 4
等待 1 名玩家完成声明
```

对应玩家手机私下提醒：

```text
本轮仍在等待你的行动声明

[现在声明]
[本轮暂不行动]
```

长时间无响应时，桌务只能：

```text
使用玩家预设缺席策略
标记本轮暂不行动
继续等待
```

桌务不能替玩家选目标、消耗资源、查看草稿或让 AI 自由托管。

---

## 18. 缺席策略

只保留两种固定策略。

### 本轮暂不主动行动 `idle`

不生成新的攻击、移动、交互、交流、目标或资源消耗。角色仍在场景中，并正常承受外部影响。

它不是自动闪避、自动防御或 AI 托管。

### 维持既有持续行为 `maintain_existing`

只维持已经成立且规则支持的持续行为，例如：

```text
继续抵住铁门
继续维持已生效仪式
继续抓住已控制对象
```

不能表达：

```text
继续保护安娜
继续攻击最近敌人
有危险就躲
看情况花 Luck
```

---

## 19. 缺席期间的固定成本和可选资源

采用：

> 确定性的规则成本和强制检定继续执行；需要玩家选择的资源或策略决定不代选。

可自动执行：

```text
固定每轮扣资源
固定每轮检定
固定持续时长
固定失败后果
```

不能代选：

```text
Luck
Push
追加 MP
牺牲 HP
使用一次性物品
改变目标
接受额外风险
```

玩家回来后不能事后补选，也不局部回滚或重算。

---

## 20. 重大离线决策节点

如果未选择项会显著影响：

```text
角色生死
昏迷或永久失能
长期状态
重要物品
大量资源
持续行为
是否退出场景或冲突
```

系统必须记录：

> 该节点曾可选择花费 Luck、执行规则允许的反应或继续投入资源，但玩家当时离线且无有效预声明，因此按未选择处理。

记录应包含轮次、冲突、触发结果、真实选项、未等待原因、处理方式、最终后果和规则依据。

---

## 21. 重新上线后的重大结果

玩家必须先打开查看，但不需要“我已了解”确认。

首页：

```text
你离线期间发生了一项重大结果

北侧铁门被撞开。
你失去了正在维持的行动，并受到重伤。

当时存在一个未选择的 Luck 选项。

[查看经过]
```

记录状态只有：

```text
unseen → viewed
```

不设置 `accepted/approved/agreed`。

连续多个重大节点合并为一份“离线重大经过”，打开一次即可恢复正常导航。

---

## 22. 整轮中途重新上线

若整轮已经锁定，玩家可以查看局势、状态、讨论、规则和笔记，但不能：

```text
补交本轮行动
修改声明
插入喊话
补选过去资源
要求重排
```

必须等下一轮恢复主动声明。

---

## 23. 下一轮重新加入局势

下一轮手机显示紧凑卡：

```text
你已重新加入

当前位置
北侧档案室

当前状态
重伤 · 可以行动

当前可见局势
· 走廊中的人影仍挡在入口
· 北侧铁门已经打开
· 安娜倒在门后

队伍当前目标
撤离地下档案层

[声明本轮行动]
```

只显示角色有权知道的内容，控制在一屏内，不重复完整离线历史。

角色无法行动时，不显示误导性的声明按钮。

## 24. 声明页的状态影响提示

只展示会直接影响当前草稿的状态，不展示完整角色状态面板。

三类结果：

### 无法按当前方式执行

```text
当前无法执行

原因：
左轮手枪不在你身上。

[修改行动]
[选择其他物品]
```

### 可以尝试但存在影响

```text
本次行动受到影响

右手受伤：
使用手枪可能受到惩罚。
```

### 当前无法完全确定

```text
部分条件将在结算时确定

安娜是否仍位于门边，
取决于本轮其他行动的结算结果。
```

提示只能来自权威角色状态、持有物、已知资源、公开距离位置和明确规则，不能泄露隐藏能力、幕后难度或所谓正确行动。

---

## 25. 最终确认：两阶段影响提示

本轮最后确认采用：

> 选择目标、技能、武器或物品时先显示一行轻量提示；点击“提交声明”后再做完整校验。自然语言输入过程中不持续刷新和跳动。

### 第一阶段：轻量提示

```text
右手受伤可能影响手枪使用
该物品当前不在你身上
该目标已经离开你的视线
```

特点：

- 一行提示；
- 不阻止继续输入；
- 不展开复杂规则；
- 不按每个字实时刷新；
- 不清空草稿。

### 第二阶段：提交时完整校验

统一检查：

```text
目标是否有效
物品是否可用
资源是否足够
角色是否具备行动能力
当前阶段是否允许
状态是否影响行动
是否存在明确资源消耗
```

结果：

```text
可以提交
可以尝试但有影响
当前无法执行
部分条件将在整轮结算时确定
```

不采用全文实时分析，是为了避免页面频繁跳动、干扰自然语言表达和提前制造错误的“系统已经理解完成”印象。

---

## 26. 轮末局势总结

每轮都必须生成：

```text
第 4 轮结束

场景变化
· 北侧铁门已经打开
· 翻倒的推车挡住了走廊中央

角色状态
· 安娜退到门后，并受到重伤
· 陈默仍留在走廊入口

敌对情况
· 走廊中的人影受伤
· 黑暗中的枪手仍然失去踪迹

公开资源变化
· 陈默消耗了一发弹药

当前局势
人影仍挡在走廊中央，北侧通道已经可以进入。
```

只总结实际提交成功的公开变化，不显示隐藏状态、精确敌人 HP、秘密行动、私人资源和完整骰点。

---

## 27. 轮末与下一轮并行衔接

公共大屏继续停留在轮末总结。

玩家手机立即开放下一轮声明：

```text
第 5 轮 · 声明行动

上一轮局势
北侧通道已打开，安娜位于门后，
走廊中的人影仍在阻挡队伍。

[描述本轮行动]
```

第一名玩家正式提交后，大屏切换为新一轮声明状态。

## 28. 最终战斗状态机

```text
ROUND_PREPARE
→ ROUND_DECLARATION_OPEN
→ ROUND_DECLARATION_PARTIAL
→ ROUND_DECLARATION_COMPLETE
→ ROUND_DECLARATION_LOCKED
→ ROUND_VISIBLE_PREPARATION
→ ROUND_PLANNING
→ ROUND_RESOLVING
→ RULE_DECISION_WAIT（仅规则真实要求）
→ ROUND_RESOLVING
→ ROUND_SUMMARY
→ NEXT_ROUND_DECLARATION_OPEN
```

缺席分支：

```text
玩家未声明
→ 私下提醒
→ 桌务使用缺席策略
→ 生成缺席声明
→ 与其他声明一起锁定
```

重连分支：

```text
整轮未锁定 → 正常提交
整轮已锁定 → 只观看与讨论
下一轮 → 重新加入
```

## 29. 本轮明确撤销的方案

```text
传统逐人输入、逐人结算
公共大屏提前显示完整后续顺序
公共大屏显示隐藏敌人占位
第一步失败后固定询问第二步
结算中自由插入角色喊话
为喊话创造规则外 ReactionDecision
AI-KP 替离线玩家选择战术
桌务替玩家消耗资源
离线玩家回来后事后补选
整轮中途重新上线后补行动
玩家输入过程中持续实时全文校验
```

## 30. 本轮最终设计原则

| 主题 | 最终结论 |
|---|---|
| 战斗输入 | 所有人先声明，后统一结算 |
| 结算顺序 | 规则、预备动作与现场关系决定 |
| AI-KP | 综合排序、逐步提交、连贯叙事 |
| 公共大屏 | 展示冲突和结果，不做控制台 |
| 隐藏敌人 | 完全不显示存在性 |
| 多阶段行动 | 同一声明内分阶段结算 |
| 后续阶段 | 由 AI-KP 根据新局势编排 |
| 多冲突 | 规则层全局排序，展示层连贯切镜 |
| 结算中输入 | 默认锁定，只开放规则真实决定 |
| 队伍讨论 | 桌外协调 |
| 角色喊话 | 仅声明锁定前有效 |
| 缺席 | 暂不行动 / 维持既有行为 |
| 资源代选 | AI 与桌务均禁止 |
| 重大离线后果 | 明确记录，不事后补选 |
| 重连 | 当前轮只观看，下一轮恢复 |
| 影响提示 | 轻量预提示 + 提交时完整校验 |

---

## 31. 本轮最终定义

> **战斗中的玩家只负责声明自己的意图；规则系统维护顺序、检定、资源与状态；AI-KP 综合所有玩家、NPC、敌人、预备动作和场景关系，将整轮行动按规则逐步结算，并编排成连贯公共叙事。公共大屏让全桌看懂冲突如何发展，玩家手机让每个人看懂自己声明了什么、受到了什么影响，以及当前是否需要处理规则真实存在的决定。**
