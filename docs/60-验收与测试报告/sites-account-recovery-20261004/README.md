## 本轮完成的行为

房主使用当前 ChatGPT 账号创建房间，自动绑定程雁；另一位账号通过邀请认领许遥。认领后按账号恢复角色。邀请有效期为 24 小时，未被使用时房主可以更新链接，旧邀请随即失效。一个账号不能同时占据两个角色；已认领的角色不能凭复制链接转交其他账号。房间成员只收到自己的私密线索，最近房间列表只返回当前账号参与的房间。

站点路由使用平台提供的已认证身份，浏览器不再保存角色身份凭据。数据库只保存站点用户 ID 的哈希，不保存邮箱。邀请认领仍要求访问者先获得该私有 Site 的访问权限，游戏邀请不会自动扩大站点的访问范围。

AI 请求最多等待 60 秒，数据库中的生成占用期限为 75 秒。成员再次访问或轮询时，已经超期的生成会转为中断状态，双方行动保留。只有明确勾选可能产生额外费用并点击重试，才会启动新请求；重试绑定当前失败尝试，重复提交不会启动多次同一重试。迟到的旧响应失去写入资格，不能覆盖恢复后的回合。

这一恢复机制依赖玩家重新访问或轮询，尚无后台任务队列。它保护游戏状态及重复落库，不能保证模型服务商只计费一次；超时的旧请求可能已经产生费用。

## 浏览器观察

本地构建后的 Worker 使用 Miniflare D1。仅测试时启用的两个回环网关分别提供合成身份；网关不包含在部署包内，测试后已关闭。固定回放房间在双方提交和同时推进后只有 1 条剧情、1 次尝试，刷新后角色及私密线索保持正确。

失败房间故意未配置本地模型，返回 `model_not_configured`。未勾选费用确认时重试按钮禁用；明确重试后尝试数增加一次，当前仍为第 1 回合、0 条剧情，双方行动保留。此截图中的本地模型配置缺失是故障注入，不代表云端模型未配置。

邀请认领页面通过本地浏览器验证。点击复制时界面显示已复制，但自动化剪贴板读取为空，因此没有把完整的剪贴板传递计为通过；测试网关更新尚未使用的邀请后，将第二个标签导向认领页面，完成余下流程。

云端真实所有者已创建新版房间并刷新，页面仍显示程雁及其正确线索，许遥等待加入。随后归档云端截图时浏览器连接连续超时，未能保存该截图；保留本地浏览器截图与云端 HTTP 检查记录，不把本地截图标为云端证据。

## 审查中修复的问题

独立审查发现两处界面问题并已修复：收到 401 或 403 后清除旧的私密视图与邀请，401 显示登录入口；已显示邀请时仍可更新未认领的链接。三项受控组件检查先复现失败，再验证修复通过。该审查没有替代平台账号分享、实际双账号或计费验收。

旧版持有者凭据房间仍保留在 D1。新版 API 对其返回 `legacy_room` 并要求新建账号房间，没有推断旧数据的账号归属，也没有删除旧记录。本轮没有数据库表结构迁移。

## 下一项验收

1. 用户提供第二位玩家的 ChatGPT 登录邮箱，并授权其访问这个私有试验站；仅给该账号开放访问，不扩大为公开站点。
2. 两位真实账号分别建房和认领，验证相互复制链接不能接管角色，退出并重新登录后恢复原角色。
3. 完成至少 3 个真实 AI 回合，检查双方视图、刷新恢复和重复推进；补测实际请求中断及明确恢复。
4. 以上通过后，再决定是否投入四玩家和一份最小旧存档导入。当前结果支持继续有限试验，尚不足以决定全量迁移 Diceframe。
