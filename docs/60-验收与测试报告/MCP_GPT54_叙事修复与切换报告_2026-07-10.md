# MCP / GPT-5.4 叙事修复与切换报告

## 本次结论

1. “`周围暂时没有新的变化`” 不是前端文案问题，而是叙事增强链路被吞掉后落回了本地兜底文案。
2. 这个兜底问题已经修复，后端现在会正确接收并展开 `generate_narrative` 的返回结果。
3. 项目里的 `kp_mcp_server` 已经支持切到 `OpenAI / GPT-5.4`，并且后端已把 `generate_narrative` 正式路由到 MCP。
4. 当前这台机器上的 **实际运行模型还不是 GPT-5.4**，因为环境里没有 `OPENAI_API_KEY`，所以现网 MCP 进程仍在走 `DeepSeek`。
5. 这也解释了为什么现在虽然不再固定回那句兜底文案，但叙事质量仍可能偏泛、偏空，或者不够贴题。

## 已完成改动

### 1. 修复叙事链路

- 修复 `generate_narrative` 对 `KpResponse / NarrativePayload / dict` 的兼容与解包。
- 修复当 provider 返回完整 `{"narrative": {...}}` 时被吞掉的问题。
- 补全 `user_message` 自动生成逻辑，避免叙事调用时上下文过空。
- 为重写场景补充 `declared_intent / previous_narrative / spoiler_constraint / room_id / character_id`。

### 2. 打通 MCP 叙事任务

- 新增 MCP tool：`kp_generate_narrative`
- 后端任务映射新增：`generate_narrative -> kp_generate_narrative`
- `KpMcpProvider` 已为叙事任务自动包一层 `{"context": ...}` 参数

### 3. MCP Server 支持 OpenAI / GPT-5.4

- `kp_mcp_server/config.py` 已支持：
  - `KP_MCP_PROVIDER=openai|deepseek`
  - `OPENAI_API_KEY`
  - `OPENAI_MODEL`（默认 `gpt-5.4`）
  - `OPENAI_BASE_URL` / `OPENAI_API_BASE`
- `kp_mcp_server/kp_brain.py` 已支持：
  - `DeepSeek Chat Completions`
  - `OpenAI Responses API`

### 4. 加强中文叙事约束

- MCP 叙事 prompt 已强制：
  - 使用简体中文
  - 不切换成日文/英文
  - 上下文不足时做最小响应
  - 不自造未提及的新地点、新人物、新机构

## 当前仍然存在的真实情况

### 1. 代码已经支持 GPT-5.4，但当前进程还没切过去

当前环境检查结果：

- `OPENAI_API_KEY`：未设置
- `DEEPSEEK_API_KEY`：已设置

因此当前 `9100` 上跑着的 MCP 还是 `DeepSeek`，不是 `GPT-5.4`。

### 2. DeepSeek 叙事质量仍可能偏泛

这次修复的是“链路坏掉导致固定兜底文案”。

但如果底层模型本身输出偏空、偏泛，修完链路后仍然可能出现：

- 叙事过短
- 贴合度不高
- 细节不足

如果你要“更像现在这个助手”的叙事质量，下一步最直接的是切到 `GPT-5.4`。

## 切到 GPT-5.4 的方式

在启动 `kp_mcp_server` 前设置：

```powershell
$env:OPENAI_API_KEY="你的 key"
$env:OPENAI_MODEL="gpt-5.4"
$env:OPENAI_BASE_URL="https://api.openai.com/v1"
$env:KP_MCP_PROVIDER="openai"
python -m kp_mcp_server
```

如果你后面换的是 **OpenAI 兼容接口**，通常只需要改：

- `OPENAI_BASE_URL`
- `OPENAI_MODEL`
- `OPENAI_API_KEY`

后端 `3002` 不用改 provider 顺序，只要继续保持：

```text
mcp,deepseek,local
```

即可优先走 MCP。

## 对“后面换别的多模态 API 能不能 loop 成功”的结论

- **如果新 API 是 OpenAI 兼容接口**：现在这套改动已经基本就绪，直接换环境变量即可继续跑 loop。
- **如果新 API 不是 OpenAI 兼容接口**：还需要再写一个 provider 适配层，但不需要再动前端和 loop 脚本主体。
