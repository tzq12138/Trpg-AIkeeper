# Diceframe《玻璃雨夜》试点记录

日期：2026-10-03。目标：验证能否用 Diceframe 原生能力减少 AI-Keeper 的维护量。结论：**内容迁移与真实双人短流程可行，尚不足以批准正式切换。**

## 已交付

- 原生 Diceframe 本机服务：`http://127.0.0.1:19876`，仅监听回环地址。
- 固定运行版本 v2.6.1，提交 `962fda45a68caa24bac38fd2313d92d66fa59a7a`。上游 checkout 无改动。
- 一个声明式内容包：一个世界、继承的 CoC 轻量规则、程雁与许遥两张角色卡。只为兼容原角色，将建卡属性上限设为 480。
- [生成、安装与重启说明](../../../experiments/diceframe/README.md)；生成包及完整剧情截图保留在忽略的本地运行目录，遵循原模组私用许可。
- 用户自行完成模型设置。实际调用模型为 `deepseek-flash`；未代为复制本机已有 MIMO 凭据。用户明确同意协议，匿名统计关闭。

## 决策相关发现

### 1. 稳定版的席位身份边界不足

正常 UI 投影能隐藏他人私信，但本地试点的对抗性身份检查没有通过：持有本房间访问权限的请求可以进入不属于它的角色视图。**不能因此把当前 v2.6.1 当成严格隔离的多人底座。**详细本地复现和运行凭据不进入 Git。

当日重新核对上游远程 `main` 为 `297da1f06d1e177ade2324eb35d9eb8e1dff89cb`，其中已经加入 GM 席位分享保护。对这个独立 checkout 执行 `tests/test_share_gm_seat_guard.py`，18 项通过，另有上游语法和 aiohttp 键类型警告。可直接查看[上游回归测试](https://github.com/diceframe/diceframe/blob/297da1f06d1e177ade2324eb35d9eb8e1dff89cb/tests/test_share_gm_seat_guard.py)。

这说明该问题存在跟随上游修复的路径；当前运行实例没有升级，也未验证新版全部多人行为或普通玩家之间的隔离。

### 2. 一次模型输出异常

第 4 行动回合，公开 GM 叙事出现了内部防注入提示文字，正常救援段落没有显示；与此同时，检定、物品和私人感知仍发生更新。第 5 回合重新产生正常叙事并完成撤离。

没有回滚或抹去失败记录。当前证据只证明一次异常，尚未定位为模型输出、解析还是提示编排问题；不能承诺“改提示词即可修好”。后续应保留本地原始回合，用第二个提供方对照，并核对上游处理。

### 3. 叙事包不能取代旧引擎约束

| 原能力 | 本试点映射 | 尚欠的保证 |
| --- | --- | --- |
| 节点门槛、线索条件 | GM 世界书与检索条目 | 确定性门槛和状态约束 |
| 私人角色钩子 | GM 世界书；开局用原生私信分别投递 | 自动按角色投递；抗串号隔离 |
| SAN 和数值检定 | 原生 CoC 轻量规则、模型检定规划 | 原模组固定触发时机和全部规则等价 |
| 倒计时 | 叙事压力 | 权威时钟与固定回合触发 |
| 结局互斥、结团归档 | 故事收束后保留普通存档 | 确定性终局和旧战役档案结构 |
| 存量团迁移 | 保留旧系统 | 未迁移进行中的数据库状态 |

## 下一步方向

继续评估 Diceframe，暂缓完整替换。优先使用包含上游席位保护的固定版本复测，避免维护自己的核心分叉。然后扩展为“独立房主 + 两个普通玩家”的身份测试，并把同一短流程换一个模型提供方复跑，确认异常输出与成本是否可控。

只有权限、模型输出与结团体验达到要求后，再扩大到四人试点；届时决定哪些旧系统强约束必须保留为小扩展。当前不继续扩建旧系统的通用 UI、模型配置和基础存档功能。
