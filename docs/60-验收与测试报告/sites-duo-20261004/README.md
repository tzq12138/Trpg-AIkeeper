# Sites 双玩家可行性验收报告

[私有空间报告](https://chatgpt.com/space/page_35abd8d9b5dc8191ab742e28367103cf)

本报告记录 2026 年 10 月 4 日的 Sites 双玩家可行性试验，回答“能否直接在 Sites 上运行云端游戏核心”。结论：小型双人回合制核心已跑通，可以继续做有限试点；尚不足以决定把完整 Diceframe 迁过去。下一步应先验证真实账号邀请和生成中断恢复，再决定是否扩大投入。

已部署的[私有试验站](https://aikeeper-duo-sites-probe.www-2682028238.chatgpt.site)使用 Sites Worker、D1 云数据库和 deepseek-flash。当前仅所有者可访问。原有 Diceframe 候选版保持独立，这次没有迁入既有存档、剧本资料或完整游戏引擎。

## 实测结果

| 检查 | 结果与证据范围 |
| --- | --- |
| 本地定向测试 | 4 项通过；TypeScript 检查与生产构建通过 |
| 云端固定回放 | API 连续 5 回合通过，另有浏览器 1 回合；固定回放不计为 AI |
| 云端真实模型 | API 连续 2 回合，加浏览器 1 回合，共 3 个真实 AI 回合 |
| 并发结算 | 7 个 API 回合各同时发出 8 次结算请求；每回合只新增 1 次生成尝试和 1 条剧情 |
| 玩家隔离 | 不带或伪造玩家凭据被拒绝；伪造座位字段被拒绝；两边只收到各自的私有线索 |
| 行动约束 | 未到齐不能推进；重复行动保持幂等；篡改已提交行动和过期回合被拒绝 |
| 刷新恢复 | 双浏览器的固定回放和真实 AI 回合均保留剧情、进度及正确的私有线索 |
| 重部署恢复 | 云端 5 回合固定回放、2 回合真实剧情在重新部署后仍可读取 |


真实 AI 的两次 API 验收完整循环耗时分别为 14.937 秒和 15.060 秒，包含行动提交、重复请求和状态读取，不能当作纯模型延迟。服务商对这两次调用共报告 3156 tokens；浏览器那次未纳入 token 统计，未计算费用。

## 测试方式与边界

我用两个独立浏览器标签和两份角色凭据模拟程雁与许遥。浏览器经临时本机服务网关访问实际云端 Worker 与 D1；网关只负责转发与站点服务认证，游戏后端与模型调用均在云端。测试结束后网关已经关闭。普通网页登录停在 ChatGPT 登录页，因此两个真实 ChatGPT 账号登录、朋友邀请与跨设备接续仍未验收。

私有线索由服务端分别投影，并且不进入模型的公开叙事输入。这验证了本试验的玩家数据隔离，不等于完整主持人权限、安全审计或 Diceframe 权限补丁的再次验收。角色链接仍是可转交的持有者凭据，尚未绑定真实账号。

生成请求由 D1 版本比较更新抢占。观察到的并发请求没有重复生成；但尚未验证进程中断、账单级幂等或自动恢复。模型失败会显式保留失败状态并停止重复调用，目前需要新建试验房间。没有 SSE、后台队列、四玩家压力、长存档或完整 data 迁移验收。

## 测试中修复的问题

首次云端 AI 请求因 Worker 不接受 fetch 的 redirect error 模式而失败。定位到运行时差异后改用 manual，并拒绝非成功响应；修复后 3 个真实 AI 回合通过。Windows 上还遇到 npm 调用路径与打包脚本的 Bash 和盘符兼容问题，已通过本次构建命令调整完成部署。

模型凭据依照本次明确授权写入该私有试验站的运行时 Secrets；源码、截图、测试证据和本报告均不包含密钥。没有扩大站点访问范围。

## 接下来怎么走

建议继续一个范围有限的验证阶段：先把真实站点身份绑定到角色，并完成两位实际账号的邀请、退出和重新进入；再补生成超时或进程中断后的恢复、明确重试及避免重复计费。通过后才推进四玩家连续回合和一份最小旧存档导入。

这次结果说明 Sites 能承载这个新写的小核心，不能据此推断完整 Python 后端可直接搬入。若优先减少维护量，仍应比较保留 Diceframe 后端的托管运维成本，与重写游戏状态、权限、模型流程和数据迁移的长期成本。现阶段保留候选版，把此站作为技术试验。

## 后续验收门槛

1. **真实账号与邀请**：角色绑定已验证的站点身份；两位真实用户分别进入，复制他人房间或角色链接不能接管角色；退出重进后恢复原身份。
2. **失败恢复**：在生成超时、请求断开和 Worker 中断时保持状态可解释；提供明确恢复路径，并证明迟到响应不会覆盖新回合、重试不会重复落库。账单层面的去重能力需单独确认。
3. **扩大试点**：前两项通过后，再做四玩家连续回合和一份最小旧存档导入；然后按实际改写量决定是否迁移更多 Diceframe 功能。

以上是下一阶段建议，尚未在本次实现。Pages 报告内容已通过接口回读核对；原生 Pages 排版未做浏览器视觉验收。
