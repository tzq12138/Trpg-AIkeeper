## 目的与边界

本手册覆盖 `docs/260718` 的最后两类外部证据：真实浏览器交互和已保存的动态 AI 供应商。所有结果应写入同次验收报告，并附截图、网络事件摘要、citation 和失败恢复证据。

- 不在截图、报告、URL、浏览器存储或前端日志记录 API Key、Bearer token、owner token、player token、原始 AI prompt 或完整上游响应。
- 使用管理员验收中心创建隔离房间和账号；不复用正在进行的玩家房间。
- 使用已发布的黄金样本剧本；优先选择带地图、调查、战斗、结束条件和至少一张素材的样本。
- 所有真实模型调用需在页面显示阶段状态。超过 30 秒、返回错误或断线时，只记录恢复链路，不把兜底叙事视为模型质量通过。

## 场景 A：单人完整行动链

1. 管理员导入并发布一个黄金样本；确认质量报告、citation、运行包门禁和素材绑定均显示可开团。
2. Host 从该发布版本开隔离房，玩家经邀请链接登录、选角并进入。
3. 玩家依次完成：自然语言调查、需要追问的歧义行动、明确的物品/移动行动、战斗或伤害/理智行动、到达结局。
4. 对一个高风险草稿确认前截图，确认后记录 `actionId`、`transactionId`、`stateVersion` 与安全 citation。
5. 在 `queued`、`resolving` 或 `completed` 中刷新页面；确认恢复的是服务器权威状态，且没有重复骰子、资源或叙事。
6. 记录叙事阶段：检索、裁决、规则校验、演绎、完成/恢复。任何失败必须记录已保持的状态和恢复操作。

通过条件：玩家只描述意图；高风险动作不会在确认前结算；AI 叙事与规则结果一致；结局有来源引用；刷新不重复应用状态。

## 场景 B：四玩家批处理与隐私隔离

1. 用同房间四名玩家进入同一场景，两名玩家在短窗口内确认自然语言行动。
2. 验证行动阶段从 `queued` 进入 `batched`，随后统一结算与叙事；不以提交先后伪造规则顺序。
3. 让一名玩家完成私密调查或接收私密物品；其余三名玩家分别刷新、重连并打开日志。
4. 确认公共舞台只显示公开叙事和安全摘要，私密正文、引用、行动 ID 与资源数据不泄露。
5. 如进入战斗，四人全部声明后再锁定；记录 DEX/规则排序、公开冲突簇和无精确敌人 HP 的摘要。

通过条件：批处理状态可见、每名玩家只有自己的私密结果、队伍讨论不创建权威 action、公共投影不泄露隐藏单位或精确数值。

## 场景 C：Host 舞台、ACK 与恢复

1. Host 分别打开导演台和公共舞台投影；确认两者显示的信息不同，公共舞台不含队列、证据、精确资源或私密 patch。
2. 播放一个带叙事步骤的已结算事务；记录 `transactionId`、`stepId`、`stepIndex`。
3. 在步骤完成后刷新 Host 页面或短暂断开再恢复；确认已 ACK 步骤不重复播放。
4. 触发或构造 `projection_pending` 后使用“恢复待发布裁决”；确认只重放已保存投影，不重新裁决、掷骰或改世界状态。

通过条件：ACK 只代表播放进度；恢复不产生新的规则写入；Host/公共舞台均不读取玩家私密正文。

## 场景 D：真实供应商与回退

1. 启用图文供应商，导入包含文本、图片或扫描页的黄金样本；核对解析文本、页/段 citation、图片素材绑定和质量问题。
2. 分别对一个缺图场景和至少一个缺图的 NPC、物品或线索执行“AI 从原文起草配图 → 编辑提示词 → 生成预览 → 采用并绑定”；确认每条建议都有目标类型、稳定 ID 与原文 citation，且建议、预览和采用三步之间没有提前写入素材或绑定。
3. 默认保持 Host 可见。若改为队伍可见，检查生成请求只使用 `public_description` 或已确认的公开可见边界，不包含真相、结局、隐藏 NPC 或未发现线索；没有公开画面依据时应显示安全错误，手动上传/绑定入口仍可用。
4. 用主供应商执行单人行动链的一次调查和一次叙事；记录模型名称、协议、阶段耗时和安全 citation，不记录 Key 或 prompt。
5. 切换到已测试的纯文本备用供应商，重复一次调查/叙事。若主供应商失败，验证进入备用链或本地 fallback；多模态不能安全完成时应显示 `awaiting_provider`，不得生成伪造结果。

通过条件：供应商切换无需重启；错误仅显示脱敏错误码；图文失败不破坏手动素材绑定；叙事不修改规则、骰点、状态或结局事实。

## 场景 E：响应式与弱网恢复

分别在 360px、390px、430px 视口完成加入、当前事项、行动输入、高风险确认、资料抽屉、地图投影和刷新恢复。

- 地图只显示玩家已知区域、地点、连接和队伍位置；点击地点只能辅助填充自然语言输入，不能直接改位置。
- 手机“待处理 / 最近发生”只显示该角色可见事件；浏览器存储不保存正文。
- 在草稿编辑、确认卡与行动结算期间各断网一次；离线草稿可编辑但不得自动发送状态型行动，恢复后以服务器状态优先。

通过条件：无横向溢出、无剧透投影、状态不重复、用户可明确继续/放弃本地草稿。

## 报告模板

每个场景单独写：环境与供应商（脱敏）→ 参与账号角色 → 操作步骤 → 观察结果 → action/transaction/state/event 对照 → citation → 截图文件 → 结论（通过/失败/阻塞）→ 失败复现与修复证据。

只有全部 25 条核心断言、单人、四人、Host 恢复、三种移动视口和主/备供应商场景都有实证，才能把当前 `260718` 目标的浏览器与真实供应商门禁标记为完成。
