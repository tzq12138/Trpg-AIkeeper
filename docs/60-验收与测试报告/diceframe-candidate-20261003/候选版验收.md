# Diceframe《玻璃雨夜》候选版验收

日期：2026-10-03。结论：本机候选版达到本阶段验收标准，可以安排小范围真人试玩。继续使用 Diceframe 底座，保留固定版本、内容转换器和一份席位权限补丁；暂不复刻旧前端或旧状态机。

入口：<http://127.0.0.1:19877/#/overview>。总览中有“候选验收 · 2 人玻璃雨夜”和“候选验收 · 4 人玻璃雨夜”两份存档，均已暂停在第 6 轮。旧试点 <http://127.0.0.1:19876> 及其数据保留。本机地址只供当前电脑访问，朋友异地接入仍需另行确定部署方式。

## 版本与修改范围

- 固定 Diceframe `297da1f06d1e177ade2324eb35d9eb8e1dff89cb`，附加 [席位补丁](../../../experiments/diceframe/patches/README.md)。上游源码、模型配置、会话、原始证据、生成内容包和导出存档均留在被忽略的 `.runtime/diceframe-candidate/`。
- 内容转换器 0.2.0 支持程雁、许遥、贺北、苏眠四张原卡；可只选两张开团。私人钩子由 GM 逐人投递，不放入公开角色模板。
- 普通玩家私信、行动和 SSE 绑定服务端会话；空席位首次认领后不能被另一会话抢占，转交 AI 不会释放身份。认领使用原有状态锁；会话按局保存席位，跨局加入和房主恢复不覆盖其他局。
- 建团第一张卡为“等待认领”或“AI 托管”时，GM 独立于所有玩家；保留原生“第一张卡由房主兼任”的选择。没有新增前端或账户系统。

浏览器抽验通过复用验收客户端自己的 cookie，分别在 `localhost` 打开普通玩家页面；房主在 `127.0.0.1` 使用管理页。两次真实页面操作分别是双人团程雁第 3 轮行动、四人团苏眠第 4 轮行动；其余行动由独立 HTTP 客户端提交。测试用浏览器会话切换后进行了完整刷新。这里的“四人”表示四个独立玩家会话，浏览器抽验覆盖其中两种角色视角。

实际模型为用户设置的 `deepseek-flash`。合计应用计数 24 次、201,064 tokens；失败请求的供应商消耗没有可核对账单，以上不能换算成最终费用。

双人团救出被困者并撤离，但未完成切断电源，叙事中发生管线反涌。四人团完成关阀、救援、证物和人员交接，总电仍由到场专业人员后续处理。两场均以实际结果收束，保留未解决疑点；没有把多步骤行动的意图等同于全部执行成功。原生任务记录分别显示救援/事故处置完成。

双人前两轮使用原生房主推进，按默认规则放弃待定幸运；后续待定幸运由对应玩家明确选择不消耗。检定结果保留成功与失败，不为验收改骰面。

四人团第一次调用“剧情概览”返回 `ok: false`，消息为“剧情概览生成失败，请检查模型连接后重试”。接口没有提供足以判定根因的细节。保留原失败响应后，在重启的候选服务上重试成功。重试后核对：仍只有 0–5 六条回合记录、20 条玩家行动、1 份回顾，没有重放游戏回合。该实测覆盖回顾失败恢复；行动回合故障仍以定向模型替身测试为证。

## 复现与试玩步骤

按 [候选运行说明](../../../experiments/diceframe/CANDIDATE.md)准备固定版本、应用补丁、启用内容包。模型在候选端口的设置页自行配置并测试，关闭匿名统计。

1. 原生创建多人《玻璃雨夜》，选择两张或四张卡，把所有卡切成“等待认领”，确保房主独立。
2. 每名玩家在自己的浏览器打开操作链接、验证房间密码并首次认领；GM 通过“角色感知”分别发送对应私人钩子。
3. 各自提交行动并处理原生检定/幸运选择。从调查、控制室、地下救援推进到撤离交接；按实际检定接受结果。
4. 中途保留浏览器 cookie，刷新并继续；停止并重新启动同一候选数据目录的服务，检查原有角色、记录和私信。原生暂停状态下的玩家新行动可恢复进行。
5. 结束本次故事后生成“剧情概览”，在总览导出存档；服务重启后应能找到暂停存档和时间线中的回顾。

自动化命令（在候选源码目录内运行，路径回到本仓的 `experiments`）：

```powershell
& ../venv/Scripts/python.exe -X utf8 -m pytest ../../../experiments/diceframe/checks/identity_http.py tests/test_share_gm_seat_guard.py tests/test_template_visibility.py tests/test_rule_system.py tests/test_round_failure_recovery.py tests/test_sse_ticket.py tests/test_webui_characters.py tests/test_player_control_authority.py tests/test_player_control_ux.py tests/test_characters_viewer.py tests/test_game_lifecycle_transactions.py -q --tb=short --disable-warnings
```

本仓根目录另运行内容/身份包装入口，设置 `DICEFRAME_ROOT`，避免两个项目的 `src` 包冲突：

```powershell
$env:DICEFRAME_ROOT = (Resolve-Path .runtime/diceframe-candidate/app).Path
& .runtime/diceframe-candidate/venv/Scripts/python.exe -X utf8 -m pytest experiments/diceframe/test_candidate_identity.py experiments/diceframe/test_glass_rain.py -q
```

包装入口显示 5 项，其中身份入口内部运行 14 项 HTTP 用例；不能将它们与 187 项重复相加。补丁在干净固定提交上通过 `git apply --check`，当前候选源码通过反向检查；8 个修改源文件通过 `mypy --follow-imports=skip`。

## 审查、取舍与下一步

一次独立全分支代码审查指出“同一浏览器跨局认领后丢失第一局身份”。新增回归先复现 403，再改为持久化按局绑定并通过回归；恢复 GM 也只影响当前局。没有尚未处理的实质代码审查问题。

执行中的取舍及代价：

1. 复用现有隔离工作树开候选分支，保留旧试点；若隔离不足，需要保全改动后再换目录。
2. 按用户选择维护一份固定提交的最小补丁；若后续兼容成本超标，撤掉补丁并退回可信本地试用。
3. 保留原生空席位邀请，用会话、状态锁和持久认领标记保护身份；代价是补丁维护，以及丢失 cookie/换设备后的恢复尚需额外方案。
4. 加入页公开详情和认领请求可携带目标 UID，但不据此获得私人身份；代价是公开投影必须持续回归检查。
5. 收紧两条原先允许跨席位认领的上游断言，并给投影测试补真实 cookie；旧裸 UID 链接不能再接管已认领角色。
6. 尊重首卡控制方式，让房主可独立并正常订阅 SSE；代价是多维护三个小型集成改动。
7. 将模型、浏览器和重启证据单独实测，不从单元测试推断；若缺项则保持试验状态。本报告现已补齐本阶段要求。
8. 公网部署、长时弱网压测和旧状态机等价迁移继续排除在范围外；后续扩展使用场景时需要单独验收。

候选版边界：同一浏览器可跨局续玩；清空 cookie 或换设备不能仅凭房间密码冒领原角色，尚无房主批准恢复的 UI。首次空位仍按房间邀请先到先得。叙事模型会保留疑点，也可能出现细节不一致；严格剧情条件、SAN 触发和结局互斥未迁移为旧引擎同等确定性规则。

下一步只安排一场真实朋友试玩，重点观察首次入座、私人线索理解、检定等待和结团找档四件事。先确定可访问的试用环境，再收集阻塞问题；继续冻结旧系统的大规模开发，只有试玩反复证明缺口时才增加补丁或 UI。上游修复覆盖同等权限合同后移除本地补丁，重新执行本报告的回归。
