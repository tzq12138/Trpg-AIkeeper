# DeepSeek 任务包索引

本目录用于把 Codex 拆好的方向交给 DeepSeek 执行。每个 Batch 都必须独立验收，不允许跨批顺手扩功能。

## 执行顺序

| 批次 | 名称 | 目标 |
|---|---|---|
| [Batch 0](./Batch-0-文档归档与索引.md) | 文档归档与索引 | 建立 `docs/` 总入口、归档历史计划、明确第一轮范围。 |
| [Batch 1](./Batch-1-开发态稳定性与实时闭环.md) | 开发态稳定性与实时闭环 | 修 WS、Host 鉴权、Lobby 同步、日志乱码、MCP/DeepSeek 剧本链路。 |
| [Batch 2](./Batch-2-状态版本屏障与投影时序.md) | 状态版本屏障与投影时序 | 解决重连补丁乱序和私密 patch 早于 Host 演出的剧透问题。 |
| [Batch 3](./Batch-3-AI反幻觉与真相锁定.md) | AI 反幻觉与真相锁定 | 强化 AI 输出校验、真相锁定、上下文过滤和 Engine 写边界。 |
| [Batch 4](./Batch-4-线索证据链与防剧透.md) | 线索证据链与防剧透 | 补齐线索归属、分享、公共摘要、事件引用和可见范围。 |
| [Batch 5](./Batch-5-验收与回归.md) | 验收与回归 | 跑全量验证，手动验收完整 AI-KP 主链路。 |

## 通用执行规则

- 每批开始先运行 `git status --short` 并记录当前工作区状态。
- 只改当前批次列出的文件方向，不做相邻重构。
- 不提交密钥、日志、本地数据库、`node_modules`、`dist`、`.runtime`。
- 后端测试必须使用测试库，不得清空开发库。
- 所有“通过”结论必须来自本批新运行的命令输出。
- 如果测试失败，先判断是本批引入还是已有失败，再决定修复或回报。
