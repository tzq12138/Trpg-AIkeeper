对，这里必须先纠正术语：

> **Host 页面不是房主后台，而是给整桌所有玩家共同观看的“公共桌面 / 公共舞台”。**  
> **Player Play 页面是每名玩家手机上的私人操作端。**

所以今后最好不要再把“Host”同时当成页面和角色，否则权限设计一定会混乱。

建议统一命名：

| 概念 | 建议名称 | 含义 |
|---|---|---|
| 大屏页面 | `Shared Stage / 公共桌面` | 所有人共同观看 |
| 玩家手机页面 | `Player Companion / 玩家终端` | 每人独立、含私密信息 |
| 创建房间的人 | `Room Owner / 房主` | 负责建房和成员管理，不看剧透 |
| 应急处理的人 | `Table Steward / 桌务` | 处理暂停、故障和无剧透裁定 |
| 真正的 KP | `AI-Keeper` | 唯一掌握幕后真相的主持运行时 |

现有代码里的 `HostStage`，产品概念上应该逐渐改叫：

```text
PartyStage
SharedStage
PublicStage
```

# 一、整个产品需要五类 UI

不是玩家端和 Host 端两个页面，而是五类不同用途的界面。

```text
1. 公共桌面：全体玩家共同观看
2. 玩家终端：每名玩家手机私人使用
3. 桌务控制：房主/桌务在私人设备使用
4. 战役准备台：建房、导入模组、配置开局
5. 平台后台：管理员和运维使用
```

其中前三类属于实际跑团现场。

# 三、A 类：公共桌面 Shared Stage

这就是你说的 **Host 页面**。

它是：

```text
电视
投影仪
房主电脑共享屏幕
Discord / QQ 屏幕分享
远程玩家打开的只读公共页面
```

它不是操作后台，也不是 KP 页面。

## 公共桌面的权限

它只能接收：

```text
Party 公开叙事
公共 NPC 对话
公共地图
公开骰子结果
队伍公开线索
公共场景变化
公共投票和选择
系统暂停状态
本局公共总结
```

它永远不能接收：

```text
玩家私密线索
玩家私人笔记
玩家个人目标
仅本人可见的观察结果
隐藏骰子的真实难度
AI-KP 内部计划
模组真相
未发现 NPC
隐藏地图
未触发线索
桌务内部事故信息
```

公共桌面本质上是：

> **AI-KP 向整桌玩家进行公共主持和公共叙事的舞台。**

# 四、公共桌面不是很多菜单，而是一张页面的多个模式

公共桌面不应该让人拿鼠标到处点。

它应该根据房间状态自动切换模式：

```text
display_pairing
→ lobby
→ campaign_recap
→ opening
→ live_stage
→ public_decision
→ paused / recovery
→ session_summary
```

## A5. 公共裁决展示

玩家手机上会得到完整私人裁决回执。

公共桌面只播放该行动允许公开的部分。

例如：

```text
陈默尝试观察教授的反应

心理学检定
骰子：32
结果：普通成功
```

然后显示公共叙事：

> 陈默提到“失踪病人”时，教授短暂地停顿了一下。

不能在公共桌面显示：

```text
隐藏难度
教授真实动机
陈默个人私密观察
完整状态 Patch
```

```text

```

手机端仍可以有自己的可缩放地图和私人标记。

## A7. 公共决定 / 全桌投票

有些决定属于全桌：

```text
是否接受某个剧情分支
是否暂停
是否进入 Fade
应急裁定选择
队伍共同决定下一步
```

```text

A. 立即离开
B. 继续搜查
C. 暂停讨论
```

每名玩家在手机上投票。

公共桌面不显示谁选了什么，除非该投票设为公开。

## A8. 暂停 / 恢复页

系统或桌务暂停时：

```text
游戏已暂停

原因：
系统正在恢复场景一致性

你的行动不会丢失。
角色状态和物品不会重复变化。
```

整桌不需要看到：

```text
后台错误堆栈
AI 内部矛盾原因
隐藏剧情对象
```

如果需要桌务介入，公共桌面只显示：

```text
等待桌务完成无剧透恢复。
```

详细选项只在桌务手机端出现。

# 十、后端 audience 也要按页面重新划分

建议事件受众不再只用：

```text
host
player
party
system
```

而是改为：

```text
party_stage
player_private
player_party
steward_ops
room_setup
keeper_internal
platform_admin
public_external
```

| Audience | 去哪里 |
|---|---|
| `party_stage` | 公共桌面 |
| `player_private` | 指定玩家手机 |
| `player_party` | 所有玩家手机，可选同步公共桌面 |
| `steward_ops` | 桌务控制 |
| `room_setup` | 战役准备台 |
| `keeper_internal` | AI-KP 内部运行时，不进人类 UI |
| `platform_admin` | 平台后台 |
| `public_external` | 未来社区公开内容 |

最关键的是：

```text
RoomOwner 不自动获得 keeper_internal。
TableSteward 不自动获得 keeper_internal。
SharedStage 永远不接收 player_private。
```

# 十三、最终收敛

你们的 UI 不是传统的：

```text
KP 后台
+
玩家前台
```

而应该是：

```text
一块所有人共同观看的公共舞台
+
每名玩家一台私人操作终端
+
一名玩家可选拥有的无剧透桌务控制
+
开团前使用的战役准备台
+
平台内部的 Admin/Ops 后台
```

最简洁的产品界面定义是：

> **公共桌面负责共同体验，玩家手机负责个人行动与私密信息，桌务控制只负责流程和故障，AI-KP 独占幕后真相。**

下一步应该直接把 **公共桌面 `/stage/:roomCode`** 拆成完整的信息架构：固定区域、事件卡片、场景切换、公共骰子、地图模式、投票模式以及不同房间状态下的页面变化。
