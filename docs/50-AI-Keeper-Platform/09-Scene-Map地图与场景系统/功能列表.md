# Scene / Map 地图与场景系统功能列表 V2.0

## 模块定位

Scene / Map 模块负责把剧本中的场景结构变成可运行的空间投影：剧本地图模板、房间地图状态、角色当前位置、探索迷雾、Host 全图监督、玩家移动入口和当前场景状态。

本模块不负责 AI 裁决、不负责规则结算、不直接写角色数值和世界真相。玩家能看到的地图永远是 Projection 的结果，Host 能看到全图但不等于 AI 或 Engine 的规则执行者。

## 当前代码真实链路

| 链路 | 当前代码锚点 | 现状判断 |
| --- | --- | --- |
| 地图生成 | `src/server/router_admin.py` 的 `POST /api/admin/scenarios/{scenario_id}/map/generate`，`src/server/ai/map_generator.py` | 已有 DeepSeek 生成和 Python fallback，但数据源读 `scenarios.scenario_assets.scenes`，与导入后的 `knowledge_graph.scenes` 存在断层 |
| 地图草稿编辑与确认 | `GET/PATCH/POST /api/admin/scenarios/{scenario_id}/map` | 已有 draft/confirmed 流程，适合作为剧本地图模板 |
| 房间开局初始化地图 | `src/server/router_rooms.py` 调 `init_room_map_state` | confirmed 地图可在开局时初始化到 `room_map_state` |
| 房间地图状态 | `src/server/map_persistence.py` 的 `room_map_state` helper | 有探索节点、隐藏节点和 `state_version`，但初始化幂等返回值不完整 |
| 玩家地图视图 | `GET /api/map/{room_id}` 和 `build_player_map_view` | 有迷雾视图，但无 token 分支会返回完整节点，读接口还会自动写入位置和 explored |
| 玩家移动 | `POST /api/map/{room_id}/move` 到 `ResolutionPipeline._apply_move_result` | 移动通过 Engine intent，成功后写位置和探索节点，基本方向正确 |
| Host 全图 | `GET /api/host/{room_id}/map/full`，`HostMapPanel.tsx` | Host 可看节点、边、位置、探索与隐藏状态 |
| Host 显隐和强制移动 | `/map/reveal`，`/map/move-character` | 已有接口和 WS 事件，但缺节点存在性、角色归属、审计和统一版本屏障 |
| 当前场景状态 | `src/server/engine/state_service.py` 的 `room_scene_state` | StateService 已能处理 `current_scene`、visited、public facts 和场景变量 |
| 前端玩家地图 | `PlayerActionPage.tsx` 内的 `PlayerMapPanel` | 有地图 tab、移动提交和地图事件刷新 |

## 数据对象

| 对象 | 类型 | 归属 | 说明 |
| --- | --- | --- | --- |
| `scenario_maps` | 剧本模板 | Admin / Module | 保存地图节点和边，状态为 draft 或 confirmed |
| `room_map_state` | 房间运行态 | Engine / Projection | 保存 explored、hidden 和地图状态版本 |
| `character_map_positions` | 角色位置 | Engine | 保存角色在房间地图上的当前位置 |
| `room_scene_state` | 当前场景运行态 | StateService | 保存当前场景、已访问场景、公开事实、场景变量和媒体资源 |
| map node | 模板节点 | MapGenerator / Admin | 当前字段含 `node_id`、name、description、NPC、clue、position、is_start |
| map edge | 模板边 | MapGenerator / Admin | 当前字段含 from、to、单向标记和 label |

## P0 MVP 必须稳定

| 功能 | 当前状态 | 进入 MVP | 依赖模块 | 验收口径 |
| --- | --- | --- | --- | --- |
| 玩家地图鉴权 | 存在无 token 返回完整节点风险 | 是 | User、Safety | 无 token 或无效 token 不返回完整节点；有效玩家 token 只返回本人所在房间投影 |
| 玩家迷雾投影 | 已有 explored/adjacent 逻辑 | 是 | Projection、Clue、NPC | 玩家只看已探索节点和安全相邻提示；未发现线索、隐藏 NPC、真相字段不出现在响应 |
| 地图读接口无副作用 | 当前 GET 会自动写位置和 explored | 是 | State、Transaction | `GET /api/map/{room_id}` 只读；首次位置初始化由开局、入房或明确动作完成 |
| 玩家移动入口 | 已有 `/move` 和 move intent | 是 | Rule、Transaction、AI-Keeper | 非相邻、隐藏节点、无地图、无当前位置都被拒绝；成功移动必须经过 Engine resolve |
| 移动成功后更新位置 | 已在 `_apply_move_result` 写位置和 explored | 是 | State、Projection | 只有裁决成功才更新 `character_map_positions` 和 explored，并发送 `s2c_player_moved`、`s2c_map_updated` |
| Host 全图监督 | 已有 `/map/full` | 是 | Host Client、User | 只有房主或 admin 可读全图；Player 端不能复用该接口 |
| Host 显隐节点 | 已有 `/map/reveal` | 是 | Host Client、Journal | 必须校验节点存在，操作后写版本和事件日志，玩家只收到安全投影变化 |
| Host 强制移动 | 已有 `/map/move-character` | 是 | Host Client、Journal | 必须校验角色属于房间、目标节点存在；强制移动写审计事件 |
| 房间开局初始化地图 | 已接在 Room start | 是 | Room、WorldBook | 房间 active 时如有 confirmed map，应得到稳定 `room_map_state` |
| 当前场景状态 | StateService 已有基础表和 apply | 是 | State、Journal | 场景变化通过 StateService，产生版本推进和 `s2c_scene_sync` |

## P1 第一轮加固

| 功能 | 当前状态 | 进入近期版本 | 依赖模块 | 验收口径 |
| --- | --- | --- | --- | --- |
| 地图生成字段对齐 | 当前读取 `scenario_assets.scenes` | 是 | WorldBook、Module | 从 `knowledge_graph.scenes` 或统一适配层生成地图，PDF 导入后可直接生成节点 |
| 生成提示词修正 | `map_generator.py` 中存在乱码提示词 | 是 | AI-Keeper | DeepSeek prompt 中文正常，失败时 fallback 可用，输出字段稳定 |
| `init_room_map_state` 幂等修正 | existing 查询只取 `room_id` | 是 | Room、State | 重复初始化返回真实 `map_id`、explored、hidden、version，不覆盖已有探索 |
| `hiddenCount` 计算修正 | 当前计数逻辑不严格 | 是 | Projection | 玩家响应中的隐藏数量与实际不可见节点一致 |
| 地图状态版本屏障 | 只 bump `room_map_state.state_version` | 是 | Transaction、Projection | 地图事件带版本，重连补丁不会乱序覆盖 |
| 地图事件 schema 固化 | 事件已存在但 payload 分散 | 是 | Projection、Journal | `s2c_map_updated`、`s2c_player_moved`、`s2c_map_revealed` 结构文档化并有测试 |
| Host 操作审计 | 当前主要是直接写表加事件 | 是 | Journal、Safety | reveal、hide、force move 可在事件日志或审计表追踪 |
| 节点内线索归属 | 当前 map node 保存线索名数组 | 是 | Clue、WorldBook | 地图节点只保存引用和安全摘要，不保存玩家未发现的完整线索正文 |
| 前端地图空态和错误态 | 已有基础空态 | 是 | Player Client、Host Client | no map、401、无当前位置、移动提交中都有明确 UI 状态 |

## P2 平台增强

| 功能 | 价值 | 依赖 | 不放入当前 MVP 的原因 |
| --- | --- | --- | --- |
| 多楼层和区域图 | 支持大型模组 | Asset、Module | 先稳定单层节点图 |
| 距离带和追逐路径 | 支持战斗、追逐、潜行 | Rule、Encounter | 规则域复杂，需等移动链路稳定 |
| Host 手动画点连线 | 降低地图生成错误成本 | Module、Asset | 需要专门编辑体验 |
| 玩家地图标注 | 团队协作记忆 | Channel、Journal | 需要权限和同步策略 |
| 地图上的道具/NPC 状态标记 | 提升舞台感 | NPC、Clue、Asset | 必须先解决防剧透引用 |
| 场景媒体绑定 | 背景图、BGM、氛围素材 | Asset、Voice / Media | 媒体系统尚未进入核心链路 |

## 不属于本模块

| 不做内容 | 交给哪个模块 | 原因 |
| --- | --- | --- |
| 玩家 HP、SAN、物品数值结算 | State、Rule | Map 只表达位置和探索，不承担规则结算 |
| 线索发现与分享正文 | Clue | 地图只能提供入口和位置引用 |
| NPC 行为、敌意、阵营变化 | NPC / Faction | 节点可引用 NPC，但不裁决 NPC 状态 |
| AI 剧情裁决 | AI-Keeper、Transaction | AI 可以建议场景变化，不能直接改地图状态 |
| 日志回放 UI | Journal | Map 只发事件，回放由 Journal 编排 |
| 地图素材上传和版权管理 | Asset | 节点图和素材库生命周期不同 |

## 当前最高风险

| 风险 | 影响 | 建议优先级 |
| --- | --- | --- |
| `GET /api/map/{room_id}` 在匿名分支返回完整 `scenario_map.nodes` | 玩家可绕过迷雾看到隐藏地点、NPC 和线索 | P0 |
| 玩家地图 GET 会写 `character_map_positions` 和 explored | 刷新页面会改变真实状态，破坏事务链路 | P0 |
| 已探索节点直接返回 `npcsPresent`、`cluesAvailable` | 未发现线索和隐藏 NPC 可能被地图泄露 | P0 |
| 地图生成读 `scenario_assets.scenes`，而导入链路主要产出 `knowledge_graph.scenes` | PDF 导入后地图生成可能无场景数据 | P1 |
| Host 显隐和强制移动缺少完整校验与审计 | 房主误操作难回溯，目标节点或角色可能不合法 | P1 |
| 地图状态版本未并入核心投影版本屏障 | 断线重连和 WS 事件可能出现乱序 | P1 |
| 源码中地图和前端部分中文乱码 | 影响维护和 UI 文案可信度 | P1 |

## MVP 验收主链路

1. Admin 导入剧本后生成地图草稿，确认地图。
2. Host 创建房间并选择该剧本。
3. 玩家加入房间并绑定角色。
4. Host 开局，房间初始化 `room_map_state`。
5. 玩家打开地图，只看到当前位置、已探索节点和安全相邻节点。
6. 玩家提交移动到相邻节点，动作进入 Engine。
7. Engine 裁决成功后更新位置和 explored。
8. Host 收到移动事件并能在全图看到位置变化。
9. Player 收到地图刷新事件，重新拉取安全地图投影。
10. 日志中能查到移动、显隐、强制移动等关键事件。
