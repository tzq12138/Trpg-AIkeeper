# Scene / Map 地图与场景系统验收文档

## 文档定位

本文件用于在收到工程师的 `回执-YYYY-MM-DD.md`、代码改动说明、测试结果后，判断 `09-Scene/Map` 本轮工作是否真正完成。

它只负责验收，不替代 `功能列表.md`、`PRD.md`、`DeepSeek计划.md`。

默认分两层结论：

- `本轮工程验收通过`：表示 Scene/Map 本轮承诺的 P0 主链路、地图投影安全边界和关键版本/审计约束已完成。
- `生产安全完成`：表示除本轮范围外，地图长期高风险缺口也已关闭。

除非证据非常完整，否则默认只评 `本轮工程验收通过`，不直接给 `生产安全完成`。

## 验收输入

验收前至少应拿到以下材料：

- 本模块四份基线文档：`功能列表.md`、`PRD.md`、`DeepSeek计划.md`、`验收文档.md`
- 工程师回执：`回执-YYYY-MM-DD.md`
- 本轮改动文件列表，至少说明改了哪些 map、host、state、projection、admin、前端、测试文件
- 测试命令与结果
- 如涉及玩家地图页、Host 地图页，附 `npm run build` 结果和手动链路验证结果

## 结论等级

| 结论 | 含义 |
|---|---|
| `本轮工程验收通过` | 玩家地图鉴权、纯读、DTO 脱敏、移动经 Engine、Host 操作校验/审计、地图事件版本和主链路测试都已对上 |
| `本轮工程验收有缺口` | 主链路基本可用，但仍缺关键证据、关键测试或关键安全边界 |
| `不通过` | 出现匿名/越权拿图、GET 写库、玩家地图剧透、移动绕过 Engine、Host 非法操作无校验、测试未过或回执与实际不符 |
| `生产安全完成` | 只有在版本屏障、断线重连、force move 强校验、角色位置隐私策略、长期审计闭环等高风险项也关闭后才可给出 |

## 一票否决项

出现任一情况，本轮不能判通过：

- 无 token、无效 token 或跨房间 token 仍能拿到玩家地图节点
- `GET /api/map/{room_id}` 仍会写 `character_map_positions`、`explored_nodes` 或 bump 版本
- `PlayerMapView` 仍直接返回原始 `npcsPresent`、原始 `cluesAvailable`、隐藏描述、Host 注释
- 玩家移动仍可绕过 Engine/ResolutionPipeline 直接改位置
- reveal/hide 被实现成公开 NPC、线索正文或真相字段
- Host force move 不校验角色归属或节点归属
- 地图事件不带 `mapVersion`，或事件中仍携带完整节点详情
- 测试命令未提供，或关键测试明显未通过

## 必备回执材料

工程师回执里至少应明确：

- 本轮对应的 Batch 范围，例如 `Map-1 ~ Map-5`

如果回执把文档中明确属于后续项的缺口写成“已完成”，验收时应直接降级处理。

## 本轮工程验收清单

### 1. 玩家地图鉴权

- 无 token 请求玩家地图返回 `401`
- 无效 token 请求玩家地图返回 `403`
- 跨房间 token 请求玩家地图返回 `403`
- token 异常不会退化成匿名地图或安全空态
- Player 不能复用 Host full map 接口

### 2. 玩家地图 GET 纯读

- 连续两次 `GET /api/map/{room_id}` 不改数据库
- GET 不写 `character_map_positions`
- GET 不写 `room_map_state.explored_nodes`
- GET 不 bump `mapVersion/state_version`
- 无当前位置时返回 `no_current_position` 或明确空态
- 初始位置由开局、入房或显式恢复链路负责，而不是 GET 自愈

### 3. `PlayerMapView` 安全 DTO

- 玩家返回结构与 `MapNodePlayerDTO` 口径一致
- 不返回原始 `npcsPresent`
- 不返回原始 `cluesAvailable`
- 不返回隐藏描述、Host 注释、AI 草稿字段
- explored 节点仍过滤未发现线索和隐藏 NPC
- 相邻未探索节点只返回安全 label / `safeHint`
- 若保留 `hiddenCount`，它只表示不可见数量，不暴露隐藏节点 ID、名称、类型
- 更理想的实现是 Player 端不返回 `hiddenCount`

### 4. 地图生成与模板初始化

- 地图生成优先读取 `knowledge_graph.scenes`
- 如兼容旧字段，回执中说明兼容层做法
- 只有 `knowledge_graph.scenes` 的剧本也能生成 draft map
- confirmed map 可被房间开局稳定引用
- `init_room_map_state` 重复调用不清空探索状态

### 5. 玩家移动与位置写入权威

- 非相邻节点移动被拒绝
- hidden 节点移动被拒绝
- locked 节点移动被拒绝
- 玩家移动通过 Engine/ResolutionPipeline 进入裁决链
- Engine 裁决失败不改位置
- Engine 裁决成功才更新位置、explored、`mapVersion`
- `character_map_positions` 只允许两类权威写入：
  - Engine 成功裁决结果
  - Host 受审计的强制移动路径

### 6. 地图与当前场景边界

- 地图移动成功只代表空间位置变化
- `current_scene` 不由 Map 路由或 persistence 直接改写
- 场景切换由 `StateService` 或事务链路负责
- 回执如声称“地图已驱动场景同步”，需说明中间是通过哪个受控入口推进

### 7. Host 全图、显隐与强制移动

- `GET /api/host/{room_id}/map/full` 仅 `owner/admin` 可读
- reveal/hide 先校验节点属于本房间地图
- force move 先校验角色属于本房间、节点属于本地图
- reveal/hide 只改变地图可见性，不直接公开 NPC、线索正文、真相
- force move 必须记录 `reason`
- 若本轮宣称已完成硬化，最好还要有 `confirm=true` 的后端硬校验
- Host 操作失败时不发成功 WS 事件

### 8. 事件与版本屏障

- `s2c_map_updated` 带 `mapVersion`
- `s2c_player_moved` 带 `mapVersion`
- `s2c_map_revealed` 带 `mapVersion`
- 事件不携带完整节点详情
- 事件不携带 NPC 原文、线索正文、真相字段
- 前端收到事件后按安全接口重新拉取，不直接信任潜在敏感 payload
- 如回执宣称修了断线重连，需给出版本顺序或补丁覆盖测试证据

### 9. 审计字段

至少应证明以下字段已进入日志或等价审计链路：

- `operation`
- `roomId`
- `actorAccountId`
- `actorRole`
- `targetNodeId`
- `targetCharacterId`
- `fromNodeId`
- `toNodeId`
- `reason`
- `mapVersion`
- `createdAt`

如果只写了粗粒度事件名，没有对象、原因、版本和操作者字段，不算审计闭环。

### 10. 前端状态与类型对齐

- Player 地图能处理 `401`
- Player 地图能处理 `403`
- Player 地图能处理 `no_map`
- Player 地图能处理 `no_current_position`
- Player 地图能处理 `moving/loading`
- 前端类型不再依赖原始 `npcsPresent/cluesAvailable`
- Host 地图操作失败时页面不显示假成功

### 11. 端到端主链路

至少应手动或自动证明以下链路：

1. Admin 导入带 scenes 的剧本
2. Admin 生成并确认地图
3. Host 创建房间并选择剧本
4. Player 加入房间并绑定角色
5. Host 开局并初始化房间地图
6. Player 打开地图，只看到安全投影
7. Player 提交一次合法移动
8. Engine 裁决成功后，位置、explored、`mapVersion` 正确推进
9. Host 与 Player 都收到各自安全刷新
10. Host 执行一次 reveal/hide 或 force move，日志可查

## 生产安全加签条件

以下条件未关闭前，不应给 `生产安全完成`：

- `force move` 仍未形成 `reason + confirm=true` 后端硬校验
- `s2c_player_moved` 的最终 audience 策略仍未完全定型
- 断线重连、补丁重放与 `mapVersion` 的长期一致性仍未经充分验证
- `hiddenCount` 若仍暴露给 Player，其剧透风险尚未完全关闭
- 地图生成仍处于双源兼容期，`knowledge_graph.scenes` 与旧字段口径尚未彻底统一
- Host debug / full map / audit 查询路径仍未形成长期稳定的权限与审计规范
- Scene/Map 与 State/Projection/Journal 的长期回放闭环仍未完全完成
