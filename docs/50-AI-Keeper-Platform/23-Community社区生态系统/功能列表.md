# Community 社区生态系统功能列表 V2.0

## 模块定位

Community 负责 AI-Keeper 的平台生态层：公开模组、公开招募、用户主页、作品收藏、评论评分、举报审核、创作者身份和社区活动。它服务“发现内容、选择团、分享成果、治理公开内容”，不服务单局跑团内的裁决和状态写入。

当前仓库没有独立 Community 实现，没有 `/api/community` 路由，没有社区表，也没有评论、收藏、评分、举报、公开主页页面。真实可复用基础是账号系统、Admin 后台、剧本导入、素材管理、质量报告、SpoilerGuard、公开 replay/export、Schedule 招募设计和 Module 模组编辑方向。V2.0 的重点是把社区能力拆清楚，并把“公开发布安全”放在所有社区互动之前。

本模块需要和以下文档保持一致：

- `docs/50-AI-Keeper-Platform/02-User用户与权限系统/`
- `docs/50-AI-Keeper-Platform/19-Module模组编辑器/`
- `docs/50-AI-Keeper-Platform/21-Safety跑团安全边界系统/`
- `docs/50-AI-Keeper-Platform/22-Schedule日程与招募系统/`
- `docs/50-AI-Keeper-Platform/24-Plugin-Admin-Ops开放API与后台运维/`

## 核心对象

| 对象 | 含义 | 当前载体 | Community 口径 |
| --- | --- | --- | --- |
| `CommunityIdentity` | 用户公开身份 | `accounts.display_name`、`role` | 当前只有显示名和角色；未来增加公开简介、头像、隐私设置 |
| `PublicProfile` | 用户主页 | 未实现 | 展示公开作品、公开招募、公开战报，不展示私密房间记录 |
| `AuthorProfile` | 创作者主页 | 未实现 | 绑定发布模组、版本、授权、审核状态 |
| `PublishedModule` | 已发布模组 | 未实现，来源可为 `scenarios` 和 Module 草稿 | 必须是脱敏后的玩家可见版本，不是 raw PDF 或完整真相 |
| `ModuleVersion` | 模组发布版本 | 未实现 | 每次发布独立版本，保留审核记录和撤回能力 |
| `CommunityPost` | 社区帖子 | 未实现 | 未来用于公告、心得、战报分享，不承载房间私密数据 |
| `PublicRecruitPost` | 公开招募帖 | 未实现，依赖 Schedule | Schedule 负责排期数据，Community 负责公开发现和搜索 |
| `Comment` | 评论 | 未实现 | 绑定目标内容，支持作者或管理员隐藏 |
| `Rating` | 评分 | 未实现 | 只允许完成体验后的账号评分，防刷要限速和反作弊 |
| `Favorite` | 收藏 | 未实现 | 私人收藏默认不公开 |
| `Report` | 举报 | 未实现 | 进入 Admin/Ops 审核队列，不直接删除内容 |
| `ModerationCase` | 审核工单 | 未实现 | 管理员处理举报、下架、封禁、恢复和申诉 |
| `PublicBattleReport` | 公开战报 | 当前只有 export/replay 基础 | 必须经过 Safety 过滤，不直接把 public export 开成社区内容 |
| `CommunityAudit` | 社区治理审计 | 未实现 | 管理员操作、下架、恢复、封禁都要留痕 |

## P0 MVP 功能

P0 不做社区产品上线，只做“未来能安全上线社区”的基础边界。核心跑团链路不依赖 Community。

| 功能 | 当前状态 | 进入 MVP | 依赖模块 | 用户价值 | 验收口径 |
| --- | --- | --- | --- | --- | --- |
| 账号身份基础 | 已有 | 是 | User | 社区内容未来能绑定作者 | 注册、登录、`/api/auth/me` 可用，账号不泄露 password hash |
| 平台角色基础 | 已有 admin/host/player | 是 | User、Admin/Ops | 区分普通用户、房主、管理员 | player 不能访问 admin；admin 可调整角色 |
| Admin 后台基础 | 已有 | 是 | Admin/Ops | 后续审核和治理有入口基础 | AdminDashboard 可进入概览、房间、账号、剧本、角色 |
| 剧本导入基础 | 已有 | 是 | Module、Safety | 未来模组发布有来源 | Admin 可导入 PDF 并结构化；Host/Admin 可列出可用剧本 |
| 剧本质量报告 | 已有 | 是 | Module | 发布前可做结构完整性检查 | quality report 可返回结构风险，不等同公开审核 |
| Spoiler 索引基础 | 已有 | 是 | Safety、AI-Keeper | 发布前识别真相和隐藏要素 | 导入后可构建 sensitive index |
| 素材管理基础 | 已有 admin-only | 是 | Asset、Admin/Ops | 未来发布模组需管理授权素材 | admin 可上传和删除 scenario assets；公开发布前需增加素材授权字段 |
| 公开 replay 基础 | 已有 | 是 | Journal、Safety | 未来公开战报有底层数据 | Host 可取 `party/system` replay，但不能直接当社区公开版本 |
| public export 基础 | 部分已有 | 是 | Journal、Safety | 未来可分享战报 | token 有遮罩；需修正 public 过滤后才能社区化 |
| 社区路由缺失确认 | 已确认 | 是 | Community | 防止误判已有社区功能 | `src` 下没有 `/api/community`、community 页面和社区表 |
| 发布安全白名单 | 未实现 | 是 | Safety、Module | 防止模组真相泄露 | 文档和后续测试必须列出可发布字段与禁止字段 |
| 审核状态模型 | 未实现 | 是 | Admin/Ops | 公开内容必须可下架 | 发布对象至少有 draft、reviewing、published、hidden、rejected、archived |

## P1 应补功能

P1 是“受控公开内容”，先做模组发布和私域可分享，不做完整社交网络。

| 功能 | 当前状态 | 进入 MVP | 依赖模块 | 用户价值 | 验收口径 |
| --- | --- | --- | --- | --- | --- |
| 公开用户主页 | 未实现 | 否 | User、Safety | 展示公开昵称、作品、招募 | 未登录可看公开资料，不能看房间私密记录 |
| 公开资料隐私设置 | 未实现 | 否 | User | 用户控制哪些资料公开 | 角色、房间、战报默认私密，用户显式发布才公开 |
| 模组发布草稿 | 未实现 | 否 | Module | 作者整理可发布版本 | 发布草稿与 `scenarios.raw_text` 分离 |
| 模组公开页 | 未实现 | 否 | Module、Safety | Host 能发现可用模组 | 只展示公开简介、标签、人数、时长、系统、内容警示 |
| 发布审核队列 | 未实现 | 否 | Admin/Ops | 管理员先审再公开 | 未审核内容不进公开列表 |
| 模组版本管理 | 未实现 | 否 | Module | 作者可修订发布内容 | 每个版本有状态、变更说明、审核记录 |
| 收藏 | 未实现 | 否 | User | 用户保存感兴趣内容 | 收藏默认私人可见，可取消 |
| 评论 | 未实现 | 否 | User、Safety | 用户反馈体验 | 评论可删除自己内容，可被作者隐藏或管理员处理 |
| 评分 | 未实现 | 否 | User、Journal | 给公开模组提供参考 | 限制重复评分，评分与评论分离 |
| 举报 | 未实现 | 否 | Admin/Ops、Safety | 违规内容可进入治理流程 | 举报产生审核工单，不直接公开举报人 |
| 下架和恢复 | 未实现 | 否 | Admin/Ops | 管理员治理公开内容 | 下架后公开页不可见，作者和管理员可见原因 |
| 私域战报分享 | 未实现 | 否 | Journal、Safety | 房间成员分享经过脱敏的战报 | owner 或成员显式创建分享链接，公开内容走白名单 |
| 公开招募入口 | 未实现 | 否 | Schedule | 玩家发现开放团 | 只展示 Schedule 公开字段，报名仍走 Schedule |

## 公开内容安全白名单

| 内容类型 | 可公开字段 | 禁止字段 |
| --- | --- | --- |
| 用户主页 | display name、公开简介、公开作品列表、公开招募列表 | username 以外的登录凭证、token、私密角色、私密房间、邮箱手机号等未实现敏感资料 |
| 模组公开页 | 标题、公开简介、规则系统、推荐人数、预计时长、标签、内容警示、授权素材封面、版本号 | raw_text、knowledge_graph truth、结局、隐藏 NPC、隐藏线索、原始 PDF 路径、RAG chunk、AI prompt |
| 招募广场 | 房间公开标题、招募说明、人数、时区、计划时间、报名方式、内容警示 | owner token、player token、未审核申请、玩家私信、剧本真相 |
| 评论评分 | 评论正文、评分、作者公开名、创建时间、状态 | 私密举报理由、管理员内部备注、玩家房间 token |
| 战报分享 | 经过 Safety 白名单过滤的公开叙事、公开事件、玩家显式同意公开的角色展示 | host-only 事件、player-only 事件、私密线索、未公开结局、token、本地路径 |
| 举报审核 | 被举报对象、原因分类、状态、处理结果摘要 | 举报人真实身份公开、内部风控备注、敏感日志 |

## 功能边界

- Community 不影响创建房间、玩家加入、ready、开局、AI 裁决、事务和状态变更。
- Community 不直接读取或发布 `scenarios.raw_text`、原始 PDF、truth、hidden clue、hidden NPC。
- Community 不把 public export 原样当公开战报；必须先走 Safety 白名单。
- Community 不替代 Schedule；招募排期和报名审批仍归 Schedule，Community 只负责公开发现入口。
- Community 不替代 Module；模组编辑、结构化和版本草稿归 Module，Community 只负责发布、发现、互动和治理。
- Community 不替代 Admin/Ops；审核队列、封禁、下架、申诉和审计需要后台支撑。
- Community 不让 AI 自动决定公开、下架、封禁或通过举报。

## 现状风险

| 风险 | 影响 | V2.0 处理口径 |
| --- | --- | --- |
| 没有社区数据模型 | DeepSeek 可能直接加页面但无权限和审核 | 先设计对象、状态和权限，再进入实现 |
| public export 过滤偏粗 | 社区战报可能泄露 host/system 敏感事件 | 公开分享前必须由 Safety 建统一 visibility helper |
| 模组源数据含真相 | 发布模组可能泄露完整剧本和结局 | PublishedModule 必须是脱敏公开版本，不引用 raw_text |
| Admin 后台不是审核后台 | 无举报、下架、恢复、申诉流程 | P1 先做审核队列和状态机 |
| 用户主页隐私未定义 | 私密角色和房间历史可能被公开 | 默认私密，用户显式发布才公开 |
| 招募和社区混用 | 公开招募可能绕过 Schedule 审批 | Community 只做发现页，报名仍走 Schedule |
| 评论和评分引入治理成本 | 垃圾内容、骚扰、刷分 | 评论评分必须有删除、隐藏、举报、限速 |
| 素材授权缺失 | 公开素材可能侵犯版权 | Asset/Module 需要授权字段和发布检查 |
| AI 审核过度自动化 | 误封、误审、不可解释 | AI 只能辅助标记，人类管理员最终处理 |

## MVP 验收主链路

1. 确认当前没有 `/api/community` 路由、社区表和社区页面。
2. 用户账号、角色、Admin 后台和剧本导入保持可用。
3. 公开发布白名单文档化，禁止字段明确。
4. public replay/export 的当前风险被记录到 Safety 或 DeepSeek 执行计划中。
5. 模组发布、招募广场、评论、收藏、评分、举报都被标记为后续能力，不进入 AI 核心链路。
6. 任何未来公开内容都必须有审核状态、可见范围、作者归属和管理员处理记录。
