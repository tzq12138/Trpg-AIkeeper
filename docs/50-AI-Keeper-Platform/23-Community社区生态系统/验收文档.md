# Community 社区生态系统验收文档

## 文档定位

本文档用于在收到工程师的 `回执-YYYY-MM-DD.md`、代码改动说明、测试结果之后，判断 `23-Community社区生态系统` 本轮工作是否真正完成。

它只负责验收，不替代：

- `功能列表.md`
- `PRD.md`
- `DeepSeek计划.md`

默认分两层结论：

- `本轮工程验收通过`：表示 Community 本轮允许进入的前置批次已经闭环；
- `生产可运营完成`：表示公开主页、模组发布、评论评分、举报后台、公开招募、公开战报及其依赖都已完整收口。

除非证据非常完整，否则默认只给 `本轮工程验收通过`，不直接给 `生产可运营完成`。

## 本轮验收范围

本轮默认验收范围只覆盖：

- `Community-0`
- `Community-1`
- `Community-2`
- `Community-3`

也就是：

- 现状复核；
- 公开发布安全与 DTO 前置；
- 审核 / 举报 / 状态机模型设计；
- 社区数据模型草案。

本轮**不默认验收**：

- `Community-4` 公开用户主页实现；
- `Community-5` 模组发布实现；
- `Community-6` 评论 / 收藏 / 评分实现；
- `Community-7` 举报与审核后台；
- `Community-8` 公开招募与公开战报；
- `Community-9` 全量 Community 工程回归。

若工程回执涉及 `Community-4+`，必须先确认用户是否已再次批准进入该阶段。

## 验收输入

验收前至少应拿到以下材料：

- 本模块四份基线文档：`功能列表.md`、`PRD.md`、`DeepSeek计划.md`、`验收文档.md`
- 工程师回执：`回执-YYYY-MM-DD.md`
- 本轮改动文件清单
- 实际测试命令与结果
- 如涉及前端路由或页面，附 `npm run build` 结果

## 结论等级

| 结论 | 含义 |
| --- | --- |
| `本轮工程验收通过` | Community-0 ~ Community-3 与文档口径对齐，且没有偷跑到未批准的 Community-4+ |
| `本轮工程验收有缺口` | 主体方向对，但缺关键测试、关键证据或关键边界说明 |
| `不通过` | 出现公开越权、源数据泄露、未授权素材公开、审核审计缺失、偷跑 Community-4+ 等硬问题 |
| `生产可运营完成` | 仅在公开主页、模组发布、评论评分、举报后台、公开招募、公开战报和依赖模块均收口后才能给出 |

## 一票否决项

出现任一情况，本轮不得判通过：

- 未经用户再次确认，直接实现 `Community-4+`
- 新增 `/api/community`、社区表、社区页面，却没有明确批准进入对应批次
- 把 `/api/admin/scenarios` 直接当公开模组市场
- 把 `/api/rooms/{room_id}/export` 或 raw replay 直接当公开战报
- `PublishedModule` 仍直接返回源 `scenario` 或其 raw 字段
- 公开模组仍包含 `raw_text`、truth、ending、hidden clue、hidden NPC、原始 PDF 路径、本地路径、RAG chunk、AI prompt
- `PublicBattleReport` 仍使用 raw events / raw replay / raw archive
- `PublicBattleReport` 没有显式发布口径，或没有成员同意 / 匿名化策略
- `PublicProfile` 仍默认暴露私密房间、角色详情、收藏、举报或审核记录
- 在 Community 内复制或改写一套 Safety visibility 规则
- 举报人身份对被举报作者可见
- 审核内部备注进入公开页
- 未授权素材进入公开 payload
- 工程回执没有说明本轮只覆盖 `Community-0 ~ Community-3`
- 关键测试命令未提供，或测试未通过
