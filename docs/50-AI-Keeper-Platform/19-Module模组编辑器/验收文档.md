# Module 模组编辑器验收文档

## 文档定位

本文档用于在收到工程师的 `回执-YYYY-MM-DD.md`、代码改动说明、测试结果之后，判断 `19-Module模组编辑器` 本轮工作是否真正完成。

它只负责验收，不替代：

- `功能列表.md`
- `PRD.md`
- `DeepSeek计划.md`

默认分两层结论：

- `本轮工程验收通过`：表示 Module 本轮 P0/P1 主链路已经闭环；
- `生产安全完成`：表示除了本轮范围外，版本快照、导出边界、长期 mutable scenario 风险也已基本收口。

除非证据非常完整，否则默认只给 `本轮工程验收通过`，不直接给 `生产安全完成`。

## 验收输入

验收前至少应拿到以下材料：

- 本模块四份基线文档：`功能列表.md`、`PRD.md`、`DeepSeek计划.md`、`验收文档.md`
- 工程师回执：`回执-YYYY-MM-DD.md`
- 本轮改动文件清单
- 实际测试命令与测试结果
- 如涉及 Admin 页面或 Host 开房页，附 `npm run build` 结果

## 结论等级

| 结论 | 含义 |
| --- | --- |
| `本轮工程验收通过` | 导入、状态口径、发布准入、模板接口、地图确认、Room 实例化与文档一致 |
| `本轮工程验收有缺口` | 主链路大体可用，但缺关键测试、关键证据或关键边界未闭环 |
| `不通过` | 出现越权读取、truth 泄露、高风险开房绕过、模板/地图/运行态反写模板等硬问题 |
| `生产安全完成` | 仅在版本快照、导出边界、长期 mutable scenario 风险也收口后才能给出 |

## 一票否决项

出现任一情况，本轮不得判通过：

- `importStatus` 与 `publishStatus` 仍混用，`structured` 仍被当作“已可开房”
- `/api/scenarios/available` 仍把 blocked 模组下发给普通 Host
- 普通 `create-room` 仍可绕过 blocked / highRisk 规则直接开房
- `GET /api/scenarios/{scenario_id}/templates` 仍不存在，或返回 truth、hiddenClueIds、adminNotes、secretBackstory、私密 `xlsx_data`
- Host / Player 仍直接收到 `scenarios` 原始记录，而不是瘦 DTO
- `AdminModuleDetailDTO` 被实现成数据库 raw dump，默认返回 `raw_text` 全文、本地路径、token 或无关 debug secret
- 地图生成仍只依赖旧 `scenario_assets.scenes`，导致 `knowledge_graph.scenes` 有内容但无法生成地图
- 坏触发器仍可在运行时直接抛异常拖垮回合结算
- 结构编辑接口仍接受整包任意 JSON 覆盖整个 scenario
- Room 运行态仍会反写 `scenarios`、`scenario_maps` 或 `character_templates`
- 导出仍把 debug/raw export 当作可分享模组包
- 关键测试命令未提供，或测试未通过

## 必备回执材料

工程师回执里至少应说明：

- 本轮覆盖了哪些 `Module Batch`
- 实际修改了哪些文件
- 实际运行了哪些测试，结果是什么
- `publishStatus` 是新增字段、兼容计算字段，还是别的过渡方案
- `qualityLevel.ready` 与 `publishStatus.ready` 在代码里如何区分
- `/api/scenarios/{scenario_id}/templates` 最终落在哪个路由层
- `highRisk` 的发布 override 与 `create-room confirm_quality_risk` 两条路径如何对齐
- `AdminModuleDetailDTO` 默认是否返回 `raw_text` 全文；如果不返回，额外明细怎么取
- map generator 现在对 `knowledge_graph.scenes` 和旧 `scenario_assets.scenes` 的优先级是什么
- 如果本轮仍未实现 `module_versions`，遗留风险具体是什么
- `admin_debug_export`、`module_manifest_export`、`public_share_package` 如何区分
- 本轮 remaining limitations 是什么

## 本轮工程验收清单

### 1. 导入、状态与基础模型

1. PDF 导入是否仍为 admin-only。
2. Player 导入 PDF 是否 403。
3. 重复 PDF 是否按 hash 返回既有 scenario。
4. 导入后是否生成 `knowledge_graph`。
5. 导入后是否生成 `quality_report`。
6. `importStatus` 是否只表示导入/结构化状态。
7. `publishStatus` 是否独立存在，或有明确兼容计算字段。
8. `structured` 是否不会被当成 `published`。
9. `qualityLevel.ready` 与 `publishStatus.ready` 是否在代码和回执中明确区分。
10. 旧 scenario 缺少 `publishStatus` 时是否有兼容策略。

### 2. Admin / Host / Player 三套视图

11. Admin 列表是否返回 `ModuleListItemDTO`。
12. Admin 列表是否不默认返回 `raw_text`。
13. Admin 列表是否不默认返回完整 truth。
14. `AdminModuleDetailDTO` 是否聚合 KG 摘要。
15. `AdminModuleDetailDTO` 是否聚合质量报告。
16. `AdminModuleDetailDTO` 是否聚合地图状态。
17. `AdminModuleDetailDTO` 是否聚合素材数量。
18. `AdminModuleDetailDTO` 是否聚合模板数量。
19. `AdminModuleDetailDTO` 是否不返回本地路径。
20. `AdminModuleDetailDTO` 是否不返回 `owner_token/player_token`。
21. `AdminModuleDetailDTO` 是否不是数据库 raw dump。
22. Host available 是否返回 `ModuleHostOptionDTO`。
23. Host available 是否只返回可开房模组。
24. Player 预览是否使用 `PlayerModulePreviewDTO` 或等价瘦视图。
25. Player 预览是否不返回完整 KG。
26. Player 预览是否不返回 truth / hidden endings / hidden clues。

### 3. 发布准入与高风险链路

27. blocked 模组是否不进 Host available。
28. blocked 模组是否不能普通 `create-room`。

35. 发布、撤回、强制发布是否记录 reason。
36. KG / 地图 / 素材 / 模板变更后是否重算 `quality_report` 或标记 stale。

### 4. templates 接口与角色模板

37. `GET /api/scenarios/{scenario_id}/templates` 是否存在。
38. templates 接口是否要求登录。
39. templates 接口是否返回 `templateId`。
40. templates 接口是否返回 `displayName`。
41. templates 接口是否返回 `occupation`。
42. templates 接口是否返回 `publicSummary`。
43. templates 接口是否返回 `suggestedSkills`。
44. templates 接口是否返回 `avatarAssetUrl` 或等价字段。
45. templates 接口是否返回 `selectable`。
46. templates 接口是否不返回 truth。
47. templates 接口是否不返回 `hiddenClueIds`。
48. templates 接口是否不返回 `adminNotes`。
49. templates 接口是否不返回 `secretBackstory`。

### 5. 地图、素材绑定与开房实例化

56. 旧 `scenario_assets.scenes` 是否仍有兼容策略。

63. AssetBinding 是否不保存本地路径。

### 6. 触发器 schema 与结构编辑 patch

### 7. 模板态与运行态隔离

78. Room start 是否不反写 `scenarios`。
79. Room 运行态地图变化是否不反写 `scenario_maps`。
80. Room 运行态角色变化是否不反写 `character_templates`。

82. active room 是否不受后续模板编辑污染，或已在回执里列为明确遗留风险。

### 8. 版本边界与导出

## 生产安全加签条件

以下条件未关闭前，不应给 `生产安全完成`：

- `module_versions` 仍未建立，active room 仍绑定 mutable scenario
- `highRisk` 发布与 create-room 两条链路仍未完全对齐
- templates、Admin 详情、Host available 仍缺专项 DTO / 权限自动化测试
- 触发器 schema 与运行时降级仍缺专项自动化测试
- 导出 scope 仍可能混淆 `debug/raw/manifest/public share`
