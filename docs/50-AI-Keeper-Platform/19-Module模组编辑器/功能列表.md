# Module 模组编辑器功能列表 V2.0

## 模块定位

Module 模组编辑器负责把“可运行的跑团素材包”组织成可复用、可校验、可发布、可开房的模板。它承接 WorldBook 抽取出来的场景、NPC、线索、真相、结局和触发器，关联 Asset 的文件资源、Scene/Map 的地图草稿、Character 的预设调查员、Rule 的机制触发，再向 Room 提供可实例化的 scenario。

当前代码还没有完整可视化编辑器，已有能力更接近“导入型模组雏形”：Admin 导入 PDF，AI 结构化为 `knowledge_graph`，生成质量报告，上传素材，生成并确认地图，Host/Admin 选择结构化 scenario 开房。V2.0 文档的目标是把这条雏形链路固化，并给 DeepSeek 后续补编辑器时提供边界。

## 当前代码真实锚点

| 位置 | 当前职责 | 现状判断 |
| --- | --- | --- |
| `src/server/scenario/router_scenarios.py` | scenario 可用列表、PDF 导入、导入状态、质量报告、从 scenario 创建房间 | 是 Module 的主入口之一；`/api/scenarios/available` 只返回 `structured` 剧本 |
| `src/server/router_admin.py` | Admin scenario 列表、素材上传、分类、地图生成/读取/编辑/确认 | 后台管理能力集中在这里，但不是独立 Module service |
| `src/server/ai/ai_kp.py` | `structure_scenario` 与 KG 标准化 | 结构化字段包含 `title/scenes/npcs/clues/truth/endings/trigger_mechanics`，但 schema 仍偏宽松 |
| `src/server/scenario/quality.py` | 质量报告 | 已有 `ready/warning/highRisk/blocked`，能检查场景、NPC、线索、真相、结局和配图缺失 |
| `src/server/db_adapter.py` | schema | `scenarios`、`character_templates`、`scenario_assets`、`scenario_maps` 是当前模组底座 |
| `src/server/ai/map_generator.py` | 从 `scenario_assets.scenes[]` 生成地图草稿 | 使用结构化场景生成 nodes/edges，有 AI 和 Python fallback |
| `src/server/map_persistence.py` | scenario map 草稿、确认、房间地图状态 | 已能确认地图并在开房时初始化 room map |
| `src/server/router_rooms.py` | 创建房间、切换 scenario、开局 | Room start 会使用 confirmed map 初始化运行态，并创建首回合和 checkpoint |
| `src/server/player/router_player.py` | 玩家入房、角色模板读取、角色卡绑定 | 入房信息会读取 `character_templates`，但模板编辑接口不完整 |
| `src/client/src/pages/AdminDashboard.tsx` | Admin 剧本与素材面板 | 支持 PDF 导入、scenario 列表、素材上传/删除；中文文案存在历史乱码 |
| `src/client/src/pages/HostCreate.tsx` | Host 选择可用 scenario 开房 | 依赖 `/api/scenarios/available`，只面向 host/admin |
| `src/client/src/pages/PlayerJoinPage.tsx` 和 `CharacterBuilderPage.tsx` | 尝试读取 scenario templates | 前端请求 `/api/scenarios/{scenarioId}/templates`，当前扫描未见同名后端路由 |
| `src/server/rules/triggers.py` | 简单触发器匹配 | 支持 `$action` 和 `itemId` 条件，Module 后续要给触发器编辑器提供 schema |
| `src/server/engine/rule_executor.py` | 读取 `scenario_assets.scenes[].triggers` 和全局 triggers | Module 的触发器会进入实际裁决链路，必须做发布前校验 |
| `tests/server/test_quality.py` | 质量报告测试 | 已覆盖 ready、warning、highRisk、blocked |
| `tests/server/test_room_security.py`、`test_rooms.py` | scenario 可见性、导入权限、开房权限 | Module 权限和 Room 实例化已有基础测试 |

## 核心对象

| 对象 | 含义 | 当前载体 | 归属边界 |
| --- | --- | --- | --- |
| `Module` | 可复用跑团模组整体 | 当前以 `scenarios` 记录承载 | Module 负责生命周期、发布状态和聚合视图 |
| `ModuleDraft` | 导入或编辑中的草稿 | `import_status`、`knowledge_graph`、`quality_report` | Module 负责草稿是否可发布 |
| `KnowledgeGraph` | 场景、NPC、线索、真相、结局 | `scenarios.knowledge_graph` | WorldBook 负责抽取，Module 负责编辑和校验 |
| `ScenarioAssetsSemantic` | 结构化触发器、物品、场景机制 | `scenarios.scenario_assets` JSONB | Rule/State 消费，Module 负责 schema 和发布前检查 |
| `AssetFile` | 图片、PDF、音频、手out 文件 | `scenario_assets` 表和数据目录 | Asset 负责文件安全，Module 负责绑定到模组节点 |
| `ScenarioMapDraft` | 模组地图草稿 | `scenario_maps` | Scene/Map 负责地图逻辑，Module 负责确认后可开房 |
| `CharacterTemplate` | 模组内预设调查员 | `character_templates` | Character 负责角色字段，Module 负责与 scenario 绑定 |
| `QualityReport` | 发布前质量结果 | `scenarios.quality_report` | Module 使用它判断 ready、warning、blocked |
| `RoomInstance` | 模组开房后的运行态 | `rooms`、`room_map_state`、events、runtime state | Room/State 负责，不反写 Module 模板 |

## P0 MVP 功能

| 功能 | 当前状态 | 进入 MVP | 依赖模块 | 用户价值 | 验收口径 |
| --- | --- | --- | --- | --- | --- |
| PDF 导入为模组草稿 | 已有 `POST /api/scenarios/import-pdf` 和 Admin 代理 | 是 | Asset、WorldBook、AI-Keeper | Admin 能从 PDF 快速生成可整理的模组 | admin 成功导入，player 导入返回 403，重复 PDF 返回既有 scenario |
| 结构化 KG 保存 | 已有 `knowledge_graph` | 是 | WorldBook | 模组可被 AI、地图、质量报告和开房链路消费 | 保存 `scenes/npcs/clues/truth/endings`，格式可解析 |
| 导入状态 | 已有 `pending/structured/requires_ocr` 等状态 | 是 | Asset | 管理员知道模组是否可继续处理 | 扫描件返回 `requires_ocr`，结构化成功为 `structured` |
| 模组质量报告 | 已有 `quality_report` 和查询接口 | 是 | Safety、WorldBook | 发布前发现关键缺失 | 空 KG 为 blocked，无场景为 blocked，缺结局为 warning |
| 模组分类 | 已有 Admin classify | 是 | Admin/Ops | Admin 能快速识别调查、恐怖、史诗等类型 | 返回 synopsis preview、实体计数、类型和状态 |
| 可用模组列表 | 已有 `/api/scenarios/available` | 是 | User、Room | Host 可选择已结构化模组开房 | host/admin 可查，player/未登录被拒绝 |
| Admin 模组列表 | 已有 `/api/admin/scenarios` | 是 | Admin/Ops | Admin 盘点导入结果 | 返回 scenario 记录并按创建时间排序 |
| 模组素材绑定入口 | 已有素材上传/列表/删除 | 是 | Asset | 给场景图、手out、音频后续引用打底 | 素材归属 scenario，非 admin 不能管理 |
| 地图草稿生成 | 已有 `/api/admin/scenarios/{id}/map/generate` | 是 | Scene/Map、AI-Keeper | 从结构化场景自动生成可编辑地图 | `scenario_assets.scenes[]` 有内容时生成 nodes/edges |
| 地图草稿编辑 | 已有 PATCH map | 是 | Scene/Map | Admin 能修正 AI/规则生成的地图 | draft 状态可编辑，confirmed 后拒绝编辑 |
| 地图确认 | 已有 confirm | 是 | Scene/Map、Room | confirmed 地图可在开房时初始化 | start room 后初始化 `room_map_state` |
| 用模组创建房间 | 已有 `/api/rooms` 和 `/api/scenarios/{id}/create-room` | 是 | Room、User | Host 可以从 ready 模组开始跑团 | host/admin 可创建，player/未登录被拒绝 |
| 模板与运行态隔离 | 已部分实现 | 是 | Room、State、Journal | 跑团过程不污染原始模组 | Room start 写 room/state/events，不反写 `scenarios` 模板 |
| 角色模板读取 | 表和入房读取已存在 | 是 | Character、Player Client | 模组可提供预设调查员 | 玩家入房信息能看到 scenario 模板列表 |
| 角色模板接口一致性 | 前端期待路由，后端扫描未见 | 是 | Character、Player Client | 修复玩家选预设的断点 | `GET /api/scenarios/{scenario_id}/templates` 返回模板，鉴权和字段一致 |
| 触发器 schema 口径 | 运行时可消费，编辑校验不足 | 是 | Rule、Transaction | 模组触发器进入裁决前可验证 | 发布前校验 `$action/itemId/mechanics` 基本结构 |
| 防剧透边界 | SpoilerGuard 已能读 KG 和 semantic assets | 是 | Safety、Projection | Player 不能看到完整真相 | available/create-room 不返回 truth，玩家接口不暴露 KG 全量 |
| 发布准入 | 当前质量报告不阻断开房 | 是 | Safety、Room | 避免 blocked 模组进入正式房间 | blocked 模组不能出现在 host 可用列表或创建房间需显式 admin override |
| 中文文案可读 | 当前多处历史乱码 | 是 | Frontend、Admin/Ops | Admin 和 Host 能使用导入和开房流程 | AdminDashboard、HostCreate、错误提示可读且 build 通过 |

| 功能 | 当前状态 | 进入 MVP | 依赖 | 验收口径 |

| 模组详情接口 | 缺少聚合 DTO | 是 | Admin、WorldBook、Asset、Map | 单接口返回 KG 摘要、质量、地图、素材、模板和发布状态 |

## P3 长期能力

- 多作者协作编辑、评论和审阅。
- 社区发布、评分、收藏和订阅。
- 付费模组、授权协议和分成。
- 模组分支、合并、差异比较和回滚。

## 不属于 Module 的内容

| 内容 | 归属模块 | 原因 |
| --- | --- | --- |
| PDF 文件安全和存储 | Asset | Module 只引用文件，不治理文件系统 |
| 文本抽取和 KG 自动生成 | WorldBook、AI-Keeper | Module 使用结构化结果，抽取质量由上游负责 |
| 地图探索、迷雾和玩家移动 | Scene/Map、State | Module 只保存地图模板 |
| 运行时 HP/SAN/背包/线索状态 | State、Character、Clue | 房间运行态不能反写模组模板 |
| 规则结算和骰子裁决 | Rule、Transaction | Module 只定义触发器和默认机制 |
| 玩家私密投影 | Projection、Player Client | Module 不直接推送事件 |
| 社区分发和运营审核 | Community、Admin/Ops | 长期平台能力，非核心导入编辑链路 |

## 现状风险清单

| 风险 | 代码锚点 | 优先级 | 处理方向 |
| --- | --- | --- | --- |
| 没有独立 Module 聚合层 | `scenarios` 分散被多模块读取 | P0 | 先定义 Module DTO 和生命周期，不急于拆服务 |
| `import_status` 承担过多含义 | `scenarios.import_status` | P0 | 区分导入状态和发布状态 |
| 质量报告不阻断开房 | `quality.py`、`available`、`create_room` | P0 | blocked/highRisk 的开房策略要明确 |
| 前端请求 templates 路由但后端缺口 | `PlayerJoinPage.tsx`、`CharacterBuilderPage.tsx`、`router_scenarios.py` | P0 | 补 `GET /api/scenarios/{scenario_id}/templates` 或调整前端来源 |
| `character_templates` 只有读取消费，没有 Admin CRUD | `db_adapter.py`、`router_player.py` | P1 | 增加 Admin 模板管理接口 |
| `knowledge_graph` 和 `scenario_assets` 语义重叠 | `scenarios` 表、RuleExecutor、MapGenerator | P0 | 明确 KG、semantic assets、file assets 三层关系 |
| 地图生成依赖 `scenario_assets.scenes[]`，PDF 导入写的是 `knowledge_graph.scenes` | `router_admin.py`、`router_scenarios.py` | P0 | 建立 scene 同步或 map generator 读取统一结构 |
| 后台文案乱码影响可用性 | `AdminDashboard.tsx`、`HostCreate.tsx`、部分后端错误 | P0 | 先修用户可见文案和构建错误 |
| 触发器缺 schema 验证 | `rules/triggers.py`、`rule_executor.py` | P1 | 发布前校验 condition/mechanics |
| Admin scenario 列表可能暴露过多原文/真相 | `/api/admin/scenarios` | P1 | Admin 可见合理，Host/Player 使用单独 DTO |
| 开房绑定 scenario 而非 version | `rooms.scenario_id` | P1 | 后续发布版本后，房间应绑定 module version snapshot |

## MVP 验收主链路

1. Admin 登录并导入 PDF。
2. 系统生成 scenario、raw text、knowledge graph、source hash 和 quality report。
3. Admin 查看模组详情，能看到结构化摘要、质量等级、素材、地图、角色模板状态。
4. Admin 修正或确认质量报告，blocked 模组不能进入普通 Host 可用列表。
5. Admin 生成地图草稿，编辑后确认。
6. Admin 上传场景图或手out，并绑定到场景、线索或地图节点。
7. Admin 配置或查看预设调查员模板。
8. Host 只能看到 published 或 ready 的模组，并创建房间。
9. Room start 使用 confirmed map 初始化运行态，创建首回合和 checkpoint。
10. 玩家加入后只能看到公开简介、预设调查员和运行态投影，不能读取 truth、完整 KG 或 Host-only 素材。
