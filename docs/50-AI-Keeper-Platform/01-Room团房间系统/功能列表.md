# Room 团房间系统功能列表

## 模块定位

Room 是所有跑团数据的组织边界。房间负责把玩家、角色、剧本、Session、频道、权限和状态快照绑定在一起。

## 功能清单

| 功能 | 优先级 | MVP | 用户价值 | 依赖 | 验收口径 |
|---|---:|---|---|---|---|
| 创建跑团房间 | P0 | 是 | 房主能开始组织一场团。 | User、Module | 房主创建房间后获得 owner token 和 room id。 |
| 邀请码 / 链接加入 | P0 | 是 | 玩家低成本入房。 | User | 玩家使用邀请码加入指定房间。 |
| 房间状态 | P0 | 是 | 区分招募中、准备中、进行中、暂停、完结。 | Journal | 状态变化写入事件日志。 |
| 玩家席位管理 | P0 | 是 | 控制人数和角色占位。 | Character | 超过席位时拒绝加入或进入候补。 |
| 当前 Session 管理 | P0 | 是 | 长团按次开局和收尾。 | Timeline、Journal | 每次开团有 session id 和开始/结束记录。 |
| 房主有限急救 | P0 | 是 | 出错时可暂停、重试、恢复。 | Transaction、State | 房主不能绕过 Engine 修改真相。 |
| Ready 同步 | P0 | 是 | Host 知道谁准备好了。 | Player Client、Host Client | ready 状态实时同步。 |
| 房间公告 | P1 | 否 | 发布规则、时间、注意事项。 | Channel | 公告可固定并进入房间信息。 |
| 房间密码 / 白名单 | P1 | 否 | 私密团防误入。 | User | 未授权用户无法加入。 |
| 旁观者模式 | P1 | 否 | 支持观众看公共演出。 | Projection、Host Client | 旁观者只能看公共投影。 |
| Session 归档 | P1 | 否 | 保存每次开团记录。 | Journal | Session 结束后生成摘要和索引。 |
| 房间模板 | P1 | 否 | 快速创建 COC、DND、恐怖团等。 | Module | 选择模板后生成默认配置。 |
| 房间复制 / 备份 | P1 | 否 | 复用模组和配置。 | State、Asset | 复制后新房间不共享玩家私密数据。 |
| 候补玩家 | P2 | 否 | 长团招募管理。 | Schedule | 候补不占正式席位。 |
| 房间导入导出 | P2 | 否 | 迁移、分享、备份。 | Plugin/Admin/Ops | 导出不包含未授权私密信息。 |

## 关键边界

- 房间是权限边界，不同房间的数据默认互不可见。
- 房主不等于全知 KP，AI-Keeper 项目中房主不能默认看到模组真相。
- 房间状态变化必须写事件日志，不能只存在前端。
