# Room 团房间系统 PRD 初版

## 目标

提供跑团房间的创建、加入、准备、开局、暂停、完结和归档能力，让 AI-Keeper 能以房间为单位稳定管理一场或多场 Session。

## 范围

包含房间创建、邀请码加入、席位管理、ready、房间状态、当前 Session、有限急救和基础归档。不包含社区招募大厅、评价系统、付费房间和跨房间社交。

## 角色

| 角色 | 权限 |
|---|---|
| 房主 | 创建房间、邀请玩家、开始/暂停/结束 Session、执行有限急救。 |
| 玩家 | 加入房间、绑定角色、ready、参与 Session。 |
| 旁观者 | 只读公共演出，不参与状态写入。 |
| Engine | 校验状态变化，写权威房间状态。 |

## 用户故事

| 编号 | 用户故事 | 优先级 |
|---|---|---:|
| ROOM-1 | 作为房主，我能创建房间并得到邀请信息。 | P0 |
| ROOM-2 | 作为玩家，我能通过邀请码加入指定房间。 | P0 |
| ROOM-3 | 作为房主，我能看到玩家 ready 状态并开始游戏。 | P0 |
| ROOM-4 | 作为房主，我能暂停或恢复当前 Session。 | P0 |
| ROOM-5 | 作为长团组织者，我能按 Session 查看历史记录。 | P1 |

## 数据边界

房间拥有 `roomId`、状态、席位、成员、当前剧本、当前 Session、房主令牌、公开配置和归档索引。玩家私密线索、角色私密信息和模组真相不直接暴露给房主 UI。

## 接口 / 事件方向

- REST：创建房间、加入房间、查询房间、开始/暂停/结束 Session。
- WS：大厅快照、成员变更、ready 变化、房间状态变化。
- Event：`room_created`、`player_joined`、`player_ready_changed`、`session_started`、`session_paused`、`session_finished`。

## 验收标准

- 房主可创建房间并邀请玩家加入。
- 玩家加入后可绑定角色并 ready。
- Host 大厅实时看到席位和 ready 状态。
- 开始游戏后房间进入进行中状态。
- 暂停、恢复、结束都写入事件日志。
