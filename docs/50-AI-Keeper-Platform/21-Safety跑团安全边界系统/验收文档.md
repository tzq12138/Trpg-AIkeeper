# Safety 跑团安全边界系统验收文档

## 文档定位

本文档用于在收到工程师的 `回执-YYYY-MM-DD.md`、代码改动说明、测试结果之后，判断 `21-Safety跑团安全边界系统` 本轮工作是否真正完成。

它只负责验收，不替代：

- `功能列表.md`
- `PRD.md`
- `DeepSeek计划.md`

默认分两层结论：

- `本轮工程验收通过`：表示 Safety 本轮 P0/P1 主链路已经闭环；
- `生产安全完成`：表示除了本轮范围外，token 生命周期、统一可见性、导出脱敏、RAG/AI 审计、桌面安全工具和部署安全基线也已基本收口。

除非证据非常完整，否则默认只给 `本轮工程验收通过`，不直接给 `生产安全完成`。

## 验收输入

验收前至少应拿到以下材料：

- 本模块四份基线文档：`功能列表.md`、`PRD.md`、`DeepSeek计划.md`、`验收文档.md`
- 工程师回执：`回执-YYYY-MM-DD.md`
- 本轮改动文件清单
- 实际测试命令与结果
- 如涉及前端或投影展示，附 `npm run build` 结果

## 结论等级

| 结论 | 含义 |
| --- | --- |
| `本轮工程验收通过` | 鉴权、可见性、reconnect、archive、export、RAG/AI、文件安全和部署基线与文档对齐 |
| `本轮工程验收有缺口` | 主链路大体可用，但缺关键测试、关键证据或关键边界未闭环 |
| `不通过` | 出现越权读取、剧透泄露、token 泄露、导出泄露、未授权素材暴露或测试未过等硬问题 |
| `生产安全完成` | 仅在 token 生命周期、统一 helper、导出脱敏、RAG/AI 审计和桌面安全工具也收口后才能给出 |

## 一票否决项

出现任一情况，本轮不得判通过：

- `public_export` 仍使用 `audience != 'player'` 作为公开判断
- reconnect snapshot 仍返回房间全量 events
- `ws_manager.reconnect()` 仍返回未过滤裸 events
- `player` audience 缺目标角色字段时仍可能放行
- Host 仍能收到 `player-only state_patch`、`private_notice` 或私密 `action_completed`
- `system_safe` 仍只按事件名放行，没有 payload field whitelist
- `public_export` 仍包含 host-only、player-only、token、本地路径、隐藏素材 URL、raw prompt 或 debug metadata
- `full_export` 被实现成 DB dump，仍包含 raw token、API key、secret、raw prompt/raw response 或账号敏感字段
- 玩家地图仍可匿名访问，或仍泄露 hidden count / hidden NPC / 未发现 clue
- 玩家 prompt 仍包含 raw truth、ending、未发现 clue 或 hidden asset title
- `SpoilerAudit` 仍可能进入 `public_export`
- 日志或导出仍含 `owner_token`、`player_token`、`account_token`、API key
- 关键测试命令未提供，或测试未通过

## 生产安全加签条件

以下条件未关闭前，不应给 `生产安全完成`：

- reconnect snapshot / delta 仍未完全复用统一 helper
- `public_export` / `full_export` / `admin_audit_export` 仍缺专项自动化测试
- CORS 生产判定与 allowlist 仍缺清晰测试或部署校验
- owner/player token 轮换与 account token 撤销仍未实现
- RAG search 到玩家 prompt 的二次过滤仍缺专项自动化测试
- 桌面安全事件仍缺限速、审计或导出边界测试
