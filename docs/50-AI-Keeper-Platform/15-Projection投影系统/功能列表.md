# Projection 投影系统功能列表 V2.0

## 模块定位

Projection 负责把已经确认的内部事实、安全叙事和事务结果，按 Host、Player、Party、System 的不同视角投递出去，并沉淀为可追溯事件。

Projection 是“分层可见性和传输层”，不是规则引擎，也不是状态写入层。它不能修改裁决结果，不能生成 AI 内容，不能把未持久化状态当成事实发出去。它的第一职责是保证：谁能看到什么、按什么顺序看到、断线后补什么、日志里能不能追溯、是否存在剧透泄露。

## 当前代码真实锚点

| 代码位置 | 当前职责 | 备注 |
| --- | --- | --- |
| `src/server/engine/projection.py` | `ProjectionDispatcher.emit` 写 `events` 并实时 WS 投递；`ProjectionBuilder` 做 audience 拆分 | Dispatcher 当前没有使用 Builder，party 事件直接以 party 广播 |
| `src/server/host/ws_manager.py` | 连接管理、定向发送、房间广播、重连补丁查询 | 实时广播按 audience 过滤，重连查询未过滤 |
| `src/server/main.py` | Player WS 鉴权和 catch-up 补发 | catch-up 使用 `EventLog.get_events`，会发全房间事件 |
| `src/server/host/router_host.py` | Host WS 鉴权、HostStore 路由、UI frame 转换、delayed event 释放 | Host 收到标准事件后转成 `host_state_update` 等 UI frame |
| `src/server/events/events_registry.py` | 事件注册表、domain、默认 audience | 注册表文案有乱码，且部分实际事件未登记 |
| `src/server/models.py` | `EngineEventType`、`Audience`、`EngineEvent` envelope | 与 registry、前端 types 需要保持一致 |
| `src/server/events/event_log.py` | 事件查询、public events、checkpoint | `get_public_events` 用 `audience != 'player'`，会把 host-only 当公开 |
| `src/server/player/router_reconnect.py` | `/api/player/reconnect`、`/api/player/actions/{action_id}` | snapshot 路径返回全量 events，普通路径复用未过滤 reconnect |
| `src/server/player/router_player_archive.py` | 玩家归档、行动、线索、技能检定回查 | player audience 过滤依赖 payload `characterId`，缺字段时风险高 |
| `src/server/engine/state_service.py` | `s2c_state_patch` 事件写入 | 当前写 audience 为 party，registry 认为 state_patch 是 player |
| `src/server/engine/resolution_pipeline.py` | 生成 reveal、state_patch、public_observation、action_completed | 当前存在先投影再 State 落库的顺序风险 |
| `src/client/src/shared/ws.ts` | PlayerWS 标准 EngineEvent 消费和 lastSequence | 只在内存追踪 sequence，未持久确认 |
| `src/client/src/pages/HostStage.tsx` | Host UI frame 消费 | 同时接收标准 `s2c_*` 和 Host WS 翻译 frame |
| `src/client/src/pages/PlayerActionPage.tsx` | Player 事件消费 | state patch 只处理部分 inventory patch，版本屏障未完成 |

## 核心数据对象

| 对象 | 所属模块 | 当前字段 | Projection 口径 |
| --- | --- | --- | --- |
| `EngineEvent` | Projection / Channel | `eventId`、`roomId`、`type`、`roomSequence`、`audience`、`visibility`、`payload` | WS 和日志的标准事件信封 |
| `events` | Journal / Projection | `sequence`、`room_id`、`event_type`、`audience`、`payload`、`issued_at` | 持久投影日志，sequence 是补发和回放顺序 |
| `Audience` | Projection / User | host、player、party、system | 顶层受众，不足以表达单个玩家目标，需要 `character_id` 或 visibility scope |
| `player_sequences` | Reconnect / Projection | character_id、room_id、last_delivered_sequence | 玩家补发游标，当前只在 reconnect 中更新 |
| `ProjectionDispatcher.emit` | Projection | room_id、event_type、audience、payload、character_id | 事件落库和实时推送入口 |
| `ConnectionManager` | WS | room_id -> connection_id -> WebSocket | 实时连接表，不是可靠存储 |
| `SpoilerGuard audit` | Safety / Projection | audit_id、room_id、action_id、violations、final_text | 投影安全网命中后的审计证据 |
| Host UI frame | Host Client | `host_state_update`、`chat_message`、`map_updated` 等 | Host WS 内部 UI 协议，不等于标准 EngineEvent |

## P0 MVP 功能

| 功能 | 当前状态 | 进入 MVP | 依赖 | 用户价值 | 验收口径 |
| --- | --- | --- | --- | --- | --- |
| 标准事件信封 | 已有 `EngineEvent` | 是 | Channel、Journal | 前后端统一解析事件 | WS 帧包含 `type/roomSequence/audience/payload` |
| 事件持久化 | `ProjectionDispatcher.emit` 和 `EventLog.log_event` 都能写 events | 是 | Journal | 断线、回放、审计有来源 | 每条投影事件有递增 sequence |
| 实时 Host 投递 | `broadcast_to_room` 可按 host 过滤 | 是 | Host Client | Host 看到舞台演出、HUD、地图、遭遇 | host-only 事件只到 Host 连接 |
| 实时 Player 定向 | `emit(..., audience="player", character_id=...)` 可定向 | 是 | User、Player Client | 私密结果只给目标玩家 | 玩家 A 收不到玩家 B 的 player-only 事件 |
| Party 广播 | party 事件广播给 Host 和所有玩家 | 是 | Channel | 公共叙事、队伍聊天、地图队伍状态同步 | Host 和 Player 都能收到公开事件 |
| 事件注册表 | 已有 `events_registry.py` | 是 | Channel、Admin/Ops | 所有事件有默认 audience 和 domain | 实际 emit 的 `s2c_*` 均在 registry 和类型中登记 |
| Player WS 鉴权 | `main.py` 用 token + room 校验 | 是 | User | 非成员不能订阅房间事件 | 无效 token 关闭连接 |
| Host WS 鉴权 | `router_host.py` 支持 owner token / account admin/owner | 是 | User、Host Client | Host 通道不被玩家伪造 | 无 token 或错 token 被拒绝 |
| 反剧透安全网 | Dispatcher 可接 spoiler_guard 扫描 player/party payload | 是 | Safety | 防止最后一公里剧透 | 命中敏感词时 redacted，并写 audit |
| Player 重连补发 | 已有 `/api/player/reconnect` 和 WS catch-up | 是 | Reconnect、Journal | 断线后不丢事件 | 只补发该玩家可见事件 |
| state patch 版本屏障 | 文档已有方向，代码未闭合 | 是 | State、Player Client | 乱序 patch 不覆盖新状态 | patch 带 `baseStateVersion/stateVersion/schemaVersion` |
| 投影先后顺序 | 当前需与 State/Transaction 一起修 | 是 | Transaction、State | 玩家看到的是已落库事实 | State 写入成功后再发 patch/completed |

## P1 强化功能

| 功能 | 当前状态 | 进入 MVP | 依赖 | 验收口径 |
| --- | --- | --- | --- | --- |
| 统一可见性过滤函数 | 当前实时、重连、archive、export 各写各的 | 是 | User、Journal | 同一事件在 live/reconnect/archive/export 可见口径一致 |
| Player catch-up 过滤 | `player_ws_endpoint` 直接用 `EventLog.get_events` | 是 | WS、Reconnect | 玩家 WS 重连不收到 host-only 或他人私密事件 |
| snapshot 补发过滤 | `/api/player/reconnect` snapshot 路径返回全量 events | 是 | Reconnect | 首次或长断线 snapshot 不泄露 |
| `get_public_events` 修正 | 当前 `audience != 'player'` | 是 | Journal、Channel | 玩家公共事件只含 party/system 白名单，不含 host-only |
| public export 修正 | 当前 public export 同样排除 player 即视为公开 | 是 | Journal、Admin/Ops | 导出的公开战报不含 Host-only 真相 |
| player archive 私密过滤 | 依赖 payload `characterId` | 是 | Journal、Player Client | player 事件缺 owner 字段时默认不展示给非目标玩家 |
| `ProjectionBuilder` 收口 | Builder 与 Dispatcher 分离 | 是 | Engine、Tests | party 拆分或广播策略只有一个权威实现 |
| 直接写 events 路径收口 | Engine/State/EventLog/Dispatcher 并存 | 是 | Transaction、State、Journal | 需要实时投递的事件统一走 Dispatcher 或显式标记只落日志 |
| Host UI frame 边界 | Host WS 会翻译标准事件 | 是 | Host Client | 文档明确标准事件和 UI frame 不混用 |
| 事件 schema 契约 | payload 松散，camel/snake 混用 | 是 | Frontend、Journal | 关键事件最小字段固定，兼容字段有迁移策略 |
| sequence 确认 | PlayerWS 只内存记录 lastSequence | 否 | Reconnect | delivered sequence 可持久确认或由 reconnect 显式更新 |

## P2 平台增强

| 功能 | 是否进入 MVP | 依赖 | 说明 |
| --- | --- | --- | --- |
| 多设备连接管理 | 否 | User、WS | 同一玩家多设备登录，支持设备级 sequence |
| 离线消息队列 | 否 | Redis / Queue | 长断线按用户存储可靠补发，不只依赖 events 查询 |
| 订阅过滤器 | 否 | Channel、Plugin | 客户端按频道、事件域、组件订阅 |
| 压缩快照补丁 | 否 | State、Journal | 长团事件太多时用 checkpoint + patch 合并 |
| 观众延迟投影 | 否 | Community、Safety | 给观众延迟、删减、脱敏版本 |
| 投影指标 | 否 | Admin/Ops | 统计投递延迟、WS 断线率、过滤命中率 |

## P3 长期能力

- 跨进程事件总线和持久消息队列。
- 插件化投影转换器。
- 多舞台、多语言、多字幕轨投影。
- 直播模式安全延迟。
- 基于事件域的精细权限策略。

## 不属于 Projection 的内容

| 内容 | 归属模块 | 原因 |
| --- | --- | --- |
| 世界状态写入 | State | Projection 只能发送已确认状态 |
| 规则成功失败 | Rule | Projection 不修改骰子、目标值、成功等级 |
| AI 叙事生成 | AI-Keeper | Projection 只安全扫描和分发已生成内容 |
| 行动事务编排 | Transaction | Projection 不决定 action 生命周期 |
| 聊天频道建模 | Channel | Projection 可承载事件，不负责频道产品模型 |
| 历史搜索和导出产品体验 | Journal | Projection 提供事件，Journal 负责查询和战报 |
| Host 播放控制 | Host Client / Transaction | Projection 发送 reveal，播放 ACK 属于事务和客户端 |

| 风险 | 代码锚点 | 优先级 | 处理方向 |
| --- | --- | --- | --- |
| Player WS catch-up 未过滤 | `main.py:player_ws_endpoint` | P0 | 补发只返回 party/system 白名单和本人 player 事件 |
| `/api/player/reconnect` 普通路径未过滤 | `ws_manager.reconnect` | P0 | 查询 events 时套用同一可见性过滤 |

| `s2c_state_patch` audience 冲突 | `state_service.py`、`events_registry.py` | P0 | 私密 patch 用 player 定向；party patch 只能放公开摘要 |
| patch 缺版本字段 | `state_service.py`、`resolution_pipeline.py` | P0 | 加 `schemaVersion/baseStateVersion/stateVersion/actionId` |

| 直接写 events 不实时推送 | `engine.py`、`event_log.py` | P1 | 区分日志事件和实时投影事件 |
| 未登记事件仍被 emit | `s2c_turn_resolved`、checkpoint events | P1 | registry、models、前端 types、测试同步 |

| Player archive 私密事件缺 owner 时可能放行 | `router_player_archive.py` | P1 | player audience 默认拒绝，只有明确 owner 才放行 |

## MVP 验收主链路

1. Engine/Transaction 在 State 成功持久化后调用 Projection。
2. Projection 写入 `events`，获得 sequence。
3. Host-only 事件只实时发给 Host。
4. Player-only 事件只实时发给目标角色连接。
5. Party 事件实时发给 Host 和所有玩家，但 payload 只能包含公开内容。
6. Player WS 断线后 catch-up 只补自己可见事件。
7. `/api/player/reconnect` 普通补发和 snapshot 补发都不泄露 Host-only 或他人私密事件。
8. Player public archive/export 不含 Host-only 真相。
9. `s2c_state_patch` 携带版本字段，客户端能识别乱序 patch。
10. 所有 emit 的 `s2c_*` 事件在 registry、Pydantic Literal、前端类型和测试中一致。
