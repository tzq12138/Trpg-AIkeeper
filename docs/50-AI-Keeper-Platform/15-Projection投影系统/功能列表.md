# Projection 投影系统功能列表 V2.1

## 模块定位

Projection 负责把已经确认的权威事实，按 Host、Player、Public、Audit 不同视角安全投递出去，并沉淀成可回放、可追溯、可审计的事件流。

它是 AI-Keeper 的“分层可见性与事件投递层”，不是规则引擎，不是世界状态写入层，也不是 Host 演出编排器。Projection 只处理三件事：

1. 哪些事件能被谁看到。
2. 同一条事件在不同视角下应该长什么样。
3. 事件何时可以被实时下发、补发、回放、导出。

## 当前阶段

当前阶段定位为：

`P0 主链路 + 分层可见性与事件投递风险识别版`

本轮先把“实时投递、断线补发、公共回放、公开导出、Host 演出协议边界、状态 patch 时序”写硬，不在本模块内扩展跨进程消息总线、复杂订阅 DSL、直播观众流或多设备可靠 ACK。

| `src/server/engine/state_service.py` | 直接写 `s2c_state_patch` 事件 | 当前 patch 仍是 `party` audience，且缺版本字段 |

## Projection 数据分层

| 层级 | 名称 | 含义 |
| --- | --- | --- |
| L0 | 权威事实 | `actions`、`rooms.state_version`、runtime state、线索归属、地图状态等真实业务状态 |
| L1 | `ProjectionRequest` | 上游模块发起的“我要投递一个事件”的请求 |
| L2 | `EngineEventEnvelope` | 标准事件信封，包含 `type / roomSequence / audience / payload` |
| L3 | `EventLog` | 持久化事件日志，提供 sequence、回放、审计、补发来源 |
| L4 | `VisibilityDecision` | 针对某个 viewer 的允许/拒绝/原因判定 |
| L5 | `PayloadProjection` | 针对某个 viewer 的安全 payload 裁剪结果 |
| L6 | `HostFrame` | Host UI 消费协议，例如 `host_state_update`、`chat_message` |
| L7 | `PlayerEventStream` | Player WS 实时事件流 |
| L8 | `ReconnectSnapshot` | Player 断线后 missed events 或 snapshot 包 |
| L9 | `PublicEventView` | public replay / archive / export 看到的公共事件视图 |
| L10 | `SpoilerAudit` | SpoilerGuard 的拦截、替换、失败审计，不等于玩家日志 |

## 核心 DTO 契约

| DTO | 作用 | 最低要求 |
| --- | --- | --- |
| `EngineEventEnvelopeDTO` | 标准事件信封 | `eventId? / roomId / type / roomSequence / audience / payload / issuedAt?` |
| `ProjectionRequestDTO` | 上游请求投递 | `roomId / eventType / audience / payload / characterId? / traceRefs?` |
| `VisibilityDecisionDTO` | 可见性判断结果 | `allowed / reason / viewerRole / viewerCharacterId?` |
| `ProjectedPayloadDTO` | 裁剪后的安全视图 | `type / roomSequence / safePayload / safeText? / sourceRefs?` |
| `StatePatchEventDTO` | 状态 patch | `actionId / schemaVersion / baseStateVersion / stateVersion / patches` |
| `PlayerReconnectEventDTO` | reconnect 返回事件 | 只能包含玩家本人可见事件，不得携带 Host-only payload |
| `PublicEventDTO` | public replay / export 事件 | 只能包含 public / system_safe 字段 |
| `HostFrameDTO` | Host UI 协议 | 来源于 `EngineEvent`，但不写回 `events`，不作为审计事实 |
| `SpoilerAuditDTO` | 投影安全审计 | 仅 Admin/Ops 可查，不进入 public export |

## P0 MVP 功能

| 功能 | 当前现状 | 进入 MVP | 依赖 | 用户价值 | 验收口径 | 现状风险 |
| --- | --- | --- | --- | --- | --- | --- |
| 标准事件信封 | 已有 `EngineEvent` | 是 | Channel、Journal | 前后端统一消费事件 | WS / reconnect / replay 使用同一事件外壳 | 事件字段未完全稳定 |
| 事件落库后实时投递 | 已有 `ProjectionDispatcher.emit()` | 是 | Journal | 断线补发、回放、审计都能追溯 | `events.sequence` 先生成，再实时下发 | 上游仍有绕过 Dispatcher 的路径 |
| Host-only 实时投递 | 已有 | 是 | User、Host Client | Host 看到完整演出与公共舞台控制流 | Host-only 不进入 Player WS / public replay / public export | Host frame 与标准事件边界不够硬 |
| Player-only 定向投递 | 已有 | 是 | User、Player Client | 私密结果只给目标玩家 | `audience=player` 时必须绑定目标角色 | 缺 owner 字段时仍可能误判 |
| Party 公共事件投递 | 已有 | 是 | Channel | 队伍共用公开叙事 | Host 与所有玩家都能收到，但 payload 只能是公共版 | 现在上游容易把“公共 audience”错当“公共全量 payload” |
| 统一可见性判断 | 只有部分 helper | 是 | User、Journal | live / catch-up / reconnect / archive / export 同口径 | 后端统一 `can_view_event + build_event_view` | 目前多个入口仍各写各的过滤 |
| Player WS catch-up | 已有 `get_events_for_player()` | 是 | WS、Journal | 玩家断线重连后不丢自己该看的事件 | catch-up 只返回本人可见事件 | `player_sequences` 语义未写硬 |
| `/api/player/reconnect` 过滤 | 现有 missed events 与 snapshot | 是 | Reconnect | 长断线恢复不泄露他人或 Host 视角 | 普通补发和 snapshot 都只返回安全事件 | snapshot 现在仍返回整房间事件 |
| `system_safe` 白名单 | 代码已有 `PLAYER_VISIBLE_SYSTEM_EVENTS` | 是 | Journal、Safety | 允许少量系统摘要进入玩家视角 | 只有白名单 system 事件能下发给玩家或 public | 目前只按事件名做白名单，payload 裁剪还不够 |
| `s2c_state_patch` 版本屏障 | 文档有方向，代码未闭环 | 是 | State、Player Client | 客户端识别乱序 patch，不覆写新状态 | patch 带 `schemaVersion / baseStateVersion / stateVersion` | 当前 patch 缺关键版本字段 |
| 投影时序 | 需与 13/14 联动修正 | 是 | State、Transaction | 玩家看到的都是已落库事实 | State 成功后再发 patch / completed | 当前 `resolution_pipeline` 先投影后写 State |
| SpoilerGuard 末端安全网 | 已有 | 是 | Safety | 最后一层防剧透 | player / party payload 命中风险词会替换并审计 | 只扫字符串，结构化泄露仍要靠上游 |
| public replay / export 安全视图 | 现有实现过松 | 是 | Journal、Admin/Ops | 公开战报不泄露 Host-only / private 真相 | public 只允许 `party + system_safe` 视图 | `export.py` 仍按 `audience != 'player'` 近似处理 |
| `player_sequences` 语义 | 已有表与写入点 | 是 | Reconnect | 玩家断线后能继续补发 | 明确它记录的是“该玩家流的 delivery cursor” | 当前容易被误解成“玩家已看完所有事件” |
| ReleaseGate 边界 | 代码已有 Host delayed release 雏形 | 是 | Transaction、Host Client | 私密结果不早于 Host 演出释放 | Gate 的创建/ACK/释放归 Transaction，Projection 只按 gate 结果投递 | 当前模块边界还不够明确 |

## P1 强化功能

| 功能 | 当前现状 | 进入 MVP | 依赖 | 验收口径 |
| --- | --- | --- | --- | --- |
| `build_event_view()` / `sanitize_event_payload()` | 当前主要是 bool 过滤 | 是 | Journal、Export | 不只判断能不能看，还能裁剪成不同视图 |
| realtime / audit-only 写入分类 | 仍有多处直接 `log_event()` | 是 | Transaction、Journal | 每条直接写 `events` 的路径都标明是否实时投递 |
| Host UI frame 边界固化 | Host 端已存在多种 frame | 是 | Host Client | 文档明确 HostFrame 只是显示协议，不是权威事实 |
| 事件最小 schema 契约 | payload 仍偏松散 | 是 | Frontend、Journal | 关键事件最低字段稳定，回放与导出可追溯 |
| 投影指标与异常审计 | 只有基础日志 | 否 | Admin/Ops | 能统计投递失败、过滤命中、SpoilerGuard 替换率 |
| 更可靠的 ACK / cursor 策略 | 只靠 reconnect 更新 cursor | 否 | WS、Reconnect | 明确什么时候写 `last_delivered_sequence`，避免重复与漏发 |

## P2 平台增强

| 功能 | 是否进入 MVP | 依赖 | 说明 |
| --- | --- | --- | --- |
| 多设备 player cursor | 否 | User、WS | 同一玩家多端登录时按设备维护 delivery cursor |
| 离线消息队列 | 否 | Redis、Queue | 长断线补发不完全依赖 `events` 查询 |
| 订阅过滤器 | 否 | Channel、Plugin | 客户端按事件域、频道、组件订阅 |
| 压缩 snapshot + patch merge | 否 | State、Journal | 长团大房间时减少 reconnect 负载 |
| 投影指标面板 | 否 | Admin/Ops | 可视化投递延迟、过滤命中、断线恢复质量 |

## P3 长期能力

- 跨进程事件总线与持久消息队列。
- 插件化投影转换器。
- 观众延迟投影与直播安全延迟。
- 跨语言、多字幕轨的投影视图。
- 更细颗粒度的事件域权限策略。

## 不属于 Projection 的内容

| 内容 | 归属模块 | 原因 |
| --- | --- | --- |
| 世界真相写入 | State | Projection 只投递已确认事实，不写世界状态 |
| 规则成功失败判断 | Rule | Projection 不计算检定、伤害、成功等级 |
| AI 叙事生成 | AI-Keeper | Projection 只投递并裁剪已生成内容 |
| 行动事务编排 | Transaction | Projection 不决定 action 生命周期和 release gate |
| Host 演出 ACK 语义 | Transaction、Host Client | Projection 只在允许释放后发出事件 |
| 归档检索与导出产品形态 | Journal | Projection 提供安全事件视图，不负责完整产品 UI |

## MVP 验收主链路

1. 上游模块在权威状态已确认后发起 `ProjectionRequest`。
2. Projection 先落 `events`，再生成标准 `EngineEvent`。
3. Host-only 事件只发给 Host。
4. Player-only 事件只发给目标角色。
5. Party 事件可发给 Host 和所有玩家，但 payload 必须已经是公共版。
6. Player WS catch-up 只补自己可见事件。
7. `/api/player/reconnect` 的 missed events 和 snapshot 都不泄露 Host-only 或他人 private 事件。
8. public replay / public export 只包含 `party` 与 `system_safe` 视图。
9. `s2c_state_patch` 携带完整版本字段，客户端能识别乱序 patch。
10. Transaction 负责 release gate，Projection 只在允许释放后投递事件。
11. 所有真实发出的 `s2c_*` 事件都在 registry、后端类型、前端类型与测试里对齐。
