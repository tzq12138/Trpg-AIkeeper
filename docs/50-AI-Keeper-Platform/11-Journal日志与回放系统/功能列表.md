# Journal 日志与回放系统功能列表 V2.1

## 当前阶段说明

本轮文档定位为：

- `P0 主链路 + Journal 可见性与导出安全风险识别版`
- 目标是先把 `事件沉淀 -> Host 审计 -> Player 档案 -> checkpoint -> export -> campaign archive` 这条链路钉牢
- 不在本轮扩展社区战报、多媒体回放、复杂搜索、长团知识检索平台
- 当前代码优先于旧文档；旧文档只用于补产品语义，不覆盖真实实现现状

## 模块定位

Journal 是 AI-Keeper 核心链路中的“审计与回放层”。

它负责把已经发生、已经过 Engine / State / Projection / Clue / Timeline 校验的结果沉淀为可追溯记录，并按视角输出为：

- Host 全量时间线与审计日志
- Player 私人档案
- public 视角战报与导出
- checkpoint 快照与恢复断点
- campaign archive 总结

Journal 不负责：

- 决定行动是否合法
- 直接写世界真相或规则状态
- 决定玩家是否应该获得线索
- 把 AI 原始 prompt / raw response 暴露给玩家或 public export

## 数据分层

| 层级 | 对象 | 归属 | 用途 | 可见边界 |
| --- | --- | --- | --- | --- |
| L0 | `events` | Journal | 房间内权威事件流水 | 只作为底层权威源，不直接裸给前端 |
| L1 | `HostTimelineView` | Journal / Host | Host 全量审计、排障、回放 | Owner / Admin |
| L2 | `PlayerArchiveView` | Journal / Player | 玩家可见事件、自己的私密结果、公开线索摘要 | 当前 Player |
| L3 | `PublicEventView` | Journal / Public | 对外可公开事件流、公开战报 | public / observer / 玩家公开视角 |
| L4 | `CheckpointSnapshot` | Journal / State | 房间恢复点 | Owner / Admin only |
| L5 | `CampaignArchive` | Journal | 结团 summary / highlights / arcs | 按 public 或 full 分层读取 |
| L6 | `ExportPackage` | Journal / Export | Markdown / JSON 导出包 | `public` 与 `full` 两套白名单 |
| L7 | `AI/Ops Audit` | Admin / Ops | raw prompt、raw response、内部安全审计 | Admin / Ops only，`never_export` |
| L8 | `SourceReferenceChain` | Cross-module | 把 action / transaction / stateVersion / clue / map / turn 串起来 | Host 可查；Player 只拿安全摘要 |

## DTO 分层

本轮先把 DTO 边界写清，避免后续 DeepSeek 继续拿底表直接透出。

| DTO | 面向对象 | 最低必需字段 | 禁止字段 |
| --- | --- | --- | --- |
| `JournalEventDTO` | 内部标准事件 | `roomId`、`sequence`、`eventType`、`audience`、`issuedAt`、`payload` | token、API key、raw prompt |
| `HostJournalEventDTO` | Host timeline 明细 | `JournalEventDTO` + `sourceRefs` + `debugMeta?` | 不应携带完整 secret |
| `PlayerArchiveEventDTO` | Player archive | `sequence`、`eventType`、`issuedAt`、`safeText`、`safePayload`、`sourceRefs?` | 他人私密 payload、host-only reason |
| `PublicExportEventDTO` | public export | `sequence`、`eventType`、`publicText`、`publicPayload`、`issuedAt` | token、raw xlsx、未公开 clue、真相字段 |
| `CheckpointDTO` | checkpoint 列表与详情 | `checkpointId`、`roomId`、`createdAt`、`createdBy`、`reason`、`snapshotMeta` | snapshot 原文默认不暴露给非 Host |
| `CampaignSummaryDTO` | 结团摘要 | `ending`、`highlights`、`characterArcs`、`publicClues` | host-only 审计、AI raw output |
| `ExportPackageDTO` | 导出结果 | `scope`、`generatedAt`、`roomSummary`、`events`、`characters?`、`clues?` | `never_export` 字段 |

## 统一可见性口径

Journal 必须复用与 `10-Timeline时间轴系统` 一致的可见性语义，至少区分：

- `host`：只给 Host / Owner / Admin
- `party`：全队公开
- `player:self`：只给当前角色本人
- `player:other`：对当前玩家永远不可见
- `system_safe`：系统事件，但 payload 已安全裁剪，可给玩家
- `admin_audit`：只给 Admin / Ops / Owner 的内部审计

本轮明确要求：

1. `public events`、`player archive`、`replay`、`export` 必须复用同一套后端 helper。
2. 不允许继续使用 `audience != 'player'` 这类反向过滤作为 public 口径。
3. `system` 事件不天然 public，只有进入白名单并完成 safe payload 的 system 事件才可视作 `system_safe`。
4. 私密事件缺少 `characterId`、`recipientCharacterId` 等归属字段时，默认拒绝下发给 Player。
5. 所有查询、补发、回放、导出都必须以 `room_id + sequence` 为边界，而不是跨房间全局 sequence 解释。

## 事件来源引用契约

| 事件类型 | 最低来源字段 | 用途 |
| --- | --- | --- |
| `action queued / submitted / completed` | `actionId`、`characterId`、`intentType`、`turnId` | 追踪谁在何时提交了什么行动 |
| `skill check resolved` | `actionId`、`characterId`、`ruleCheckId`、`rolls` | 回看检定依据与结果 |
| `s2c_state_patch` | `transactionId`、`stateVersion`、`patchScope` | 追踪状态变更归因 |
| `clue discovered / shared` | `clueId`、`sourceEventSequence`、`ownerCharacterId`、`sharedBy`、`sharedTo` | 形成线索证据链 |
| `map updated / revealed / moved` | `mapId`、`sceneId`、`transactionId`、`sourceEventSequence` | 对齐地图变化与回合结算 |
| `s2c_turn_resolved` | `turnId`、`transactionBatchId`、`stateVersion` | 标记一轮结算边界 |
| `s2c_checkpoint_created` | `checkpointId`、`sourceSequence`、`reason` | 追踪断点来源 |
| `s2c_checkpoint_restored` | `checkpointId`、`actorAccountId`、`reason`、`restoreMode` | 解释恢复行为 |
| `campaign ended / archived` | `archiveId`、`endingType`、`sourceSequences[]` | 追踪战役归档来源 |

## 不属于 Journal 的内容

| 内容 | 归属模块 | Journal 只负责什么 |
| --- | --- | --- |
| 行动是否合法 | Rule、AI-Keeper、Engine | 只记录结算结果和来源引用 |
| 世界真相如何写入 | State | 只记录 patch、版本号和安全摘要 |
| 玩家是否应当获得线索 | Clue、Safety | 只按授权展示、归档和导出 |
| 游戏内时间推进 | Timeline | 只引用时间轴结果，不负责推进时钟 |
| AI 输出是否安全 | Safety、Projection | 只沉淀已通过安全裁剪的结果 |
| 运维排障日志 | Admin/Ops | 只在需要时引用审计摘要，不进入 Player Journal |

## MVP 主链路验收口径

1. Host 创建房间，玩家加入、绑定角色、ready。
2. 玩家提交行动，Engine 完成裁决，State 写入变更，Projection 发送 Host / Player 事件。
3. `events` 中可以查到行动、检定、状态 patch、地图变化、回合完成等关键记录。
4. Host 通过 timeline 能按 `room_id + sequence` 查看完整事件流，并创建 checkpoint。
5. Player 通过 archive 只能看到公开事件与自己的私密结果，不能看到他人私密信息。
6. Host 恢复 checkpoint 时必须显式确认并填写 `reason`，恢复后写入新的 restore 审计 marker。
7. public export 不包含 token、未公开线索、host-only 事件、raw prompt、世界真相字段。
8. full export 仅 Owner / Admin 可取，且仍不允许导出 raw token、API key、原始 AI prompt/response。
