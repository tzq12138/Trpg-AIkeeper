# Journal 日志与回放系统功能列表 V2.0

## 模块定位

Journal 负责把跑团过程中已经发生的事实沉淀为可追溯记录，并提供 Host 审计、Player 个人档案、Checkpoint、战役归档、回放和导出能力。它是核心链路中“状态变更 -> 分层投影 -> 日志沉淀”的落点。

Journal 不负责裁决规则、不直接写世界真相、不决定玩家能否获得线索。它只记录来自 Engine、State、Projection、Clue、Timeline、AI-Keeper 等模块已经校验过的结果，并在查询、回放、导出时严格执行可见性边界。

## 数据对象

| 对象 | 归属 | 用途 | 关键边界 |
| --- | --- | --- | --- |
| `events` | Journal | 权威事件流水、投影记录、回放来源。 | 按 `audience` 和 payload 归属过滤，不把 Host 私密内容发给 Player。 |
| `checkpoints` | Journal/State | 房间状态快照与恢复点。 | 只允许 Owner/Admin 创建、查看、恢复。 |
| `campaign_archives` | Journal | 战役结束后的 summary、highlights、角色弧光。 | public 摘要必须来自玩家可见事实。 |
| `ai_call_logs` | Admin/Ops | AI 调用诊断。 | 运维审计数据，不进入 Player Journal。 |
| `spoiler_audits` | Safety/Admin | 防剧透审计。 | 只给 Admin/Owner 排查，不作为玩家回放内容。 |
| 导出文件 | Journal | Markdown/JSON 战报、审计包。 | public/full scope 必须有不同字段集合。 |

## P0 MVP 功能

| 功能 | 当前状态 | 进入 MVP | 依赖模块 | 验收口径 |
| --- | --- | --- | --- | --- |
| 统一事件流水 | 已有多处写 `events` | 是 | Engine、Projection、State | 行动、裁决、状态变化、投影都有 `sequence`、`event_type`、`audience`、`payload`。 |
| Host 全量日志 | 已有 `/api/rooms/{room_id}/events` 和 `/timeline` | 是 | User、Room | Owner/Admin 可分页查看房间全量事件，普通 Player 不能访问。 |
| Player 可见日志 | 已有 `/events/public` 和 `/api/player/archive` | 是 | Projection、Safety | Player 只能看到 party/public/system 中明确允许公开的事件，以及属于自己的 private/player 事件。 |
| 行动与检定档案 | 已有 actions、skill-checks 接口 | 是 | Rule、Character | 玩家能查到自己的行动、检定、结果，不看到他人私密行动。 |
| 线索档案入口 | 已有 archive/clues，需强化证据链 | 是 | Clue、Safety | 私密线索只给获得者，公开线索可被全队查看，并能追到来源事件。 |
| Checkpoint 创建和列表 | 已有 `/checkpoint`、`/checkpoints` | 是 | State、Room | Owner/Admin 可创建手动或自动 checkpoint，Player 无权读取快照。 |
| Checkpoint 恢复 | 已有 `/restore/{checkpoint_id}` | 是 | State、Transaction | 恢复需要 `confirm: true`，恢复后写审计事件，并验证主状态、角色、地图、回合一致。 |
| Host 回放 | 已有 timeline 单事件和 replay 雏形 | 是 | Projection、Timeline | Host 可按 `sequence` 复盘关键事件，能定位一次行动的输入、结果和投影。 |
| 战役结束归档 | 已有 `/end` 和 `campaign_archives` | 是 | Room、Timeline | 结束房间后生成 summary/highlights/character arcs，房间状态变为 completed。 |
| Markdown/JSON 导出 | 已有 `/export` | 是 | Safety、User | public 导出无 token、私密线索、Host-only 事件、AI prompt 和世界真相。 |
| 事件类型注册 | 部分已有 registry | 是 | Core | 新增日志事件必须进入 registry 或明确兼容旧事件。 |
| 日志乱码治理 | 多文件存在乱码 | 是 | DevOps | 新增或修改的用户可见文案必须为 UTF-8 中文。 |

## P1 强化功能

| 功能 | 当前状态 | 进入 MVP | 依赖模块 | 验收口径 |
| --- | --- | --- | --- | --- |
| Journal 可见性统一 helper | 当前各接口各自过滤 | 是 | Safety、Projection | public、player archive、export、replay 复用同一套事件可见性判断。 |
| public 过滤修正 | 当前多处使用 `audience != 'player'` | 是 | Safety | Host-only、admin、AI debug、私密 payload 不进入 public API 和 public export。 |
| Player archive 私密归属修正 | 当前缺少 `characterId` 时可能放行 | 是 | Character、Clue | `audience='player'` 或私密事件无明确归属时默认不向 Player 返回。 |
| campaign summary 鉴权 | 当前 `/campaign` 路由需加鉴权 | 是 | User、Room | 未授权请求不能读取战役摘要。 |
| Checkpoint 完整性 | 当前未覆盖 `clue_shares`、`encounter_participants` | 是 | Clue、Scene/Map | 恢复后线索分享、遭遇参与关系、地图位置与回合状态不丢。 |
| 恢复审计语义 | 当前恢复会删除并重插 events | 是 | State、Transaction | 明确 restore 后事件序列策略，并至少保留 `s2c_checkpoint_restored` 审计记录。 |
| 导出字段白名单 | 当前 JSON public 导出字段偏宽 | 是 | Safety | public JSON 不含 `owner_token`、`player_token`、`xlsx_data` 私密原文、账号 ID、内部 prompt。 |
| 前端筛选一致性 | Player UI 有 `narrative`，后端不支持 | 是 | Player Client | 前后端 archive type 一致，失败时有可读错误。 |
| 事件来源引用 | 部分 payload 已有 action/character 信息 | 是 | Transaction、Clue | 关键事件包含 `actionId`、`transactionId`、`stateVersion`、`clueId` 或 `sourceEventSequence`。 |
| 导出测试覆盖 | 当前缺少专项导出测试 | 是 | Test | public/full 导出分别有脱敏和权限测试。 |

## 不属于 Journal 的内容

| 内容 | 归属模块 | Journal 的接口边界 |
| --- | --- | --- |
| 行动是否合法 | Rule、AI-Keeper、Engine | Journal 只记录结算后的结果和来源。 |
| 世界真相如何写入 | State | Journal 只记录 state patch 和版本引用。 |
| 玩家是否获得线索 | Clue、Safety | Journal 只按归属展示和导出线索事件。 |
| 游戏内时间推进 | Timeline | Journal 使用时间轴信息作为回放字段，不负责推进时钟。 |
| AI 输出是否安全 | Safety、Projection | Journal 记录安全后的投影和审计摘要，不公开原始 prompt。 |
| 后台运维日志 | Admin/Ops | 只在必要时引用审计结果，不给普通玩家展示。 |

## 现状风险清单

| 风险 | 代码位置 | 优先级 | 修正方向 |
| --- | --- | --- | --- |
| public 事件过滤过宽 | `EventLog.get_public_events`、`export.py` | P0 | 不再用 `audience != 'player'`，改为显式允许公开事件和字段。 |
| Player archive 私密事件可能误放行 | `router_player_archive.py` | P0 | 私密事件缺少 `characterId` 或归属字段时默认拒绝。 |
| campaign summary 路由未做权限校验 | `router_archive.py` | P0 | public summary 需要 Player token，full summary 需要 Owner/Admin。 |
| Checkpoint 快照缺少间接关联表 | `event_log.py` | P1 | 通过 clue/encounter 关联补入 `clue_shares`、`encounter_participants`。 |
| 恢复会重建 events sequence | `event_log.py` | P1 | 文档化当前语义，并逐步改为保留审计或追加恢复事件策略。 |
| 导出字段过宽 | `export.py` | P0 | public/full 使用字段白名单，public 不导出角色卡原始私密数据。 |
| 事件写入入口分散 | `engine.py`、`projection.py`、`event_log.py` | P1 | 先盘点所有写入点，再收敛到可审计写法。 |
| registry 与实际事件不完全一致 | `events_registry.py`、`models.py` | P1 | checkpoint、turn、archive 相关事件补齐定义和测试。 |
| 前端 archive type 不一致 | `PlayerActionPage.tsx` | P1 | 移除或实现 `narrative` 类型。 |
| 日志和导出文案乱码 | 多处源码与旧文档 | P1 | 修改触达用户的文案，保持 UTF-8。 |

## MVP 验收主链路

1. Host 创建房间，Player 加入并 ready。
2. Player 提交行动，Engine 结算，State 写入变化，Projection 发出 Host/Player 事件。
3. `events` 中能查到行动、裁决、状态变化、投影和可见性字段。
4. Host 可以通过 timeline 查全量事件，并创建 checkpoint。
5. Player 只能在 archive 中看到公开事件和自己的私密事件。
6. Host 恢复 checkpoint 后，系统写入恢复审计事件，主状态、角色、地图、回合不丢。
7. public export 不包含 token、Host-only 内容、未发现线索、世界真相、AI 原始 prompt。
8. full export 仅 Owner/Admin 可获取，并仍对 token 和 secret 做脱敏。
