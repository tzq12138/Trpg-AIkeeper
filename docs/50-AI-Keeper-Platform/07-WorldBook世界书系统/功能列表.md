# WorldBook 世界书系统功能列表 V2.0

## 一句话定位

WorldBook 是 AI-Keeper 的“剧本知识源”和“防剧透真相源”。它负责把导入剧本变成结构化世界书、RAG 索引、质量报告和敏感项索引；它不负责运行态状态写入，不负责玩家可见投影，也不直接裁决玩家行动。

## 当前代码真实链路

1. Admin 调用 `POST /api/scenarios/import-pdf` 上传 PDF，入口在 `src/server/scenario/router_scenarios.py`。
2. 接口校验账号角色必须为 `admin`，并只接受 `.pdf` 文件。
3. 读取文件内容，计算 `source_sha256`，如果已有相同 hash，直接返回 `already_imported`。
4. 临时保存 PDF，调用 `extract_text_from_pdf` 抽取页文本；扫描版 PDF 标记为 `requires_ocr`。
5. 将页文本合并为 `raw_text`，并计算 `chunks = chunk_text(pages)`。
6. 优先调用 `app.state.gateway.structure_scenario(full_text)`；失败后回退到 `structure_scenario`，无 API key 时走 mock。
7. 写入 `scenarios`：`scenario_id`、`title`、`raw_text`、`knowledge_graph`、`import_status=structured`、`source_filename`、`source_sha256`、`original_file_path`。
8. 调用 `QualityReportGenerator.evaluate(knowledge_graph)`，把结果写入 `scenarios.quality_report`。
9. 如果 `app.state.rag` 可用，只调用 `index_npc_graph(scenario_id, knowledge_graph)`。
10. 调用 `SpoilerGuard.build_sensitive_index(scenario_id, knowledge_graph, {})` 写入 `spoiler_sensitive_items`。
11. Host/Admin 通过 `GET /api/scenarios/available` 选择结构化剧本。
12. Host/Admin 调用 `POST /api/scenarios/{scenario_id}/create-room` 创建房间。

## 数据对象

### `scenarios`

- `scenario_id`：剧本模板 ID。
- `title`：当前使用上传文件名，后续应优先使用结构化标题。
- `raw_text`：PDF 全文，属于敏感内容，不能给玩家。
- `knowledge_graph`：世界书结构化主体。
- `scenario_assets`：剧本素材语义 JSON，目前与素材表同名，语义容易混淆。
- `quality_report`：导入质量报告。
- `import_status`：`pending`、`structured`、`requires_ocr` 等状态。
- `source_filename`、`source_sha256`、`original_file_path`：导入来源追踪。

### `document_chunks`

- `source_type=scenario`：剧本文本 chunk，导入时尚未写入。
- `source_type=npc`：NPC chunk，导入时会写入，但房间搜索范围未覆盖。
- `source_type=rule`：全局规则书 chunk。
- `source_type=event/clue/character/asset`：其他模块写入。

### `spoiler_sensitive_items`

- `category=truth`：真相摘要，默认 Host-only。
- `category=hidden_clue`：隐藏线索，需被发现或分享后才可进入玩家上下文。
- `aliases`：用于输出侧敏感词命中。
- `source_ref`：指向 `knowledge_graph.truth.summary` 或 clue 来源。

## P0 功能

### P0-1 导入链路可闭环

- Admin 上传 PDF 后必须得到明确状态：`structured`、`requires_ocr`、`already_imported`、`failed`。
- `structured` 状态必须同时具备：`knowledge_graph`、`quality_report`、RAG 索引、spoiler index。
- 中途失败不能把低质量半成品标记为可用剧本。

### P0-2 世界书 schema 稳定

最小结构：

```json
{
  "title": "string",
  "synopsis": "string",
  "scenes": [],
  "npcs": [],
  "clues": [],
  "truth": {},
  "endings": [],
  "trigger_mechanics": [],
  "spoiler_boundaries": []
}
```

### P0-3 RAG 索引完整

- 导入成功后必须索引 `raw_text` 的 scenario chunk。
- NPC chunk 必须能被当前剧本房间检索命中。
- 搜索不能跨剧本命中其他模组的 NPC、真相或线索。

### P0-4 防剧透索引可靠

- truth summary 必须进入 `spoiler_sensitive_items`。
- 隐藏线索必须进入敏感索引。
- 玩家输出命中未解锁敏感项时，由 Safety/Projection 拦截。

### P0-5 质量报告可用于决策

- `blocked` 剧本不能出现在 Host 可开房列表。
- `highRisk` 剧本可以给 Admin 调试，但 Host 普通开房应提示风险。
- 质量报告不能只是展示信息，必须参与可用剧本筛选。

## P1 功能

- Admin 可重建 RAG 索引和 spoiler index。
- Admin 可查看结构化字段计数、缺失项和导入来源。
- `knowledge_graph.scenes` 与地图生成所需 `scenario_assets.scenes` 统一或建立转换。
- 支持人工修正结构化结果，但先不做大型可视化编辑器。
- 支持结构化结果版本号，避免修订后无法追踪。

## P2 功能

- Markdown/JSON/XLSX 模组导入。
- 世界书实体编辑器：地点、NPC、线索、结局、触发器。
- 发布前校验：缺少关键字段时禁止发布到社区。
- 多房间复用同一模组模板。

## 不属于本模块

- 玩家已发现线索归属：归 `Clue`。
- 房间运行态事实：归 `State`。
- AI 裁决和骰子：归 `AI-Keeper`、`Rule`。
- 玩家可见过滤：归 `Projection`、`Safety`。
- 素材二进制上传：归 `Asset`。
- 完整模组编辑器 UI：归 `Module`。

## 当前最高风险

| 风险 | 等级 | 说明 | 处理方向 |
| --- | --- | --- | --- |
| raw_text 未在导入时进入 RAG | 高 | 导入返回 `chunks` 数量，但未调用 `index_scenario` | P0 修复 |
| NPC chunk 房间搜索可能不可见 | 高 | `search(room_id)` 只放行 scenario/rule/room chunk，不含 npc | P0 修复 |
| 提示词和 fallback 文案乱码 | 高 | 影响 AI 结构化质量，也影响测试可读性 | P0 修复 |
| quality_report 不阻断开房 | 中 | blocked 剧本仍可能被列为 available | P0/P1 修复 |
| `scenario_assets` 命名冲突 | 中 | 表名和 JSON 字段同名但语义不同 | P1 梳理 |
| 扫描 PDF 只有状态无后续流程 | 中 | OCR 后续未实现 | P2 规划 |
