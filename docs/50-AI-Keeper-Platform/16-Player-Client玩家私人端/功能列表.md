# Player Client 玩家私人端 功能列表 V2.1

## 当前阶段说明

- 本文档当前阶段为：`P0 主链路 + 玩家私人端可用性与恢复安全风险识别版`。
- 本轮只锁定玩家私人端主链路：`加入房间 -> 绑定角色 -> Lobby ready -> 开局跳转 -> 提交行动 -> 接收授权结果 -> 刷新/断线恢复`。
- 本轮不把 Player Client 写成规则层、状态写入层或真相持有层；AI、State、Transaction、Projection 的权威行为分别引用对应模块文档。
- 文档已识别当前代码中的主要风险：中文乱码、`player_token` 本地存储暴露、WS query token、前端缺少完整 `stateVersion` 屏障、断线恢复补发口径不稳、`clue_id/id` 字段兼容、匿名地图视图风险。

## 模块定位

Player Client 是玩家在团内的私人调查终端，不是聊天窗，也不是规则引擎。

它负责：

- 加入房间、绑定角色、恢复玩家会话。
- 在 Lobby 查看成员、切换 ready、发送队内消息。
- 在行动页提交 `intent`，等待事务与裁决结果。
- 查看服务端授权后的角色、背包、线索、日志、地图视图。
- 在刷新、弱网、断线后恢复到服务端认可的状态。

它不负责：

- 直接写世界状态。
- 本地判定检定成功失败。
- 读取 Host/KP 全图或未公开真相。
- 以本地过滤替代服务端权限控制。

## 当前代码真实锚点

| 位置 | 当前职责 | 现状判断 |
| --- | --- | --- |
| `src/client/src/shared/identity.ts` | 身份槽、`localStorage`/`sessionStorage` 管理 | 适合开发态多号测试，但会把 `account_token`、`owner_token`、`player_token` 同步到本地存储，必须在文档中标成风险 |
| `src/client/src/shared/api.ts` | `authHeaders()`、`apiFetch()`、`getPlayerToken()` | 当前 `getPlayerToken()` 会在缺失时本地生成 UUID，和“Player token 必须以服务端返回为准”的产品口径冲突 |
| `src/client/src/shared/ws.ts` | Player WS、自动重连、`lastSequence` | 当前使用 query token，`lastSequence` 只保存在内存，尚未形成完整恢复闭环 |
| `src/client/src/pages/PlayerJoinPage.tsx` | 登录检查、房间加入、预设卡/xlsx/builder/template 入房 | 角色来源能力已较完整，但错误提示和会话恢复口径还需要统一 |
| `src/client/src/pages/PlayerLobby.tsx` | 大厅成员、ready、队内消息、Lobby WS | 已接主链路，但 ready 乐观更新回滚和开局跳转防重仍需固化 |
| `src/client/src/pages/PlayerActionPage.tsx` | 行动输入、快捷动作、日志、地图、语音输入 | 已是核心入口，但状态机较粗，`s2c_state_patch` 仅部分消费，未形成版本屏障 |
| `src/client/src/pages/PlayerInventory.tsx` | 背包与线索视图 | 当前前端以 `id` 为主，需和后端 `clue_id` 做明确适配 |
| `src/client/src/components/VoiceInput.tsx` | 浏览器录音与 STT | 属于增强能力，必须保留文本主路径 |
| `src/server/player/router_player.py` | join、restore、intent、team-message、sync、character | 当前已提供主链路接口，且 `/character` 已按 runtime 优先生命值 |
| `src/server/player/router_reconnect.py` | reconnect、action status | 已返回 `pending_actions` 和 `stateVersion`，但 snapshot 路径当前存在事件补发收口风险 |
| `src/server/player/router_clues.py` | 玩家线索列表与分享 | 后端已以 `clue_id` 为权威主键，前端必须跟随 |
| `src/server/player/router_player_archive.py` | 玩家日志查询 | 应统一复用 Projection 可见性 helper，不允许另写一套反向过滤 |
| `src/server/router_map.py` | 玩家地图视图和移动 | 移动是 intent 方向；匿名或弱鉴权地图视图必须列为安全验收项 |

## 数据分层

| 层级 | 对象 | 用途 | 禁止混用 |
| --- | --- | --- | --- |
| L0 `AccountSession` | `account_token`、账号摘要 | 登录、恢复本人角色 | 不等于房间内角色身份 |
| L1 `PlayerRoomSession` | `player_token`、`room_id`、`character_id` | 房间内玩家会话 | 不能由前端自造 |
| L2 `IdentitySlot` | 本地身份槽 | 开发态多号切换 | 不是生产安全会话方案 |
| L3 `PlayerIntentDraft` | 输入草稿、语音转写、快捷动作参数 | 待提交意图 | 不等于已入队 action |
| L4 `ActionViewState` | `idle/submitting/queued/batched/resolving/resolved/rejected/timeout` | UI 行动状态 | 不决定事务真实状态 |
| L5 `PlayerEventStream` | Player WS 事件流 | 实时消费授权事件 | 不包含 Host-only 或他人私密事件 |
| L6 `StateSyncModel` | `stateVersion`、patch buffer、snapshot | 版本屏障与恢复 | 不能本地自增版本 |
| L7 `PlayerResourceView` | character/inventory/clues/archive/map | 玩家授权资源视图 | 不能前端自行公开私密内容 |
| L8 `LocalDisplayCache` | 本地消息与列表缓存 | 体验优化 | 不是 Journal 审计来源 |
| L9 `ErrorRecoveryState` | 401/403/404/409/429/500 恢复动作 | 错误恢复 | 不能吞掉权限错误 |
| L10 `EnhancementInput` | VoiceInput、战术按钮 | 体验增强输入 | 不阻断文本主链路 |

## 核心 DTO 契约

| DTO | 作用 | 最低要求 |
| --- | --- | --- |
| `PlayerJoinRequestDTO` | 玩家入房请求 | roomCode、displayName、单一角色来源 |
| `PlayerJoinResultDTO` | 入房结果 | `playerToken`、`roomId`、`characterId`、`joinStatus` |
| `PlayerSessionDTO` | 当前房间会话 | 只描述当前房间当前角色，不扩散到其他 slot |
| `PlayerLobbySnapshotDTO` | 大厅快照 | roomStatus、scenarioTitle、成员、ready 状态 |
| `PlayerActionSubmitDTO` | 提交行动 | `actionId`、`intentType`、`declaredIntent`、params |
| `PlayerActionStatusDTO` | 行动状态查询 | actionId、status、reason、safeResult |
| `PlayerReconnectDTO` | 重连结果 | session、recentEvents、pendingActions、lastSequence、stateVersion |
| `PlayerSyncSnapshotDTO` | 状态全量同步 | character、inventory、clues、stateVersion |
| `PlayerStatePatchDTO` | 状态补丁 | `schemaVersion`、`baseStateVersion`、`stateVersion`、`actionId?` |
| `PlayerCharacterViewDTO` | 角色页视图 | runtime 当前值优先，背景与技能分层清楚 |
| `PlayerClueViewDTO` | 玩家线索视图 | 前端内部统一 `clueId`，适配后端 `clue_id` |
| `PlayerArchiveEventDTO` | 玩家日志视图 | 只包含玩家可见 `safeText/safePayload` |
| `PlayerMapViewDTO` | 玩家地图视图 | 只返回玩家当前可见区域 |
| `PlayerApiErrorDTO` | 统一错误模型 | `status/code/message/recoveryAction` |

## P0 MVP 功能

| 功能 | 当前现状 | 进入 MVP | 依赖模块 | 用户价值 | 验收口径 |
| --- | --- | --- | --- | --- | --- |
| 登录后加入房间 | 已有 `PlayerJoinPage` | 是 | Room、User | 玩家能从公开入口进入房间 | 未登录先跳 `/login`，登录后回到 `/player/join` |
| 单一角色来源入房 | 已支持 preset/xlsx/builder/template | 是 | Character、Module | 玩家可用多种来源创建调查员 | 四种来源互斥；提交后服务端创建/绑定角色 |
| 服务端权威 `player_token` | 后端已返回，前端仍有自造风险 | 是 | User | 房间身份可信 | 成功 join/restore 后必须覆盖当前房间会话；`shared/api.ts` 的本地自造 token 路径必须移除，或仅限显式 dev/mock mode |
| 本人角色恢复 | 已有 `/me/characters` 和 `restore-session` | 是 | User、Character | 刷新或换浏览器后可找回身份 | 仅允许恢复本人角色；恢复只覆盖当前 slot/当前房间 |
| Lobby 快照与成员同步 | 已有 join-info + WS snapshot | 是 | Room、Projection | 玩家知道谁已加入、是否 ready | 成员加入、离开、ready 变化后大厅刷新 |
| ready 切换 | 已有 `ready_toggle` | 是 | Room、Transaction | 配合 Host 开局 | 成功后同步快照；失败必须回滚乐观 UI |
| 队内消息 | 已有 `/team-message` 和 `s2c_team_message` | 是 | Channel、Projection | 玩家之间可短沟通 | 只进入队内频道，不触发 AI 裁决；失败撤回本地消息 |
| 开局自动跳转 | 已接主链路 | 是 | Room、Projection | 游戏开始后进入行动终端 | 房间变为 `active` 后自动跳 `/player/{roomId}`，轮询兜底不得重复跳转 |
| 自由行动与快捷动作 | 已有文本和战术按钮 | 是 | Transaction、Rule、AI-Keeper | 玩家表达行动 | 统一经 `/api/player/intent`；前端不本地结算 |
| 行动状态机 | 当前仅部分实现 | 是 | Transaction | 玩家知道行动是否已受理/结算 | 至少覆盖 `submitting/queued/batched/resolving/resolved/rejected/timeout` |
| `stateVersion` 屏障 | 代码未闭合 | 是 | State、Projection | 避免旧 patch 覆盖新状态 | 旧 patch 丢弃；未来 patch 缓冲并触发 `/api/player/sync` |
| reconnect 恢复 | 后端已回 `pending_actions` 和 `stateVersion` | 是 | Projection、State、Journal | 刷新和弱网可恢复 | 恢复当前角色、待处理 action、事件流位置与状态版本 |
| 角色当前值视图 | `/api/player/character` 已 runtime 优先 | 是 | Character、State | 玩家看到真实当前 HP/SAN/MP/Luck | 当前值优先 runtime；技能与背景不被 runtime 覆盖 |
| 背包/线索/日志/地图视图 | 已有接口 | 是 | Clue、Journal、Scene/Map、Projection | 玩家查看授权资源 | 一律以服务端过滤结果为准 |
| 统一错误模型 | 当前分散 | 是 | Frontend、User、Transaction | 失败可恢复 | 401/403/404/409/429/500 都有明确提示与恢复动作 |
| 中文可读性 | 当前多处乱码 | 是 | Frontend | 玩家能实际使用界面 | Join/Lobby/Action/Character/Inventory/Logs/Map 主要文本无乱码 |

## P1 强化功能

| 功能 | 当前现状 | 依赖模块 | 验收口径 |
| --- | --- | --- | --- |
| Token 存储分级策略 | 当前开发态本地存储较重 | User、Security | 文档和实现明确区分开发态 identity slot 与生产态安全会话 |
| WS query token 收口 | 当前直接放在 URL | User、Projection | 至少补日志脱敏；目标演进到短期握手票据或更安全方案 |
| 事件消费白名单 | 当前靠页面分支消费 | Projection | 前端只消费允许事件；未知 `s2c_*` 默认忽略并 debug 记录 |
| pending action 精细恢复 | 当前未闭合 | Transaction、Projection | reconnect 后区分 queued/batched/resolving/resolved/rejected/timeout |
| `clueId` 适配层 | 当前前端字段不统一 | Clue | 前端统一 `clueId`，share 后重新拉 `/api/player/clues` |
| 归档类型对齐 | 当前前端 `narrative` 与后端类型有偏差 | Journal | archive tab 类型与服务端枚举一致 |
| 移动端与可访问性 | 未系统收口 | Frontend | 键盘可用、焦点清晰、底部 tab 不遮挡输入 |
| 语音降级 | 已有 VoiceInput | Voice/Media | 无麦克风/STT 失败时文本输入不受影响 |

- 玩家头像、立绘和角色皮肤。
- 只读观察者/观众延迟视角。
- 跨团角色档案与长期调查员履历。

## 不属于 Player Client 的内容

| 内容 | 归属模块 | 原因 |
| --- | --- | --- |
| AI 裁决与叙事生成 | AI-Keeper | 玩家端只提交意图和消费结果 |
| 规则成功失败判定 | Rule | 玩家端不能决定检定、伤害、线索发现 |
| 世界状态权威写入 | State | HP/SAN、地图、背包、线索归属由服务端写入 |
| 事务排队与回合结算 | Transaction | 玩家端显示状态，不管理事务生命周期 |
| 最终事件过滤与防剧透 | Projection、Safety | 前端过滤不能作为安全边界 |
| Host 舞台端与完整 KP 视角 | Host Client | 玩家端不能读 Host-only 内容 |

## MVP 验收主链路

1. 玩家登录后进入 `/player/join`，输入房间码并选择唯一角色来源。
2. 服务端返回权威 `player_token`，前端进入 Lobby。
3. Lobby 能显示成员和 ready 状态；队内消息只在玩家间传播。
4. 玩家点击 ready，失败会回滚，成功后 Host 端与其他玩家都看到更新。
5. Host 开局后玩家自动进入行动终端。
6. 玩家提交自由行动或快捷动作后进入等待态，不能盲目重复提交。
7. 服务端完成事务/裁决后，玩家只接收自身可见结果和队伍公共结果。
8. 玩家查看角色、背包、线索、日志、地图时，内容全部来自授权接口。
9. 玩家刷新或断线后，通过 reconnect 恢复 `pending_actions`、`recent_events`、`stateVersion` 和当前角色状态。
10. 玩家不能通过 API、WS、archive、map、clue 或本地缓存看到他人私密内容或 Host-only 真相。
