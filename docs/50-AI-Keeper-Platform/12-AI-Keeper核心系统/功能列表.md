# AI-Keeper 核心系统功能列表 V2.0

## 模块定位

AI-Keeper 核心系统负责把玩家意图转化为“可校验建议”：机制编译、叙事生成、知识检索、剧本结构化、反剧透协作、模型降级和调用审计。它是核心链路里的 AI 建议层，不是状态写入者。

本模块必须服从 `docs/20-核心链路/AI-Keeper核心链路架构.md`：AI 可以建议叙事、检定、状态变化和线索释放，但最终规则结算由 Rule/Engine 完成，权威状态由 State 写入，玩家可见内容由 Projection/Safety 过滤，日志由 Journal 沉淀。

## 核心数据和契约

| 对象 | 归属 | 用途 | 边界 |
| --- | --- | --- | --- |
| `KpResponse` | AI Gateway | 回合裁决建议、叙事、roll request、state mutation、citation。 | mutation 只是建议，不能直接落库。 |
| `NarrativePayload` | AI Gateway | public/per-character 叙事文本。 | public 必须过 SpoilerGuard，private 必须按角色投影。 |
| `MechanicCompileResult` | Rule/AI | 把玩家自然语言意图编译成规则机制。 | 非法或不确定输出必须 fallback。 |
| `AIResponse` | legacy AIKP | 旧批处理输出。 | 后续应与 `KpResponse` 兼容或收口。 |
| `document_chunks` | RAG | 检索规则、剧本、NPC、线索、事件、角色。 | Player 查询不得跨房间或命中未授权真相。 |
| `ai_call_logs` | Admin/Ops | provider、任务、状态、耗时、fallback 链路。 | 不保存 API key 和完整敏感 prompt。 |
| `spoiler_sensitive_items` | Safety | 隐藏真相、结局、隐藏线索、隐藏 NPC 的拦截索引。 | 只服务安全过滤，不直接展示给 Player。 |
| `spoiler_audits` | Safety/Admin | 被拦截输出的审计。 | Admin/Owner 排查用，不进入公共日志。 |

## P0 MVP 功能

| 功能 | 当前状态 | 进入 MVP | 依赖模块 | 验收口径 |
| --- | --- | --- | --- | --- |
| AI 调用入口鉴权 | `/ai-turn`、`/ai-status` 需收紧 | 是 | User、Room | 未授权用户不能触发房间 AI 结算或查看 AI 状态。 |
| Provider fallback 链 | 已有 DeepSeek/MCP/local | 是 | Admin/Ops | 任一 provider 失败时自动 fallback，并写 `ai_call_logs`。 |
| 机制编译 | 已有 `MechanicCompiler` | 是 | Rule、Player Intent | DeepSeek 坏 JSON、非法枚举、超时均降级为 Python fallback。 |
| AI 建议与 Engine 执行分离 | 已有主方向 | 是 | Engine、State | AI 不直接写 HP/SAN/线索/地图，状态变化必须走 Rule/State。 |
| 叙事生成降级 | 已有 fallback narrative | 是 | Projection | AI 不可用时仍返回可读叙事，不让主链路空白。 |
| 输出侧反剧透 | 已有 `SpoilerGuard` | 是 | Safety、WorldBook | public 叙事命中未解锁敏感项时 retry 或 fallback，并写 audit。 |
| AI 调用日志 | 已有 `ai_call_logs` | 是 | Admin/Ops | 记录 task、provider、status、duration、fallback_chain、摘要。 |
| RAG 房间隔离 | 已有基础权限测试 | 是 | WorldBook、User | Player 只能检索自己所在房间授权范围，Owner/Admin 可管理索引。 |
| 剧本结构化 | `AIKP.structure_scenario` 和 Gateway 均有 | 是 | Module、WorldBook | 输出 scenes、npcs、clues、truth、endings 后必须质量校验和敏感索引。 |
| Prompt 与 fallback 文案 UTF-8 | 当前多处乱码 | 是 | DevOps | 用户可见叙事、系统 prompt、fallback 文案可读可审计。 |

## 不属于 AI-Keeper 核心系统的内容

| 内容 | 归属模块 | AI-Keeper 的接口边界 |
| --- | --- | --- |
| 掷骰数学和成功等级 | Rule | AI 只提出 roll request 或叙事，RuleExecutor 执行数学。 |
| 权威状态写入 | State | AI mutation 只是建议，StateService 唯一落库。 |
| 事务播放顺序 | Transaction、Projection | AI 不决定 Host/Player 投影时序。 |
| 玩家最终可见性 | Projection、Safety | AI 输出先审查，再按 audience 投影。 |
| 世界真相编辑 | WorldBook、Module | AI 可辅助生成草稿，确认后才入库。 |
| 运维成本和告警 | Admin/Ops | AI 记录必要指标，不在本模块做完整计费系统。 |

## MVP 验收主链路

1. Player 提交自然语言行动。
2. `MechanicCompiler` 将意图编译为机制，AI 失败时 fallback。
3. `RuleExecutor` 执行检定和规则，AI 不直接决定骰子结果。
4. `ResolutionPipeline` 生成 fallback 叙事，必要时调用 Gateway 增强叙事。
5. public 叙事进入 `SpoilerGuard`，命中敏感项时 retry 或 fallback。
6. State mutation 只由 StateService 执行并写入事件。
7. Projection 分发 Host/Player 视角，Player 不获得未授权真相。
8. `ai_call_logs` 记录 provider、task、耗时、fallback 链路和脱敏摘要。
9. 当 DeepSeek/MCP 不可用时，主链路仍能完成并给出可解释降级结果。
