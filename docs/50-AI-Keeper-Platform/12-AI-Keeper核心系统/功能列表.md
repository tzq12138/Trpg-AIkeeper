# AI-Keeper 核心系统功能列表 V2.1

## 当前阶段说明

本轮文档定位为：

- `P0 主链路 + AI 安全建议层风险识别版`
- 目标是把 AI-Keeper 固定在“统一 Gateway + 可校验建议 + Engine 权威执行 + Safety 过滤 + Journal 审计”的链路上
- 不是 AI-Keeper 的最终生产安全完成版
- 文档补齐的是边界和验收口径，不代表当前代码里的风险已经全部关闭

## 模块定位

AI-Keeper 核心系统负责把玩家意图转成“可校验建议”：

- 机制编译
- 叙事生成
- RAG 检索
- 结构化剧本辅助
- 反剧透协作
- provider fallback
- AI 调用审计

它不是权威状态写入者，也不是第二套规则引擎。

最终边界必须保持：

- Rule / RuleExecutor 负责规则结算
- State / Transaction 负责权威状态变更
- Projection / Safety 负责可见性与反剧透
- Journal 负责证据链沉淀
- AI 只能理解、建议、叙事、检索，不能把猜测直接变成事实

## AI 数据分层

| 层级 | 数据对象 | 用途 | 禁止混用 |
| --- | --- | --- | --- |
| L0 | `PlayerIntent` | 玩家自然语言与结构化动作输入 | 不等于已发生事实 |
| L1 | `AIRequestContext` | 送入 AI 的结构化上下文包 | 不能直接包含未授权 truth |
| L2 | `AIVisibleContextChunk` | 已通过 viewer 过滤的上下文块 | 不等于原始 RAG chunk |
| L3 | `RAGRawChunk` | `document_chunks` 原始检索结果 | 不可直接进 Player prompt |
| L4 | `AIRawResponse` | provider 原始输出 | 不可直接下发玩家，不可直接落权威状态 |
| L5 | `TypedAIContract` | `KpResponse` / `NarrativePayload` / `MechanicCompileResult` 等校验后结果 | 不等于权威执行结果 |
| L6 | `MechanicSuggestion` | AI 对 skill / difficulty / reason 的建议 | 不包含权威骰值、targetValue、successLevel |
| L7 | `RuleResult` | RuleExecutor 的权威规则结果 | AI 不能覆盖 |
| L8 | `AIMutationProposal` | AI 建议的状态变化 | 不可直接写入 State |
| L9 | `StatePatch` | StateService / Transaction 产出的权威状态变化 | AI 不是写入者 |
| L10 | `PublicNarrative` | 面向 party / public 的文本 | 必须经 Safety / SpoilerGuard |
| L11 | `PrivateNarrative` | 面向特定角色的私密文本 | 缺少角色归属时不得广播 |
| L12 | `AICallLog` | provider、task、状态、耗时、fallback 审计 | 不保留 raw secret / 完整 raw prompt |
| L13 | `SpoilerAudit` | 输出拦截审计 | 不进入 Player Journal / public export |
| L14 | `AgentToolCallAudit` | Agent 工具调用审计 | 不得绕过主链路 |

## DTO 分层

| DTO | 面向对象 | 最低字段 | 禁止字段 |
| --- | --- | --- | --- |
| `AIRequestContextDTO` | Gateway 输入 | `task`、`roomId`、`viewerRole`、`characterId?`、`actionId?`、`contextChunks[]` | token、API key、未过滤 raw truth |
| `AIVisibleContextChunkDTO` | 可送入 AI 的单条上下文 | `sourceType`、`sourceId`、`visibility`、`reason`、`roomId`、`scenarioId`、`characterScope`、`unlockState` | 未授权 raw chunk |
| `MechanicSuggestionDTO` | AI 机制建议 | `triggeredMechanic`、`skillName`、`difficulty`、`reason` | 权威 `roll`、`targetValue`、`successLevel` |
| `NarrativePayloadDTO` | AI 叙事输出 | `publicText`、`privateTexts`、`keeperNotes?` | 未经 Safety 的 public 文本 |
| `AIMutationProposalDTO` | AI 状态建议 | `type`、`target`、`payload`、`permission`、`sourceRefs` | SQL、JSON Patch、直接权威状态写入 |
| `AIProviderResultDTO` | provider 调用结果 | `task`、`provider`、`status`、`schemaVersion`、`outputSummary` | raw API key、完整 raw prompt |
| `AICallLogDTO` | 管理端 AI 调用日志 | `roomId`、`task`、`provider`、`status`、`durationMs`、`fallbackChain`、`inputSummary`、`outputSummary`、`errorClass?` | owner/player token、完整 hidden truth、完整 raw prompt |
| `AgentToolCallAuditDTO` | Agent 工具审计 | `toolName`、`roomId`、`characterId`、`actionId?`、`allowed`、`reason`、`sourceRefs`、`createdAt` | 绕过服务层的裸写结果 |

兼容说明：

- 当前代码里的 `NarrativePayload(public, perCharacter)` 可以保留兼容 alias
- 但文档口径必须明确它等价于 `publicText + privateTexts`
- 不能把“字段名兼容”误实现成“public / private 语义混用”

## Gateway 任务状态模型

当前代码里 `ai_call_logs.status` 仍偏粗。文档阶段先把目标状态模型写死：

- `success`
- `schema_fail`
- `provider_error`
- `timeout`
- `fallback_used`
- `local_fallback`
- `rejected_by_safety`
- `empty_response`

每次 Gateway 调用至少应记录：

- `task`
- `provider`
- `status`
- `durationMs`
- `fallbackChain`
- `schemaVersion`
- `inputSummary`
- `outputSummary`
- `errorClass`
- `roomId?`
- `actionId?`

禁止记录：

- API key
- `owner_token`
- `player_token`
- 完整 raw prompt
- 完整 hidden truth
- 未授权私密线索原文

## 不属于 AI-Keeper 核心系统的内容

| 内容 | 归属模块 | AI-Keeper 只负责什么 |
| --- | --- | --- |
| 掷骰、目标值、成功等级 | Rule | 只给机制建议，不给权威结果 |
| 权威状态写入 | State | 只给 mutation proposal |
| 事务顺序与播放时序 | Transaction、Projection | 不决定谁先看到什么 |
| 玩家最终可见内容 | Projection、Safety | 先审查，再投影 |

| 运维计费体系 | Admin/Ops | 只提供必要审计字段 |

## public / private narrative 边界

必须明确：

1. `NarrativePayloadDTO.publicText` 只允许进入 `party/public` projection。
2. `NarrativePayloadDTO.privateTexts` 必须以 `characterId` 为 key。
3. 缺少 `characterId` 的 private narrative 不得下发。
4. `publicText` 与 `privateTexts` 都要过 Safety，但审查策略可以不同。
5. 不允许把 private text 合并进 public narration。

## RAG final context filter

RAG 检索可以先召回较宽集合，但进入 AI prompt 前必须执行 `final context filter`。
这条是 `P0 安全边界`，不是体验优化，也不能后移成仅在输出侧兜底。

最小过滤维度：

- `viewer_role`
- `room_id`
- `scenario_id`
- `character_id`
- `source_type`
- `visibility`
- `unlock_state`

Admin context preview 至少应显示：

- `included / excluded`
- `sourceType`
- `visibility`
- `reason`
- `unlockState`

## Agent 审计契约

所有 Agent 写工具必须产出 `AgentToolCallAuditDTO`，至少包括：

- `toolName`
- `roomId`
- `characterId`
- `actionId?`
- `allowed`
- `reason`
- `sourceRefs`
- `createdAt`

失败调用也必须审计，成功调用必须能追到后续 Clue / State / Journal 事件。

优先级约束：

- 如果 Agent 在当前环境默认关闭，且生产中不可被任意接口触发，可把完整治理视作 P1 批次执行。
- 如果 Agent 写工具当前可被触发，尤其是 `engine_save_clue` 仍直接写库，则必须按 P0 风险处理。

## MVP 主链路验收口径

1. Player 提交自然语言行动。
2. `MechanicCompiler` 输出机制建议；失败时 Python fallback 接管。
3. `RuleExecutor` 产出权威检定结果，AI 不能覆盖骰值与成功等级。
4. `ResolutionPipeline` 先生成 fallback narrative，再在可用时调用 Gateway 增强叙事。
5. public narrative 进入 `SpoilerGuard`，命中敏感项时 retry 或 fallback。
6. AI mutation proposal 不直接写状态，只能进入 Rule / State / Clue / Map 对应链路。
7. Projection 分发 Host / Player 视角，private narrative 只到目标角色。
8. `ai_call_logs` 记录 provider、task、status、duration、fallback chain 和脱敏摘要。
9. 即使 DeepSeek / MCP 都不可用，主链路仍能完成，并返回可解释的降级结果。
