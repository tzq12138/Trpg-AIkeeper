# Character 角色卡系统功能列表

## 模块定位

Character 模块负责“玩家在房间里的调查员身份”和“角色卡数据”的入口、绑定、展示与运行态衔接。它承接 Room 的入房流程，向 Rule 提供技能与属性来源，向 State 提供 HP/SAN/MP/Luck 等可变状态的初始化基础，向 Projection 提供可公开展示的角色摘要。

本模块不承载 AI 裁决，不直接改写世界真相，不替代 Clue/Inventory 的归属系统，也不让前端本地角色卡成为规则权威。

## 当前代码锚点

| 类型 | 现状 |
|---|---|
| 数据表 | `characters`、`character_templates`、`character_profiles`、`character_runtime_state` |
| 玩家路由 | `src/server/player/router_player.py` 中的加入、预览、导入、查询、恢复会话、技能检定入口 |
| 解析与预设 | `src/server/scenario/xlsx_parser.py`、`src/server/scenario/character_presets.py` |
| 运行态 | `src/server/engine/state_service.py` 初始化和更新角色 HP/SAN/MP/Luck、状态标签、临时修正 |
| Host 展示 | `src/server/host/hud_builder.py` 优先读取 `character_runtime_state`，缺失时回退到 `xlsx_data` |
| 前端页面 | `PlayerJoinPage.tsx`、`CharacterBuilderPage.tsx`、`PlayerCharacter.tsx`、`HostLobby.tsx`、`HostStage.tsx` |
| 测试覆盖 | `test_character_join_import.py`、`test_xlsx_parser.py`、`test_player_runtime_state.py`、`test_state_service.py`、`test_player_features.py` |

## P0 功能

| 功能 | 当前代码状态 | MVP | 依赖模块 | 验收口径 | 现状风险 |
|---|---|---|---|---|---|
| 玩家角色身份绑定 | 已有 `player_token` 和 `character_id`，多数玩家接口通过 `X-Room-Token` 定位角色 | 进入 | Room、User | 无 token 返回 401，错误 token 返回 403，玩家只能读取自己的角色 | token 是核心权限凭据，日志和导出中必须脱敏 |
| 入房即建卡 | `POST /api/player/rooms/{room_id}/join-with-character` 已支持创建角色并入房 | 进入 | Room | 成功后返回 `character_id`、`player_token`、`investigator_name`、`status` | 旧 `/join` 仍会创建空白角色，需要标为兼容入口 |
| 多来源角色创建 | 支持 XLSX 上传、预设卡、剧本模板、前端建卡器、复制已有角色 | 进入 | Room、Scenario、User | 同一次请求只能选择一种来源；预设卡在同房间不能重复占用 | 复制已有角色的前端入口不完整，先按后端能力记录 |
| XLSX 预览与导入 | `preview-xlsx` 只解析不落库，`join-with-character` 和 `import-xlsx` 会写入角色 | 进入 | Rule | 解析失败不创建占位角色；预览返回姓名、职业、HP/SAN/MP/Luck、技能摘要 | 当前仅覆盖键值表和 CY20 类 COC 表，默认值可能掩盖缺字段 |
| 前端建卡器 | `CharacterBuilderPage` 生成属性、派生值、技能、背景，入房时转成 `character_data` | 进入 | Rule | 建卡完成后能在入房页预览并提交 | 页面存在历史编码乱码，需先修正文案再扩展交互 |
| 剧本模板角色 | 后端读取 `character_templates`，入房页可把模板作为快速角色来源 | 进入 | Scenario、Module | 选模板后能生成 HP/SAN/MP/Luck、技能、背景 | 模板创建和维护入口不属于本轮 Character 主线 |
| 大厅公开摘要 | `join-info` 和 `s2c_room_lobby_snapshot` 返回玩家名、调查员名、职业、状态、ready | 进入 | Room、Projection | Host 和玩家大厅只能看到公开摘要，不看到完整私密背景 | 未来新增私密字段前必须建立字段分级 |
| Ready 状态 | `ready_toggle` 更新 `characters.is_ready` 并广播大厅快照 | 进入 | Room、Engine、Projection | 玩家切换 ready 后 HostLobby 和玩家大厅同步变化 | `is_ready` 和角色状态是两条状态线，不能混用 |
| 进行中加入审批 | 活跃房间入房角色状态为 `pending_approval`，Host 可 approve/reject | 进入 | Room、Host | approve 后变 `joined`，reject 后变 `left` | 前端 HostLobby 未形成完整审批操作面板 |
| 运行态初始化 | 加入或导入后调用 `StateService.initialize_character_state` | 进入 | State | `character_runtime_state` 记录 HP/SAN/MP/Luck、状态标签和版本 | 初始化失败被吞掉为警告，需补观测和重试路径 |
| 玩家角色页 | `GET /api/player/character` 返回角色基础信息、生命值、技能、背景、ready、房间状态 | 进入 | Player Client | 玩家页能显示自己的调查员与技能列表 | 当前主要读取 `xlsx_data`，未合并运行态，HP/SAN/MP 可能滞后 |
| Host 公共状态 | Host HUD 从 `character_runtime_state` 读取生命值和状态标签 | 进入 | Host Client、State | HostStage 展示当前 HP/SAN/MP/Luck 和状态标签 | 玩家端与 Host 端数据源不完全一致 |
| 技能检定入口 | 玩家页优先提交 `skill_check` intent，失败时走 `/api/player/skill-check` 兜底 | 进入 | Rule、Transaction | 检定结果能回到玩家端；主链路进入意图队列 | 兜底接口信任前端传入 `skill_value`，只能作为临时兼容能力 |
| 账号角色恢复 | `GET /api/player/me/characters` 与 `restore-session` 允许账号找回自己的 player token | 进入 | User | 只允许恢复本账号拥有的角色 | 长期角色库和跨房复用还未成为完整产品流 |

| 角色事件日志 | 角色加入、导入、审批、ready、运行态变化需要可追溯 | 进入 | Journal、Transaction | 关键变更能在日志中按角色检索 | 当前部分事件已写入，未形成角色维度索引 |

## 关键边界

- `characters.xlsx_data` 是导入或创建时的静态角色卡快照；HP/SAN/MP/Luck 的战局变化应以 `character_runtime_state` 为准。
- 玩家可以提交意图和查看自己的角色，但不能直接写运行态。
- Host 可以审批进行中加入和查看公共战局状态，但不应获得玩家私密背景的无限视角。
- AI-Keeper 可以读取裁剪后的角色上下文，但不能直接把输出写入角色状态。
- Rule/Engine/State 是技能检定和状态变化的权威链路，前端传入数值只能作为展示或兼容参数。
