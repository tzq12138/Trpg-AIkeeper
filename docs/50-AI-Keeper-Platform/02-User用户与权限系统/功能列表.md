# User 用户与权限系统功能列表

## 模块定位

User 模块定义平台身份、房间身份、角色绑定和操作权限。它是防越权、防剧透和审计的基础。

## 功能清单

| 功能 | 优先级 | MVP | 用户价值 | 依赖 | 验收口径 |
|---|---:|---|---|---|---|
| 用户账号 | P0 | 是 | 标识真实平台用户。 | Admin/Ops | 用户可登录并拥有稳定 user id。 |
| 昵称 / 头像 | P0 | 是 | 跑团中可识别身份。 | Asset | 房间成员展示昵称和头像。 |
| 房间身份 | P0 | 是 | 同一用户在不同房间可为房主、玩家、旁观者。 | Room | 权限按 room membership 判断。 |
| KP / 房主身份 | P0 | 是 | 管理房间而不全知真相。 | Room、Projection | 房主只能执行授权操作。 |
| 玩家身份 | P0 | 是 | 提交行动和查看个人投影。 | Player Client | 玩家只能操作绑定角色。 |
| 角色绑定玩家 | P0 | 是 | 防止冒用角色。 | Character | token 与 character owner 匹配。 |
| 权限分级 | P0 | 是 | 控制看、写、删、投放内容。 | Projection、State | 未授权接口返回拒绝。 |
| 私密信息权限 | P0 | 是 | 暗线和私聊不外泄。 | Clue、Channel | 私密数据只投给授权受众。 |
| 操作审计 | P1 | 否 | 追踪谁改了什么。 | Journal、Admin/Ops | 管理操作写审计日志。 |
| 助理 KP | P1 | 否 | 多人主持或人工辅助 AI。 | Room | 助理权限可配置且受限。 |
| 临时授权 | P1 | 否 | 代骰、代管角色。 | Rule、Character | 临时授权有过期时间。 |
| 黑名单 / 踢出 | P1 | 否 | 管理恶意用户。 | Room | 被移除者无法继续订阅私密事件。 |
| 多端登录管理 | P2 | 否 | 手机和 PC 同时跑团。 | Admin/Ops | 可查看和撤销会话。 |

## 关键边界

- 前端传来的 `characterId` 不能作为安全身份，只能作为请求目标。
- 房主权限不等于传统全知 KP 权限。
- AI 读取上下文也必须受权限裁剪约束。
