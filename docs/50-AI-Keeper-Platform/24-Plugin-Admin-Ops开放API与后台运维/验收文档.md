# Plugin / Admin / Ops 开放 API 与后台运维验收文档

## 文档定位

本文件用于在收到工程师的 `回执-YYYY-MM-DD.md`、代码改动说明、测试结果之后，判断 `24-Plugin / Admin / Ops 开放 API 与后台运维` 本轮工作是否真正完成。

它只负责验收，不替代：

- `功能列表.md`
- `PRD.md`
- `DeepSeek计划.md`

默认分两层结论：

- `本轮工程验收通过`：表示本轮允许进入的控制面、安全、脱敏、MCP/Agent 治理与设计约束已经闭环；
- `生产安全完成`：表示真实第三方开放、正式 backup/restore、插件 runtime、webhook、监控告警等都已闭环。

除非证据非常完整，否则本轮默认只给 `本轮工程验收通过`，不给 `生产安全完成`。

## 本轮验收范围

本轮默认验收范围覆盖：

- `Ops-0`
- `Ops-1`
- `Ops-2`
- `Ops-3`
- `Ops-4`
- `Ops-5`
- `Ops-6`
- `Ops-7`
- `Ops-8`

但要注意：

- `Ops-7` 是设计批次，不代表本轮要实现真实 API key、plugin runtime、webhook。
- 即使 `Ops-0 ~ Ops-8` 都通过，也不代表平台已进入“可对外开放第三方集成”的生产阶段。

## 验收输入

验收前至少应拿到以下材料：

- 本模块四份基线文档：`功能列表.md`、`PRD.md`、`DeepSeek计划.md`、`验收文档.md`
- 工程师回执：`回执-YYYY-MM-DD.md`
- 本轮改动文件清单
- 实际测试命令与结果
- 如涉及前端后台页面，附 `npm run build` 结果

## 结论等级

| 结论 | 含义 |
| --- | --- |
| `本轮工程验收通过` | 控制面基线、Admin 权限、生产配置、安全脱敏、MCP/Agent 治理、migration/backup 约束与 OpenAPI 设计边界与文档口径对齐 |
| `本轮工程验收有缺口` | 主方向正确，但缺关键测试、关键证据或关键边界说明 |
| `不通过` | 出现越权、敏感泄露、生产误配置、MCP 公网裸奔、Agent 直写状态、restore 高风险无保护等硬问题 |
| `生产安全完成` | 仅在正式 API key、plugin runtime、webhook、backup/restore、监控告警、审计和开放边界全部落地并复核后才可给出 |

## 一票否决项

出现任一情况，本轮不得判通过：

- 未经再次确认，直接实现真实 API key、plugin runtime、webhook；
- 把 FastAPI `/docs` 直接当 external OpenAPI 对外开放；
- 生产模式仍允许 `CORS=*`；
- 生产模式仍允许无鉴权 MCP 以 `0.0.0.0` 暴露；
- `engine_save_clue` 或等价工具仍可 direct write 主库；
- Admin 审计里出现 `password_hash`、`owner_token`、`player_token`、JWT、API key、raw prompt、raw response、完整请求体；
- public health 泄露 secret、DSN、provider key、完整 provider error 或绝对路径；
- restore 不要求 `confirm + target DB`；
- 测试流程允许 destructive fixture 连接非 test DB；
- 工程回执没有明确说明本轮是否仍未开放真实 API key / plugin runtime / webhook。

## 不能给出“生产安全完成”的条件

以下条件未闭环前，不应给 `生产安全完成`：

- 真实 API key / plugin runtime / webhook 尚未进入实现与复核；
- 正式 backup/restore、告警与监控平台尚未完成；
- Admin 审计仍未覆盖全部高风险操作；
- production MCP 暴露策略仍未经过真实环境复核；
- Agent 受控写入策略仍停留在文档层；
- external OpenAPI 仍只有设计，没有真实 allowlist 和 scope enforcement。
