# Plugin / Admin / Ops 开放 API 与后台运维 PRD 初版

## 目标

提供可控开放能力和上线运维能力，让 AI-Keeper 能安全扩展、可观测、可恢复、可控成本。

## 范围

包含协议文档、导出、规则/角色卡/Prompt 插件接口、管理后台、AI 调用日志、限流、备份、快照、日志脱敏、权限审计和数据删除。不包含插件市场、付费套餐和完整内容审核平台。

## 角色

| 角色 | 权限 |
|---|---|
| 开发者 | 使用开放 API、Webhook 和导出格式。 |
| 管理员 | 查看监控、审计、错误和成本。 |
| 房主 | 使用导出、备份和有限恢复。 |
| Engine | 拒绝插件越权写状态。 |

## 用户故事

| 编号 | 用户故事 | 优先级 |
|---|---|---:|
| OPS-1 | 作为管理员，我能查看 AI 调用失败和成本。 | P1 |
| OPS-2 | 作为房主，我能从快照恢复房间。 | P0 |
| OPS-3 | 作为开发者，我能按文档订阅公开事件。 | P1 |
| OPS-4 | 作为系统，我能限制滥用请求。 | P1 |

## 数据边界

运维数据包括审计、AI 调用摘要、错误、成本、备份和快照。敏感字段包括 API key、token、完整 prompt、私密线索、玩家安全边界和未公开模组真相，默认脱敏或不记录。

## 接口 / 事件方向

- Admin REST：健康检查、AI 调用日志、房间监控、限流配置、快照管理。
- Developer API：导出 JSON/Markdown、Webhook 订阅、协议文档。
- Event：`admin_action_audited`、`backup_created`、`rate_limit_triggered`、`ai_cost_recorded`。

## 验收标准

- 房间快照和数据备份可恢复。
- AI 调用日志不含 key 和完整敏感 prompt。
- 限流能保护 join、AI 调用和上传。
- 插件或 Webhook 不能绕过 Engine 写状态。
