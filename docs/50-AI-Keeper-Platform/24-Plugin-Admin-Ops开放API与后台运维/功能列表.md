# Plugin / Admin / Ops 开放 API 与后台运维功能列表 V2.0

## 模块定位

本模块是 AI-Keeper 的平台控制面：Admin 负责后台管理和安全审计，Ops 负责部署、配置、健康、日志、备份和回滚，Open API 负责把内部能力以受控接口暴露给未来集成方，Plugin 负责未来第三方或内部扩展的权限、生命周期和审计。

当前仓库已经有 FastAPI 自动 OpenAPI、Admin API、AdminDashboard、RAG 管理、AI 配置和日志、KP MCP Server、`/api/health`、`dev.py`、Docker Compose、日志配置、测试数据库隔离。当前仓库没有第三方插件注册、API key、Webhook、开发者应用、插件市场、多租户、备份恢复、版本化迁移和生产监控告警。

本模块必须保护核心链路：插件、MCP、Admin、Open API 都不能绕过 Auth、Safety、State、Transaction、Projection 和 Journal。任何写状态、写线索、写素材、重建索引、导出数据、调用 AI 的能力都必须有明确权限、可见范围和审计。

## 功能边界

- Admin/Ops 不定义跑团规则，不直接替代 Room、AI、State、Transaction、Projection 的业务职责。
- Open API 不默认等于公开 API；当前接口多数是内部或登录态接口。
- Plugin 不允许直接写数据库表；所有写入必须走 Engine/State/Room/Journal 的受控服务。
- MCP 是内部 AI provider，不是第三方插件；MCP 输出仍需 schema 校验、反剧透和 Engine 验证。
- Admin 可看到敏感运营数据，但 public export、社区公开页和普通日志必须脱敏。
- Ops 配置和脚本不能使用生产默认弱密钥、全开放 CORS、无鉴权 MCP 暴露到公网。

## 现状风险

| 风险 | 影响 | V2.0 处理口径 |
| --- | --- | --- |
| CORS 全开放 | 生产跨站调用风险 | P1 收紧为环境 allowlist |
| 默认 `JWT_SECRET` | 生产 token 可伪造 | P1 强校验非开发环境 secret |
| KP MCP 默认 `0.0.0.0` 且无鉴权 | MCP 工具被外部调用 | 生产默认 localhost/内网，增加服务间凭证 |
| Admin API 权限强但审计弱 | 追责和回滚困难 | 增加 admin audit log |
| AI call summary 可能含敏感内容 | 日志泄露 prompt 或剧透 | 增加日志脱敏和摘要策略 |
| public health 过细 | 公开暴露内部组件 | health 分 public/admin 级别 |
| 无版本化 migration | schema 演进不可控 | 增加 migration_versions |
| 无备份恢复 | 数据丢失无法恢复 | 增加备份脚本、恢复演练和测试库保护 |
| Agent 写入工具未分 scope | AI 工具可绕过业务边界 | 写入工具进入插件权限治理，优先禁写或走 Engine |
| OpenAPI 自动暴露内部接口 | 开放边界不清 | 未来生成 external OpenAPI 时按 scope 过滤 |

## MVP 验收主链路

1. Admin 登录后能访问 overview、rooms、accounts、scenarios、characters。
2. Player 访问 Admin API 返回 403，未登录返回 401。
3. Admin 角色详情不泄露 `player_token`，账号列表不泄露 `password_hash`。
4. `/api/health` 能反映 DB、RAG、compiler、cache、AI 状态。
5. RAG index 只允许 admin/owner，room player 只能 search 自己房间。
6. `python dev.py --check` 能报告后端和前端状态。
7. 测试数据库 URL 不含 `test` 时拒绝运行 destructive fixture。
8. KP MCP mock 模式可启动并返回 health，但生产文档明确不得无鉴权公网暴露。
9. 插件和 Open API 仍保持设计阶段，不对第三方开放写入能力。
