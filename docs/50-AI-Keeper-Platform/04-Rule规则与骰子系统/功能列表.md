# Rule 规则与骰子系统功能列表

## 模块定位

Rule 模块负责骰子表达式、COC 检定、SAN、伤害、暗骰、规则插件和规则解释。它是 Engine 权威裁决的一部分。

## 功能清单

| 功能 | 优先级 | MVP | 用户价值 | 依赖 | 验收口径 |
|---|---:|---|---|---|---|
| 基础骰子表达式 | P0 | 是 | 支持 1d100、2d6+3 等基础投掷。 | Journal | 服务端生成结果并记录日志。 |
| 公开骰 | P0 | 是 | 建立玩家信任。 | Channel | 结果进入公共或系统频道。 |
| 暗骰 | P0 | 是 | COC 恐怖和隐藏信息需要。 | Projection | 暗骰结果只给授权受众。 |
| 私密骰 | P0 | 是 | 单独调查和暗线。 | User | 只投给相关玩家和 Engine。 |
| 技能检定 | P0 | 是 | 绑定角色卡数值。 | Character | 成功等级按规则计算。 |
| 大成功 / 大失败 | P0 | 是 | 自动识别关键结果。 | Character | 边界值有测试。 |
| 成功等级 | P0 | 是 | 普通、困难、极难。 | Character | 结果结构化返回。 |
| SAN Check | P0 | 是 | COC 核心玩法。 | State | SAN 变化由 Engine 写入。 |
| HP / MP / SAN 自动变化 | P0 | 是 | 减少手动维护。 | State | 变化写事件日志。 |
| 骰子日志 | P0 | 是 | 防争议和复盘。 | Journal | 每次投掷可追溯。 |
| 骰子防作弊 | P0 | 是 | 防止前端伪造结果。 | Engine | 前端不能提交骰子结果。 |
| 对抗检定 | P1 | 否 | 战斗、说服、潜行等。 | Character | 对抗双方结果可解释。 |
| 奖励骰 / 惩罚骰 | P1 | 否 | COC 常用。 | Character | 十位骰规则正确。 |
| 技能成长标记 | P1 | 否 | 长团成长。 | Character、Journal | 成长标记可查询。 |
| 自定义骰子命令 | P1 | 否 | 适配不同规则。 | Plugin | 命令权限和范围可控。 |
| 规则插件 | P1 | 否 | 支持 COC、DND、PF2E。 | Plugin | 插件不能绕过 Engine。 |
| 规则版本管理 | P2 | 否 | 多版本兼容。 | Module | 房间绑定规则版本。 |
| AI 判定解释 | P1 | 否 | 告诉玩家为什么检定。 | AI-Keeper | 解释不改写数学结果。 |

## 关键边界

- AI 可以建议检定，不能伪造检定结果。
- 前端不能生成权威骰子结果。
- 规则执行结果优先于叙事文本。
