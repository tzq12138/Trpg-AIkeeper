# NPC / Faction 系统功能列表

## 模块定位

NPC / Faction 模块负责把剧本中的非玩家角色、怪物、组织、阵营关系和世界外部压力变成可查询、可防剧透、可进入 AI 上下文、可在遭遇中临时参与结算的资产。

第一轮定位不是完整世界模拟器，而是服务核心链路：剧本导入识别 NPC，AI 扮演时能引用 NPC 性格和目标，玩家只看到已公开信息，隐藏 NPC 不被投到玩家侧，遭遇系统能临时放入敌对参与者。

## 当前代码锚点

| 类型 | 现状 |
|---|---|
| 剧本结构 | `scenarios.knowledge_graph.npcs` 存放结构化 NPC 列表 |
| 场景绑定 | `scenario_assets.scenes[].npcs_present`、地图节点 `npcsPresent` 记录场景出现的 NPC 名 |
| RAG | `RAGStore.index_npc_graph()` 把 NPC 写入 `document_chunks`，`source_type='npc'` |
| AI 工具 | `ToolExecutor._tool_query_npcs()` 根据当前场景查询 NPC 名、类型、定位、性格、动机 |
| 防剧透 | `SpoilerGuard` 从 `knowledge_graph.npcs[].is_hidden` 提取 `hidden_npc` 敏感项 |
| 玩家可见过滤 | `SpoilerController.filter_for_player()` 生成 `visible_npcs` |
| 遭遇系统 | `encounters`、`encounter_participants` 支持 `character_id='npc:{uuid}'` 的临时 NPC 参与者 |
| 前端 | `EncounterPanel.tsx` 支持快速创建遭遇 NPC；地图面板展示当前节点是否有 NPC |
| 测试覆盖 | `test_quality.py`、`test_spoiler.py`、`test_spoiler_guard.py`、`test_ai_kp.py`、RAG 相关测试 |

当前没有独立的 `npcs`、`npc_states`、`factions`、`faction_clocks` 主表。NPC 主要是剧本 JSON 资产、AI 上下文片段、防剧透敏感项和遭遇临时参与者。

## P0 功能

| 功能 | 当前代码状态 | MVP | 依赖模块 | 验收口径 | 现状风险 |
|---|---|---|---|---|---|
| 剧本 NPC 抽取 | PDF 导入后 `structure_scenario` 生成 `knowledge_graph.npcs` | 进入 | Module、WorldBook | 导入后能统计 NPC 数量，质量报告能识别缺 NPC | 当前 prompt 只稳定要求 name/role/description，性格、动机、隐藏状态不稳定 |
| NPC 基础档案 | 以 JSON 形式存在于 `knowledge_graph.npcs[]` | 进入 | WorldBook | 每个 NPC 至少有 name、role、description | 没有独立 ID 规范，后续引用可能只能靠名称匹配 |
| NPC 场景绑定 | `scenario_assets.scenes[].npcs_present` 和地图节点 `npcsPresent` 可记录场景 NPC | 进入 | Scene/Map | AI 查询当前场景时能拿到该场景 NPC | 若隐藏 NPC 名直接进入地图节点，玩家探索节点后可能看到剧透名 |
| AI 查询当前 NPC | Agent tool `query_npcs` 可按场景查 NPC 详情 | 进入 | AI-Keeper、Scene | AI 扮演对话时能引用 NPC role/personality/motivation | 工具依赖 `scenario_assets.scenes`，单纯 `knowledge_graph.scenes` 不一定可用 |
| NPC RAG 索引 | `index_npc_graph` 已写入 `document_chunks` | 进入 | AI-Keeper、RAG | 导入剧本后 NPC 能成为可检索知识片段 | 按房间搜索时全局 NPC chunk 可能被 room filter 排除，需补测试 |
| 隐藏 NPC 防剧透 | `SpoilerGuard.build_sensitive_index` 支持 `is_hidden` NPC | 进入 | Safety、Projection | 未公开隐藏 NPC 名或别名进入 party/player 输出时被拦截 | 结构化导入未强制标注 `is_hidden`，输入质量不足会削弱防线 |
| NPC 可见上下文 | `SpoilerController.filter_for_player` 返回 `visible_npcs` | 进入 | AI-Keeper、Safety | strict/standard/cinematic 下隐藏 NPC 可见程度符合配置 | 当前是上下文过滤，不等于玩家有独立 NPC 列表接口 |
| NPC 公开出现解锁 | `SpoilerGuard.compute_unlock_state` 从 `s2c_public_observation.payload.npcName` 聚合已公开 NPC | 进入 | Journal、Projection | 带 `npcName` 的公共事件能解锁对应隐藏 NPC | 事件 payload 约定不统一时无法解锁 |
| 遭遇临时 NPC | Host 可通过 `/api/host/{room_id}/encounter/npc` 添加 `npc:{uuid}` 参与者 | 进入 | Rule、Host Client | 快速 NPC 能进入战斗/追逐面板并参与回合 | 不是长期 NPC 档案，且名称未作为 participant 字段稳定展示 |
| 剧本质量检查 | `QualityReportGenerator` 把缺 NPC 记为 warning | 进入 | Module | 无 NPC 的剧本质量报告有明确提示 | 只检查数量，不检查 NPC 字段完整性 |

## P1 功能

| 功能 | 当前代码状态 | MVP | 依赖模块 | 验收口径 | 现状风险 |
|---|---|---|---|---|---|
| NPC schema 标准化 | 当前字段松散 | 进入 | WorldBook、Module | 规范 `npc_id/name/public_name/role/type/personality/motivation/is_hidden/public_description/secrets/location_refs/faction_refs` | 不先标准化会让 RAG、防剧透、地图和 AI 工具各写各的 |
| 玩家已知 NPC 列表 | 目前只有 AI 过滤上下文和地图节点信息 | 进入 | Player Client、Projection | 玩家能查“已见过/已公开”的 NPC 摘要 | 不能把 KP-only 细节、隐藏身份、动机直接展示 |
| Host NPC 摘要面板 | 当前 Host 可通过剧本详情、地图、遭遇间接查看 | 不进入首轮 | Host Client、WorldBook | Host 能查看 NPC 公开摘要、隐藏标记和场景引用 | Host 不是规则引擎，不直接改真相 |
| NPC 公开/私密字段分层 | SpoilerGuard 只覆盖隐藏 NPC 敏感项 | 进入 | Safety、Projection | 字段分为 public、known、host_only、ai_only、truth | 只靠 `is_hidden` 粒度太粗 |
| NPC 运行态 | 无独立运行态表 | 不进入首轮 | State、Journal | 存活、位置、警觉、态度等变更有事件来源 | 不能让 AI 直接改 NPC 状态 |
| NPC 态度与记忆 | 无独立实现，近期事件可被 AI 工具查询 | 不进入首轮 | Journal、AI-Keeper | NPC 对角色态度变化可追溯 | 未经日志沉淀的“记忆”会导致 AI 幻觉 |
| 遭遇 NPC 名称持久化 | `encounter_participants` 有 notes、武器、技能，但没有 name 字段 | 进入 | Rule、Host Client | 快速创建 NPC 后面板显示可读名称，事件也带名称 | 当前前端主要显示 `npc:` ID 截断值 |
| 遭遇系统测试 | 没看到独立 `test_encounters.py` | 进入 | Rule、Transaction | confirm、reject、next-round、resolve、npc 创建都有测试 | 遭遇 NPC 目前容易回归 |
| RAG NPC 房间隔离 | RAG 有鉴权测试和索引接口 | 进入 | User、AI-Keeper | A 房间不能搜到 B 房间 NPC；当前房间能搜到本剧本 NPC | source_type='npc' 与 room/scenario scope 需要统一 |

## 关键边界

- 剧本 NPC 是世界书/模组资产，不等于房间运行态。
- 遭遇 NPC 是战斗或追逐的临时参与者，不等于长期 NPC 档案。
- 隐藏 NPC 的真实身份、动机和秘密属于真相层，未公开前不能进入玩家投影。
- AI 可以建议 NPC 反应，但 NPC 状态、线索释放和世界事实必须通过 Engine/State/Journal 确认。
- Faction 第一阶段只做规划口径，不在本模块里抢 Timeline 和 WorldBook 的职责。
