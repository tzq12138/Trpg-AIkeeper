# NPC / Faction 系统验收文档

## 文档定位

本文用于在收到工程师的 `回执-YYYY-MM-DD.md` 后，判断 `06-NPC/Faction` 本轮工作是否真正完成。
06 的验收核心不是“能把 NPC 列出来”，而是“NPC 的公开信息、隐藏真相、玩家已知事实、RAG 检索、地图展示和遭遇临时参与者，是否已经按不同观众和不同事实层严格分开”。

默认分两层结论：

- `本轮工程验收通过`：表示 NPC 的 P0 主链路、可见性边界、RAG entitlement 和地图/遭遇边界已达到本轮文档要求。
- `生产安全完成`：表示 reveal 契约、字段级 visibility、同剧本跨房隔离、player-facing AI/RAG 裁剪、地图防泄露和临时 NPC 生命周期等高风险项也已经闭环。

## 验收输入

- 本模块三份基线文档
- 工程师回执：`回执-YYYY-MM-DD.md`
- 修改文件列表
- 测试命令与结果
- 如改了 Host 地图、玩家地图、遭遇面板或相关 UI，附 `npm run build` 结果

## 结论等级

| 结论 | 含义 |
|---|---|
| `本轮工程验收通过` | NPC schema、reveal、RAG、地图、玩家摘要、临时 NPC 边界与本轮文档口径一致 |
| `本轮工程验收有缺口` | 主链路基本可用，但缺关键测试、关键脱敏证据、或仍存在明显 entitlement / reveal / DTO 风险 |
| `不通过` | 出现 hidden NPC 泄露、同名误解锁、跨房间/跨剧本检索串出、匿名地图泄露、或临时 NPC 写入 Character |
| `生产安全完成` | 仅在 reveal 契约、字段级 visibility、room-scoped 派生视图、player-facing AI/RAG 裁剪和跨房隔离也全部闭环后给出 |

## 一票否决项

- `knowledge_graph.npcs[]` 仍没有稳定 `npc_id`，或 reveal / RAG / 地图 / 玩家摘要仍主要靠 `npcName` 做主键
- hidden NPC 的名字、别名、真实身份、秘密目标、阵营关系可通过 player / party 输出直接看到
- player-facing AI 或 player-facing RAG 可以读取或输出 `truth` / `ai_only` 字段
- 匿名地图或玩家地图直接返回原始 `npcsPresent`、`cluesAvailable`、完整节点描述或隐藏 NPC 真名
- 同 scenario 不同 room 共享 reveal / unlock_state / 玩家已知 NPC 结果
- `PlayerKnownNpcDTO` 直接从 `knowledge_graph.npcs` 全量扫描得出，导致未出场或未公开 NPC 提前出现
- 遭遇临时 NPC 写入 `characters`、被 Character 查询误认为玩家角色，或结束后自动升级成长期 NPC 档案

## 本轮工程验收清单

### 1. 剧本 NPC schema 与稳定主键

- `knowledge_graph.npcs[]` 能稳定兼容 `npc_id/public_name/name/role/type/public_description/description/is_hidden`
- AI 未给 `npc_id` 时，系统能生成稳定 ID
- `npc_id` 成为 reveal、RAG metadata、地图引用、玩家摘要的主键方向
- 名字只作为展示字段，而不是唯一主键
- 质量报告不只检查“有没有 NPC”，还会提示关键字段缺失

### 2. 数据分层没有混用

- 剧本 NPC 资产、场景 NPC 引用、地图 NPC 引用、RAG chunk、防剧透敏感项、玩家 DTO、Host DTO、遭遇临时 NPC 在实现中有清晰边界
- 场景中有 NPC 不等于玩家已知道该 NPC
- 地图节点绑定 NPC 不等于玩家已看到该 NPC
- RAG NPC chunk 不等于 player-facing 可见文本
- 遭遇临时 NPC 不等于长期 NPC 档案

### 3. reveal 与隐藏 NPC 契约

- hidden NPC 会进入 `spoiler_sensitive_items`
- hidden NPC 的 name / alias / identity / 关键描述片段在 public / party 输出里会被拦截或改写
- reveal 优先使用 `npcId`
- `npcName` 如仍保留，只能是兼容辅助，不得成为唯一权威解锁键
- 至少区分 `appearance_revealed / identity_revealed / secret_revealed`
- 同名 NPC 不会因为 `npcName` 文本命中被误解锁

### 4. Player-facing AI / RAG 裁剪

- `NPCContextForPlayerFacingAI` 与 `NPCContextForHostAI` 已有实际分层或等价实现
- player-facing AI 不会读取或输出 `truth` 字段
- `ai_only` 字段只允许进入内部推理上下文，不能直接进入玩家可见事实区
- player-facing RAG 不会返回 hidden / truth / 未解锁字段
- RAG metadata 至少带有 `npc_id/scenario_id/visibility/is_hidden` 或等价信息

### 5. RAG entitlement 与跨房隔离

- 当前房间能检索本剧本 NPC
- 不同 scenario 的房间不能互相检索 NPC
- 同 scenario 的基础 NPC 档案可复用，但 room-scoped reveal / unlock_state / 玩家已知事实不会跨房复用
- `room_id IS NULL` 不会被错误解释为“所有房间可读”
- hidden NPC chunk 在 player-facing 检索前仍会经过 visibility / unlock 过滤

### 6. 玩家 / Host / 地图 DTO 边界

- `PlayerKnownNpcDTO` 只来自 room-scoped reveal / 探索 / 线索派生
- `PlayerKnownNpcDTO` 不直接扫描完整 `knowledge_graph.npcs`
- 玩家 NPC 摘要不包含 `motivation/secret_goal/true_name/faction_refs/host_notes`
- Host NPC 摘要能看隐藏标记和授权字段，但不直接推进世界事实
- `known` 的语义被实现为“当前房间当前观众已解锁”，不是“全局公开”

### 7. 地图防泄露

- 匿名地图视图只返回 `MapNodePublicDTO` 或等价最小字段
- 匿名或无 token 请求不返回 `npcsPresent`
- 匿名或无 token 请求不返回 `cluesAvailable`
- 匿名或无 token 请求不返回完整节点描述
- 玩家已探索节点只返回授权 NPC 摘要，不直接吐出隐藏 NPC 真名
- Host 视图可查看完整节点、NPC、线索和隐藏标记

### 8. 遭遇临时 NPC 边界

- 快速创建 NPC 后，后续查询和广播仍能看到稳定 `displayName`
- 临时 NPC 至少能稳定到 `participantId/displayName/source/sourceNpcId/hp/dex/mov/mainSkill`
- 临时 NPC 仍使用 `npc:{uuid}` 或等价临时身份，不写入 `characters`
- 临时 NPC 不会被 Character 查询误当成玩家角色
- 遭遇结束后只保留日志/参与者记录，不自动升级成长期 NPC 档案

### 9. Faction 范围控制

- 06 只实现 NPC 与 Faction 的引用关系
- 没有在 06 中新增 `faction_clock`、资源经济、复杂社会模拟
- faction lore 仍由 WorldBook 承接
- faction clock / 行动推进仍由 Timeline / State / Transaction 承接

### 10. 端到端主链路

至少应手动或自动证明以下链路：

1. Admin 导入一个含公开 NPC 和隐藏 NPC 的剧本
2. 质量报告能提示 NPC 数量与字段问题
3. Host 创建房间
4. 玩家探索公开场景，只看到授权 NPC 摘要
5. 玩家询问 NPC，AI 输出不泄露隐藏身份
6. Host 公开某 NPC 后，玩家侧摘要发生正确更新
7. 匿名地图请求看不到 NPC/线索明细
8. Host 快速创建临时 NPC 进入遭遇并推进一轮
9. 遭遇结束后日志可查，且临时 NPC 未写入 Character 或长期 NPC 档案

## 生产安全加签条件

以下条件未关闭前，不应给 `生产安全完成`：

- reveal 仍主要依赖 `npcName`，`npcId` 还未真正成为主键
- 字段级 visibility 与全局 Projection / audience 映射仍未稳定
- `known`、`ai_only`、`truth` 的语义仍未在实现中完全分开
- 同 scenario 多房间仍可能共享 reveal / unlock / 玩家已知事实
- player-facing AI / RAG 仍存在 truth 或 hidden 字段泄露路径
- 匿名地图或玩家地图仍可能返回原始 `npcsPresent/cluesAvailable`
- 临时 NPC 的 `displayName` 仍未稳定持久化，或生命周期边界仍会误写到 Character / 长期档案
- Faction 虽未完整实现，但引用关系、事件归属和后续模块边界仍未稳定
