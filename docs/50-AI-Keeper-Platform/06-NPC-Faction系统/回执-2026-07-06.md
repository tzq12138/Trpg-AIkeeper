## 三、npc_id 生成与使用现状

### 已实现

- `structure_scenario()` 的 AI 路径：`_normalize_kg()` → `_ensure_npc_ids()` 自动补齐缺失的 npc_id
- `structure_scenario()` 的 mock 路径：`_structure_mock()` → `_ensure_npc_ids()` 自动补齐
- AI prompt 已要求生成 `npc_id`（英文 slug 格式），AI 提供的优先使用
- 自动生成规则：SHA-256(name:role) 前 8 位 hex → `npc-xxxxxxxx`

### npcId 优先使用路径

| 路径 | 状态 |
|------|------|
| SpoilerGuard itemId | ✅ 优先使用 `npc_id`，回退数组下标 |

| SpoilerUnlockState | ✅ 新增 `revealed_npc_ids`，向后兼容 `revealed_npc_names` |
| RAG metadata | ✅ 包含 `npc_id` |
| query_npcs 输出 | ✅ 包含 `npc_id` |
| 地图 NPC 引用 | ⚠️ 仍用 name 字符串对齐（npcs_present 存的是名称列表） |
