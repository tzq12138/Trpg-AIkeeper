# Voice / Media 语音与媒体系统验收文档

## 文档定位

本文档用于在收到工程师的 `回执-YYYY-MM-DD.md`、代码改动说明、测试结果之后，判断 `20-Voice-Media语音与媒体系统` 本轮工作是否真正完成。

它只负责验收，不替代：

- `功能列表.md`
- `PRD.md`
- `DeepSeek计划.md`

默认分两层结论：

- `本轮工程验收通过`：表示 Voice / Media 本轮 P0/P1 主链路已经闭环；
- `生产安全完成`：表示除了本轮范围外，长期 STT 隐私、媒体播放器、导出脱敏和运行时消费语义也已基本收口。

除非证据非常完整，否则默认只给 `本轮工程验收通过`，不直接给 `生产安全完成`。

## 验收输入

验收前至少应拿到以下材料：

- 本模块四份基线文档：`功能列表.md`、`PRD.md`、`DeepSeek计划.md`、`验收文档.md`
- 工程师回执：`回执-YYYY-MM-DD.md`
- 本轮改动文件清单
- 实际测试命令与结果
- 如涉及前端页面或 HostStage，附 `npm run build` 结果

## 结论等级

| 结论 | 含义 |
| --- | --- |
| `本轮工程验收通过` | 语音录制、STT、确认提交、氛围事件、媒体引用与 Journal 边界和文档对齐 |
| `本轮工程验收有缺口` | 主链路大体可用，但缺关键测试、关键证据或关键边界未闭环 |
| `不通过` | 出现未确认文本入链路、原始音频泄露、未授权媒体暴露、状态口径错乱、测试未过等硬问题 |
| `生产安全完成` | 仅在 STT 隐私、媒体播放、导出脱敏和一次性消费语义也收口后才能给出 |

## 一票否决项

出现任一情况，本轮不得判通过：

- `TranscriptDraft` 仍会进入 Journal、`team-message`、`Player Intent` 或 AI
- 语音提交行动仍依赖 `setState` 后立即读取旧值
- 前端仍不上传真实 `durationMs`，且回执没有明确兼容说明
- 后端仍完全信任客户端 `durationMs`，没有结合文件大小、MIME、空文件或 provider 约束校验
- STT 状态命名仍混用 `timeout` / `provider_timeout`
- STT 日志仍包含原始音频、`owner_token`、`player_token`、provider API key、未确认 transcript 或 provider 原始响应
- `s2c_atmosphere` 仍可夹带 `player-only patch`、状态 mutation、本地路径或未授权 URL
- BGM / SFX / video / image 仍可绕过 Asset 授权直接播放
- SFX 一次性消费仍会在刷新或重连后无限重复，且回执没有明确遗留说明
- 回执把“Host 氛围 schema 已完成”表述成“BGM/SFX 播放器已闭环”，但实际播放器未完成
- Journal / replay / export 仍包含原始音频、临时音频路径、provider key、未授权媒体 URL 或本地绝对路径
- 关键测试命令未提供，或测试未通过

## 本轮工程验收清单

### 1. 前端可用性与录音入口

1. `npm run build` 是否通过。
2. `VoiceInput.tsx` 中文是否无乱码。
3. `PlayerActionPage.tsx` 语音相关中文是否无乱码。
4. `HostStage.tsx` 音频相关中文是否无乱码。
5. STT disabled 时，文本输入是否仍可正常使用。
6. 麦克风权限拒绝后是否有可读提示。
7. `MediaRecorder` 是否能录制短音频。
8. 取消录音是否不会上传。
9. 上传 `FormData` 是否包含 `audio`。
10. 上传 `FormData` 是否包含真实 `durationMs`。

### 2. STT endpoint、provider 与错误口径

11. 无 `X-Room-Token` 是否返回 401。
12. 错 `X-Room-Token` 是否返回 403。
13. 非房间角色是否不能上传 STT。
14. 空音频是否返回 400。
15. 非音频 MIME 是否返回 400。
16. 不支持 MIME 是否返回 400。
17. 超大音频是否返回 413。
18. `durationMs` 超限是否返回 400。
19. `durationMs` 缺失是否被拒绝或有明确兼容说明。
20. `durationMs` 非数字是否有稳定错误。
21. 后端是否不是只信任客户端 `durationMs`。
22. 后端是否结合文件大小、MIME、空文件或 provider 限制做联合判断。
23. STT provider 默认 disabled 是否返回 503。
24. mock provider 是否返回稳定 `transcribedText`。
25. HTTP provider 是否有稳定 timeout。
26. HTTP provider 超时是否统一返回 `provider_timeout`。
27. provider 认证失败是否有稳定错误。
28. provider 返回非 JSON 是否返回 `provider_bad_response`。
29. provider 返回空文本是否有稳定处理。
30. 成功与失败路径是否都清理临时音频文件。
31. STT 状态命名是否只使用完整状态模型。
32. 前端、后端、日志里是否没有 `timeout` / `provider_timeout` 双轨并存。
33. STT 是否有短窗口速率限制或明确遗留说明。
34. 超限是否返回 429。
35. 前端是否有外部 STT 隐私提示。

### 3. Transcript 草稿、确认与行动/队伍消息链路

36. 转写结果是否进入可编辑确认卡片。
37. 未确认转写是否不会发队伍消息。
38. 未确认转写是否不会提交行动。
39. 未确认转写是否不会进入 Journal。
40. 未确认转写是否不会触发 AI。
41. 点击“发给队伍”是否调用 `/api/player/team-message`。
42. `team-message` 请求是否包含 `source=voice`。
43. `team-message` 是否产生 `s2c_team_message`。
44. `team-message` 是否不触发 Engine 裁决。
45. 点击“提交行动”是否调用 `/api/player/intent`。

## 生产安全加签条件

以下条件未关闭前，不应给 `生产安全完成`：

- STT 仍缺专项速率限制或缺少自动化测试
- `durationMs` 仍主要依赖客户端值，服务端联合校验不充分
- `Player Intent` 的语音来源审计仍缺专项自动化测试
- SFX `onceKey` 仍只有前端内存去重，跨刷新/重连语义不稳定
- HostStage 仍只有音频解锁或 visual，未形成稳定 BGM/SFX 播放器
- Journal / replay / export 的语音边界仍缺专项自动化测试
