# Voice / Media 语音与媒体系统 PRD 初版

## 目标

为玩家提供语音优先的行动输入和可选媒体沉浸能力，同时保证语音不会绕过 Engine 和隐私边界。

## 范围

首版只包含语音意图入口和文字兜底。STT、TTS、BGM、SFX、实时语音视频、录制和同步播放作为后续能力。

## 角色

| 角色 | 权限 |
|---|---|
| 玩家 | 录入语音行动或文字行动。 |
| AI KP | 接收转写文本作为意图候选。 |
| Engine | 校验并处理最终意图。 |
| 房主 | 控制公共舞台音频播放。 |

## 用户故事

| 编号 | 用户故事 | 优先级 |
|---|---|---:|
| VM-1 | 作为玩家，我能按住说话提交行动。 | P0 |
| VM-2 | 作为玩家，语音不可用时我能打字。 | P0 |
| VM-3 | 作为系统，我不会把语音绕过 Engine 处理。 | P0 |
| VM-4 | 作为房主，我能在后续播放 BGM/SFX。 | P2 |

## 数据边界

语音原始文件默认不长期保存。STT 文本进入 intent 前需要展示、确认或直接按统一意图处理。转写错误以澄清请求处理，不直接改状态。

## 接口 / 事件方向

- REST：上传短语音或提交转写文本、查询 STT 状态。
- Event：`voice_recording_started`、`voice_transcribed`、`voice_intent_submitted`、`audio_cue_triggered`。
- Player：语音和文字共用行动回执状态。

## 验收标准

- 语音、文字、按钮最终都走统一 intent。
- STT 失败有文字兜底。
- 音频功能关闭时核心链路仍可跑。
- 录制和转写有隐私提示。
