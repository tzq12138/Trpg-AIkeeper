# Voice / Media 语音与媒体系统功能列表 V2.0

## 模块定位

Voice / Media 负责 AI-Keeper 中“声音、转写、舞台氛围和多媒体播放”的运行时体验。第一轮它不是核心裁决链路的前置条件，核心链路仍以文本意图、AI 裁决、事务、状态、投影和日志为准。

本模块的近期价值是把现有语音转文字入口和 Host 氛围指令做稳：玩家可以录音转成文本，编辑确认后再发队伍频道或提交行动；Host 舞台可以接收 BGM、SFX、视觉氛围和事务音频动作，但真正的世界状态仍由 State 与 Transaction 写入。实时语音房、视频会议、直播推流和长期录音归长期平台能力，不进入第一轮核心主线。

## 核心对象

| 对象 | 含义 | 当前载体 | 归属边界 |
| --- | --- | --- | --- |
| `VoiceRecording` | 玩家浏览器录制的短音频片段 | `Blob` / `UploadFile` | Voice / Media 临时处理，不默认入库 |
| `SpeechToTextRequest` | STT 上传请求 | `/api/player/speech-to-text` | 需要 `X-Room-Token`，只服务当前玩家 |
| `Transcript` | 转写后的文本和置信度 | `transcribedText/confidence/provider` | 玩家确认前只是草稿文本 |
| `VoiceCommandIntent` | 语音产生的玩家行动文本 | `PlayerIntent.voice_command` 或普通 `dialogue` | 必须走 Player Intent 和 Engine，不直接写状态 |
| `TeamVoiceMessage` | 语音转写后发到队伍频道 | `s2c_team_message` payload `source=voice` | 属于 Channel 和 Journal，可被投影过滤 |
| `AtmosphereCommand` | 舞台氛围指令 | `bgm/sfx/visual` | Projection 发给 Host，不能改变世界事实 |
| `AudioAction` | 事务期间的音频动作 | `RevealTransaction.audioAction`、`HostHUD.audioAction` | 只影响舞台播放，如暂停或压低 BGM |
| `MediaAsset` | 可复用音频、视频、图片素材 | `scenario_assets` 表和 Asset 模块 | 由 Asset 管存储、URL、可见性和删除 |
| `RuntimePlaybackState` | Host 舞台当前播放或视觉状态 | HostStore `atmosphere` | Host Client 使用，不作为真相源 |
| `TempMedia` | STT 临时文件 | OS temp file | 请求结束后删除，不进入长期素材库 |

| 内容 | 归属模块 | 原因 |

| 玩家文字行动的裁决 | AI-Keeper、Rule、Transaction | STT 只产出文本，不能决定结果 |
| 世界状态真相写入 | State | 媒体效果不等于状态事实 |
| 线索图片和手out 可见性 | Clue、Asset、Projection | Voice / Media 只播放或展示已授权素材 |

| Host 是否允许公开某段信息 | Projection、Safety、Host Client | 媒体模块不决定剧透边界 |

## MVP 验收主链路

1. Player 进入行动页，点击语音输入并授权麦克风。
2. Player 录制一段 30 秒内音频，前端上传音频和真实时长。
3. 后端验证 `X-Room-Token`、MIME、大小和时长，使用配置的 STT provider 返回转写文本。
4. Player 在转写卡片中编辑文本，选择“发给队伍”后产生 `s2c_team_message`，选择“提交行动”后产生 Player Intent。
5. 提交行动后的文本继续进入 AI / Rule / Transaction 链路，STT 不直接写状态。
6. Projection 发出 `s2c_atmosphere` 后，HostStore 更新 BGM、SFX 或视觉状态，HostStage 收到 `atmosphere_update`。
7. Host 已解锁音频时可播放授权素材；未解锁时不报错，并给出可读提示。
8. Journal 可查到确认后的文本行动、队伍消息和氛围事件，但不保存原始语音文件。
