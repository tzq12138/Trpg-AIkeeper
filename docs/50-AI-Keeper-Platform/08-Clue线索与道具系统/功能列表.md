# Clue 线索与道具系统功能列表 V2.0

## 一句话定位

Clue 模块是玩家侧“证据链”和“可用资源”的管理层。它负责玩家已发现线索、线索分享公共版本、角色背包、追溯道具主张和目标提示；它不保存世界真相，不替代 Rule 结算，也不允许玩家直接写状态。

## 当前代码真实链路

### 线索读取链路

1. 玩家请求 `GET /api/player/clues`。
2. `router_clues._get_character` 读取 `X-Room-Token`，定位当前角色。
3. 查询 `clues` 中当前角色拥有的线索，原文返回给拥有者。
4. 查询 `clue_shares JOIN clues`，返回同房间其他角色分享的线索。
5. 分享线索返回 `public_version`，不是原始私密字段。

### 线索分享链路

1. 玩家请求 `POST /api/player/clues/{clue_id}/share`。
2. 仅允许线索拥有者分享。
3. 若 `clue_shares` 已存在同一 `clue_id`，返回 409。
4. 生成 `public_version`：当前等于原始 `text` 加分享备注。
5. 插入 `clue_shares`，并将 `clues.is_private` 更新为 `FALSE`。

### 背包链路

1. 玩家请求 `GET /api/player/inventory`。
2. 后端通过 `X-Room-Token` 定位角色。
3. 查询 `inventory` 中当前角色道具。
4. 玩家追溯道具主张走 `POST /api/player/intent` 的 `retroactive_item_claim` 分支。
5. 成功后直接插入 `inventory`，递增 `rooms.state_version`，发送 `s2c_state_patch` 和 `s2c_action_completed`。

### 目标链路

1. 玩家请求 `GET /api/player/objectives`。
2. 返回同房间 `type=team` 的团队目标。
3. 返回当前角色 `type=personal` 的个人目标。
4. 当前没有 create/update/complete 目标接口。

### AI 和归档链路

1. `agent/tools.py` 的 `_tool_query_clues` 查询当前角色自己的线索。
2. `_tool_engine_save_clue` 可直接插入 `clues`，当前未走 StateService。
3. `RAGContextBuilder` 能检索 `source_type=clue` chunk，但线索保存时未必自动进入 RAG。
4. `router_player_archive.py` 通过事件日志做玩家归档，但线索分享接口本身未写专门事件。

## 数据对象

### `clues`

- `clue_id`：线索 ID。
- `room_id`：所属房间。
- `character_id`：发现者或拥有者。
- `text`：线索原文，默认视为拥有者私密内容。
- `source`：来源，可指向 action、AI 工具、剧本节点或手工来源。
- `is_private`：是否私密。
- `discovered_at`：发现时间。

### `clue_shares`

- `share_id`：分享记录 ID。
- `clue_id`：被分享线索。
- `shared_by`：分享者角色 ID。
- `shared_at`：分享时间。
- `public_version`：队伍可见版本。

当前缺口：没有 `room_id`、没有目标范围字段、没有引用事件 ID，后续查询必须通过 `clues` join 限定房间。

### `inventory`

- `id`：道具 ID。
- `character_id`：持有人。
- `room_id`：所属房间。
- `name`、`description`、`quantity`。
- `is_secret`：是否仅持有人可见。
- `source`：来源，例如 `backstory`、`scene`、`clue_reward`。
- `acquired_at`：获得时间。

### `objectives`

- `objective_id`：目标 ID。
- `room_id`：所属房间。
- `character_id`：为空表示团队目标，不为空表示个人目标。
- `type`：`team` 或 `personal`。
- `status`：目标状态。
- `assigned_at`：分配时间。

## P0 功能

### P0-1 私密线索边界

- 拥有者可以看到 `clues.text`。
- 非拥有者只能在分享后看到 `clue_shares.public_version`。
- 未分享线索不进入队友列表、公共日志、玩家 RAG 上下文。

### P0-2 分享公共版本安全

- 分享不能默认把完整私密原文无脑公开。
- 最小实现可以先由玩家确认 `public_version`。
- 后续可让 AI 生成摘要，但必须经过 SpoilerGuard。
- public version 要可追溯到原始 clue，但队友不能通过接口反查原文。

### P0-3 线索写入收口

- AI 工具、StateService、规则裁决发现线索时，应统一生成 `clue_id`、`source`、事件记录。
- 不再让 `_tool_engine_save_clue` 直接插库后静默完成。
- 新线索应写 Journal 事件，便于归档和回放。

### P0-4 背包写入收口

- 追溯道具成功后写入 `inventory`，但应通过 StateService 或受控状态事务。
- Luck 消耗不能只改 `characters.xlsx_data`，要同步运行态或明确迁移策略。
- 道具添加、移除、消耗都应产生事件。

### P0-5 AI 上下文过滤

- AI 只能读取当前角色拥有线索、队伍已分享公共版本、已公开事件。
- 不得把未发现世界书线索或完整 truth 放进玩家请求上下文。
- `source_type=clue` RAG chunk 必须按 room 和 visibility 过滤。

## P1 功能

- 玩家 `sync` 返回 shared clues，与 `/clues` 口径一致。
- 线索分享写入 Journal：发现、分享、公共摘要、来源 action。
- clue share 支持分享备注和 public_version 分离。
- objective 增加 Host/Admin 创建和完成接口。
- 背包支持使用、消耗、转让和事件引用。
- 归档接口可按 clue_id 查询证据链。

## P2 功能

- 玩家线索板：按地点、NPC、时间、事件归类。
- 队伍线索墙：只展示公共版本。
- 线索标注：已讨论、可疑、已验证。
- 道具转让和队伍公共物资。
- AI 生成线索摘要，但玩家/Host 可确认后发布。

## 不属于本模块

- 剧本真相和未发现线索模板：归 `WorldBook`。
- 线索是否应该释放：归 `Rule`、`AI-Keeper`、`State` 协作。
- 线索投影给谁看：归 `Projection`。
- 反剧透审查：归 `Safety`。
- 长期复盘导出：归 `Journal`，Clue 只提供证据链数据。

## 当前最高风险

| 风险 | 等级 | 说明 | 处理方向 |
| --- | --- | --- | --- |
| 分享默认公开原文 | 高 | `public_version` 当前由原文加备注生成 | P0 引入确认/摘要策略 |
| StateService 分享写入缺字段 | 高 | `clue_shares.public_version` 是 NOT NULL | P0 修复 |
| AI 工具直接保存线索 | 高 | `_tool_engine_save_clue` 绕过 State/Journaling | P0 收口 |
| 追溯道具直接改 Luck | 高 | `_decrement_luck` 改 `xlsx_data`，未统一运行态 | P0/P1 收口 |
| 线索事件不足 | 中 | 分享和发现不一定写入 Journal | P1 补证据链 |
| sync 与 clues 口径不一致 | 中 | `/sync` 只返回自己 clues，不含 shared clues | P1 修正 |
| objectives 只读 | 中 | 目标创建和完成路径缺失 | P1 补接口 |
