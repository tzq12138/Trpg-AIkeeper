# Channel 聊天与信息流系统 PRD 初版

## 目标

建立可见范围明确、可追溯、可被 AI 安全消费的信息流系统，支持文字团和半语音团的日常协作。

## 范围

包含公共剧情、OOC、系统、骰子、私聊、消息引用、可见范围、基础搜索。不包含论坛广场、复杂社区 Thread、Reaction 经济和跨房间私信。

## 角色

| 角色 | 权限 |
|---|---|
| 玩家 | 在授权频道发言、引用可见消息、查看私聊。 |
| 房主 | 发布公告、固定消息、查看公共和授权后台频道。 |
| AI KP | 发送旁白、系统提示和私密反馈。 |
| Engine | 写系统消息和状态变更消息。 |

## 用户故事

| 编号 | 用户故事 | 优先级 |
|---|---|---:|
| CH-1 | 作为玩家，我能区分公共剧情和 OOC。 | P0 |
| CH-2 | 作为玩家，我能收到只属于我的私密消息。 | P0 |
| CH-3 | 作为系统，我能把骰子和状态变化写入系统频道。 | P0 |
| CH-4 | 作为长团玩家，我能搜索历史消息。 | P1 |

## 数据边界

消息属于房间和频道，带有 audience、sender、mode、sourceEventId、visibility、createdAt。OOC 和玩家猜测不得默认进入事实层。私密消息必须记录受众，搜索和摘要必须继承受众限制。

## 接口 / 事件方向

- REST：发送消息、查询频道消息、搜索、固定/取消固定。
- WS：新消息、消息更新、消息撤回、频道摘要刷新。
- Event：`channel_message_created`、`system_message_created`、`message_pinned`、`message_visibility_changed`。

## 验收标准

- 公共、私密、系统消息可区分。
- 非受众无法通过 REST 或 WS 读取私密消息。
- OOC 不被 AI 当作世界事实。
- 骰子和状态消息可追溯到权威事件。
