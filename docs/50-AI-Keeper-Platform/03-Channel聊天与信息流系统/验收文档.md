# Channel 聊天与信息流系统验收文档

## 文档定位

本文件用于在收到工程师的 `回执-YYYY-MM-DD.md` 后，判断 `03-Channel` 本轮工作是否真正完成。

Channel 的验收核心不是“消息能发出去”，而是“WS、archive、reconnect、events 查询、AI 消费都不越权、不污染事实层”。

默认分两层结论：

- `本轮工程验收通过`：表示事件流、队伍消息、查询与权限过滤达到本轮文档范围。
- `生产安全完成`：表示统一过滤 helper、语义分层、恢复与长期归档等高风险项也已关闭。

## 验收输入

- 本模块三份基线文档
- 工程师回执：`回执-YYYY-MM-DD.md`
- 修改文件列表
- 测试命令与结果
- 如改了玩家大厅、玩家终端、Host 日志 UI，附 `npm run build` 结果

## 结论等级

| 结论 | 含义 |
|---|---|
| `本轮工程验收通过` | 队伍消息、事件过滤、archive/messages、WS 基线已对上 |
| `本轮工程验收有缺口` | 基本可用，但仍缺关键过滤、关键证据或关键测试 |
| `不通过` | 出现越权事件泄漏、聊天绕过权威链路、测试未过或回执与实际不符 |
| `生产安全完成` | 仅在统一过滤口径、reconnect、语义分层等高风险项闭环后给出 |

## 一票否决项

- 玩家 B 能通过 WS / reconnect / archive / public events 拿到玩家 A 的私密事件
- `host` audience 事件进入 Player WS、Player archive 或 player-facing 查询
- team-message 可以伪造 `characterId/playerName`
- 队伍聊天能触发 State Patch、Transaction 写入或 AI 裁决
- 工程回执不提供关键测试结果

## 必备回执材料

回执至少应说明：

- 本轮完成了哪些 Channel 批次
- 改了哪些 WS、archive、reconnect、router、前端日志/大厅文件
- 关键测试结果
- 当前仍未关闭的过滤或语义缺口

## 本轮工程验收清单

### 1. 事件与消息主链路

- `s2c_team_message` 可以正常写入并广播
- 事件信封字段与前端解析字段一致
- 玩家大厅、游戏内、Host 日志都能按当前职责读到对应消息

### 2. team-message 输入边界

- 服务端负责生成 `messageId/createdAt/characterId/playerName`
- 文本会 trim
- 空文本返回 400
- 超长文本有稳定错误码
- source 有白名单限制
- 有频率限制
- player 不能继续使用 `system_import`

### 3. 玩家可见性过滤

至少要验证：

- WS catch-up 不泄露其他玩家私密事件
- `/api/player/reconnect` 不泄露其他玩家私密事件
- `/api/rooms/{room_id}/events/public` 不返回 `host` audience 事件
- `/api/player/archive?type=messages` 不泄露其他玩家私密事件

### 4. Host 边界

- Host timeline 只能 owner/admin 访问
- Host 不应借 Channel 直接读到 `scenario_truth` 或未投影私密内容
- 队伍聊天不应默认混成主舞台叙事

### 5. AI 事实层边界

- 玩家聊天默认只是玩家表达
- OOC / player_chat / system / narrative 至少在协议或上下文层有分离
- 工程回执若声称已接 AI，需要明确 AI 不会把 OOC 或闲聊直接当世界事实

## 必跑测试

至少应包含：

```powershell
pytest tests/server/test_ws_auth.py tests/server/test_archive.py tests/server/test_event_log.py tests/server/test_projection.py tests/server/test_player_intent.py tests/server/test_reconnect.py tests/server/test_channel_messages.py tests/server/test_channel_security.py -q
```

如改了玩家大厅、玩家终端或 Host 日志：

```powershell
cd src/client
npm run build
```

## 生产安全加签条件

以下条件未关闭前，不应给 `生产安全完成`：

- `reconnect` 仍存在 snapshot 全量事件回传风险
- WS / reconnect / archive / public events 仍未复用统一可见性 helper
- `characterId/character_id` 键名仍混乱，过滤只覆盖一半 payload 形态
- archive 仍停留在 `offset/limit`，没有 sequence 游标
- OOC / IC / narrative / system / dice 语义仍未稳定分层

1. 本轮覆盖了哪些 Batch
