# Channel 聊天与信息流系统功能列表

## 模块定位

Channel 模块负责房间内所有“可被人阅读的信息流”：大厅队伍聊天、游戏内战术消息、AI/KP 公开叙事、系统事件、骰子与状态提示、玩家归档日志。它不负责裁决规则、不直接写世界状态、不把聊天自动升级为世界事实。

当前代码还没有独立 `channels` 或 `messages` 表。运行态主要依赖 `events` 表、`EngineEvent` 信封、`ProjectionDispatcher`、WebSocket 和前端本地消息列表拼出信息流体验。

## 当前代码锚点

| 能力 | 当前文件 | 现状 |
|---|---|---|
| 事件信封 | `src/server/models.py` | `EngineEvent` 定义 `type/audience/visibility/payload/roomSequence`，含 `s2c_team_message`。 |
| 事件注册 | `src/server/events/events_registry.py` | 维护 `s2c_chat_stream`、`s2c_public_observation`、`s2c_private_notice`、`s2c_team_message` 等事件。 |
| 事件落库 | `src/server/events/event_log.py`、`src/server/engine/projection.py` | 写入 `events(room_id,event_type,audience,payload,issued_at)` 并返回 sequence。 |
| 队伍消息发送 | `src/server/player/router_player.py` | `POST /api/player/team-message` 校验 `X-Room-Token`，生成 `s2c_team_message`。 |
| 玩家实时通道 | `src/server/main.py`、`src/server/host/ws_manager.py` | `/ws?role=player` 支持 token、lastSequence 和断线补发。 |
| Host 实时通道 | `src/server/host/router_host.py`、`src/server/host/host_store.py` | Host 过滤私密事件，渲染叙事、公开观察和队伍消息。 |
| 大厅聊天 UI | `src/client/src/pages/PlayerLobby.tsx` | 乐观发送、WS 回声去重、本地保留最近消息。 |
| 游戏内终端 | `src/client/src/pages/PlayerActionPage.tsx` | 处理战术提示、公开观察、状态提示、队伍消息和本地行动回显。 |
| Host 日志 UI | `src/client/src/components/HostLogsPanel.tsx` | 通过 `/api/rooms/{room_id}/timeline` 查询事件时间线。 |
| 玩家归档 | `src/server/player/router_player_archive.py` | 查询线索、行动、检定、状态变更；当前未纳入队伍聊天。 |

## P0 功能

| 功能 | MVP | 当前代码 | 依赖 | 验收口径 | 现状风险 |
|---|---|---|---|---|---|
| 统一事件信封 | 是 | 已有 `EngineEvent` 与 camelCase alias | Projection、Journal | WS 帧包含 `type/roomSequence/audience/payload` | `tests/server/test_events.py` 的事件枚举仍偏旧，需要同步。 |
| 队伍聊天发送 | 是 | `POST /api/player/team-message` | User、Room、Projection | 有效玩家 token 可发送文本，返回 `messageId` | 缺少长度上限、频率限制、source 枚举校验。 |
| 队伍聊天广播 | 是 | `s2c_team_message` audience 为 `party` | WS、EventLog | Host 与玩家都能收到同一条队伍消息 | 当前是房间全队频道，没有分队和私聊。 |
| 大厅聊天体验 | 是 | `PlayerLobby.tsx` | Room、User | 发送后本地先显示，WS 回声不会重复 | 刷新页面后队伍聊天不从历史恢复。 |
| 游戏内战术信息流 | 是 | `PlayerActionPage.tsx` | AI-Keeper、Rule、Projection | 战术提示、公共叙事、系统提示能进玩家终端 | 本地消息只保留约 50 条，和持久日志不是同一数据源。 |
| Host 公共信息流 | 是 | `HostStage.tsx`、`HostStore` | Host Client、Projection | Host 能看到公开叙事、队伍消息、场景演出 | 队伍消息进入舞台叙事区，后续应区分舞台与后台消息。 |
| 事件落库与 sequence | 是 | `events` 表、`ProjectionDispatcher.emit` | Journal、Replay | 每条权威事件有递增 sequence，可按房间查询 | 直接写 events 的路径和 dispatcher 路径并存，口径需要收敛。 |
| 玩家 WS 断线补发 | 是 | `player_ws_endpoint` 用 `lastSequence` 补发事件 | User、Projection | 玩家重连后收到漏掉的事件 | 当前补发未按受众和角色过滤，是高优先级安全风险。 |
| Host 时间线查询 | 是 | `GET /api/rooms/{room_id}/timeline` | User、Journal | 房主或管理员可按类型、关键词查看事件 | Host 全量时间线应继续限制在 owner/admin。 |
| 玩家归档查询 | 是 | `GET /api/player/archive` | Journal、Projection | 玩家只能查自己可见的行动、线索、状态 | 队伍聊天没有进入 archive 类型，长团追溯不完整。 |

## P1 功能

| 功能 | MVP | 当前代码 | 依赖 | 验收口径 | 说明 |
|---|---|---|---|---|---|
| 正式频道模型 | 否 | 未建表 | Room、User | 有 `channel_id/type/audience/mode`，消息归属清晰 | 建议先逻辑建模，再决定是否从 events 派生。 |
| 公共剧情频道 | 是 | 由 `s2c_public_observation` 承担 | AI-Keeper、Projection | 玩家与 Host 都能看到公开叙事 | 不等同于玩家聊天。 |
| OOC 闲聊频道 | 否 | 未实现 | User、Safety | OOC 不进入 AI 事实上下文 | 需要明确 IC/OOC 标记和 AI 消费策略。 |
| 系统频道 | 是 | 多个 `s2c_*` 事件承担 | Rule、State、Journal | 骰子、状态、错误可追溯到事件 | 需要统一展示标签和来源事件。 |
| 骰子消息归档 | 否 | 部分在 `s2c_action_completed` payload 中 | Rule、Journal | 玩家可查检定原因、目标值、结果 | 禁止前端自造骰子结果。 |
| 队伍聊天历史 | 否 | events 已落库，缺专用查询 | Journal | 重进大厅能加载最近 N 条队伍消息 | 可先扩展 archive，再考虑 messages 表。 |
| 消息 source 标记 | 否 | `team-message` 有 `source` 字段 | Voice/Media | 文本、语音转写、系统生成可区分 | source 需要白名单和显示策略。 |
| 消息引用与来源事件 | 否 | 事件有 sequence，消息无引用字段 | Journal、Clue | 可引用可见消息或事件 | 引用目标必须继承可见范围。 |
| 搜索与过滤 | 否 | Host timeline 有关键词；玩家 archive 有关键词 | Journal、User | 玩家搜索只返回授权内容 | 不能靠前端过滤私密文本。 |
| 固定消息 | 否 | 未实现 | User、Room | Host 可固定公开规则或提示 | 固定内容不能包含未公开真相。 |

## P2 功能

| 功能 | MVP | 依赖 | 验收口径 | 说明 |
|---|---|---|---|---|
| 玩家私聊频道 | 否 | Projection、User | 只有指定角色收到和查到消息 | 应先修好玩家补发过滤。 |
| 分队频道 | 否 | Room、Scene/Map | 分头行动时小队成员可见 | 需要队伍成员关系。 |
| 线索讨论频道 | 否 | Clue、Journal | 只围绕已发现或已分享线索讨论 | 未分享线索不能被搜索泄露。 |
| 消息撤回与编辑 | 否 | Safety、Journal | 记录审计痕迹，不物理抹掉权威事件 | 适合 OOC，剧情事件不应随意改写。 |
| 未读与已读回执 | 否 | User、Client | 玩家可看到新消息提示 | 不作为核心链路阻塞项。 |
| 内容安全拦截 | 否 | Safety、Admin/Ops | 敏感词、剧透词、刷屏行为可被记录和限制 | 先做限流和日志，再做复杂审核。 |

| 功能 | MVP | 说明 |
|---|---|---|
| 跨房间私信 | 否 | 属于社区生态，不进入第一轮核心链路。 |

## 边界原则

- 聊天内容默认只是玩家表达，不自动成为世界事实。
- 玩家写入世界状态只能走 Player Intent 或受控接口，不能通过频道消息绕过 Engine。
- AI 可以参考公开叙事、行动结果和授权消息，但必须区分 OOC、玩家猜测、系统事实和 KP 裁决。
- 私密信息的保护必须在服务端完成，REST、WS、archive、replay 都要继承同一套受众过滤。
- Host 可以查看运行与审计所需信息，但普通房主不应获得完整剧本真相或未公开玩家私密反馈。
