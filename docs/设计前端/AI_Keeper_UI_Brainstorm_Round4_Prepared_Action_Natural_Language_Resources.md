# AI-Keeper UI 头脑风暴第四轮总结：预备动作自然语言、生命周期与资源结算

**日期：2026-07-21**  
**承接文档：`AI_Keeper_UI_Brainstorm_Round3_Prepared_Actions.md`**  
**本轮范围：预备动作的自然语言交互、歧义追问、确认摘要编辑、普通行动与预备动作互转、备用动作限制、单次生命周期、锁定后取消限制、动作复杂度、附带位移、工具与资源校验、内部准备阶段、资源消耗节点、分阶段资源不足、效果降级与可变投入。**

---

# 1. 本轮核心修正

第三轮已经确定了预备动作的权威结构、可观察触发、目标绑定、触发依据和时序。本轮进一步明确：

> **玩家端始终使用自然语言，不展示条件树、触发器编辑器、AND/OR 表单或资源执行脚本。结构化规则只存在于后台。**

同时，预备动作采用严格的单次生命周期：

```text
玩家确认并锁定
→ 等待触发
→ 首次有效触发后执行
或
→ 条件/执行基础失效后结束
或
→ 本轮结束时未触发而结束
```

旧预备动作一旦结束，不会自动恢复。玩家如需继续，只能在新的声明阶段重新声明。

---

# 2. 玩家端只使用自然语言描述

玩家可以直接输入：

```text
如果北侧门打开后出现一个拿着武器的人，
我就用左轮向他开枪。
```

系统应生成自然语言确认摘要：

```text
确认预备动作

当北侧门打开，并且你看见门后出现持械者时，
你会使用左轮向该持械者射击。

如果本轮没有出现这种情况，
动作不会执行，本轮主动行动仍然消耗。

[确认预备]
[修改描述]
[改为普通行动]
```

玩家不需要看到：

```text
主要事件
附加条件
AND / OR
条件树
事件类型
TargetSelector
perceptionLogic
```

这些内容只能作为服务端内部结构存在。

---

# 3. 只询问影响核心语义的歧义

系统只在歧义会改变以下内容时追问：

```text
触发时点
触发对象
执行目标
具体动作
使用的武器、物品、技能或方式
```

必须追问的例子：

```text
“门打开时开枪”
→ 门刚开始移动，还是打开到可以看见门后？

“有人靠近就攻击”
→ 靠近谁？进入什么范围才算靠近？
```

不需要追问：

```text
举枪姿势
动作修饰
语气
不影响规则的叙事细节
```

这些细节由 AI-KP 按通常语义叙述，并通过最终摘要供玩家检查。

---

# 4. 每份候选声明最多追问一次

流程：

```text
提交自然语言候选
→ 检查核心歧义
→ 无歧义：生成确认摘要
→ 有歧义：只追问一个最关键问题
→ 根据回答重新解析
→ 仍不明确：拒绝锁定
```

拒绝时：

```text
这项预备动作仍无法确定触发时机或目标，
因此不能锁定。

你可以：
· 修改完整描述
· 改为普通行动
· 取消本轮声明
```

固定规则：

- 一次只追问一个最关键歧义；
- 不把玩家带入连续问卷；
- 追问后仍不明确时，AI-KP不能自行补全；
- 候选解析失败不消耗本轮行动；
- 原始草稿完整保留。

---

# 5. 每次重新提交都重新获得一次追问机会

玩家修改描述后，新文本视为新的声明候选：

```text
旧候选解析失败
→ 玩家修改完整描述
→ 重新提交
→ 重新获得一次关键歧义追问机会
```

不限制玩家在声明锁定前的修改次数。

规则：

- 未锁定候选不占用本轮行动；
- 每次解析都以最新完整文本为准；
- 不能偷偷继承旧候选中已被删除的目标、条件或工具；
- 前一次追问结果如果仍适用，应体现在新的确认摘要中；
- 只有最终确认后才占用本轮主动行动。

---

# 6. 玩家可以直接编辑系统确认摘要

系统生成摘要后，玩家可以直接修改自然语言：

```text
原摘要：
当北侧门打开到能够看见门后，
你会用左轮射击第一个越过门槛的可见持械者。

玩家修改：
当北侧门打开到能够看见门后，
并且第一个可见人员举起武器时，
我才用左轮向他射击。
```

修改后的摘要必须作为**新的自然语言候选**重新解析：

```text
编辑确认摘要
→ 保存为新候选
→ 重新进行语义解析
→ 必要时追问一次
→ 重新生成确认摘要
→ 玩家最终确认
```

不能只修改显示文本而继续使用旧后台结构。

---

# 7. 行动类型可以自动互转

## 7.1 预备动作改成普通行动

玩家将：

```text
如果门打开，我就射击门口的人。
```

改为：

```text
我不等门打开了，现在就向门口射击。
```

系统应提示：

```text
行动类型已改变

修改后的内容不再包含未来触发条件，
将按本轮普通行动处理：

现在使用左轮向北侧门口射击。

[确认普通行动]
[继续修改]
[取消]
```

转换时必须清除：

```text
触发事件
触发阈值
触发依据
等待状态
未触发处理
预备动作排序信息
```

## 7.2 普通行动改成预备动作

玩家将：

```text
我向门口的人影射击。
```

改为：

```text
如果他越过推车，我再向他射击。
```

系统应提示：

```text
行动类型已改变

修改后的内容包含未来触发条件，
将按预备动作处理。

预备动作会占用你的本轮主动行动。
若本轮未触发，行动不会返还。

[继续确认预备动作]
[继续修改]
[取消]
```

随后重新执行完整预备动作校验。

## 7.3 类型转换的原则

- 页面标签和后台结构必须同时转换；
- 旧类型的规则校验结果不得沿用；
- 新文本中仍明确存在的目标、工具可重新解析保留；
- 新文本已经删除的内容不得偷偷继承；
- 编辑阶段不消耗行动；
- 最终确认后才锁定。

---

# 8. “否则”不能包含备用主动行动

不允许：

```text
如果人影越过推车，我就开枪；
否则我去帮助安娜。
```

它实际包含：

```text
触发时执行射击
+
未触发时执行另一项主动行动
```

这会让预备动作变成无成本保险。

系统提示：

```text
这项声明包含两个备选主动行动：

· 条件满足时射击
· 条件未触发时帮助安娜

预备动作未触发时，
本轮主动行动仍然消耗，
不能自动执行另一项主动行动。
```

允许的“否则”内容仅限不产生新机制效果的等待描述：

```text
否则继续保持瞄准，直到本轮结束。
否则本轮什么也不做。
```

不能产生：

```text
新检定
新移动
新目标
物品使用
状态修改
额外资源消耗
```

---

# 9. 预备动作是单次生命周期

本轮对“暂时失效后是否恢复”作了进一步收紧。

最终原则：

> **只要已锁定预备动作赖以成立的观察、目标、工具或执行条件中途失去，旧预备动作的监听循环就结束，不会自动恢复。**

状态：

```text
locked_waiting
→ triggered
→ resolving
→ completed
```

或：

```text
locked_waiting
→ invalidated
→ closed
```

不存在：

```text
closed → locked_waiting
```

如需继续：

```text
下一轮声明阶段
→ 玩家重新创建 PreparedActionDeclaration
```

---

# 10. 中途失效后立即关闭

例如：

```text
锁定的观察方式失效
武器被击落
目标离开锁定区域
指定入口坍塌
角色失去行动能力
执行所需的唯一对象不再存在
```

处理：

```text
等待中
→ 条件或执行基础失效
→ 立即关闭
→ 停止匹配后续事件
→ 本轮行动不返还
```

即使之后：

```text
烟雾散去
武器被捡回
目标重新进入
设备重新通电
```

旧预备动作也不会恢复。

手机：

```text
预备动作已结束

结束原因：
你已无法继续通过锁定方式观察该区域。

该预备动作不会自动恢复。
如需再次准备，请在下一轮重新声明。
```

---

# 11. 锁定后不能主动取消

一旦玩家确认并锁定：

```text
预备动作已锁定
→ 占用本轮主动行动
→ 等待触发
```

玩家不能根据后续局势主动选择：

```text
放弃射击
取消预备
换成观察
保留到更好的时机
```

否则预备动作会变成“先保留时序优势，看到局势后再决定是否执行”的免费期权。

锁定后的预备动作只能通过以下方式结束：

```text
首次有效触发并执行
触发时无法执行
成立基础中途失效
本轮结束仍未触发
```

手机不提供“取消预备”按钮。

---

# 12. 预备动作只允许一个主要动作

合法：

```text
人影越过推车时，用左轮向它射击。
```

其中：

```text
举枪
瞄准
扣动扳机
```

可以属于同一主要动作的自然过程。

不合法：

```text
射击后退到门后
射击后把钥匙交给安娜
先开门再攻击
攻击目标 A 后压制目标 B
```

系统提示：

```text
这项预备声明包含多个独立行动：

1. 向人影射击
2. 退到门后

预备动作只能包含一个主要行动。
```

预备动作不复用普通组合行动的双步骤能力。

---

# 13. 允许完成主要动作所需的附带位移

允许：

```text
从门框后探身射击
转身拉下身后的开关
伸手接住物品
原地调整姿势
侧身让出射击角度
```

前提：

```text
位移只是完成主要动作的自然组成部分
且规则包不将其视为独立移动
```

不允许获得独立战术收益：

```text
移动到另一区域
改变距离等级
进入或离开近战范围
移动到新掩体
绕到目标侧面
越过门槛
射击后撤退
攻击后追击
```

判断标准不是“走了几步”，而是：

> 位移是否独立改变了区域、距离、掩体、位置关系或战术状态。

若产生这些权威状态变化，就不是附带位移。

---

# 14. 锁定时不预留武器和资源

锁定预备动作时只记录计划：

```text
武器引用
预计弹药
预计 MP
预计物品次数
```

不进行：

```text
资源扣除
资源冻结
武器锁定
弹药预留
使用次数预占
```

触发时才：

```text
重新校验武器与资源
→ 到达实际消耗节点时扣除
→ 原子提交规则和状态
```

这样允许场景中的真实变化正常发生，例如：

```text
武器被击落
武器被夺走
武器损坏
弹药因其他规则消耗
```

但一旦这些变化破坏了预备动作成立条件，旧预备动作按单次生命周期立即关闭，不会因资源恢复而重新激活。

---

# 15. 锁定当下必须已经具备最低执行条件

虽然资源不冻结，但锁定时动作必须当前可执行。

校验：

```text
角色当前能行动
目标或选择器有效
武器、物品当前可用
最低必要资源当前充足
感知依据已建立
规则允许预备该动作
```

例如左轮弹药为 0 时，不能锁定“目标出现后开枪”。

不能依赖未来可能发生的：

```text
队友递交弹药
另一角色替你装填
角色可能捡到武器
资源可能恢复
```

因为这些尚未成为事实。

---

# 16. 工具准备是否属于主要动作，由规则包裁定

前端和 AI-KP不能仅按动词数量或叙事合理性自行合并。

例如：

| 声明 | 规则包认定 | 处理 |
|---|---|---|
| 从枪套拔出左轮并射击 | 单一攻击允许拔枪 | 允许 |
| 解除保险并射击 | 属于射击必要过程 | 允许 |
| 举起手电照射 | 单一使用动作 | 允许 |
| 从背包取出燃烧瓶并投掷 | 规则认定为同一动作 | 允许 |
| 给空枪装填后射击 | 两个独立动作 | 拒绝 |
| 跑到武器旁、拾取后射击 | 多个独立动作 | 拒绝 |

规则包版本必须随房间策略锁定，战斗中不能临时改变。

---

# 17. 必要准备检定属于预备动作内部阶段

如果规则允许“拔枪并射击”，但要求快速拔枪检定：

```text
触发成立
→ 进行快速拔枪检定
→ 提交准备结果
→ 按规则判断是否继续射击
```

仍然是一项预备动作，而不是：

```text
一次预备拔枪
+
额外一次射击
```

准备失败后不询问换动作。

手机可显示：

```text
预备动作已触发

✓ 触发条件
● 快速拔枪：正在结算
○ 射击：等待准备结果
```

准备失败后的结果由规则包定义：

```text
射击无法完成
或
带惩罚继续射击
或
其他明确规则结果
```

AI-KP不能修改规则结论，只负责叙事。

---

# 18. 资源按实际消耗节点结算

不能统一规定：

```text
预备一触发就扣全部资源
```

也不能统一规定：

```text
最终成功才扣资源
```

资源必须按规则阶段的实际节点结算：

```text
准备成本
启动成本
执行成本
结果成本
```

例如：

```text
快速拔枪失败，尚未扣动扳机
→ 不扣弹药

已经开枪但未命中
→ 扣弹药

燃烧瓶已经点燃但投掷失败
→ 道具已进入新状态，按规则处理

已经支付能力启动成本
→ 后续失败不自动退款
```

每个资源节点应有：

```text
resourceRef
amount
consumeWhen
refundPolicy
failureBehavior
```

---

# 19. 每个阶段开始前重新校验资源

预备动作可以存在多个规则阶段：

```text
准备阶段
→ 启动阶段
→ 主动作阶段
→ 结果阶段
```

每个阶段开始前重新检查该阶段需要的资源。

例如：

```text
准备阶段消耗 1 MP
→ 提交 MP -1

其他规则效果又扣除 1 MP

主效果需要 2 MP
→ 当前只剩 1 MP
→ 主效果无法执行
```

已发生的准备成本：

```text
不返还
不补偿
不回滚
```

除非规则包明确规定退款。

---

# 20. 资源不足时不自动采用弱化版本

若规则支持：

```text
完整效果：3 MP
弱化效果：1 MP
```

玩家锁定完整效果后，触发时不足 3 MP：

```text
完整效果无法执行
→ 不自动降级
→ 不询问临时改选
→ 不改变作用范围、时长或目标数量
```

弱化版本属于另一项玩家选择，不能由系统代选。

---

# 21. 玩家自由决定的资源投入量必须提前锁定

例如：

```text
投入 1—5 MP，越多越强
使用多发弹药进行压制
消耗任意 Luck 提升效果
```

预备声明必须写明具体数值：

```text
触发时消耗 3 MP
触发时使用 3 发弹药
```

不允许：

```text
视情况投入
最多投入 5 MP
有多少用多少
按危险程度决定
使用剩余全部资源
```

触发后：

```text
资源足够 → 按锁定量执行
资源不足 → 动作无法按原声明执行
```

不自动降低，也不临时询问。

---

# 22. 自动计算型资源消耗可以锁定公式与上限

本轮最后确定：

> **如果资源消耗量不是玩家临时选择，而是由规则根据触发时实际合法对象数量或客观状态自动计算，则可以在声明时锁定规则公式和最大上限。**

例如规则规定：

```text
每影响 1 个合法目标消耗 1 MP
```

玩家可以声明：

```text
如果邪教徒进入房间，
我就对进入区域的所有合法目标施法。

每个合法目标消耗 1 MP，
最多影响 3 个目标，
最大消耗 3 MP。
```

内部锁定：

```text
costFormula = 1 MP × actualLegalTargetCount
targetCap = 3
resourceCap = 3 MP
```

触发时：

```text
规则系统计算实际合法目标数量
→ 套用已锁定公式
→ 不超过锁定目标上限和资源上限
→ 校验资源
→ 执行
```

若实际有 2 个合法目标：

```text
消耗 2 MP
影响 2 个目标
```

若实际有 5 个合法目标：

```text
最多选入前 3 个符合锁定确定性顺序的目标
消耗 3 MP
```

目标选择必须仍然来自预先锁定的确定性选择规则，不能由 AI-KP挑选最危险目标。

---

# 23. 公式消耗与自由投入的区别

## 自由投入

玩家可以决定投入多少：

```text
投入 1—5 MP，投入越多越强
```

必须锁定具体数值：

```text
投入 3 MP
```

## 自动计算

规则根据客观数量确定：

```text
每个实际合法目标消耗 1 MP
```

可以锁定：

```text
公式 + 目标上限 + 资源上限
```

关键判断：

> 触发时的实际消耗是否存在玩家自由裁量。

若存在玩家自由裁量，则不能用公式逃避提前锁定具体值。

---

# 24. 自动计算型消耗的边界

允许：

```text
每个合法目标消耗 1 MP，最多 3 个目标
每米有效屏障消耗固定资源，最多建立 5 米
每个已锁定区域节点消耗固定次数，最多 2 个节点
```

不允许：

```text
根据当时危险程度决定投入
选择最值得影响的若干目标
系统判断投入多少最划算
资源够多少就使用多少
优先保留足够资源用于之后
```

这些仍然属于策略判断。

---

# 25. 公式消耗触发时资源不足

例如锁定：

```text
每个目标 1 MP
最多 3 个目标
```

触发时有 3 个合法目标，但角色只有 2 MP。

系统不能自动问玩家，也不能自动借用其他资源。

需要由规则包明确处理方式，例如：

```text
规则要求必须覆盖全部已解析目标
→ 资源不足，动作无法执行

规则允许按确定顺序处理可支付数量
→ 按锁定顺序处理前 2 个目标，消耗 2 MP

规则规定效果自动缩小
→ 按规则处理
```

前端和 AI-KP不能自行决定采用哪一种。

因此内部规则必须包含：

```text
insufficientResourcePolicy
```

# 28. 本轮明确否决的方案

```text
玩家端展示条件树或 AND/OR 编辑器
对所有模糊点持续追问
一次解析连续问多个问题
追问失败后由 AI-KP补全
只改确认摘要文字、不重新解析后台结构
行动类型改变但后台类型不变
预备未触发时执行备用主动行动
预备动作暂时失效后自动恢复
锁定后允许主动取消
一份预备动作包含多个主要动作
附带独立移动获得战术收益
锁定时冻结武器或预留资源
锁定时资源不足但赌未来补充
由 AI-KP自行判断准备步骤是否免费
准备检定失败后重新让玩家选动作
触发时一次性扣除全部预计资源
最终成功后才统一扣资源
后续阶段资源不足时返还准备成本
资源不足时自动采用弱化效果
可变投入触发时再决定
用“最多投入”让系统替玩家选择实际量
自动计算资源时由 AI-KP选择最优目标数量
```

# 29. 本轮最终决策表

| 主题 | 最终决定 |
|---|---|
| 玩家输入 | 只使用自然语言 |
| 内部结构 | 后台解析，不暴露条件编辑器 |
| 歧义追问 | 只追问影响核心语义的一项 |
| 追问次数 | 每份候选最多一次 |
| 重新提交 | 重新获得一次追问机会 |
| 确认摘要 | 允许直接编辑，但必须重新解析 |
| 行动类型 | 普通与预备可自动互转 |
| 备用动作 | 未触发时禁止另一项主动行动 |
| 生命周期 | 一次性，结束后不恢复 |
| 锁定后取消 | 不允许 |
| 动作复杂度 | 一个主要动作 |
| 附带位移 | 仅规则认定的必要组成 |
| 资源预留 | 不预留、不冻结 |
| 锁定资格 | 当前状态下必须可执行 |
| 工具准备 | 由规则包判断是否属于同一动作 |
| 准备检定 | 预备动作内部规则阶段 |
| 资源扣除 | 在实际消耗节点执行 |
| 阶段校验 | 每阶段开始前重新校验资源 |
| 已付成本 | 不自动返还 |
| 弱化版本 | 不自动降级 |
| 自由投入 | 提前锁定具体数值 |
| 规则计算投入 | 锁定公式、目标上限和资源上限 |
| 资源不足策略 | 必须来自规则包 |

# 30. 本轮最终产品表达

> **玩家只需要用自然语言说明“什么情况发生时，我准备做什么”。系统最多针对一个关键歧义进行追问，并用可编辑的自然语言摘要让玩家确认。确认后，预备动作成为一项不可取消、只在本轮有效的单次行动计划。工具、准备检定和资源成本全部按规则包分阶段结算；玩家自由决定的投入必须提前锁定，规则客观计算的投入则可以锁定公式与上限。AI-KP负责把这些确定性规则结果组织成连贯叙事，而不能替玩家恢复失效动作、选择备用行动、改变资源投入或优化目标。**
