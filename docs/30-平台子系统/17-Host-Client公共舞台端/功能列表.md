# Host Client 公共舞台端功能列表 V2.1

## 当前阶段说明

- 本文档当前阶段为：`P0 主链路 + Host 公共舞台可用性、鉴权与审计风险识别版`。
- 第一轮目标是把 Host 端定义成一个可信的“公共舞台 + 房主控制台”，承接 `开房 -> 大厅 -> 开局 -> 舞台投影 -> 日志/恢复` 主链路。
- 本轮不把 Host Client 扩成规则引擎、AI 裁决层、世界真相编辑器或完整演播软件。

## 模块定位

Host Client 是房主和管理员使用的公共舞台端，负责：

- 房主创建房间后的等待室协作；
- 开局前的剧本选择、成员观察、ready 检查、显式 `force_start`；
- 开局后的公共叙事投影、玩家 HUD、地图监管、遭遇管理；
- Host 视角日志、checkpoint、恢复、导出和审计入口。

它不负责：

- 规则判定、骰子结算、伤害计算；
- AI 生成是否可信的最终裁决；
- 直接写入世界真相或绕过 State/Transaction/Projection 落库；
- 通过前端本地过滤承担安全边界。

## 数据分层与显示边界

| 层级 | 数据对象 | 说明 |
| --- | --- | --- |
| L0 `AccountSession` | `account_token`、账号摘要 | 账号登录态，只用于创建房间和 owner/admin 身份恢复 |
| L1 `HostRoomSession` | `room_id`、`owner_token`、owner/admin 鉴权态 | Host 房间会话；是 Host REST/WS 的真实入口 |
| L2 `HostLobbyView` | 房间状态、剧本、成员、ready、pending approval | Host 大厅只读/控制视图 |
| L3 `HostHUDView` | 玩家公开状态、队列状态、引擎状态、场景图 | 由 `/api/host/{room_id}/hud` 和 HostStore 合成 |
| L4 `EngineEvent` | 标准 `s2c_*` 事件 envelope | 可审计事件流，不等于前端直接渲染协议 |
| L5 `HostFrame` | `host_state_update`、`chat_message` 等 UI frame | 仅服务 Host UI，不回写 `events` |
| L6 `RevealTransactionView` | 叙事步骤、骰子步骤、摘要文本 | Host 舞台只读展示层 |
| L7 `HostStoreStageState` | 当前舞台队列、暂停态、延迟私密事件 | 舞台播放状态，不是世界事实源 |
| L8 `HostMapFullView` | 全图、玩家位置、探索/隐藏节点 | Host-only 视图，绝不复用给 Player |
| L9 `HostOperationAudit` | force start、restore、force move、retry-turn 等操作审计 | 特权操作必须可追踪 |
| L10 `HostTimelineView` | Host 可见完整 timeline、checkpoint、恢复标记 | Host 复盘和排障使用 |
| L11 `ExportView` | `public/full` 导出结果 | 导出视图，不等于数据库原样导出 |

## 不属于 Host Client 的内容

| 内容 | 归属模块 | 原因 |
| --- | --- | --- |
| 规则判定与骰子计算 | Rule | Host 只展示结果，不计算结果 |
| AI 是否可信的最终裁决 | AI-Keeper | Host 可确认建议，但不是 AI 真相层 |
| 世界状态权威写入 | State | Host 请求必须经后端服务和审计 |
| 事务生命周期机 | Transaction | Host 只播放和 ACK，不定义事务真相 |
| 事件可见性安全过滤 | Projection、Safety | 前端本地隐藏不是安全边界 |
| 玩家私人端体验 | Player Client | Host 只看公共与主持视角 |

## MVP 验收主链路

1. Host/admin 登录并创建房间。
2. 创建成功后，当前 Host 会话获得 `owner_token`，进入 Lobby。
3. 玩家加入并 ready，Host 大厅实时看到成员和 ready 变化。
4. 普通 start 受玩家人数、剧本和 ready 条件约束。
5. Host 只有显式 `force_start` 时才能跳过检查，并写入审计。
6. 开局后房间转为 `active`，首回合和初始 checkpoint 已建立，Host 进入 Stage。
7. Stage 打开后先通过 HUD API 或 WS 初帧拿到玩家状态。
8. 玩家提交行动后，Host 只看到 reveal/public 结果，不看到 player-private patch。
9. Host 可查看全图、公开节点、强制移动角色；Player 只看到被授权地图。
10. Host 可确认或结束遭遇，并在日志中追踪特权操作。
11. Host 可创建 checkpoint、执行带 `confirm + reason` 的 restore、查看 Host timeline。
12. public/full export 均经过字段脱敏，且 public 导出不含任何 Host-only 真相。
