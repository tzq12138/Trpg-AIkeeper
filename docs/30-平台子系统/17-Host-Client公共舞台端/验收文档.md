# Host Client 公共舞台端验收文档

## 文档定位

本文档用于在收到工程师的 `回执-YYYY-MM-DD.md`、代码改动说明、测试结果之后，判断 `17-Host-Client公共舞台端` 本轮工作是否真正完成。

它只负责验收，不替代：

- `功能列表.md`
- `PRD.md`
- `DeepSeek计划.md`

默认分两层结论：

- `本轮工程验收通过`：表示 Host Client 本轮 P0/P1 主链路已经闭环；
- `生产安全完成`：表示除了本轮范围外，长期 `owner_token`、WS 握手、catch-up、占位页、导出脱敏等遗留项也已基本收口。

除非证据非常完整，否则默认只给 `本轮工程验收通过`，不直接给 `生产安全完成`。

## 验收输入

验收前至少应拿到以下材料：

- 本模块四份基线文档：`功能列表.md`、`PRD.md`、`DeepSeek计划.md`、`验收文档.md`
- 工程师回执：`回执-YYYY-MM-DD.md`
- 本轮改动文件清单
- 实际测试命令与测试结果
- 如涉及前端页面、WS 或导出，附 `npm run build` 结果

## 结论等级

| 结论 | 含义 |
| --- | --- |
| `本轮工程验收通过` | Host 主链路、鉴权、舞台投影、日志恢复、导出边界与文档对齐 |
| `本轮工程验收有缺口` | 主链路大体可用，但缺关键测试、关键证据或关键边界未闭环 |
| `不通过` | 出现越权访问、私密泄露、协议错位、导出泄露、测试未过等硬问题 |
| `生产安全完成` | 仅在 `owner_token`、WS 握手、catch-up、导出和长期遗留项也收口后才能给出 |

## 一票否决项

出现任一情况，本轮不得判通过：

- Host REST 或 Host WS 仍允许普通 `player_token` 进入
- 跨房间 `owner_token` 仍可访问 Host REST 或 Host WS
- `HostStage` 仍会显示 `s2c_state_patch`、`s2c_private_notice`、`s2c_action_completed` 的玩家私密 payload
- `retry-turn` 被实现或回执表述成“完整回合重算已完成”
- `force_start` 未要求 `reason + confirm`
- `restore` 未要求 `confirm=true + reason`
- `force_move` 未要求 `reason`
- `public export` 仍包含 `owner_token`、`player_token`、账号敏感字段、Host-only reveal、全图、隐藏真相、raw AI prompt/response、debug/admin payload
- `database` tab 仍展示会误导主持人的 mock 资料库内容
- 关键测试命令未提供，或测试未通过

## 必备回执材料

工程师回执里至少应说明：

- 本轮覆盖了哪些 `Host Batch`
- 实际修改了哪些文件
- 实际运行了哪些测试，结果是什么
- Host WS 是否真的接上了 `lastSequence`；若未接上，是否明确列为遗留项
- 当前 `owner_token` 是否仍保留在 identity slot / localStorage；若保留，是否明确为开发态遗留
- 是否对 query `ownerToken` 做了日志脱敏；是否引入短期 WS ticket
- `HostEventAdapter` 的最终入口放在哪里
- `HostFrameDTO` 是否带 `sourceEventType/sourceSequence` 或等价来源
- `database` tab 本轮是隐藏、占位还是接入真实数据
- 本轮 remaining limitations 是什么

如果回执把文档里明确标为“遗留风险/后续目标”的内容写成“已生产安全完成”，验收时应直接降级处理。

## 本轮工程验收清单

### 1. 前端可用性与构建

1. `npm run build` 是否通过。
2. `HostCreate.tsx` 中文是否无乱码。
3. `HostLobby.tsx` 中文是否无乱码。
4. `HostStage.tsx` 中文是否无乱码。
5. `HostMapPanel.tsx`、`HostLogsPanel.tsx`、`EncounterPanel.tsx` 中文是否无乱码。
6. `database` tab 是否被隐藏，或明确标注“开发中/占位”。
7. `database` tab 是否不再展示误导性的 mock 资料库内容。

### 2. Host 身份与鉴权

8. host/admin 是否可以创建房间。
9. player 创建房间是否 403。
10. 创建房间是否必须选择有效剧本。
11. 创建成功后 `owner_token` 是否只进入当前 Host 会话槽位。
12. `owner_token` 是否不进入 UI、错误提示、日志样例和 public export。
13. Host REST 是否支持 `X-Owner-Token`。
14. Host REST 是否支持 owner account `Authorization`。
15. Host REST 是否支持 admin `Authorization`。
16. 普通 `player_token` 调 Host REST 是否失败。
17. 跨房间 `owner_token` 调 Host REST 是否失败。
18. Host WS owner token 是否可连接。
19. Host WS owner account/admin 是否有测试或明确回执。
20. Host WS 无 token / 错 token / player token 是否失败。
21. query `ownerToken` 是否做了日志脱敏，或明确列为遗留风险。

### 3. Lobby 与开局

22. HostLobby 是否显示成员、ready、pending approval。
23. 普通 start 是否要求至少 1 名玩家且 ready。
24. `force_start` 是否只能通过显式按钮触发。
25. `force_start` 是否显示未 ready 玩家名单。
26. `force_start` 是否要求 `reason + confirm`。
27. `force_start` 是否写审计事件。
28. 开局后是否创建首回合和初始 checkpoint。

### 4. Stage、HUD 与协议

29. Stage 是否先通过 `/api/host/{room_id}/hud` 初始化。
30. HUD 是否从 runtime state 读取玩家 HP/SAN/status。
31. `HostEventAdapter` 是否是标准事件进入 Host UI 的单一入口。
32. `HostFrameDTO` 是否能追到 `sourceEventType/sourceSequence` 或 HUD API。
33. `HostFrameDTO` 是否不回写 `events`。
34. `s2c_reveal_transaction` 是否只作为只读演出。
35. Host 是否不能修改 reveal transaction payload。
36. `s2c_public_observation` / `s2c_team_message` 是否进入公共舞台流。
37. `s2c_map_*` 是否只触发地图面板刷新。
38. `s2c_encounter_*` 是否只触发遭遇面板刷新。
39. `HostStage` 是否不显示 `player-only s2c_state_patch`。
40. `HostStage` 是否不显示 `s2c_private_notice`。
41. `HostStage` 是否不显示 `player-only s2c_action_completed`。

### 5. ACK、catch-up 与 retry-turn

42. Host ACK 是否绑定 `transactionId`。
43. Host ACK 是否绑定 `stepId` 或 `stepIndex`。
44. Host ACK 是否绑定 `actorAccountId` 或等价审计身份。
45. Host ACK 是否不携带规则结果、骰子结果、状态 mutation。
46. `lastSequence` 是否真的被 Host WS 消费。
47. 如 `lastSequence` 未接上，是否明确说明当前靠 HUD 重拉或别的兜底方案。
48. `retry-turn` 是否仍只是 replay/step reset，不重算已完成回合。

### 6. 地图与遭遇特权操作

49. `map/full` 是否仅 owner/admin 可访问。
50. player 是否不能访问 Host full map。
51. `map reveal/hide` 是否记录 `actor/target/reason/visible`。
52. `force_move` 是否要求 `reason`。
53. `force_move` 是否校验 character 和 node 属于当前 room。
54. `force_move` 是否写事件或审计。
55. encounter confirm/reject/next/resolve/npc 是否校验 room 归属。
56. encounter reject 是否有事件或审计闭环。
57. encounter npc 是否能触发前端一致刷新。

### 7. Timeline、checkpoint 与导出

58. Host timeline 是否只允许 owner/admin。
59. checkpoint restore 是否要求 `confirm=true + reason`。
60. restore 是否写 `s2c_checkpoint_restored`。
61. Player 是否看不到 restore 原始审计 payload。
62. `public export` 是否复用 Projection public view。
63. `public export` 是否不含 `owner_token`。
64. `public export` 是否不含 `player_token`。
65. `public export` 是否不含 `account_id/email`。
66. `public export` 是否不含 Host-only reveal payload。
67. `public export` 是否不含全图节点和隐藏地图信息。
68. `public export` 是否不含 hidden truth / hidden NPC / hidden clue。
69. `public export` 是否不含 player-only patch / private notice / action completed。
70. `full export` 是否继续脱敏 token、API key、secret、raw prompt/raw response。

## 生产安全加签条件

以下条件未关闭前，不应给 `生产安全完成`：

- `owner_token` 仍长期保存在 identity slot / `localStorage`
- Host WS 仍主要依赖 query `ownerToken`
- `lastSequence` / catch-up 仍未真正接上，仅靠 HUD 重拉兜底
- `database` tab 仍是占位语义，未形成真实产品边界处理
- export 安全仍缺专项自动化测试
- Host ACK / ReleaseGate 仍缺严格字段约束或自动化测试
