# Voice / Media 语音与媒体系统功能列表 V2.1

## 当前阶段说明

- 本文档当前阶段为：`P0 主链路 + 语音转写安全、确认提交与 Host 氛围事件风险识别版`。
- 当前仓库已经有真实锚点：`VoiceInput.tsx`、`PlayerActionPage.tsx`、`router_player.py`、`stt.py`、`models.py`、`host_store.py`、`router_host.py`、`HostStage.tsx`、`events_registry.py`、`router_admin.py`、`db_adapter.py`。
- 本轮重点锁定：Player 短语音录制、STT 鉴权、MIME/大小/时长限制、临时文件清理、转写草稿确认、队伍消息/行动分流、Host 音频解锁、`s2c_atmosphere` schema、`audioAction` 枚举、Asset 受控媒体引用、Journal 不保存原始音频。
- 本轮不做实时语音房、视频会议、直播推流、长期录音存档、自动语音主持、社区音效市场。
- 文档里识别出的风险，不代表代码中已经关闭；后续必须通过工程批次和测试验收确认。

## 模块定位

Voice / Media 是“语音转文本 + Host 舞台氛围 + 媒体播放运行时体验层”。

它的职责是：

- 把玩家的短语音安全地转成“可编辑的文本草稿”；
- 让玩家确认后再把文本发到队伍频道或提交 Player Intent；
- 让 Host 舞台接收安全的 BGM、SFX、视觉氛围事件；
- 让媒体素材引用走 Asset 的 `assetId` 或受控 URL；
- 让 Journal 只记录确认后的文本与安全媒体事件，而不是原始音频。

它不负责：

- WebRTC 实时语音房；
- 视频会议、屏幕共享、直播推流；
- 语音直接裁决、直接写状态或直接写 truth；
- 原始音频长期存档；
- 社区音效市场和版权平台。

## 数据分层

| 层级 | 数据对象 | 用途 | 禁止混用 |
| --- | --- | --- | --- |
| L0 `BrowserRecording` | 浏览器 `Blob` / `MediaRecorder` 输出 | 临时录音 | 不等于已提交文本 |
| L1 `SpeechToTextRequest` | `audio + durationMs + room token` | STT 请求 | 不携带 truth / token 给外部 provider |
| L2 `TempMedia` | 临时音频文件 | provider 临时处理 | 不进入 AssetRecord / Journal |
| L3 `TranscriptDraft` | `transcribedText/confidence/provider/status` | 玩家本地草稿 | 未确认不入 Journal |
| L4 `ConfirmedTranscript` | 玩家编辑确认文本 | 队伍消息或行动输入 | 不代表已裁决 |
| L5 `TeamVoiceMessage` | `source=voice` 的 team message | Channel / Journal | 不触发 Engine |
| L6 `VoiceIntent` | 语音来源的 Player Intent | 进入 AI / Rule / Transaction | 不绕过 Player Intent |
| L7 `AtmosphereCommand` | `bgm/sfx/visual` | Host 舞台氛围命令 | 不写世界事实 |
| L8 `AudioAction` | `suspend/duck/resume/stop/play_sfx` 等 | 事务演出音频动作 | 不改变状态事实 |
| L9 `RuntimePlaybackState` | HostStore atmosphere | 舞台播放状态 | 不是 State 真相 |
| L10 `MediaAssetReference` | `assetId / assetUrl` | 媒体素材引用 | 不暴露本地路径 |
| L11 `VoiceMediaJournalView` | 确认文本与媒体事件 | 日志 / 回放 / 导出 | 不含原始音频 |

## STT 状态模型

本模块建议统一 STT 结果状态：

- `success`
- `disabled`
- `invalid_audio`
- `duration_exceeded`
- `size_exceeded`
- `unsupported_mime`
- `auth_failed`
- `rate_limited`
- `provider_timeout`
- `provider_auth_failed`
- `provider_bad_response`
- `provider_error`

前后端状态名必须统一使用上面的完整模型，禁止同时出现 `timeout` 和 `provider_timeout` 两套命名。

日志只允许记录：

- `provider`
- `status`
- `durationMs`
- `sizeBytes`
- `latencyMs`
- `errorClass`
- `roomId`
- `characterId`

禁止记录：

- 原始音频
- `owner_token` / `player_token`
- provider API key
- 未确认 transcript draft
- provider 原始响应全文

## Transcript 草稿与确认边界

### `TranscriptDraft`

- 只在当前玩家前端本地展示；
- 未确认前不进入 Journal；
- 未确认前不进入 `team-message`；
- 未确认前不进入 Player Intent；
- 未确认前不触发 AI。

### `ConfirmedTranscript`

- 玩家点击“发给队伍”或“提交行动”后才形成；
- Journal 只记录确认后的文本；
- 如果玩家编辑了转写文本，提交时以编辑后的文本为准；
- STT 只产生草稿，不能直接代表行动事实。

## 实施补充口径

1. `durationMs` 由前端真实上传，但后端只能把它当作校验提示，仍需结合文件大小、MIME、provider 限制和空文件检查共同判断；`durationMs` 缺失或非数字时，必须明确拒绝或在回执里写出兼容策略。
2. 语音来源 action 不能只停留在前端组件层；`Player Intent` 或 action metadata 需要带 `source=voice`、`inputSource=voice` 或等价审计字段。
3. `onceKey` 的消费记录位置必须在工程回执里写明，是前端内存、HostStore 运行态还是事件 cursor；如果只是前端内存去重，也要明确这是暂时能力边界。
4. `s2c_atmosphere` schema 完成，不等于 HostStage BGM/SFX 播放器完成；`audioUnlocked=true` 也不等于“媒体播放已闭环”。

## 不属于 Voice / Media 的内容

| 内容 | 归属模块 | 原因 |
| --- | --- | --- |
| 玩家文字行动的裁决 | AI-Keeper / Rule / Transaction | STT 只产出文本，不能决定结果 |
| 世界状态真相写入 | State | 媒体效果不等于状态事实 |
| 线索图片和 handout 可见性 | Clue / Asset / Projection | Voice / Media 只播放或展示已授权素材 |

| Host 是否允许公开某段信息 | Projection / Safety / Host Client | 媒体模块不决定剧透边界 |
| 社区素材版权和审核 | Community / Admin/Ops | 属于平台运营能力 |

| SFX 队列会持久保留 | `host_store.py` | P1 | 增加 `onceKey` / consumed 语义 |
| 媒体素材引用可能暴露路径 | `router_admin.py`、`HostStage.tsx` | P1 | 统一改为 `assetId` 或受控 URL |
| `audioAction` 只短暂进入 HUD | `router_host.py`、`models.py` | P1 | 固定枚举和一次性消费语义 |
| 语音来源行动审计不够硬 | `router_player.py`、`event_log.py`、`archive` | P1 | 给 `Player Intent` / action metadata 增加 `source=voice` 或等价来源字段 |
| 音效/视觉触发审计字段不统一 | `events_registry.py`、`archive` | P1 | 统一 atmosphere payload schema 和日志展示 |

## MVP 验收主链路

1. Player 进入行动页，点击语音输入并授权麦克风。
2. Player 录制一段 30 秒内音频，前端上传音频和真实时长。
3. 后端验证 `X-Room-Token`、MIME、大小和时长，使用配置的 STT provider 返回转写文本。
4. Player 在转写卡片中编辑文本，选择“发给队伍”后产生 `s2c_team_message`，选择“提交行动”后产生 Player Intent。
5. 提交行动后的文本继续进入 AI / Rule / Transaction 链路，STT 不直接写状态。
6. Projection 发出 `s2c_atmosphere` 后，HostStore 更新 BGM、SFX 或 visual 状态，HostStage 收到 `atmosphere_update`。
7. Host 已解锁音频时可播放授权素材；未解锁时不报错，并给出可读提示。
8. Journal 可查到确认后的文本行动、队伍消息和氛围事件，但不保存原始语音文件。
