## 三、P0 修复详情

### 1. `rooms.state_version` 语义收口

| 污染源 | 修复前 | 修复后 |
|--------|--------|--------|
| action 入队 (`engine.submit_intent`) | `UPDATE rooms SET state_version = state_version + 1` | **不 bump** — 队列状态不属于世界真相 |
| `ready_toggle` | 不 bump（已正确） | ✅ |
| 空 `StateChangeSet` | bump +1 | **no_op=true**，不 bump |

### 2. `apply_change()` 事务契约

| 修复前 | 修复后 |
|--------|--------|
| 进入即 `_bump_room_version()` | 先 `_read_room_version()`，计算实际变化，仅在 `has_changes=True` 时 bump |
| 返回 `{"state_version", "applied", "events"}` | 返回 `{"base_state_version", "state_version", "applied", "event_refs", "no_op"}` |
| 空变更静默推进版本 | 空变更 → `no_op=True`，不 bump，不发 patch |

### 3. `s2c_state_patch` 契约

当前已有 `s2c_state_patch` 事件，但 payload 尚未补全 `schemaVersion`。本轮已在返回值中补齐 `base_state_version`，供 Projection 组装完整 patch。

### Map 双版本策略

- 地图使用独立 `room_map_state.state_version`，不推进 `rooms.state_version`
- 地图变化通过 `s2c_map_updated`/`s2c_player_moved`/`s2c_map_revealed` 事件投影
- 事件带 `mapVersion`（来自 `room_map_state.state_version`）
- 地图属于专项服务，允许多版本并存，但需在事件中明确携带版本号
