# Clue 线索与道具系统功能列表 V2.1

## 一句话定位

Clue 模块是 AI-Keeper 的玩家证据链与资源链路层。它负责“已发现线索、线索分享公共版本、背包道具、追溯道具主张、目标提示、归档证据链、AI 可读证据过滤”；它不保存 WorldBook 真相，不负责规则裁决，不允许玩家或 AI 直接裸写状态。

## 当前阶段说明

- 本文档已可作为 `08-Clue` 模块工程执行入口，但当前阶段仍是 `P0 主链路 + 证据链安全风险识别版`。
- 文档已识别私密线索泄露、`public_version` 默认公开原文、`clues.is_private` 语义误用、StateService 分享路径缺字段、AI 工具直接插入线索、追溯道具绕过统一状态写入、`/sync` 与 `/clues` 口径不一致、Archive 事件不足、public export 走错字段、RAG/AI 读取未发现线索等风险。
- 这些风险不代表已经在代码中关闭；只有后续工程批次和测试验收通过后，边界才算真正落地。

## 当前代码真实链路

### 1. 线索读取链路

1. 玩家请求 `GET /api/player/clues`。
2. `router_clues._get_character()` 用 `X-Room-Token` 定位当前角色。
3. 第一段查询返回当前角色自己拥有的 `clues` 原文。
4. 第二段查询返回同房间其他角色分享过的 `clue_shares.public_version`。
5. 当前拥有者视图和队友视图已经分离，但都共用 `text` 字段返回，接口层还没有更明确的视图类型。

### 2. 线索分享链路

1. 玩家请求 `POST /api/player/clues/{clue_id}/share`。
2. 只允许拥有者分享。
3. 若 `clue_shares` 已存在该 `clue_id`，当前直接返回 `409`。
4. 当前 `public_version` 默认等于 `clues.text`，再拼接备注。
5. 插入 `clue_shares` 后，当前会执行 `UPDATE clues SET is_private = FALSE WHERE clue_id = %s`。
6. 这意味着当前代码把“已存在公共版本”和“原文已经公开”混进了同一个布尔字段。

### 3. 玩家同步与目标链路

1. `GET /api/player/sync` 当前只读取当前角色自己的 `inventory` 和 `clues`。
2. `/sync` 不会带上他人已分享的 `public_version`。
3. `GET /api/player/objectives` 会返回同房间 `type=team` 的目标，以及当前角色自己的 `type=personal` 目标。
4. 当前没有目标创建、完成、撤销接口。

### 4. 道具与追溯道具链路

1. 玩家通过 `POST /api/player/intent` 的 `retroactive_item_claim` 分支主张追溯道具。
2. `RetroactiveItemService.evaluate_claim()` 负责判断 `auto_pass / roll_required / forbidden`。
3. 成功后当前直接插入 `inventory`。
4. 当前直接递增 `rooms.state_version`。
5. 如果需要扣 Luck，当前直接修改 `characters.xlsx_data.luck`，不是 `character_runtime_state.luck`。
6. 然后广播 `s2c_state_patch` 和 `s2c_action_completed`。

### 5. AI、Archive 和 Export 链路

1. `_tool_query_clues()` 当前只查当前角色自己的 `clues.text`。
2. `_tool_engine_save_clue()` 当前直接 `INSERT INTO clues`，没有统一走 StateService / Journal。
3. `RAGContextBuilder` 支持 `source_type=clue`，但当前线索保存链路未保证 clue 自动进索引，也没写死 visibility 规则。
4. `archive_clues()` 当前只读 `s2c_private_notice` 和 `s2c_public_observation`，没有专门的 `s2c_clue_discovered / s2c_clue_shared` 契约。
5. `export_markdown(scope="public")` 当前按 `clues.is_private` 决定是否导出 `clues.text`，而不是导出 `clue_shares.public_version`。
6. `SpoilerGuard.compute_unlock_state()` 当前尝试按 `clue_shares.room_id` 读取分享线索，但表结构里没有 `room_id` 字段，这条路径现在并不可靠。

## 数据分层

| 层 | 来源 | 用途 | 禁止混用 |
|---|---|---|---|
| WorldBook 线索模板 | `knowledge_graph.clues[]` | 剧本里可能存在的线索定义 | 不等于玩家已发现线索 |
| 玩家私密线索 | `clues.text` | 当前角色真正拿到的原始证据 | 不给队友、不进 public export |
| 分享公共版本 | `clue_shares.public_version` | 队伍共享摘要 | 不等于原始 clue 原文 |
| 线索发现事件 | `s2c_clue_discovered` 或等价私密事件 | 归档、回放、审计 | 不直接公开原始文本给他人 |
| 线索分享事件 | `s2c_clue_shared` | 队伍证据链 | 只携带公共版本 |
| AI 线索上下文 | 裁剪后的 clue view / clue chunk | AI 推理输入 | 不含未发现 WorldBook clue |
| 玩家同步 DTO | `/api/player/sync` | 玩家当前可见状态 | 不应和 `/clues` 口径冲突 |
| Archive DTO | `/api/player/archive*` | 复盘证据链 | 非拥有者不查私密原文 |
| Inventory 当前状态 | `inventory` + 受控状态写入 | 当前角色资源 | 不由玩家或 AI 直接裸写 |
| Objective 当前状态 | `objectives` | 团队/个人目标 | `personal` 不泄露给其他玩家 |

## Visibility / Access Model

本模块区分两类“可见性”：

- 事件投影受众：`player / party / host / system`
- 数据访问级别：`self / party / host / admin / internal / never_export`

推荐口径如下：

| 对象 | 字段 | 默认访问级别 | 说明 |
|---|---|---|---|
| 玩家私密线索 | `clues.text` | `self` | 原始 clue 文本只给拥有者 |
| 线索公共分享 | `clue_shares.public_version` | `party` | 队友看到的是公共版本，不是原文 |
| 线索来源 | `clues.source` | `self + host/admin` | Host 默认看 public_version、事件摘要和进度；如需查看原始 `clues.text`，应走 Host/Admin debug 路径并记录审计 |
| 隐秘道具 | `inventory.is_secret=true` 的条目 | `self + host/admin` | 队友接口不应暴露 |
| 普通道具名/描述 | `inventory.name/description` | `self`，非 secret 可扩到 `party` | 本轮先不强制开放共享背包 |
| 团队目标 | `objectives.type=team` | `party` | 同房间玩家可见 |
| 个人目标 | `objectives.type=personal` | `self` | 其他玩家不可见 |
| WorldBook 未发现线索 | `knowledge_graph.clues[]` | `host / internal` | 不进 player-facing prompt |
| 公开导出 | public export | `party` | 只能用 `public_version`、公开事件摘要 |

## 关键语义

### 1. WorldBook clue template 不等于玩家 clue

- `knowledge_graph.clues[]` 是“剧本里可能存在的线索模板”。
- `clues` 表才是“玩家已经发现的证据”。
- 未经 Rule / Engine / State / ClueService 释放到 `clues` 表的内容，不得进入玩家证据链，不得进入 player-facing AI prompt。

### 2. `clues.is_private=false` 不等于原文公开

- 当前代码会在分享后把 `clues.is_private` 改成 `FALSE`。
- 文档口径必须明确：这最多表示“该 clue 已存在 party-visible 公共版本”。
- 队友视角永远读取 `clue_shares.public_version`，不是读取 `clues.text`。

### 3. 本轮 share 默认作用域是 `party`

- 当前 `clue_shares` 本质上是整房间共享一次。
- 本轮不扩展 `target_scope`、`target_character_id`。
- 后续若要支持私聊分享、分队分享、Host-only 分享，再扩展 share scope。

### 4. `public_version` 默认不能从原文自动生成

- 当前代码是 `public_version = clues.text + note`，这正是本轮最高风险。
- 本轮目标是：未显式确认时，不自动公开完整原文。
- 若未传 `public_version`，安全默认文案可以固定为：`玩家分享了一条线索，但未公开完整内容。`
- `share_full_text=true` 不是绕过 SpoilerGuard 的开关，显式全文分享仍要经过安全检查。

## P0 功能

### P0-1 私密线索边界

- 拥有者可以看到 `clues.text`。
- 非拥有者只能看到 `clue_shares.public_version`。
- 未分享线索不进入队友接口、不进入 public export、不进入 player-facing AI / RAG。

### P0-2 分享公共版本安全化

- 分享接口必须支持安全的 `public_version` 传入或安全默认摘要。
- `share_full_text=true` 必须是显式动作，且需要服务端确认字段。
- 默认安全摘要不得直接从 `clues.text` 自动摘要生成，以免把隐藏真相压缩后再次泄露。
- `party` 事件和 public export 只能写 `public_version`，不能写原始 `text`。

### P0-3 线索写入收口

- AI 工具、StateService、规则裁决、Engine 释放线索时必须走统一受控路径。
- 这条路径至少要负责：`room_id/character_id` 绑定、`clue_id` 生成、来源记录、Journal 事件、投影通知、可选索引更新。
- 不接受“只是把直接 insert 从 A 文件搬到 B 文件”的改法。

### P0-4 道具与 Luck 统一状态写入

- 追溯道具成功应通过受控事务写 `inventory`。
- Luck 消耗应优先落到 `character_runtime_state`；若仍兼容 `xlsx_data`，`xlsx_data` 只能作为派生/同步字段，不能作为唯一权威。
- `inventory` 写入成功、Luck 扣减成功、Action 状态、State patch、事件记录应是一致结果。

### P0-5 事件、Journal 与 Archive 证据链

- 发现线索必须有私密事件或等价 clue 事件。
- 分享线索必须有 `party` 事件，且只携带 `public_version`。
- 归档必须能按 `clue_id` 聚合“发现 -> 分享 -> 查看/引用”。

### P0-6 AI / RAG 证据过滤

- AI 只能读取 owned private clue、shared public clue、公开事件。
- WorldBook 未发现线索模板不进入玩家 prompt。
- `truth` 不因 share 或 archive 被完整释放。
- `source_type=clue` 检索必须有 room 和 visibility 过滤。

## P1 功能

- `/sync` 和 `/clues` 复用同一个 ClueViewBuilder。
- `clue_shares` 扩展 `target_scope / target_character_id`。
- Objectives 增加 Host/Admin 创建、完成、失败接口。
- 背包支持使用、消耗、转让、公共物资。
- public export 使用 `public_version` 和公开事件摘要，而不是 `clues.text`。
- Admin context preview 显示 clue 被过滤原因，例如 `owned / shared_public / hidden_worldbook / truth_blocked / other_player_private`。

## P2 功能

- 玩家线索板与队伍线索墙。
- 线索标注、归类、引用、交叉关联。
- AI 生成分享摘要，但发布前仍需玩家或 Host 确认。
- 目标链路和时间轴、日志、地图节点的深度联动。

## 不属于本模块

- 剧本真相与未发现线索模板：归 `07-WorldBook`。
- 线索是否应该释放：归 `04-Rule`、`12-AI-Keeper`、`13-State`、`14-Transaction` 协作。
- 事件最终投影给谁看：归 `15-Projection`。
- 完整反剧透策略：归 `21-Safety`。
- 长期复盘导出产品形态：归 `11-Journal`，Clue 只提供证据链数据。
