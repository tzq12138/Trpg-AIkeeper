## 三、P0 修复详情

### 1. 分享 `public_version` 安全化

| 场景 | 修复前 | 修复后 |
|------|--------|--------|
| 未传 public_version | `public_version = clues.text` (原文泄露) | `"玩家分享了一条线索，但未公开完整内容。"` |
| 全文分享 | 无确认机制 | `share_full_text=true` + `confirm_share_full_text=true` 双重确认 |
| SpoilerGuard | 不检查分享内容 | 全文分享 + 自定义摘要均经 SpoilerGuard 拦截 |
| 分享事件 | 无 | 写入 `s2c_clue_shared` (audience=party) |
| `clue_shares.room_id` | 缺失 | 新增列 + 写入 |

### 2. 统一写入路径

| 路径 | 修复前 | 修复后 |
|------|--------|--------|
| `_tool_engine_save_clue` | 直接 INSERT clues | INSERT + 写入 `s2c_clue_discovered` 事件 |
| `_apply_clue_changes` | INSERT clue_shares 缺 public_version | 安全默认 + room_id |

### 3. Luck 运行态

| 函数 | 修复前 | 修复后 |
|------|--------|--------|
| `_character_luck` | 只读 xlsx_data | xlsx_data 读取（待后续从 runtime_state 读） |
| `_decrement_luck` | 只写 xlsx_data | 优先写 character_runtime_state，xlsx_data 降为派生同步 |

### 4. /sync + query_clues 口径

| 接口 | 修复前 | 修复后 |
|------|--------|--------|
| `/sync` | 只返回 owned clues | + shared clues (public_version) |
| `_tool_query_clues` | 只查 owned raw clues | + shared public clues (public_version) |

### 5. Public export

| 路径 | 修复前 | 修复后 |
|------|--------|--------|
| public export | 按 `is_private` 导出 `clues.text` | 只导出 `clue_shares.public_version` |
| private export | — | 新增 debug 路径（含 character_id 脱敏） |

## 四、`clue_shares` room scope 方案

采用 **补 `room_id` 列** 方案：
- DB: `ALTER TABLE clue_shares ADD COLUMN IF NOT EXISTS room_id TEXT`
- 所有 INSERT 均写入 `room_id`
- SpoilerGuard `compute_unlock_state` 按 `room_id` 查询（原有代码已写，现在列存在后生效）

## 七、结论

### 本轮工程验收：✅ 通过

分享安全化（安全默认文案 + SpoilerGuard + 双重确认）、写入路径（事件闭环）、Luck 运行态、Export 脱敏、/sync 口径统一全部闭环。

### 生产安全完成：⚠️ 未达到

以下项尚未闭环：

1. **Host/Admin debug 路径审计** — 当前无独立 debug 接口读取 `clues.text` 原文的审计记录
2. **share scope 扩展** — 当前固定 `party`，未支持 `target_character_id`
3. **Inventory 共享背包** — 当前只支持自读写
4. **AI 摘要生成** — 玩家分享时仍需手动写 public_version，无 AI 辅助摘要
