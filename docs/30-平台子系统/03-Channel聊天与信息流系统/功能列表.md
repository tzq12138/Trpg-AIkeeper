# Channel 聊天与信息流系统功能列表

## 模块定位

Channel 模块负责房间内所有“可被人阅读的信息流”：大厅队伍聊天、游戏内战术消息、AI/KP 公开叙事、系统事件、骰子与状态提示、玩家归档日志。它不负责裁决规则、不直接写世界状态、不把聊天自动升级为世界事实。

当前代码还没有独立 `channels` 或 `messages` 表。运行态主要依赖 `events` 表、`EngineEvent` 信封、`ProjectionDispatcher`、WebSocket 和前端本地消息列表拼出信息流体验。

当前阶段说明：

- 本文件已可作为 Channel 模块工程执行入口，但当前阶段仍是“P0 主链路 + 受众过滤风险识别版”。
- 文档已识别玩家 WS 补发、`/api/player/reconnect`、`/events/public`、team-message 输入校验、OOC/IC 分层、events 直接写入与 `ProjectionDispatcher` 并存等风险。
- 这些风险不代表已经在代码中关闭；文档完成不等于生产安全完成。

## P0 功能

| 功能 | MVP | 当前代码 | 依赖 | 验收口径 | 现状风险 |
|---|---|---|---|---|---|
| 统一事件信封 | 是 | 已有 `EngineEvent` 与 camelCase alias | Projection、Journal | WS 帧包含 `type/roomSequence/audience/payload` | `tests/server/test_events.py` 的事件枚举仍偏旧，需要同步。 |
| 队伍聊天发送 | 是 | `POST /api/player/team-message` 已做 trim、`2000` 字符上限、source 白名单、每角色每秒 `3` 条限频 | User、Room、Projection | 有效玩家 token 可发送文本，返回 `messageId` | 当前 player 接口仍允许 `system_import`；超长返回码仍是 `400`；尚无按房间或分钟级限速策略。 |
| 队伍聊天广播 | 是 | `s2c_team_message` audience 为 `party` | WS、EventLog | Host 与玩家都能收到同一条队伍消息 | 当前是房间全队频道，没有分队和私聊。 |
| 大厅聊天体验 | 是 | `PlayerLobby.tsx` | Room、User | 发送后本地先显示，WS 回声不会重复 | 刷新页面后队伍聊天不从历史恢复。 |
| 游戏内战术信息流 | 是 | `PlayerActionPage.tsx` | AI-Keeper、Rule、Projection | 战术提示、公共叙事、系统提示能进玩家终端 | 本地消息只保留约 50 条，和持久日志不是同一数据源。 |
| Host 公共信息流 | 是 | `HostStage.tsx`、`HostStore` | Host Client、Projection | Host 能看到公开叙事、队伍消息、场景演出 | 队伍消息仍会污染舞台叙事区；Host 侧时间线/日志也必须持续防止被做成 `scenario_truth` 或未投影私密内容的 dump 口。 |
| 事件落库与 sequence | 是 | `events` 表、`ProjectionDispatcher.emit` | Journal、Replay | 每条权威事件有递增 sequence，可按房间查询 | 直接写 events 的路径和 dispatcher 路径并存，口径需要收敛。 |
| 玩家 WS 断线补发 | 是 | `player_ws_endpoint` 用 `lastSequence` 补发事件，并调用 `EventLog.get_events_for_player` | User、Projection | 玩家重连后收到漏掉的事件 | WS catch-up 已有第一层过滤，但 `/api/player/reconnect`、archive、`/events/public` 仍未统一复用同一套过滤口径，且 `characterId/character_id` 键名不一致有漂移风险。 |
| 玩家公共事件查询 | 是 | 当前有 `GET /api/rooms/{room_id}/events/public`，要求 `X-Room-Token` 且角色属于该房间 | User、Projection | 玩家只能查自己可见的公共事件 | 接口名容易被误解为匿名公开接口；当前实现按 `audience != 'player'` 取数，若不收紧会把 `host` audience 也算进来，是 P0 风险。 |
| Host 时间线查询 | 是 | `GET /api/rooms/{room_id}/timeline` | User、Journal | 房主或管理员可按类型、关键词查看事件 | Host 全量时间线应继续限制在 owner/admin。 |
| 玩家归档查询 | 是 | `GET /api/player/archive` 已支持 `messages` 类型 | Journal、Projection | 玩家只能查自己可见的行动、线索、状态和队伍消息 | 当前 archive 仍手写自己的过滤逻辑，和 WS catch-up、`reconnect`、`events/public` 没有共用一套 helper；同时仍使用 `offset/limit` 而非 sequence 游标。 |

## P1 功能

| 功能 | MVP | 当前代码 | 依赖 | 验收口径 | 说明 |
|---|---|---|---|---|---|
| 正式频道模型 | 否 | 未建表 | Room、User | 有 `channel_id/type/audience/mode`，消息归属清晰 | 建议先逻辑建模，再决定是否从 events 派生。 |
| 公共剧情频道 | 是 | 由 `s2c_public_observation` 承担 | AI-Keeper、Projection | 玩家与 Host 都能看到公开叙事 | 不等同于玩家聊天。 |

| 系统频道 | 是 | 多个 `s2c_*` 事件承担 | Rule、State、Journal | 骰子、状态、错误可追溯到事件 | 需要统一展示标签和来源事件。 |
| 骰子消息归档 | 否 | 部分在 `s2c_action_completed` payload 中 | Rule、Journal | 玩家可查检定原因、目标值、结果 | 禁止前端自造骰子结果。 |
| 队伍聊天历史 | 否 | events 已落库，缺专用查询 | Journal | 重进大厅能加载最近 N 条队伍消息 | 可先扩展 archive，再考虑 messages 表。 |
| 消息 source 标记 | 否 | `team-message` 有 `source` 字段 | Voice/Media | 文本、语音转写、系统生成可区分 | source 需要白名单和显示策略。 |
| 消息引用与来源事件 | 否 | 事件有 sequence，消息无引用字段 | Journal、Clue | 可引用可见消息或事件 | 引用目标必须继承可见范围。 |
| 搜索与过滤 | 否 | Host timeline 有关键词；玩家 archive 有关键词 | Journal、User | 玩家搜索只返回授权内容 | 不能靠前端过滤私密文本。 |
| 固定消息 | 否 | 未实现 | User、Room | Host 可固定公开规则或提示 | 固定内容不能包含未公开真相。 |

## 边界原则

- 聊天内容默认只是玩家表达，不自动成为世界事实。
- 玩家写入世界状态只能走 Player Intent 或受控接口，不能通过频道消息绕过 Engine。
- AI 可以参考公开叙事、行动结果和授权消息，但必须区分 OOC、玩家猜测、系统事实和 KP 裁决。
- 私密信息的保护必须在服务端完成，REST、WS、archive、replay 都要继承同一套受众过滤。
- Host 可以查看运行与审计所需信息，但普通房主不应获得完整剧本真相或未公开玩家私密反馈。

## 统一可见性过滤方向

后续 Channel 不应让每个入口各写一套事件过滤。至少应统一抽象为一套服务端 helper，例如：

- `can_view_event(viewer, event)`
- `build_event_view_for_viewer(viewer, event)`

这一层至少要同时考虑：

- `viewer.role`
- `viewer.room_id`
- `viewer.character_id`
- `event.audience`
- `event.visibility`
- `payload.characterId / payload.character_id`

WS catch-up、`/api/player/reconnect`、`/api/rooms/{room_id}/events/public`、`/api/player/archive`、replay/导出都应复用这一口径，不能只修一个入口。

## 事件分类与 AI 事实层

| 分类 | 典型事件/字段 | 默认是否进入 AI 事实层 | 说明 |
|---|---|---|---|
| 玩家聊天 | `s2c_team_message` | 否 | 默认只是玩家表达，若被 AI 消费应标记为 `player_chat`。 |
| OOC | `mode=ooc` | 否 | 不是角色发言，不得自动升级为世界事实。 |
| 公开叙事 | `s2c_public_observation` | 是 | 属于已投影给全体玩家的公开事实。 |
| 事务演出 | `s2c_reveal_transaction` | 有条件 | 可作为公开演出事实，但应按 step/semanticType 解读。 |
| 私密通知 | `s2c_private_notice` | 否 | 只对目标角色可见，不能跨玩家扩散。 |
| 状态补丁 | `s2c_state_patch` | 是 | 属于权威状态变更事实。 |
| 骰子/规则结果 | `s2c_action_completed`、Rule 结果 | 是 | 由 Rule/Engine 产生，不允许前端自造。 |
| 系统提示 | `audience=system` | 视类型而定 | 不能默认全部进入世界事实层。 |
