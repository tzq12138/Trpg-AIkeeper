# NPC / Faction 系统功能列表

## 模块定位

NPC / Faction 模块负责把剧本中的非玩家角色、怪物、组织与势力引用，整理成可查询、可防剧透、可进入 AI 上下文、可在遭遇中临时参与结算的资产。

第一轮定位不是完整世界模拟器，而是服务核心链路：

- 剧本导入后能识别并整理 NPC 资产。
- AI 扮演和检索时能引用 NPC 的公开信息与授权信息。
- 玩家只看到已公开或已解锁的 NPC 摘要。
- 隐藏 NPC 不会通过地图、RAG、公共事件或玩家 DTO 提前泄露。
- Host 可把临时敌人放入遭遇，但不把它们误写成长期 NPC 档案。

当前阶段说明：

- 本文档已可作为 `06-NPC/Faction` 模块工程执行入口，但当前阶段仍是`P0 主链路 + NPC 可见性风险识别版`。
- 文档已识别 `npc_id` 缺失、字段级 visibility 不足、RAG entitlement、地图节点泄露、隐藏 NPC 解锁、临时 NPC 与长期 NPC 混用、Faction 范围膨胀等风险。
- 这些风险不代表已经在代码中关闭；必须通过后续工程批次和测试验收确认。

## 当前代码锚点

| 类型 | 现状 |
|---|---|
| 剧本结构化 | `src/server/ai/ai_kp.py` 中 `structure_scenario()` 默认只稳定产出 `scenes/npcs/clues/truth/endings`，未强制 `npc_id/public_description/faction_refs` |
| 剧本质量检查 | `src/server/scenario/quality.py` 目前只检查是否识别到 NPC，不检查 NPC 字段完整性 |
| 剧本 NPC 资产 | `scenarios.knowledge_graph.npcs` 存放结构化 NPC 列表，是当前唯一长期 NPC 档案来源 |
| 场景绑定 | `scenario_assets.scenes[].npcs_present` 记录场景出现的 NPC 名称 |
| AI 工具 | `src/server/agent/tools.py` 的 `query_npcs` 先读 `npcs_present`，再按 `knowledge_graph.npcs[].name` 精确匹配详情 |
| Player AI 可见过滤 | `src/server/ai/spoiler_control.py` 会构造 `visible_npcs`，已兼容 `npc_id/public_description`，但它是 AI 上下文过滤，不是正式玩家 NPC API |
| 防剧透索引 | `src/server/engine/spoiler_guard.py` 从 `knowledge_graph.npcs[].is_hidden` 提取 `hidden_npc`，当前 itemId 仍主要基于数组下标 |
| 隐藏 NPC 解锁 | `SpoilerGuard.compute_unlock_state()` 目前主要从 `s2c_public_observation.payload.npcName` 聚合已公开 NPC |
| RAG | `src/server/ai/rag.py` 的 `index_npc_graph()` 目前只写 `name/role/description`，metadata 只有 `npc_name/index` |
| RAG 搜索范围 | `RAGStore.search()` 已按 `room_id` 和 `scenario` 做基础限定，但没有单独的 NPC visibility / unlock 过滤语义 |
| 地图持久层 | `src/server/map_persistence.py` 的玩家已探索节点会返回 `npcsPresent/cluesAvailable`；隐藏只依赖节点 fog，不区分隐藏 NPC |
| 地图匿名接口 | `src/server/router_map.py` 在无 token 时会回完整 `scenario_map.nodes`，当前有泄露节点 NPC/线索的风险 |
| 遭遇临时 NPC | `src/server/host/router_host.py` 使用 `npc:{uuid}` 创建参与者；`encounter_participants` 当前没有稳定 `display_name` 字段 |
| 前端 | `EncounterPanel.tsx`、`HostMapPanel.tsx`、`PlayerActionPage.tsx` 都已消费部分 NPC/地图数据 |
| 测试覆盖 | 当前已有 `test_ai_kp.py`、`test_quality.py`、`test_spoiler.py`、`test_spoiler_guard.py`、RAG 测试；地图和遭遇尚缺独立 NPC 口径测试文件 |

当前没有独立的 `npcs`、`npc_states`、`factions`、`faction_clocks` 主表。NPC 目前主要是剧本 JSON 资产、AI 上下文片段、防剧透敏感项、地图节点引用和遭遇临时参与者。

## 数据分层

| 层 | 来源 | 含义 | 禁止混用 |
|---|---|---|---|
| 剧本 NPC 资产 | `knowledge_graph.npcs[]` | 剧本结构化出的长期 NPC 档案 | 不等于房间运行态 |
| 场景 NPC 引用 | `scenario_assets.scenes[].npcs_present` | 某场景可能出现的 NPC 引用 | 不等于玩家已知 NPC |
| 地图 NPC 引用 | `scenario_maps.nodes[].npcsPresent` | 地图节点关联的 NPC 提示 | 不等于可直接展示给玩家 |
| RAG NPC chunk | `document_chunks(source_type='npc')` | AI 检索用知识片段 | 不等于 player-facing 可见文本 |
| 防剧透敏感项 | `spoiler_sensitive_items(category='hidden_npc')` | 隐藏 NPC 的名字、别名、身份、描述片段 | 不等于已公开 NPC |
| 玩家已知 NPC DTO | 公开事件 / 探索 / 线索派生 | 玩家可见 NPC 摘要 | 不返回完整 NPC 档案 |
| Host NPC DTO | 剧本摘要 + 隐藏标记 + 授权字段 | Host 运营视角 | 不直接推进世界事实 |
| 遭遇临时 NPC | `encounter_participants` 中 `npc:{uuid}` | 战斗/追逐临时参与者 | 不等于长期 NPC 档案，不写入 Character |
| Faction 草案 | WorldBook / Timeline 后续承接 | 势力关系和长期推进 | 不在本轮做成完整系统 |

## P0 功能

| 功能 | 当前代码状态 | MVP | 依赖模块 | 验收口径 | 现状风险 |
|---|---|---|---|---|---|
| 剧本 NPC 抽取 | `structure_scenario()` 会产出 `knowledge_graph.npcs[]` | 进入 | Module、WorldBook | 导入后能统计 NPC 数量，至少形成基础 NPC 列表 | 结构化目前未强制 `npc_id/public_description/personality/motivation/is_hidden` |
| NPC 稳定标识与基础 schema | 代码已有 `npc_id` 兼容读取，但未强制生成 | 进入 | Module、AI-Keeper、Safety | `knowledge_graph.npcs[]` 至少稳定到 `npc_id/name/role/type/public_description/description/is_hidden` | 只靠名字会导致同名 NPC、别名、公开名与真名混淆 |
| NPC 场景绑定 | `npcs_present` 已被 AI 工具和地图使用 | 进入 | Scene/Map | AI 能按当前场景读取对应 NPC；地图和场景引用保持一致 | 现在主要靠 `name` 对齐，缺稳定 ID |
| AI 查询当前场景 NPC | `query_npcs` 已可查询当前场景 NPC | 进入 | AI-Keeper、Scene | AI 扮演链路能读到裁剪后的 NPC 信息，而不是完整 truth 层 | 当前工具直接按 `name` 回查，未区分 player-facing 与 host-facing 上下文 |
| NPC RAG 索引与 entitlement | `index_npc_graph()` 已写入 `document_chunks` | 进入 | AI-Keeper、RAG、User | 当前房间能检索本剧本 NPC；不同剧本不能串；hidden NPC 不会直接落到 player-facing 检索 | 当前 metadata 只有 `npc_name/index`，room/scenario/visibility 语义不足 |
| 隐藏 NPC 防剧透 | `SpoilerGuard` 已支持 `hidden_npc` | 进入 | Safety、Projection、Channel | 隐藏 NPC 名、别名、身份描述不会通过 party/player 输出提前泄露 | 当前解锁主要依赖 `payload.npcName`，同名 NPC 风险高 |
| NPC 公开出现与解锁 | `compute_unlock_state()` 已从公共事件读 `npcName` | 进入 | Journal、Projection、Channel | 公开出现、身份揭示、秘密揭示至少区分不同 revealLevel | 当前事件契约没有强制 `npcId` |
| 地图节点 NPC 防泄露 | 玩家已探索节点目前会看到 `npcsPresent` | 进入 | Scene/Map、Safety、Projection | 匿名地图和玩家地图只返回授权字段；hidden NPC 不会因已探索节点提前暴露 | 当前匿名接口直接返回完整 nodes |
| 遭遇临时 NPC | `encounter_participants.character_id='npc:{uuid}'` 已存在 | 进入 | Rule、Host Client | Host 可创建临时 NPC 进入战斗/追逐，且不写入 `characters` | 当前 `name` 未稳定持久化到 participant 数据 |
| 剧本质量检查 | `QualityReportGenerator` 会提示未识别到 NPC | 进入 | Module | 质量报告能识别 NPC 缺失与关键字段不足 | 当前只看数量，不看字段质量 |

## 关键边界

- 剧本 NPC 是世界书/模组资产，不等于房间运行态。
- `npc:{uuid}` 遭遇参与者不是 `characters.character_id`，不能写入 Character 模块。
- `npc_id` 应尽量成为所有公开、解锁、RAG metadata、地图引用和玩家摘要的稳定主键；名字只是展示字段。
- `is_hidden` 只能作为整体默认策略，不能替代字段级 visibility。
- Player-facing AI 与 player-facing RAG 不能读取或输出 truth 层 NPC 字段。
- 地图里“节点绑定了 NPC”不代表“玩家已经知道这个 NPC 存在或身份已公开”。
- Faction 第一阶段只做引用关系和产品边界，不在 06 里实现 faction clock、势力行动推进和复杂世界模拟。
