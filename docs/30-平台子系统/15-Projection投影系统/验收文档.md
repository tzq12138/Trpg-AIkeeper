# Projection 投影系统验收文档

## 文档定位

本文档用于在收到工程师的 `回执-YYYY-MM-DD.md`、代码改动说明、测试结果后，判断 `15-Projection` 本轮工作是否真正完成。

它只负责验收，不替代：

- `功能列表.md`
- `PRD.md`
- `DeepSeek计划.md`

默认分两层结论：

- `本轮工程验收通过`：表示 Projection 本轮承诺的 P0 / P1 主链路已经闭环。
- `生产安全完成`：表示除了本轮范围外，长期投递可靠性、审计恢复、跨设备 ACK、长链路回归也已基本稳定。

除非证据非常完整，否则默认只给 `本轮工程验收通过`，不直接给 `生产安全完成`。

## 验收输入

验收前至少应拿到以下材料：

- 本模块四份基线文档：`功能列表.md`、`PRD.md`、`DeepSeek计划.md`、`验收文档.md`
- 工程师回执：`回执-YYYY-MM-DD.md`
- 本轮改动文件清单
- 实际测试命令与测试结果
- 如涉及前端共享类型、WS 消费或相关页面，附 `npm run build` 结果

## 结论等级

| 结论 | 含义 |
| --- | --- |
| `本轮工程验收通过` | Projection 本轮 P0 / P1 目标完成，可见性、裁剪、补发、导出、版本屏障与模块边界与文档对齐 |
| `本轮工程验收有缺口` | 主链路大体可用，但缺关键证据、关键测试或关键边界没有闭环 |
| `不通过` | 出现泄露、顺序错误、未分类写路径、类型未对齐、测试未过或回执与实现不符 |
| `生产安全完成` | 仅在更广回归、长期遗留和恢复策略也关闭后才可给出 |

## 一票否决项

出现任一情况，本轮不得判通过：

- live / catch-up / reconnect / archive / public replay / public export 没有复用同一套 `can_view_event + build_event_view`
- `/api/player/reconnect` snapshot 仍返回整房间原始 `events`
- `public export` 仍使用 `audience != 'player'` 近似 public
- `system` 事件仍默认对玩家可见
- `s2c_state_patch` 仍缺 `schemaVersion / baseStateVersion / stateVersion / actionId`
- Projection 仍在 State 落库前下发 patch 或 completed
- Host frame 被写回 `events`，或被拿来做 replay / export 数据源
- Projection 自己决定 ReleaseGate 释放时机
- direct `events` write path 未逐条分类为 `realtime` / `audit-only`
- public export 仍包含 token、raw prompt、hidden truth、未公开 clue 原文、hidden node、debug payload
- 关键测试命令未提供，或测试未通过

## 必备回执材料

工程师回执里至少应说明：

- 本轮覆盖了哪些 `Projection Batch`
- 实际修改了哪些文件
- 实际运行了哪些测试，结果是什么
- 哪些路径改走 `ProjectionDispatcher.emit()`
- 哪些路径保留 `EventLog.log_event()`
- 哪些路径是 `audit-only`
- `system_safe` 白名单最终包含哪些事件与字段
- `player_sequences` 的更新时机与语义
- `ProjectionBuilder` 是否保留，职责边界是什么
- 本轮仍保留的 known limitations

如果回执把文档里明确属于后续阶段的缺口写成“已完成”，验收时应直接降级处理。

## 本轮工程验收清单

### 1. 事件注册与 DTO 契约

1. 所有真实发出的 `s2c_*` 是否进入 registry。
2. 所有真实发出的 `s2c_*` 是否进入后端 `EngineEventType`。
3. 所有真实发出的 `s2c_*` 是否进入前端 TS 类型。
4. registry 是否包含 `domain / defaultAudience / minimumPayload`。
5. `EngineEventEnvelopeDTO` 字段是否稳定。
6. `ProjectionRequestDTO` 字段是否稳定。
7. `VisibilityDecisionDTO` 字段是否稳定。
8. `ProjectedPayloadDTO` 字段是否稳定。

### 2. 统一可见性 helper 与 payload 裁剪

9. Player WS catch-up 是否复用统一 helper。
10. `/api/player/reconnect` missed events 是否复用统一 helper。
11. `/api/player/reconnect` snapshot `recent_events` 是否复用统一 helper。
12. player archive 是否复用统一 helper。
13. public replay 是否复用 public view helper。
14. public export 是否复用 public view helper。
15. `audience=player` 缺 owner 时是否默认对普通玩家不可见。
16. Player A 是否收不到 Player B 的 `s2c_state_patch`。
17. Player A 是否收不到 Player B 的 `s2c_action_completed`。
18. Host-only reveal 是否不会进入 public replay。
19. Host-only reveal 是否不会进入 public export。

### 3. `system_safe` 与 public 视图边界

20. `system` 事件是否默认不 public。
21. `system_safe` 白名单是否有测试。
22. `system_safe` 是否做 payload 字段裁剪，而不是只按事件名。
23. `s2c_turn_resolved` 是否只带安全摘要。
24. `s2c_checkpoint_created` 是否不带 raw snapshot / path / debug payload。
25. `s2c_checkpoint_restored` 是否保持 `audit-only`。
26. `host_force_move` 是否保持 `audit-only` 或 Host/Admin only。

### 4. `player_sequences`、catch-up 与 reconnect

27. `player_sequences.last_delivered_sequence` 语义是否在回执中明确写成 delivery cursor。
28. sequence 跳号是否在文档或测试中被解释为正常现象。
29. WS catch-up 后是否更新 `player_sequences`；如不更新，是否说明原因。
30. reconnect 后是否更新 `player_sequences`。
31. snapshot 分支是否推进到 room max sequence；如不是，是否说明策略。
32. 本轮是否仍不做 per-device ACK；如是，是否明确写出限制。
33. Player reconnect 是否不会返回 Host-only 事件。
34. Player reconnect 是否不会返回其他玩家 private 事件。

### 5. public / full export 边界

35. public export 是否不含 `owner_token`。
36. public export 是否不含 `player_token`。
37. public export 是否不含 `account_id / email`。
38. public export 是否不含 raw prompt / raw response。
39. public export 是否不含 hidden truth。
40. public export 是否不含未公开 `clue.text` 原文。
41. public export 是否不含 hidden node / hidden NPC。
42. full export 是否仍脱敏 token / API key / secret / raw AI prompt。
43. `full export` 与未来 `admin_audit export` 的边界是否仍被保留。

### 6. 状态 patch 版本契约与投影时序

44. `s2c_state_patch` 是否包含 `schemaVersion`。
45. `s2c_state_patch` 是否包含 `baseStateVersion`。
46. `s2c_state_patch` 是否包含 `stateVersion`。
47. `s2c_state_patch` 是否包含 `actionId`。
48. Projection 是否只投递已落库的 State patch。
49. Projection 是否不伪造 `stateVersion`。
50. party patch 是否只包含公共摘要。
51. private patch 是否 `audience=player` 且绑定目标角色。

### 7. Host frame、ReleaseGate 与 direct write path

52. ReleaseGate 未释放前，Projection 是否不会下发 player-only completed。
53. ReleaseGate 释放后，Projection 是否只定向给目标角色。
54. `HostFrameDTO` 是否不写入 `events`。
55. `HostFrameDTO` 是否不作为 public replay / export 数据源。
56. Host frame 是否不携带 player-only patch、raw mutation、hidden truth。
57. direct `log_event()` / `events` write path 是否全部盘点完成。
58. 每条 direct write path 是否都标记为 `realtime` 或 `audit-only`。
59. 哪些路径改走 `ProjectionDispatcher.emit()` 是否在回执中逐条列清。
60. `ProjectionBuilder` 是否保留、职责边界是否说清。

### 8. SpoilerGuard 与审计

61. SpoilerGuard 命中 player payload 时是否替换为安全文本。
62. SpoilerGuard 命中 party payload 时是否替换为安全文本。
63. SpoilerGuard 失败时是否有日志 / audit，不静默放过未审计内容。
64. Host payload 是否不会被 player 规则误拦截。
65. spoiler audit 是否不进入 Player archive / public export。

### 9. 端到端主链路

66. Host 创建房间并开局后，Player A / B 加入是否正常。
67. Player A 私密结果是否只投递给 Player A。
68. Host 是否收到 Host-safe reveal / frame。
69. Player B 是否看不到 Player A 的 private patch。
70. Player A 断线重连后只补回 `party` 事件和自己的 `player` 事件。
71. Player B 断线重连后不会补回 Player A 的 private 事件。

## 生产安全加签条件

以下条件未关闭前，不应给 `生产安全完成`：

- per-device ACK 与多设备 cursor 仍未落地
- `ProjectionBuilder` 与 `ProjectionDispatcher` 的长期边界仍可能继续变化
- direct write path 仍未完全收口，只做了第一轮分类
- `system_safe` 只覆盖了本轮主链路，未来系统事件仍需继续补白名单测试
- projection_failed / redelivery / replay 的长期恢复策略仍未完整闭环
- 更长链路的 public export、campaign export、跨模块回归还未充分覆盖
