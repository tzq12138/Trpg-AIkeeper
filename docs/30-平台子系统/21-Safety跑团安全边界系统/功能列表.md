# Safety 跑团安全边界系统功能列表 V2.1

## 当前阶段说明

- 本文档当前阶段为：`P0 主链路 + 鉴权、可见性、反剧透与导出安全风险识别版`。
- 本轮重点锁定：REST/WS 鉴权、Player reconnect/catch-up、archive/export/public events 统一过滤、RAG 权限、AI prompt 裁剪、SpoilerGuard 审计、文件与媒体安全、生产配置基线。
- 本轮不是生产安全完成版；token 轮换、账号 token 撤销、多端 session 管理、社区审核、观众模式、完整安全看板进入后续批次。
- X-card、fade、private feedback 属于桌面安全工具，但优先级必须排在真实泄露风险之后。
- 文档里列出的风险以当前仓库代码为准，不沿用旧 PRD 的过期口径。

## 模块定位

Safety 是 AI-Keeper 的统一安全红线与验收口径层。

它负责定义：

- 谁能请求；
- 谁能看到；
- AI 能不能说；
- 日志、archive、reconnect、export 能不能导出；
- 文件、素材、STT 能不能进系统；
- 生产默认配置是否危险；
- 跑团桌面安全工具如何被记录、限速和投影。

它不替代：

- User 的身份与角色系统；
- Projection 的事件投影实现；
- State 的事实写入；
- Asset 的文件存储；
- AI-Keeper 的叙事生成。

Safety 的职责是要求这些模块遵守同一套底线。

## Safety 数据分层

| 层级 | 数据对象 | 用途 | 禁止混用 |
| --- | --- | --- | --- |
| L0 `Credential` | `account_token` / `owner_token` / `player_token` / API key | 身份凭证 | 不进 DTO、日志、AI prompt、export |
| L1 `Principal` | Account / RoomOwner / Character / Admin | 当前请求主体 | 不靠前端声明自证 |
| L2 `AuthDecision` | allowed / denied / reason | REST/WS 鉴权结果 | 不等于事件可见性 |
| L3 `EventEnvelope` | `audience` / `payload` / `roomId` / `sequence` | 权威事件记录 | 不直接给 Player |
| L4 `VisibilityDecision` | allowed / reason / scope / safeFields | 事件是否可见 | 默认拒绝 |
| L5 `SanitizedPayload` | 安全裁剪后的 payload | live/reconnect/archive/export 输出 | 不含 raw payload |
| L6 `PublicEventView` | `party + system_safe` | public events / public export | 不等于 `audience != player` |
| L7 `PlayerPrivateView` | self player-only + party | 玩家视图 | 缺 owner 默认拒绝 |
| L8 `HostSafeView` | host + party + safe system | Host 视图 | 不含 player-only 私密 patch |
| L9 `SensitiveIndex` | truth / ending / hidden clue / hidden NPC / hidden asset | 反剧透索引 | 不给 Player |
| L10 `UnlockState` | clue share / map reveal / event facts | 已解锁事实 | 不由 AI 伪造 |
| L11 `SpoilerAudit` | 命中、retry、fallback、actor、scope | Admin/Ops 审计 | 不进 public export |
| L12 `DeploymentSafetyConfig` | `JWT_SECRET` / CORS / log redaction | 部署基线 | 非 dev 不能弱默认 |
| L13 `TableSafetyEvent` | X-card / fade / private feedback | 桌面安全事件 | 不直接改 State |

- `AuthDecisionDTO`
- `PrincipalDTO`
- `VisibilityDecisionDTO`
- `SanitizedEventDTO`
- `PublicEventDTO`
- `PlayerVisibleEventDTO`
- `HostVisibleEventDTO`
- `ExportSafetyDecisionDTO`
- `SpoilerReviewResultDTO`

- `RagAccessDecisionDTO`
- `FileSafetyDecisionDTO`
- `DeploymentSafetyCheckDTO`
- `TableSafetyEventDTO`
- `SafetyApiErrorDTO`

### 统一 helper 方向

```python
can_view_event(event, viewer, scope) -> VisibilityDecisionDTO
build_event_view(event, viewer, scope) -> SanitizedEventDTO | None
```

`scope` 至少覆盖：

- `live`
- `catch_up`
- `reconnect`
- `archive`
- `public_events`
- `public_export`
- `full_export`
- `admin_audit`

### 当前代码与目标口径

- 当前代码已存在 `EventLog._can_player_see_event()` 与 `get_events_for_player()`；
- V2.1 目标不是另起一套规则，而是把这套 helper 提升成全模块统一契约；
- `router_reconnect.py`、`ws_manager.py`、`router_player_archive.py`、`router_archive.py`、`export.py`、Projection live 路径都要复用同一套 helper。
- 工程执行时禁止在 EventLog、Projection、Archive、Export、Reconnect 中各自复制一套新规则，最多保留兼容 wrapper。

## `system_safe` 最小白名单口径

当前代码里的最小白名单锚点是：

- `s2c_turn_resolved`
- `s2c_checkpoint_created`

V2.1 需要把它提升成明确的“事件类型 + payload 字段白名单”，而不是只认事件名。

### 可作为 `system_safe` 的最小样例

- `s2c_turn_resolved` 的安全摘要
- `s2c_game_time_updated` 的 `safeReason`
- `s2c_checkpoint_created` 的安全摘要（前提是不含路径、restore reason、debug payload）

### 默认禁止进入 Player/public 的 system 事件

- `s2c_checkpoint_restored` raw audit
- admin override
- spoiler audit
- internal error/debug
- raw restore reason
- AI call log
- host force move audit

## Export Scope 分层

| Scope | 允许范围 | 明确禁止 |
| --- | --- | --- |
| `public_export` | `party + system_safe` | host-only、player-only、token、本地路径、隐藏素材、raw prompt、debug metadata |
| `full_export` | owner/admin 可导出的较完整战役包 | raw token、API key、明文 secret、raw prompt/raw response、账号敏感字段 |
| `admin_audit_export` | 如未来需要导出 AI/Ops 原始审计，必须单独 scope | 不能复用 `full_export`，不能默认对 owner/player 开放 |

补充约束：

- `full_export` 是完整业务导出，不是数据库原样导出；
- 如未来需要原始 AI/Ops 审计，必须单独走 `admin_audit_export`，不能塞进 `full_export`。

## Token 生命周期边界

### P0 先锁定

- token 不进入 DTO、日志、export、AI prompt；
- 错 token、跨房 token 一律拒绝；
- owner/player token 仅在受控恢复路径返回；
- public export、public events、replay、RAG 返回结果都不能带 token。

### P1 遗留

- `owner_token` 轮换；
- `player_token` 轮换；
- account token 撤销；
- session 表或 tokenVersion；
- 泄露补救流程。

工程回执必须明确：

- 本轮是否仍是长期有效 owner/player token；
- token 轮换是否仍未实现；
- account token 撤销是否仍未实现；
- 若未实现，必须列为遗留风险，不能写成“token 安全完成”。

## 实施补充口径

1. `HostSafeView` 不是“Host 可以看所有东西”；它必须持续排除 `player-only state_patch`、`private_notice`、`action_completed` 等玩家私密结果。
2. `public_export` 的脱敏范围不因发起人是 owner/admin 而放宽；public 就是 public。
3. `full_export` 不得被实现成 DB dump；raw token、API key、secret、raw prompt/raw response 仍必须脱敏。
4. CORS 生产判断必须写入工程回执，至少说明使用哪个环境变量识别 production，以及 `CORS_ALLOW_ORIGINS` 如何配置。

## MVP 验收主链路

1. Player 无 token 不能访问 player-only API、WS、地图和 archive。
2. Player A 不能读取 Player B 的私密事件、action、线索、状态 patch。
3. Host 能看公共舞台和 Host HUD，但不能收到 player-only 私密事件。
4. Admin 能审计和管理，但 `public export` 不因 admin 权限而泄露全量数据。
5. AI 生成给 party/player 的文本命中未解锁敏感项时被 retry 或 fallback。
6. 玩家断线重连只拿到自己可见的事件和 pending actions。
7. `public events`、replay、archive、export 与实时 WS 使用同一 visibility 口径。
8. 文件上传、STT、PDF 导入、素材删除均不允许路径穿越、超大文件和危险类型。
9. 生产配置不允许默认 `JWT_SECRET`，CORS 不允许无限制 `*`。
10. 所有安全失败返回 401/403/400/413/429 等明确状态码，并且不泄露资源是否存在的敏感细节。
