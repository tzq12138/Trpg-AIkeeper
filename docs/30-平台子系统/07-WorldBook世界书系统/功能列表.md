# WorldBook 世界书系统功能列表 V2.1

## 一句话定位

WorldBook 是 AI-Keeper 的“剧本知识源”和“防剧透真相源”。它负责把导入剧本变成结构化世界书、质量报告、RAG 索引和敏感项索引；它不负责房间运行态写入，不负责玩家可见投影，也不直接裁决玩家行动。

当前阶段说明：

- 本文档已可作为 `07-WorldBook` 模块工程执行入口，但当前阶段仍是`P0 主链路 + 世界书安全索引风险识别版`。
- 文档已识别 PDF 导入半成品状态、结构化 schema 漂移、`raw_text/truth` 泄露、RAG scenario entitlement、防剧透索引缺失、quality_report 不参与开房、地图字段不一致、Admin 调试接口脱敏、重建幂等不足等风险。
- 这些风险不代表已经在代码中关闭；必须通过后续工程批次和测试验收确认。

## 当前代码真实链路

1. Admin 调用 `POST /api/scenarios/import-pdf` 上传 PDF，入口在 `src/server/scenario/router_scenarios.py`。
2. 接口校验账号角色必须为 `admin`，并只接受 `.pdf` 文件。
3. 读取文件内容，计算 `source_sha256`；如果已有相同 hash，直接返回 `already_imported`。
4. 临时保存 PDF，调用 `extract_text_from_pdf` 抽取页文本；扫描版 PDF 标记为 `requires_ocr`。
5. 将页文本合并为 `raw_text`，并计算 `chunks = chunk_text(pages)`。
6. 优先调用 `app.state.gateway.structure_scenario(full_text)`；失败后回退到 `structure_scenario`，无 API key 时走 mock。
7. 写入 `scenarios`：`scenario_id/title/raw_text/knowledge_graph/import_status=structured/source_filename/source_sha256/original_file_path`。
8. 调用 `QualityReportGenerator.evaluate(knowledge_graph)`，把结果写入 `scenarios.quality_report`。
9. 如果 `app.state.rag` 可用，当前只调用 `index_npc_graph(scenario_id, knowledge_graph)`，没有调用 `index_scenario(scenario_id, raw_text)`。
10. 调用 `SpoilerGuard.build_sensitive_index(scenario_id, knowledge_graph, {})` 写入 `spoiler_sensitive_items`。
11. Host/Admin 通过 `GET /api/scenarios/available` 选择结构化剧本；当前只按 `import_status='structured'` 过滤。
12. Host/Admin 调用 `POST /api/scenarios/{scenario_id}/create-room` 创建房间；当前不检查 quality level。

## 数据分层

| 层 | 来源 | 用途 | 禁止混用 |
|---|---|---|---|
| 导入源文件 | PDF / `source_filename` / `source_sha256` / `original_file_path` | 去重、审计、Admin 排错 | 不进入玩家接口 |
| 原始文本 | `scenarios.raw_text` | 结构化、Admin 调试、RAG 内部索引源 | 不等于玩家可见知识 |
| 结构化世界书 | `scenarios.knowledge_graph` | 剧本结构、场景、NPC、线索、真相、结局 | 不等于房间运行态 |
| 质量报告 | `scenarios.quality_report` | 判断可用性、风险等级、导入质量 | 不应只是展示字段 |
| RAG chunk | `document_chunks` | AI 检索世界知识 | 不等于可直接输出给玩家 |
| 防剧透索引 | `spoiler_sensitive_items` | truth / hidden clue / hidden NPC 输出拦截 | 不等于玩家已解锁事实 |
| 可用剧本 DTO | available scenarios list | Host 选剧本开房 | 不含 `raw_text/truth/original_file_path` |
| 地图输入 DTO | `knowledge_graph.scenes` / `scenario_assets.scenes` | 地图生成与场景派生 | 不等于玩家地图节点 |
| Admin 调试 DTO | 管理接口、reindex、quality override | 排错、重建、审计 | 不得扩散本地路径、token、绝对路径 |

## 状态口径

当前代码里主要落库的是 `import_status`。文档层建议至少区分三类状态语义：

| 概念 | 含义 | 当前代码现状 | 后续方向 |
|---|---|---|---|
| `import_status` | 导入与结构化是否完成 | 已有 `requires_ocr/structured` 等 | 保留 |
| `readiness_status` | 是否可进入 Host 普通可用列表 / 普通开房 | 当前未独立建模 | 文档先定义，工程可先派生实现 |
| `index_status` | RAG / spoiler index 是否完整 | 当前未独立建模 | 文档先定义，工程可先派生实现 |

最小口径建议：

- `import_status=already_imported`
- `import_status=requires_ocr`
- `import_status=structured`
- `import_status=failed`

配套派生语义：

- `readiness_status=ready`
- `readiness_status=partial`
- `readiness_status=blocked`

说明：

- `structured` 只代表 `knowledge_graph + quality_report` 形成，不天然等于“RAG 和 spoiler 已完全就绪”。
- RAG 或 spoiler index 缺失时，可保留 `structured`，但 `readiness_status` 不应为 `ready`。
- `blocked` 剧本不得进入 Host 普通可用列表。

## P0 功能

### P0-1 导入链路可闭环

- Admin 上传 PDF 后必须得到明确状态：`structured`、`requires_ocr`、`already_imported`、`failed`。
- `structured` 至少意味着 `knowledge_graph + quality_report` 成功落库。
- RAG 或 spoiler index 缺失时，必须在返回体、日志或派生 readiness 中明确体现。
- 中途失败不能把低质量半成品标记为普通可用剧本。

### P0-2 世界书 schema 稳定

最小结构：

```json
{
  "title": "string",
  "synopsis": "string",
  "scenes": [],
  "npcs": [],
  "clues": [],
  "truth": {},
  "endings": [],
  "trigger_mechanics": [],
  "spoiler_boundaries": [],
  "key_skills": [],
  "recommended_tags": []
}
```

标准 normalization 方向至少包括：

- `triggerMechanics -> trigger_mechanics`
- `spoilerBoundaries -> spoiler_boundaries`
- `keySkills -> key_skills`
- `recommendedTags -> recommended_tags`
- `npcsPresent -> npcs_present`
- `cluesAvailable -> clues_available`
- `imageUrl -> image_url`

### P0-3 RAG 索引完整

- 导入成功后必须索引 `raw_text` 的 scenario chunk。
- 导入成功后必须索引 NPC chunk。
- 当前剧本房间必须能检索 scenario chunk 和 NPC chunk。
- 不同剧本房间不能互相命中对方的世界书 chunk。
- player-facing RAG 不得直接返回 `raw_text/truth` 原文。

### P0-4 防剧透索引可靠

- `truth.summary` 必须进入 `spoiler_sensitive_items`。
- 隐藏线索必须进入敏感索引。
- 隐藏 NPC 如由 `knowledge_graph.npcs[].is_hidden` 标记，也应进入敏感索引。
- 玩家输出命中未解锁敏感项时，由 Safety / Projection 拦截。
- `truth` 永远不是玩家“完整解锁后即可直接读取”的公开对象。

### P0-5 质量报告参与业务决策

- `blocked` 剧本不能出现在 Host 可开房列表。
- `highRisk` 剧本可以给 Admin 调试，但 Host 普通开房应提示风险并做显式确认。
- `quality_report` 不能只是展示信息，必须参与可用剧本筛选。

## P1 功能

- Admin 可重建 RAG 索引和 spoiler index，并记录版本与重建人。
- Admin 可查看结构化字段计数、缺失项和导入来源。
- `knowledge_graph.scenes` 与地图生成所需 `scenario_assets.scenes` 统一或建立转换。
- 支持人工修正结构化结果，但先不做大型可视化编辑器。
- 支持 `knowledge_graph_version / rag_index_version / spoiler_index_version / quality_report_version` 或等价版本号。
- 支持质量 override，但必须 Admin-only 且有审计事件。

## P2 功能

- Markdown / JSON / XLSX 模组导入。
- 世界书实体编辑器：地点、NPC、线索、结局、触发器。
- 发布前校验：缺少关键字段时禁止发布到社区。
- 多房间复用同一模组模板。

## 不属于本模块

- 玩家已发现线索归属：归 `Clue`。
- 房间运行态事实：归 `State`。
- AI 裁决和骰子：归 `AI-Keeper`、`Rule`。
- 玩家可见过滤：归 `Projection`、`Safety`。
- 素材二进制上传：归 `Asset`。
- 完整模组编辑器 UI：归 `Module`。

## 质量等级最小规则

| 情况 | 建议等级 |
|---|---|
| 没有 scenes | `blocked` |
| 没有 truth 或 endings | `highRisk` 或更高 |
| 没有 clues | `highRisk` |
| 没有 NPC | `warning` |
| mock fallback 结构化 | 不得为 `ready` |
| RAG index 失败 | 至少 `partial/highRisk` |
| spoiler index 失败 | 不得 `ready` |
| `requires_ocr` / 抽取不到文本 | 不得进入普通可用列表 |

## 当前最高风险

| 风险 | 等级 | 说明 | 处理方向 |
|---|---|---|---|
| raw_text 未在导入时进入 RAG | 高 | 导入返回 `chunks` 数量，但未调用 `index_scenario` | P0 修复 |
| `raw_text` 进入 RAG 后 player-facing 泄露 | 高 | worldbook 真相可能被 AI / RAG 直接吐给玩家 | P0 明确 visibility 和输出边界 |
| quality_report 不阻断可用剧本 | 高 | `blocked/highRisk` 当前不会影响 Host 列表与开房 | P0/P1 修复 |
| `structured` 与索引完整性口径冲突 | 高 | 结构化成功但 RAG/spoiler 缺失时语义不清 | P0 收敛状态口径 |
| Admin 地图生成字段源不一致 | 高 | 导入主要写 `knowledge_graph.scenes`，地图生成读 `scenario_assets.scenes` | P1 修复 |
| `original_file_path` 扩散风险 | 中 | 本地绝对路径若进入普通响应会泄露部署信息 | P0/P1 脱敏 |
| schema normalization 不稳定 | 中 | camelCase/snake_case 混用会影响 06/09/04 等下游模块 | P0 锁定规则 |
| reindex / rebuild 幂等和版本不清 | 中 | 重建路径可用，但未明说版本与审计 | P1 补强 |
