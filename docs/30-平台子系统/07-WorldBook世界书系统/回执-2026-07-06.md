## 三、`structured` / `readiness_status` / `index_status` 语义

| 状态 | 含义 | 实现方式 |
|------|------|----------|
| `import_status=structured` | `knowledge_graph + quality_report` 已成功落库 | DB 列，导入时写入 |
| `import_status=requires_ocr` | PDF 无法抽取文本 | DB 列，导入时写入 |
| `import_status=failed` | 结构化或关键写入失败 | DB 列 |
| `import_status=already_imported` | 相同 SHA256 已存在 | 接口返回，不重复写入 |
| `readiness_status=ready` | quality NOT blocked + RAG ok + spoiler ok | 派生字段（返回体），不落库 |
| `readiness_status=partial` | RAG 或 spoiler index 缺失 | 派生字段（返回体） |
| `readiness_status=blocked` | quality_level=blocked | 派生字段（返回体） |
| `index_status=ready` | RAG scenario + spoiler index 均已建立 | 派生字段（返回体） |
| `index_status=partial` | 部分索引成功 | 派生字段（返回体） |
| `index_status=failed` | 全部索引失败 | 派生字段（返回体） |

## 九、结论

### 本轮工程验收：✅ 通过

导入链路（status 三层语义）、RAG 索引闭环（scenario chunk）、质量门禁（blocked 排除 + highRisk 确认）、Admin 脱敏（original_file_path 不扩散）、重建审计（rebuilt_by/rebuilt_at）全部闭环。

### 生产安全完成：⚠️ 未达到

以下项尚未闭环：

1. **`readiness_status` / `index_status` 未落库** — 当前为派生字段（返回体计算），未写入 DB 列。后续可增加持久化列以实现跨请求一致性。
2. **RAG visibility 过滤未在检索层实现** — `visibility='internal'` 已写入 metadata，但 `RAGStore.search()` 尚未按 visibility 过滤。
3. **版本号追踪未实现** — `knowledge_graph_version / rag_index_version / spoiler_index_version` 仍为文档概念。

### 后续 P1 建议

| # | 项目 |
|---|------|
| 1 | `readiness_status` / `index_status` 持久化到 scenarios 表 |
| 2 | RAG search 按 visibility 过滤（internal → host only, public → party） |
| 3 | knowledge_graph / quality_report / rag / spoiler 版本号 |
| 4 | PDF 导入异步化（当前同步阻塞） |
| 5 | `highRisk` override 正式 Admin UI + 审计日志查询 |
