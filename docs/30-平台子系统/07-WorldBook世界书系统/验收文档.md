# WorldBook 世界书系统验收文档

## 文档定位

本文件用于在收到工程师的 `回执-YYYY-MM-DD.md`、代码改动说明、测试结果后，判断 `07-WorldBook` 本轮工作是否真正完成。

它只负责验收，不替代 `功能列表.md`、`PRD.md`、`DeepSeek计划.md`。

默认分两层结论：

- `本轮工程验收通过`：表示 WorldBook 本轮承诺的 P0 主链路、安全索引边界和质量门禁已完成。
- `生产安全完成`：表示除本轮范围外，WorldBook 的长期高风险缺口也已关闭。

除非证据非常完整，否则默认只评 `本轮工程验收通过`，不直接给 `生产安全完成`。

## 验收输入

验收前至少应拿到以下材料：

- 本模块三份基线文档：`功能列表.md`、`PRD.md`、`DeepSeek计划.md`
- 工程师回执：`回执-YYYY-MM-DD.md`
- 本轮改动文件列表，至少说明改了哪些导入、质量报告、RAG、防剧透、地图、Admin、测试文件
- 测试命令与结果
- 如涉及 Admin 页面或地图页面，附 `npm run build` 结果和手动验证结果

## 结论等级

| 结论 | 含义 |
|---|---|
| `本轮工程验收通过` | PDF 导入、状态口径、RAG 索引、防剧透索引、quality gate、DTO 脱敏与关键测试都已对上 |
| `本轮工程验收有缺口` | 主链路基本可用，但仍缺关键证据、关键测试或关键安全边界 |
| `不通过` | 出现真相泄露、玩家可直接读 worldbook 敏感内容、状态口径错误、available/create-room 越权放行、测试未过或回执与实际不符 |
| `生产安全完成` | 只有在 override 审计、重建幂等、地图防剧透、player-facing AI/RAG 裁剪和长期版本追踪也闭环后才可给出 |

## 一票否决项

出现任一情况，本轮不能判通过：

- `structured` 仍被当成“完全 ready”，RAG 或 spoiler index 缺失时仍允许 `readiness_status=ready`
- 玩家侧 RAG 或 AI 可以直接返回 `raw_text`、`knowledge_graph.truth`、hidden clue 正文或 hidden NPC 真名
- `blocked` 剧本仍出现在 Host 普通可用列表，或仍可普通开房
- `highRisk` 剧本没有后端显式确认就能开房
- `original_file_path` 出现在 Host / Player 响应、公开 DTO 或普通日志
- reindex / spoiler rebuild 重复执行后产生重复 chunk 或重复 sensitive item
- 地图草稿或公开地图直接带出 hidden clue 正文、hidden NPC 真名或完整 truth
- 测试命令未提供，或关键测试明显未通过

## 必备回执材料

工程师回执里至少应明确：

- 本轮对应的 Batch 范围，例如 `WB-1 ~ WB-3`
- 实际修改文件
- 实际测试命令
- 实际测试结果
- 明确完成项
- 明确未完成但保留为后续 Batch 的项
- 如做了 override、reindex、rebuild，说明审计记录写在何处

如果回执把文档里明确属于后续项的缺口写成“已完成”，验收时应直接降级处理。

## 本轮工程验收清单

### 1. 导入链路与状态口径

- PDF 导入成功后，至少形成 `knowledge_graph`、`quality_report`
- `requires_ocr` 只表示导入识别受阻，不进入普通可用剧本
- 结构化失败应明确落到 `failed` 或等价错误状态
- `structured` 只代表 `knowledge_graph + quality_report` 已形成，不代表索引全部 ready
- `readiness_status` 和 `index_status` 已有明确实现或等价派生规则
- `already_imported` 如被使用，只能作为接口返回语义，不应污染已有 scenario 的真实落库状态

### 2. 数据分层与响应边界

- 导入源文件、`raw_text`、`knowledge_graph`、`quality_report`、RAG chunk、防剧透索引、available DTO、地图输入 DTO、Admin DTO 已有清晰边界
- Host 可见剧本 DTO 不包含 `raw_text`、完整 `truth`、`original_file_path`
- Player 不存在直接读取 WorldBook 原文、真相或内部调试字段的接口
- `GET /api/scenarios/{scenario_id}/quality-report` 若开放给 Host，返回内容也必须脱敏，不得带 `raw_text`、完整 `truth`、`original_file_path`

### 3. RAG 索引闭环

- 导入成功后会调用 scenario 级索引，真正写入 `raw_text` 的 scenario chunk
- 导入成功后会调用 NPC 级索引，写入 npc chunk
- RAG metadata 至少带有 `scenario_id`、`source_type`、`index`、`visibility`
- 如本轮已细化 visibility，应能说明默认值：
  - scenario chunk 默认为 `host` 或 `internal`
  - npc chunk 按 NPC 可见性派生
  - rule chunk 允许 `global`
- 当前房间能检索本剧本所需的 scenario / npc chunk
- 不同 scenario 房间不能互相检索到彼此世界书 chunk

### 4. Player-facing AI / RAG 防剧透

- player-facing RAG 不能直接返回 `raw_text` 原文
- player-facing RAG 不能直接返回 `knowledge_graph.truth` 原文
- hidden NPC、hidden clue、未解锁 truth 仍需经过 visibility / unlock / guard 过滤
- AI 输出仍经过 SpoilerGuard、Projection 或等价拦截层
- 玩家即使发现全部线索，也不能直接把 `truth` 当作完整可读对象拿到

### 5. 质量报告进入业务决策

- `quality_report` 不再只是展示字段
- `blocked` 默认不出现在 Host 普通可用剧本列表
- `blocked` 默认不能普通 `create-room`
- `mock fallback` 不得被判为 `readiness_status=ready`
- `spoiler index` 缺失不得被判为 `readiness_status=ready`
- `highRisk` 开房必须有后端显式确认，例如 `confirm_quality_risk=true`
- 仅前端弹窗提醒，不算完成 quality gate

### 6. 防剧透索引与 unlock 闭环

- `truth.summary`、hidden clue、hidden NPC 关键敏感项能进入 `spoiler_sensitive_items`
- 同一场景重复 rebuild 不产生重复 sensitive item
- 玩家发现线索后，公开摘要更新的是“可投影信息”，不是直接把 worldbook 真相原文公开
- 同 scenario 多个 room 不会共享 room-scoped 的已发现事实或 reveal 结果

### 7. Admin 调试、override 与重建审计

- `original_file_path` 不进入 Host / Player 响应
- Admin 场景列表、调试接口默认也应优先返回脱敏字段，如 `source_filename`、`source_sha256`
- `highRisk` override 只能由 Admin 执行
- override 必须有审计记录，至少说明 `scenario_id`、调整前后等级、操作者、时间、原因
- RAG reindex / spoiler rebuild 可重复执行且幂等
- 若实现了版本追踪，应能说明 `knowledge_graph_version / quality_report_version / rag_index_version / spoiler_index_version` 或等价字段的写入位置

### 8. 地图生成字段对齐

- 地图生成优先读取 `knowledge_graph.scenes` 或文档约定的统一字段
- hidden clue 正文、hidden NPC 真名、完整 truth 不直接进入地图公开节点
- 地图草稿生成后，Host 可以继续确认；未确认前不进入玩家公开视图
- 如果本轮宣称修复了地图字段断点，必须给出地图专项测试或手动链路证明

### 9. 端到端主链路

至少应手动或自动证明以下链路：

1. Admin 导入一个包含公开内容和隐藏真相的 PDF
2. 系统生成 `knowledge_graph`、`quality_report`
3. 系统生成 scenario chunk、npc chunk、防剧透索引
4. Host 在可用剧本列表中只能看到符合质量门禁的剧本
5. Host 用该剧本创建房间
6. 房间内 AI / RAG 能拿到所需世界书上下文
7. 玩家提问或探索时，不会直接看到 `raw_text` / `truth` 原文
8. Host 触发 reveal 或玩家发现线索后，玩家侧只看到授权后的公开摘要
9. 若执行 reindex / rebuild，结果仍稳定且无重复数据

## 生产安全加签条件

以下条件未关闭前，不应给 `生产安全完成`：

- player-facing AI / RAG 仍存在 `raw_text`、`truth` 或 hidden 内容泄露路径
- `readiness_status` / `index_status` 仍只是文档概念，没有稳定落在代码口径里
- `highRisk` 仍只靠前端确认，没有后端硬校验
- `original_file_path` 仍可能通过 Admin 调试链路扩散到前端
- reindex / rebuild 仍没有完整版本追踪、操作审计和重复执行证明
- 地图生成虽然可用，但 hidden clue、hidden NPC、truth 过滤仍不稳定
- 同 scenario 多 room 的 room-scoped 发现事实、unlock 状态仍可能串房

## 回执最小模板

1. 本轮覆盖了哪些 WB Batch
2. 改了哪些文件
3. 跑了哪些测试，结果是什么
4. `structured`、`readiness_status`、`index_status` 现在各自代表什么
5. 导入后是否真正调用了 scenario chunk 索引与 npc chunk 索引
6. player-facing AI / RAG 现在如何拦截 `raw_text` / `truth`
7. `blocked` 和 `highRisk` 剧本现在如何进入或不能进入开房流程
8. `original_file_path` 现在在哪些响应里被脱敏
9. reindex / spoiler rebuild 是否已证明幂等
10. 哪些项已达到 `本轮工程验收通过`，哪些仍未达到 `生产安全完成`
