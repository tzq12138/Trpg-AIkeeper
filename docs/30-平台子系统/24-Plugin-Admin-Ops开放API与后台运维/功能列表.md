# Plugin / Admin / Ops 开放 API 与后台运维功能列表 V2.1

## 当前阶段说明

- 本文件当前阶段为 `P0 控制面基线 + Admin 权限、生产安全、日志脱敏、MCP/Agent 治理与 Open API 设计风险识别版`。
- 当前仓库已存在：Admin API、`AdminDashboard.tsx`、RAG 管理接口、AI Gateway、KP MCP Server、`/api/health`、`dev.py`、`docker-compose.yml`、基础日志配置、测试库隔离测试。
- 当前仓库未实现：第三方 API key、插件注册中心、Webhook 订阅、多租户、插件市场、正式 backup/restore、生产监控告警平台。
- 本轮目标是先把控制面和运维安全口径收紧，不代表现在可以开放第三方 API、创建 API key、注册插件、开放 Webhook，或允许插件/MCP/Agent 直接写状态。

## 模块定位

`24-Plugin / Admin / Ops` 是 AI-Keeper 的平台控制面与运维治理层，负责四件事：

1. 管住后台权限与高风险操作；
2. 管住生产配置、健康检查、日志脱敏和数据库运维；
3. 管住 AI、RAG、MCP、Agent tools 的治理入口；
4. 为未来 Open API / Plugin 预留设计，但本轮不开放第三方运行时。

它不是跑团业务真相层，不承载 AI 裁决、规则结算、世界状态写入，也不能绕过 `User / Safety / State / Transaction / Projection / Journal`。

## MCP 与 Agent 治理规则

### MCP

- `production` 下 `MCP_BIND_HOST` 不允许为 `0.0.0.0`，除非显式 `MCP_PUBLIC_EXPOSE=true` 且启用服务间 token。
- MCP 请求必须校验 service-to-service token。
- MCP token 永不进入前端。
- MCP tool call 必须进入审计。
- MCP 不允许直接连接主库写状态。

### Agent tools

`AgentToolPermission` 固定四档：

- `read_only`
- `suggest_only`
- `controlled_write`
- `disabled`

`engine_save_clue` 规则：

- 第一轮默认 `disabled` 或 `suggest_only`。
- 禁止 direct `INSERT`。
- 若启用，必须经过 `Clue / State / Journal` 服务链。
- 必须写入 `AgentToolCallAudit`。

## Open API scope 禁止清单

| scope | 允许方向 | 禁止方向 |
| --- | --- | --- |
| `read:public` | 公开模块、公开招募、公开摘要 | 不读 `raw_text`、`truth`、private events |
| `read:room` | 授权房间的 safe DTO | 不读 `owner_token`、`player_token`、hidden truth |
| `write:intent` | 代表玩家提交意图 | 不得绕过 Player Intent，不得无授权，不得无 rate limit |
| `write:message` | 授权消息发送 | 不得伪造系统消息，不得越 audience |
| `write:clue` | 默认禁用 | 不得 direct write，必须经 Clue/State/Journal |
| `admin:read` | 仅内部后台 | 不给第三方 API key |
| `admin:write` | 仅内部后台 | 不给第三方 API key |
| `ai:invoke` | 内部 AI 调用 | 不开放 raw provider 能力给第三方 |
| `rag:read` | 授权检索 | 不读未授权房间内容 |
| `rag:write` | admin/owner 重建索引 | 不开放给 public/client key |

## Internal `/docs` 与 external OpenAPI 的边界

### Internal `/docs`

- 是当前 FastAPI 自动生成的开发文档。
- `development` 可用。
- `production` 默认关闭或仅 admin/internal 可访问。
- 不等于对外 API 契约。

### external OpenAPI

- 未来只能由 allowlist routes + scope schema 生成。
- 不包含 Admin API。
- 不包含 raw scenario / raw events / truth。
- 不包含 `owner_token` / `player_token`。
- 不包含内部 MCP / AI provider 调用。

## 与其他模块的衔接

- 对 `21-Safety`：secret、CORS、日志脱敏、health 分级、MCP 暴露策略必须对齐。
- 对 `12-AI-Keeper`：24 管 provider/MCP/Agent 的治理，不改变 AI 裁决边界。
- 对 `13-State` / `14-Transaction`：Plugin / MCP / Agent 不得直写状态。
- 对 `15-Projection`：未来 webhook/plugin 推送必须先过可见性过滤。
- 对 `18-Asset`：上传/删除/路径脱敏/force delete 必须有 Admin audit。
- 对 `23-Community`：社区的 moderation / audit / backend ops 依赖 24 的最小治理面。

## P0 主链路验收

1. Admin 登录后可访问 overview、rooms、accounts、assets、AI、RAG。
2. 未登录访问 Admin API 返回 401，Player 返回 403。
3. public health 不返回 secret、DSN、provider key、完整 provider error。
4. admin health 仅 Admin 可见，返回脱敏后的组件细节。
5. 角色修改、房间状态修改、素材删除、AI 配置修改、RAG reindex、spoiler rebuild 至少能写审计。
6. 普通日志、AI logs、export 均不包含 token、API key、raw prompt、raw response。
7. `engine_save_clue` 默认不能 direct write。
8. production 模式下不允许无鉴权 MCP 公网暴露。
9. 当前仍不创建真实 API key，不开放 plugin runtime，不开放 webhook。
