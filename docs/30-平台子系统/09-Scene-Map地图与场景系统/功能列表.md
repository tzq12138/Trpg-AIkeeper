# Scene / Map 地图与场景系统功能列表 V2.1

## 当前阶段说明

本模块当前处于 `P0 主链路 + 地图投影安全风险识别版`。

第一轮目标不是做完整 VTT，而是先把 `地图模板 -> 房间地图状态 -> 玩家安全投影 -> 移动入口 -> Host 舞台监管 -> 场景同步` 这条链路钉牢，尤其要避免地图读接口越权、剧透和绕过主事务链路。

## 模块定位

Scene / Map 模块负责把剧本中的场景结构转成可运行的空间投影，承接：

- 剧本地图模板生成、编辑、确认
- 房间运行态地图初始化
- 玩家地图安全投影
- 玩家移动入口
- Host 全图监管、显隐、急救式强制移动
- 与当前场景状态的衔接

本模块不负责：

- AI 裁决
- 规则结算
- 角色数值改写
- 线索正文归属
- NPC 行为状态机
- 世界真相写入

这些能力分别交给 `AI-Keeper`、`Rule`、`State`、`Clue`、`NPC/Faction`、`Transaction`、`Projection` 模块处理。

## 数据分层

| 层级 | 数据对象 | 归属模块 | 说明 |
| --- | --- | --- | --- |
| L0 | `knowledge_graph.scenes` | WorldBook / Module | 剧本语义源，记录场景、出口、摘要，是地图生成的首选输入 |
| L1 | `scenario_maps` draft/confirmed | Scene / Map / Admin | 剧本级地图模板，不带房间运行态 |
| L2 | `room_map_state` | State / Projection | 房间级地图运行态，保存 explored、hidden、mapVersion 等 |
| L3 | `character_map_positions` | State | 角色当前地图位置，只能由受控链路写入 |
| L4 | `room_scene_state` | StateService | 当前场景、已访问场景、公开事实，不等于地图位置表 |
| L5 | `PlayerMapView` | Projection | 面向玩家的安全投影，只能返回可见和可公开字段 |
| L6 | `HostMapView` | Host Client / Projection | 面向 Host 的监管视图，可见完整节点结构和运行态 |
| L7 | 地图 WS 事件 | Projection / Journal | 地图变化的事件摘要，必须带版本，不能承载完整剧透内容 |
| L8 | 地图生成草稿 | AI-Keeper / Admin | AI 生成的中间结果，只能落到 draft，不直接进入房间真相 |

## 节点 DTO 分层

| DTO | 用途 | 允许字段 | 禁止字段 |
| --- | --- | --- | --- |
| `MapNodePublicDTO` | 最基础公开节点摘要 | `nodeId`、`label`、`position`、`isStart` | NPC、线索、隐藏描述、内部注释 |
| `MapNodePlayerDTO` | 玩家地图节点 | `nodeId`、`label`、`position`、`explored`、`isCurrent`、`isAdjacent`、`safeHint`、`movementState` | 原始 `npcsPresent`、原始 `cluesAvailable`、真实隐藏描述、Host 注释 |
| `MapNodeHostDTO` | Host 全图节点 | 模板字段 + 当前显隐/探索/角色占位信息 | AI 内部草稿、系统私有调试字段 |
| `MapNodeInternalDTO` | 服务端内部处理 | 可含原始 clue/NPC 引用、场景源字段、调试字段 | 不得直接下发到前端 |

## 状态语义

| 状态 | 取值 | 含义 |
| --- | --- | --- |
| `template_status` | `draft` / `confirmed` | 剧本模板是否可用于开局 |
| `node_visibility` | `normal` / `hidden` | 节点是否允许出现在玩家投影中 |
| `player_node_state` | `current` / `explored` / `adjacent` / `unknown` | 玩家对单个节点的可见层级 |
| `movement_state` | `allowed` / `blocked` / `locked` / `requires_check` | 当前是否可发起移动，以及失败原因类型 |

补充约束：

- `hidden` 只影响地图可见性，不等于线索已删除、NPC 不存在、场景真相释放。
- `adjacent` 只表示“当前公开可尝试到达”，不自动等于已切场景。
- `requires_check` 表示玩家可以提交 intent，但最终是否通过由 Rule/Engine 判定。

## 初始位置责任

玩家初始地图位置必须由显式业务链路负责，优先级建议如下：

1. 房间开局时按 confirmed map 的 start node 初始化
2. 玩家加入并绑定角色时，若规则要求，可显式补齐当前位置
3. Host 急救恢复或 Engine 补偿链路可写入当前位置
4. `GET /api/map/{room_id}` 只读，不负责自动写位置

当角色没有当前位置时，玩家地图接口应返回明确空态，例如 `no_current_position`，而不是在读取时偷偷落库。

## 移动与场景切换边界

- 玩家移动成功，首先表示地图位置变化成立。
- 是否推动 `current_scene` 变化，要交给 `StateService` 或事务链路判断。
- 进入某个 node 不自动等于当前场景立刻切换。
- Scene/Map 负责提供“候选空间位置”，State 负责定义“当前叙事场景”。

## Host 显隐与强制移动语义

- `reveal/hide` 只改变节点在玩家地图中的可见性，不直接公开 NPC、线索正文、真相字段。
- `force move` 是急救式舞台调度能力，不是常规玩家移动替代品。
- `force move` 必须记录操作人、目标角色、起点、终点、原因、时间、版本号。
- `force move` 默认要求 `reason`，并建议前端增加显式确认。

| 房间开局初始化地图 | 已接入 Room start | 是 | Room、State | active 房间可得到稳定 `room_map_state` |

| 玩家移动经 Engine | 已通过 intent 进入裁决链 | 是 | Rule、Transaction、AI-Keeper | 非相邻、隐藏、锁定节点被拒；成功移动必须经 Engine |

## 不属于本模块

| 内容 | 交给哪个模块 | 原因 |
| --- | --- | --- |
| 角色 HP、SAN、背包数值 | Character、Rule、State | 地图只表达空间与可见性 |
| 线索发现与分享正文 | Clue | 地图只给位置入口和安全摘要 |
| NPC 行为、敌意、阵营 | NPC/Faction | 地图节点不承载 NPC 状态机 |
| AI 剧情裁决 | AI-Keeper、Transaction | Map 不能直接写运行真相 |
| 回放 UI 编排 | Journal | Map 只产生事件，不负责回放界面 |

## 当前最高风险

| 风险 | 影响 | 优先级 |
| --- | --- | --- |
| `GET /api/map/{room_id}` 在异常 token 分支退化为匿名读取 | 玩家可能绕过迷雾直接拿到完整节点列表 | P0 |
| 玩家地图 GET 和 `build_player_map_view` 仍会自动写位置/探索状态 | 刷新页面会改变真实状态，破坏事务边界 | P0 |
| explored 节点直接返回原始 `npcsPresent`、`cluesAvailable` | 未发现线索和隐藏 NPC 可被地图 JSON 剧透 | P0 |
| `hiddenCount` 统计逻辑不严格 | 前端收到的隐藏计数不可信 | P1 |
| 地图生成源仍偏向 `scenario_assets.scenes` | 新导入剧本可能生成不到场景图 | P1 |
| Host reveal/force move 缺少归属校验与审计字段 | 误操作难追溯，且可能作用到非法目标 | P1 |
| 地图版本未完全纳入统一版本屏障 | 断线重连、补丁重放可能乱序 | P1 |

## MVP 验收主链路

1. Admin 导入带 `knowledge_graph.scenes` 的剧本并生成 draft map。
2. Admin 确认地图为 confirmed。
3. Host 创建房间并选择该剧本。
4. Player 加入房间并绑定角色。
5. Host 开局，系统初始化 `room_map_state`。
6. Player 打开地图，只看到当前节点、已探索节点和安全相邻节点。
7. Player 提交一次合法移动，请求进入 Engine intent。
8. 裁决成功后，系统更新位置、探索状态，并发布带 `mapVersion` 的事件。
9. Host 收到全图变化，Player 收到安全投影刷新。
10. Journal 或审计日志中可查到移动、显隐、强制移动等关键记录。
