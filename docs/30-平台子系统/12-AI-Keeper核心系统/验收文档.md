# AI-Keeper 核心系统验收文档

## 文档定位

本文档用于在收到工程师的 `回执-YYYY-MM-DD.md`、代码改动说明、测试结果后，判断 `12-AI-Keeper核心系统` 本轮工作是否真正完成。

它只负责验收，不替代：

- `功能列表.md`
- `PRD.md`
- `DeepSeek计划.md`

默认分两层结论：

- `本轮工程验收通过`：表示本轮承诺的 P0 主链路、AI 安全建议层边界、RAG 最终过滤、输出反剧透、Agent 工具治理和关键测试已闭环。
- `生产安全完成`：表示除本轮范围外，AI-Keeper 的长期高风险缺口也已基本关闭。

除非证据非常完整，否则默认只给 `本轮工程验收通过`，不直接给 `生产安全完成`。

## 验收输入

验收前至少应拿到以下材料：

- 本模块四份基线文档：`功能列表.md`、`PRD.md`、`DeepSeek计划.md`、`验收文档.md`
- 工程师回执：`回执-YYYY-MM-DD.md`
- 本轮改动文件清单，至少说明改了哪些 router、gateway、contracts、rag、spoiler_guard、agent、admin、tests 文件
- 实际测试命令与测试结果
- 如涉及前端 shared types 或 AI 状态入口，附 `npm run build` 结果和手动链路验证结果

## 结论等级

| 结论 | 含义 |
| --- | --- |
| `本轮工程验收通过` | AI-Keeper 本轮 P0 / P1 目标已实现，关键鉴权、上下文过滤、执行边界、日志脱敏和测试结果对齐 |
| `本轮工程验收有缺口` | 主链路基本可用，但仍缺关键证据、关键测试或关键安全边界闭环 |
| `不通过` | 出现越权触发、RAG 泄露、AI 直写状态、private/public narrative 混用、日志泄密、测试未过或回执与实际不符 |
| `生产安全完成` | 只有在长期遗留项也基本关闭、raw debug 与 admin audit 分层稳定、回归覆盖充分后才可给出 |

## 一票否决项

出现任一情况，本轮不能判通过：

- 未登录或普通 Player 仍可调用 `/ai-turn`
- `/ai-status` 对 Player 泄露 provider key、endpoint、prompt、模型配置细节
- Gateway 坏 JSON 或 schema_fail 仍会直写状态
- AI 返回 `roll`、`targetValue`、`successLevel` 能覆盖 RuleExecutor 权威结果
- AI mutation 可直接写 HP / SAN / Luck / clue / 地图位置 / 世界真相
- SQL / JSON Patch 形式的 mutation 未被直接拒绝
- player-facing RAG 仍可读到 truth / ending / 未发现 hidden clue / hidden NPC 真名
- `/rag/search` 结果未经 final filter 直接进入 player-facing AI prompt
- private narrative 缺少 `characterId` 仍会下发
- private narrative 被合并进 public narrative
- public narrative 未经过 SpoilerGuard 或等价安全审查
- `ai_call_logs` 泄露 raw prompt、raw response、API key、token、完整 hidden truth
- `spoiler_audits` 或 Agent 工具审计可被 Player 访问
- `engine_save_clue` 等 Agent write tool 仍直接 `INSERT clues`
- legacy AIKP 与 AiGateway 双轨扩张成两套新 prompt / schema
- 关键测试命令未提供，或明显未通过

如果回执把文档里明确属于后续项的缺口写成“已完成”，验收时应直接降级处理。

## 本轮工程验收清单

### 1. AI 调度入口鉴权

- `/ai-turn` 仅允许 Owner / Admin / Host 触发
- 普通 Player 不能触发全房间 queued action 结算
- 未登录、错误房间身份、无效 token 返回 401 / 403

### 2. `/ai-status` 分层返回

- Player 版只返回低敏状态：
  - `enabled`
  - `mock`
  - `fallback`
  - `degraded`
- Player 版不返回：
  - provider key
  - endpoint
  - prompt
  - 模型配置细节
- Owner / Admin 版可查看更完整诊断信息

### 3. Gateway 状态模型与 schemaVersion

以下状态至少应有明确落地：

- `success`
- `schema_fail`
- `provider_error`
- `timeout`
- `fallback_used`
- `local_fallback`
- `rejected_by_safety`
- `empty_response`

并验证：

- 所有 Gateway task 都有 `schemaVersion`
- `TASK_SCHEMAS` 与 public method 不一致时，测试失败
- 坏 JSON 不会穿透到权威执行层

### 4. AICallLogDTO 与 raw debug log 分层

普通 `AICallLogDTO` 至少记录：

- `task`
- `provider`
- `status`
- `durationMs`
- `fallbackChain`
- `schemaVersion`
- `inputSummary`
- `outputSummary`
- `errorClass`

同时必须满足：

- 不含 API key
- 不含 `owner_token` / `player_token`
- 不含完整 raw prompt / raw response
- 不含完整 hidden truth

如存在 raw debug log，必须满足：

- `admin_only`
- `never_export`
- 单独权限校验
- 不回灌到普通 `ai_call_logs.responseSummary`

### 5. 机制建议与权威规则边界

- AI 只给 `skill / difficulty / reason` 之类建议
- RuleExecutor 生成 `roll`、`targetValue`、`successLevel`
- AI 返回 `roll=1` 或 `success=critical` 也不能覆盖权威结果
- 非法 mechanic 类型不能进入 RuleExecutor 敏感执行路径

### 6. AI mutation proposal 边界

以下 mutation 不得由 AI 直接落库：

- HP / SAN / Luck
- clue release
- map move
- current scene
- NPC reveal
- truth / worldbook 修改

必须验证：

- AI mutation 进入统一校验点
- 被拒绝的 mutation 只作为审计记录，不写状态
- SQL / JSON Patch 直接拒绝

### 7. RAG final context filter

这条是 `P0 安全边界`，不是体验优化。

进入 player-facing AI prompt 前，至少按以下维度裁剪：

- `viewer_role`
- `room_id`
- `scenario_id`
- `character_id`
- `source_type`
- `visibility`
- `unlock_state`

重点验证：

- `source_type=scenario` 的 raw text 默认 internal / host
- `source_type=clue` 只允许 owned clue 或 shared `publicVersion`
- `source_type=event` 只允许 player-visible Journal view
- `source_type=npc` 过滤 hidden / truth / ai_only 字段
- `/rag/search` 的检索权限不等于“可进入 player-facing AI prompt 的权限”

### 8. Admin context preview

Admin context preview 至少应显示：

- `included / excluded`
- `sourceType`
- `visibility`
- `reason`
- `unlockState`

验收时应能解释“为什么这条上下文能给 AI 看”。

### 9. public / private narrative 边界

- `publicText` 只进 `party/public projection`
- `privateTexts` 必须按 `characterId` 分发
- 缺 `characterId` 的 private narrative 不下发
- private narrative 不合并进 public narrative
- `keeperNotes` 默认为 `host/admin/internal`

并确认：

- `keeperNotes` 不进入 Player projection
- `keeperNotes` 不进入 Player Journal
- `keeperNotes` 不进入 public export

### 10. 输出侧反剧透

- public narrative、party event、player-visible projection 全部经过 SpoilerGuard 或等价安全审查
- retry prompt 不包含完整敏感真相原文
- fallback 文本不泄露敏感项
- `spoiler_audits` 记录：
  - `actionId`
  - `violations`
  - `retryCount`
  - `finalStatus`
- Player 不能访问 `spoiler_audits`

### 11. Agent 工具治理

先确认 Agent 当前部署条件：

- 如果 Agent 默认关闭，且生产中不可被任意入口触发，则完整治理可以保留为 P1
- 如果 Agent 当前可被触发，`engine_save_clue` 这类直写问题必须按 P0 风险处理

必须验证：

- Agent 有 feature flag
- 默认关闭
- `engine_save_clue` 不再直接 `INSERT clues`
- Agent `recent events` 复用 Journal / Timeline 可见性 helper
- 所有工具执行写 `AgentToolCallAuditDTO`
- Agent write tool 成功后能追到 Clue / State / Journal 事件
- Agent 不能直接写 HP / SAN / 地图位置 / 世界真相

### 12. legacy AIKP 与 AiGateway 双轨收口

必须明确：

- 主裁决链路以 `AiGateway + ResolutionPipeline` 为准
- legacy AIKP 只保留兼容层或结构化剧本辅助用途
- 新功能不再扩展第二套独立 prompt / schema
- 如同一任务同时支持两者，回执中说明优先级与 fallback 顺序

### 13. 编码与文案可读性

至少确认：

- prompt 中文无乱码
- fallback 文案无乱码
- Admin / Player 可见 AI 文案无乱码

### 14. 端到端主链路

至少应手动或自动证明以下链路：

1. Host 创建房间并开启可用 AI 配置。
2. Player 加入、ready、提交自然语言行动。
3. `MechanicCompiler` 输出建议。
4. `RuleExecutor` 产出权威结果。
5. Gateway 可用时生成增强叙事，不可用时走 fallback。
6. public narrative 命中敏感项时被 SpoilerGuard 拦截并降级。
7. AI mutation 只作为 proposal，经 Rule / State / Clue / Map 对应模块确认后才写入。
8. Projection 分发 Host / Player 视角。
9. Journal / Admin logs 能查到 action、AI task、provider、status、fallback chain。

## 生产安全加签条件

以下条件未关闭前，不应给 `生产安全完成`：

- final context filter 仍依赖手工规则，尚未形成稳定的可见性治理基线
- raw debug log 与普通 `ai_call_logs` 的长期分层策略仍未完全定型
- Agent 默认关闭，但未来启用后的治理与回归覆盖仍不足
- legacy AIKP 与 Gateway 虽已收口，但历史兼容路径仍未完全退场
- 多 provider fallback 的长期观测、成本统计与误报排障能力仍不充分
- 前端管理面、批量回放、长团记忆摘要等长期能力仍未成型
