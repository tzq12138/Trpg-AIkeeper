## 三、P0 修复详情

### 1. public events 白名单化

| 修复前 | 修复后 |
|--------|--------|
| `audience IN ('party', 'system')` — 所有 system 事件默认公开 | `audience = 'party'` + system_safe 白名单（`event_type = ANY(...)`） |
| restore/debug/internal 事件可出现在 public 流 | 仅 `s2c_turn_resolved`、`s2c_checkpoint_created` 的白名单通过 |

### 2. restore 硬化

| 修复前 | 修复后 |
|--------|--------|
| 仅需 `confirm: true` | 需 `confirm=true` + `reason`（必填） |
| audit payload 仅 `checkpointId` + `restoredBy`(token 截断) | `checkpointId` + `actorAccountId` + `reason` + `restoreMode: full` + `createdAt` |
| audience=`system`（可被 Player 看到） | audience=`host`（仅 Host/Admin 可见） |

### 3. `/campaign` 鉴权

| 修复前 | 修复后 |
|--------|--------|
| 无鉴权，任何人可访问 | `scope=public` → player token 验证；`scope=full` → owner/admin 验证 |

### 4. checkpoint snapshot 补表

| 修复前 | 修复后 |
|--------|--------|
| 未覆盖 `clue_shares` | ✅ 已补（有 room_id 列，直接 WHERE room_id） |
| 未覆盖 `encounter_participants` | ✅ 已补（通过 JOIN encounters ON room_id） |
| snapshot/restore 未处理间接关系表 | `_build_snapshot` + `_apply_snapshot` 均添加 JOIN 查询 |
