# User 用户与权限系统验收文档

## 文档定位

本文件用于在收到工程师的 `回执-YYYY-MM-DD.md` 后，判断 `02-User` 本轮工作是否真正完成。

它只定义验收方法，不替代 `功能列表.md`、`PRD.md`、`DeepSeek计划.md`。

默认分两层结论：

- `本轮工程验收通过`：表示账号、owner、player 三层身份边界和本轮承诺的权限主链路已完成。
- `生产安全完成`：表示 token 生命周期、WS 鉴权、bootstrap、RAG 结果裁剪等高风险项也关闭。

## 验收输入

- 本模块三份基线文档
- 工程师回执：`回执-YYYY-MM-DD.md`
- 修改文件列表
- 测试命令与结果
- 如涉及前端登录页/Admin/身份切换，附 `npm run build` 结果

## 结论等级

| 结论 | 含义 |
|---|---|
| `本轮工程验收通过` | 账号、owner、player 三层边界已对上，主权限链路可回归 |
| `本轮工程验收有缺口` | 主链路大体可用，但仍缺关键证据、关键测试或关键安全项 |
| `不通过` | 出现越权、鉴权混用、DTO 泄露、恢复他人身份或关键测试未过 |
| `生产安全完成` | 仅在 JWT/bootstrap/WS/token 生命周期/RAG 裁剪等高风险项关闭后给出 |

## 一票否决项

- `account_token`、`owner_token`、`player_token` 被混用
- player 账号可以创建房间或进入后台
- account token 可以直接提交玩家 intent
- 登录用户可以恢复他人角色 session
- 公开 DTO 泄露 `password_hash`、`owner_token`、`player_token`
- 错误 token 或错误 room 的 WS 连接仍可建立

## 本轮工程验收清单

### 1. 账号主链路

- 注册成功返回账号摘要和 `account_token`
- 登录成功返回账号摘要和 `account_token`
- `/api/auth/me` 正常返回当前账号信息
- `admin/host/player` 三类平台角色边界清晰

### 2. 管理与角色提升

- 只有 admin 可访问 `/api/admin/*`
- admin 可以修改账号 `role/display_name`
- player 不能伪装成 host/admin

### 3. owner 权限链路

- 房间管理同时支持 owner token、owner account、admin
- 非房间 owner 的 host 账号不能管理别人的房间
- owner token 不应出现在公开 DTO、公开导出、可分享链接

### 4. player 身份链路

- 玩家接口通过 `player_token -> character_id` 反查身份
- 前端传入 `characterId` 不能成为授权依据
- 复制角色必须满足同账号或持有源角色 token
- action / clue / objective / archive 不能查到他人的私密资源

### 5. WS 与重连

- Host WS：错误 owner token 或错误账号被拒绝
- Player WS：错误 token、错误 room 被拒绝
- 若回执声称完成了 WS 升级，还必须说明 query token 是否已被 `ws_ticket` 替代

### 6. 恢复链路

- 登录账号只能恢复自己名下角色
- 回执若声称“游客恢复”已做，需要明确恢复凭证模型和风险边界

### 7. RAG 权限入口

- admin 可全局读写
- owner 可房间级写
- room 成员可房间级读
- 若回执声称“RAG 已完全安全”，必须额外提供玩家结果 `visibility/audience/discovered_state` 裁剪证据


```powershell
cd src/client
npm run build
```

## 生产安全加签条件

以下条件未关闭前，不应给 `生产安全完成`：

- `JWT_SECRET` 默认值在正式环境仍可启动
- 首账号 admin bootstrap 仍可裸暴露
- Host/Player WS 仍长期依赖 query token
- owner/player token 仍无 rotate/revoke/hash
- account token 仍无 `token_version` / `disabled_at` / 强制失效能力
- Player-facing RAG 仍只做成员级鉴权，不做结果裁剪
