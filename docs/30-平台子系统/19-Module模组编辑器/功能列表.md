# Module 模组编辑器功能列表 V2.1

## 当前阶段说明

- 本文档当前阶段为：`P0 主链路 + 模组导入、发布准入与开房实例化风险识别版`。
- 当前仓库已经有可落地的真实锚点：`router_scenarios.py`、`router_admin.py`、`quality.py`、`db_adapter.py`、`map_generator.py`、`router_rooms.py`、`router_player.py`、`rule_executor.py`、`AdminDashboard.tsx`、`HostCreate.tsx`。
- 本轮重点锁定：PDF 导入草稿、KG 结构化、质量报告、导入状态与发布状态分离、Host 可用模组列表、地图确认、角色模板接口、触发器 schema、素材绑定、Room 实例化隔离。
- 本轮不是完整可视化剧情树编辑器，不做社区市场、不做付费授权、不做多作者协作、不做完整版本合并。
- 文档中识别出的风险，不代表代码中已经关闭；后续必须通过工程批次和测试验收确认。

## 模块定位

Module 是“可运行跑团素材包”的治理层，负责把已经导入、结构化、校验过的内容组织成可复用、可发布、可开房、可实例化的模组模板。

它不负责：

- WorldBook 的自动抽取和文本理解；
- Asset 的文件安全与存储治理；
- Rule / Transaction 的裁决执行；
- Room / State 的运行态事实写入；
- Projection 的私密投影；
- 社区分发、付费、运营市场。

当前代码还不是完整可视化编辑器，更接近“导入型模组雏形”：Admin 导入 PDF，系统结构化为 `knowledge_graph`，生成 `quality_report`，上传素材，生成并确认地图，Host/Admin 选择结构化 scenario 开房。Module V2.1 的目标，是把这条链路写成一套明确的工程边界。

## 数据分层

| 层级 | 数据对象 | 用途 | 禁止混用 |
| --- | --- | --- | --- |
| L0 `SourceDocument` | PDF 原件、`source_filename`、`source_sha256` | 导入来源追踪 | 文件安全归 Asset |
| L1 `ImportJob / ImportStatus` | `pending/importing/requires_ocr/structured/failed` | 导入与结构化过程状态 | 不等于发布状态 |
| L2 `ModuleDraft` | `raw_text`、`knowledge_graph`、`quality_report` | 可编辑模组草稿 | 不直接给 Player |
| L3 `KnowledgeGraph` | `scenes/npcs/clues/truth/endings` | 故事结构语义 | Player 不可见完整 KG |
| L4 `SemanticScenarioAsset` | `scenarios.scenario_assets` JSON | 触发器、机制、结构化语义资产 | 不等于上传文件表 |
| L5 `AssetBinding` | `assetId/refType/refId/visibility` | 文件绑定到场景、线索、NPC、地图节点 | 文件安全归 Asset |
| L6 `ModuleMapDraft` | `scenario_maps` draft/confirmed | 模组地图模板 | 不等于 `room_map_state` |
| L7 `ModuleCharacterTemplate` | `character_templates` | 预设调查员模板 | 玩家加入后复制，不反写模板 |
| L8 `ModuleTrigger` | `triggerId/scope/condition/mechanics/visibility` | 触发器定义 | 不执行裁决 |
| L9 `ModuleReadiness` | `ready/warning/highRisk/blocked` | 发布准入结果 | 不只是 UI 提示 |
| L10 `PublishState` | `draft/review/ready/published/archived` | 模组生命周期 | 不等于 `importStatus` |
| L11 `ModuleVersion` | 发布快照 | 未来开房绑定不可变版本 | 不破坏旧房间 |
| L12 `RoomInstantiation` | `roomId/moduleVersionId/scenarioId` | 运行态实例 | 不反写模板 |

## 状态口径与发布准入

### `importStatus`

只描述导入和结构化过程：

- `pending`
- `importing`
- `requires_ocr`
- `structured`
- `failed`

### `publishStatus`

只描述模组生命周期：

- `draft`
- `review`
- `ready`
- `published`
- `archived`

补充约束：

- `structured` 不等于可发布；
- `ready` 不等于已发布；
- `published` 不等于永久安全；
- `archived` 不等于删除原始数据。

### `ModuleReadiness` 准入矩阵

| qualityLevel | 默认能否发布 | 默认能否出现在 Host 可用列表 | 处理要求 |
| --- | --- | --- | --- |
| `ready` | 可以 | 可以 | 正常发布 |
| `warning` | 可以 | 可以 | 展示 warning，不阻断 |
| `highRisk` | 默认不普通发布 | 默认不普通可见 | 仅 Admin 可 override，且必须 `reason + qualitySnapshot` |
| `blocked` | 不可发布 | 不可见 | 后端硬拒绝，必须修复 |

当前代码现状要点：

- `/api/scenarios/available` 已排除 blocked；
- `/api/scenarios/{scenario_id}/create-room` 已对 `highRisk` 要求 `confirm_quality_risk: true`；
- `/api/admin/scenarios` 仍是原始 scenario 列表，尚未按 Module DTO 收口。

## 关键契约

### 1. `GET /api/scenarios/{scenario_id}/templates`

访问口径：

- 已登录 Player 可在加入房间或角色构建流程读取该 scenario 的公开模板；
- Host/Admin 可读可用模组的模板；
- 未登录用户拒绝；
- 不返回隐藏背景、真相、Host-only 备注。

最小返回字段：

- `templateId`
- `displayName`
- `occupation`
- `publicSummary`
- `suggestedSkills`
- `avatarAssetUrl`
- `selectable`

禁止返回：

- `secretBackstory`
- `truthLink`
- `hiddenClueIds`
- `adminNotes`
- `raw xlsx_data` 私密字段

### 2. 地图数据源统一策略

当前代码已经采用：

1. 优先读取 `knowledge_graph.scenes`
2. 兼容回退 `scenario_assets.scenes`

本模块文档固定这套优先级，后续回执必须说明：

- 是否仍支持旧数据兼容；
- 是否存在只在旧 `scenario_assets.scenes` 中有图而 KG 中没有的遗留场景。

### 3. 触发器 schema 最低要求

```json
{
  "triggerId": "trg_xxx",
  "scope": "global|scene|item|clue",
  "condition": {
    "type": "action_match|item_used|skill_check|state_flag",
    "field": "$action",
    "operator": "contains|equals|in",
    "value": "search"
  },
  "mechanics": [
    {
      "type": "skill_check|clue_reveal|state_change|map_reveal",
      "params": {}
    }
  ],
  "visibility": "host_only|public_after_trigger",
  "validationStatus": "valid|warning|invalid"
}
```

补充约束：

- 未知 `mechanics.type` 默认为 `invalid` 或 `ignored_with_audit`；
- 坏触发器不能拖垮回合结算；
- 发布前必须校验，运行时只能降级，不能把错误结构当成功事实。

### 4. 版本快照边界

- 本轮可以不完整实现 `module_versions`；
- 但必须明确：进行中的 active room 不应受后续模板编辑影响；
- 若当前仍绑定 `mutable scenario` 开房，必须在回执中列为明确遗留风险；
- 后续目标是新房间绑定 `moduleVersionId`，而不是直接吃可变 scenario。

### 5. 结构编辑接口约束

- 只能使用字段级 patch 或受控 section patch；
- `truth` / `spoiler_boundary` / `trigger` / `map` / `template` 分开接口；
- 不接受整包任意 JSON 覆盖整个 scenario；
- 保存后必须重算 `quality_report` 或标记 `stale`；
- 必须记录 `actor + field summary + changedAt`。

## MVP 验收主链路

1. Admin 登录并导入 PDF。
2. 系统生成 scenario、`knowledge_graph`、`quality_report`、source hash。
3. Admin 查看模组详情，能看到结构摘要、质量等级、地图、素材、模板状态。
4. Admin 修正结构字段或补素材，必要时重新生成地图草稿并确认。
5. blocked 模组不能进入普通 Host 可用列表；highRisk 需要明确 override。
6. Admin 至少配置一个公开可选的角色模板。
7. Host 只能看到 `published` 或符合准入口径的模组，并创建房间。
8. Room start 使用 confirmed map 初始化运行态并创建首回合与 checkpoint。
9. Player 在公开流程里只看到公开简介、公开角色模板和运行态投影。
10. 玩家、地图、线索、状态的运行态变化都不反写 Module 模板。
