# 整场验收与发布操作手册 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐项实施；以下复选框仅供后续执行记录，本轮只编写文档。

**Goal:** 修复缺证据仍可发布的门禁，建设真实场次采集器，交付可复核的 P0 RC 验收证据。
**Architecture:** 真实服务运行场次，Trace 与独立审计记录产生观测，聚合器只计算指标；发布校验器同时检查来源、样本资格、指标和 Requirement 映射。确定性夹具、真实 Provider、真实浏览器分别出证据。
**Tech Stack:** Windows PowerShell、Python 3.11+、FastAPI、PostgreSQL、React/Vite、pytest、Vitest。
**Spec:** [本日评审](2026-09-05-project-review-and-next-work.md)、[冻结 P0 检查表](../20260823/AI_KEEPER_P0_P1_执行文档包_2026-08-22/01_P0_RELEASE_CHECKLIST.md)、[冻结任务包 v1.1](../20260820/AI_KEEPER_P0_纯AI模式_冻结决策与实施任务包_v1.1.md)。

## Global Constraints

- CoC 7e、`runtime_version=v2`、`session_mode=ai_only`、固定参考短模组 Glass Rain；Engine 是唯一权威写入口，Stage 为可选只读端。
- 自动仿真至少 30 场，其中双人至少 15 场、四人至少 15 场；另有至少两场真实浏览器多人 Golden Run。
- 硬阻断：人工裁决、Host exception、非法权威写入、严重剧透、重复骰点、重复事务、不可恢复卡死均为 0；Trace 完整率 100%。
- 冻结质量门槛：authored ending ≥80%、澄清率 ≤15%、有机械影响的静默误解 0、普通文本动作 P95 ≤15 秒、真实玩家评分平均 ≥4/5。
- 完整 Trace 加密保留 30 天，脱敏 Trace/指标保留 180 天；Owner/Stage 不可读取未揭示秘密、原始 Prompt 或他人私密信息。
- 沿用总评 **P0 20–35 人日**，本手册不追加或重复估工；主链开局、恢复、申诉未具备运行条件时，先完成前置工作。
- 当前已有 `src/server/scenario/ai_only_benchmark.py` 聚合器和 `tests/server/test_ai_only_benchmark.py` 单测，没有真实 Benchmark runner。
- `scripts/run_golden_module_suite.py` 已存在，但使用确定性结构化/规则夹具；旧检查表提议的 `run_session_benchmark.py`、`run_ai_only_acceptance.py` 当前不存在。

## V3：建设真实 runner 和 Trace→观测采集链

**Files:** 新建 `scripts/run_session_benchmark.py`（驱动）、`src/server/scenario/benchmark_evidence.py`（校验/转换）、`tests/server/test_benchmark_evidence.py`、`tests/server/test_session_benchmark_runner.py`；按需修改现有 `resolution_trace.py`、`resolution_pipeline.py` 补真实测量点，禁止填常量伪造观测。
**Interfaces（本任务拟新增，当前不可调用）:** `validate_evidence_manifest(manifest: dict) -> list[str]` 返回阻断码；`collect_session_observation(session: dict, actions: list[dict]) -> BenchmarkObservation` 仅转换已验证原始数据，非法输入抛 `ValueError`。

- [ ] 先写契约测试：同一真实 action 的三次 technical retry 只产生一个逻辑行动、一个原骰和一次事务；重复源文件、缺 action、篡改 hash、过期版本束和文件缺失分别拒绝；使用最小 fixtures，不把这些 fixtures 计入实跑。
- [ ] runner 通过正常 HTTP/WebSocket 链路注册独立身份、加入新房间、选择已发布冻结运行包、完成真实 Session Zero 探测、提交行动并等待服务端回执；不得 SQL 设置 running/completed，也不得直接调用 `_resolve_action_background` 替代生产调度。
- [ ] 使用固定种子决定玩家 persona、行动选择与预登记故障点；模拟玩家只能看到自身和公开投影。AI KP 必须走登记并 probe 成功的真实 Provider；记录实际模型/配置修订和请求 ID，不使用 `DeterministicGoldenGateway`。
- [ ] 保存模型输入/输出的加密审计引用和每步选择，以便诊断重放；固定种子不保证外部模型逐字确定性。分别标记“真实 Provider 复跑”和“已捕获响应重放”，不能混算。
- [ ] 每场预设 120 个逻辑行动或 60 分钟的采集上限（这是本次运行配置，不改变产品门槛）；先触发者结束采集并记录 `timeout`/未到结局及当前游标，不擅自 Owner 结束制造结果，不静默无限等待。
- [ ] 从正式持久化 Trace、行动/事务/揭示记录读取原始证据；现有 Trace 含 `authority_chain`、`provider`、版本束等，但没有现成完整延迟/评分采集器。缺字段时先补测量点和回归，再允许出可发布报告。

| 新建原始记录 | 必填字段与校验 |
|---|---|
| `benchmark/run-config.json` | schema_version、rc_id、git_commit、32+场次计划、seed、每玩家 persona、真实玩家模型/参数、故障点、超时上限、版本束、实际 Provider 配置修订；禁止密钥 |
| `benchmark/sessions.jsonl` | session_id/room_id 唯一映射、run_kind=`simulation/browser/fault`、开始/结束 UTC、player_count、seed、ending_id/type/Engine 提交事件 ID、eligibility/disqualification_reason、人工介入审计引用 |
| `benchmark/actions.jsonl` | session_id、action_id、action_kind、technical_retry_of、intent_contract_hash、status/outcome、accepted_at、resolve_started_at、resolved_at、等待区间、服务端活跃耗时、原 RollReceipt ID/hash、事务/揭示/投影事件 ID、Trace ID/hash |
| `traces/trace-manifest.json` | 全部进入流水线 action 的预期集合、对应 Trace ID、完整性结果、版本束 hash、授权导出审计 ID、脱敏文件相对路径及 SHA-256；集合不能从“已有 Trace”反推 |
| `browser/*/ratings.json` | session_id、匿名真人参与者 ID、清晰度/主动权/氛围各 1–5 分、采集时间、问卷版本；每个真实玩家一份，记录缺答，不允许模型代填 |
| `benchmark/annotations.jsonl` | action_id、澄清/纠正/不必要检定/静默误解判定、mechanical_effect、评审者匿名 ID、理由、证据引用；未知必须保留，不可默认为 0 |

- [ ] 计数必须是非负整数；延迟必须有限且非负；评分必须有限且在 1–5；完整 Trace 数不得超过进入流水线行动数。零风险动作可不投骰，但 Trace 要有适用性说明，不能把无 RollReceipt 机械地当缺 Trace。
- [ ] `trace_complete_actions` 要逐 action 核对阶段、authority_chain 的适用标记、Provider 尝试、版本束及 hash；不能只检查 Trace 存在或 `status=completed`。一个 gameplay failure 也可有完整 Trace；缺省的硬阻断计数 0 必须有审计采集覆盖证明。
- [ ] `accepted_actions` 分母限定接受的自然语言游戏行动，排除 consent/choice/confirmation 响应、系统按钮、OOC、同 action 重传；澄清行动按 action 去重。现有聚合器字段必须由此口径生成。
- [ ] P95 用普通文本行动从服务端接纳到权威结算及必要玩家投影可用的活跃时间；记录排队/Provider/重试耗时，扣除可证明的玩家等待，排除前端打字机。跨重启保存阶段区间，不能跨进程相减单调时钟或丢弃失败慢动作。
- [ ] authored ending 只信 Engine 提交事件与冻结 ending_id，包含 victory/mixed/defeat/safe_abort；Owner `aborted` 不得入成功分子。原始所有尝试、合格样本数和冻结分母分别列出，不以删失败行改善比率。
- [ ] 人工修复、Admin patch、Owner 终止、Trace 不完整的场次不计合格样本，保留原场次、原因与硬阻断；需补样本时登记新场次和新 seed。失败/低评分不可作为剔除理由，旧缺陷不能被补跑覆盖。
- [ ] 输出 `per-session.csv`、`observations.jsonl`、`summary.json` 和 `excluded-sessions.csv`；每个汇总值能追溯到原 action/Trace/问卷。发布计数按唯一且合格 simulation 场次统计，browser 两场独立计算。
