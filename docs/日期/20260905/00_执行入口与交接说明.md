## 4. 环境预检与测试隔离

以下为 Windows PowerShell，工作目录包含 `&`，必须使用带引号的 `-LiteralPath`。这些命令由接手人执行，本次编写文档没有安装依赖或启动服务。

```powershell
$repoRoot = 'G:\hermes-agent-workplace\D&D\CodeX-aikeeper'
Set-Location -LiteralPath $repoRoot
New-Item -ItemType Directory -Force -Path '.runtime\p0-handoff' | Out-Null
git status --short
git rev-parse HEAD
git diff --stat
python --version
node --version
npm --version
docker compose ps
```

优先使用已经能导入本项目的专属 Python 环境。评审使用的 PATH Python 属于 Hermes，缺少 `mcp.server.fastmcp`；不要直接修改 Hermes 的共享环境。若已激活项目专属环境，先显式保存解释器路径：

```powershell
$pythonExe = (Get-Command python -ErrorAction Stop).Source
& $pythonExe -c 'import sys; print(sys.executable)'
# 核对输出确实属于项目环境；不是则不要向它安装依赖，使用下方新环境分支。
if (-not (Test-Path -LiteralPath $pythonExe)) { throw 'Project Python executable not found' }
```

如果没有项目专属环境，可创建以下隔离环境，先从现有锁文件导出主依赖，不直接解析一套新的主依赖版本：

```powershell
python -m venv '.runtime\p0-venv'
$pythonExe = Join-Path $repoRoot '.runtime\p0-venv\Scripts\python.exe'
uv export --locked --extra dev --format requirements.txt --no-emit-project --output-file '.runtime\p0-handoff\project-requirements.txt'
if ($LASTEXITCODE -ne 0) { throw 'Project lock does not match; investigate in B0 before changing it' }
uv pip install --python $pythonExe -r '.runtime\p0-handoff\project-requirements.txt' -r kp_mcp_server/requirements.txt defusedxml
if ($LASTEXITCODE -ne 0) { throw 'Python dependency installation failed' }
& $pythonExe -c 'import fastapi, psycopg2, pytest, defusedxml; from mcp.server.fastmcp import FastMCP; print("runtime imports OK")'
if ($LASTEXITCODE -ne 0) { throw 'Project runtime imports failed' }
```

`defusedxml` 是当前 `main.py` 的直接导入，但未列在根依赖表；B0 要同步直接依赖声明，并记录实际 Python、MCP、前后端依赖版本。其他缺失依赖同样按实际 import 核对，不能靠吞掉 ImportError 隐藏。安装过程应遵守项目锁文件；若必须修订依赖/锁文件，在交付中写明原因。

下面只在运行自动测试的终端设置。数据库名必须含 `test`；多人测试各自换成独立名字。

```powershell
$env:TEST_DATABASE_URL = 'postgresql://aikeeper:aikeeper123@localhost:5432/aikeeper_p0_executor_test'
$env:DATABASE_URL = $env:TEST_DATABASE_URL
$env:AIKEEPER_DEV_MODE = '1'
$env:AI_CONFIG_MASTER_KEY = 'aikeeper-p0-test-only-key'
$env:PYTHONUTF8 = '1'
$env:PYTHONUNBUFFERED = '1'
$runStamp = Get-Date -Format 'yyyyMMdd-HHmmss'
$runTemp = ".pytest-tmp-p0-$runStamp"
& $pythonExe -m pytest tests/server --collect-only -q --basetemp=$runTemp
```

示例凭据来自仓库本地测试默认值；如果本机已改凭据，使用自己的本地测试配置，不写进报告。pytest 的 `test_db` 会 TRUNCATE 多张表，**浏览器运行库和 pytest 测试库不得共用**。不要使用 `docker compose down -v` 或重建业务数据库处理测试失败。

前端在 `src/client` 下使用现有 package-lock：

```powershell
Push-Location -LiteralPath (Join-Path $repoRoot 'src\client')
try {
  npm ci
  if ($LASTEXITCODE -ne 0) { throw 'Frontend dependency installation failed' }
  npm run test
  if ($LASTEXITCODE -ne 0) { throw 'Frontend tests failed' }
  npm run build
  if ($LASTEXITCODE -ne 0) { throw 'Frontend build failed' }
} finally { Pop-Location }
```

每次命令保存退出码与本地日志；先读失败原因再修复。全量慢可以记录阶段进度和人工停止原因，但必须写“未完成”；不拿定向通过替代全量。

## 5. 浏览器与真实 Provider 的边界

- 浏览器使用独立验证库、测试账号和冻结模组；Provider 凭据通过现有管理界面/本地配置设置。不要复制真实玩家数据作为夹具。
- 如已有 3001/5173 服务，先确认它们来自哪个工作区与哪个数据库，再决定复用；不自动杀掉别人的端口进程。
- 使用现有 `python dev.py --check` 做健康检查；实际启动沿用仓库开发方式，并确认配置指向浏览器专用库。不要在上述 pytest 环境终端直接启动浏览器后端。
- 不随机替换已有 Provider 配置的主密钥。随机新密钥只能用于全新隔离测试库；否则已有密文将无法解密。
- Owner 开始房间属于运营操作；手工填写 Session Zero 数据、推进场景、改骰点、改状态、代做 AI 申诉均不能计入正常黄金路径。
- 日志、HAR、截图可能包含 player/owner/stage token、私密线索与 AI prompt，原件保留在 `.runtime/p0-handoff/`；提交的文档只放脱敏引用、摘要和哈希。
