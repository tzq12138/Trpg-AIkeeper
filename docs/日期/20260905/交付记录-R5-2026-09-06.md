## 实现内容（`automatic_action_review.py` 追加）

- `AUTOMATIC_REVIEW_STATUSES`（D07 六终态：upheld / explanation_corrected / projection_repaired / compensated + R4 已有 review_rejected / system_paused）；`_MUTATION_ALLOWED_STATUSES = {compensated}`。
- `apply_automatic_review_resolution(app_state, conn, review_request_id, resolution) -> dict`：
  - 校验：case 必须 pending + `awaiting_engine_review`（非此状态 → `not_awaiting_engine_review`；同终态重放 → 已知状态返回）；`source_action_id` 必须等于冻结 action（防跨 action 复用）；`expected_current_state_version` 必填且须等于当前版本；
  - `_validated_mutations`：仅允许 `replace`、仅 `/character/{hp,san,mp,luck,hp_max,san_max,mp_max}` 一级路径、值必须存在（非法 → `invalid_mutation`/`invalid_mutation_path`）；
  - `_deterministic_id(kind, review_id)`：uuid5 命名空间派生 transaction id——重放即幂等，同事务 `INSERT ... ON CONFLICT` 语义（先查后插，同 tx 内）；
  - 补偿路径：`StateChangeSet(characterMutations=[case.character])` → `state_service.apply_change(..., transaction=tx)`——与原事务同一原子边界，钳制/版本语义由 StateService 保证；`no_op` 或版本未递增 → `compensation_noop` 拒绝；
  - `_write_automatic_terminal` 复用 R4 append-only history；补偿/纠正行 `compensation_transactions`（`transaction_type='review_correction'`，payload 含因果引用）；
  - 状态不匹配 → `pause_room_for_system_integrity(tx=tx)` 同事务暂停。
- 原 action result / resolution_bundle / trace **零覆盖**（本模块无任何 upsert 这些表的路径）。

## 一致性断言

- 每条 applied 终态恰好一行补偿/纠正记录；重放零新行、零版本递增。
- 补偿只作用于冻结 action 的原授权 character，路径白名单 + clamp + 版本门禁三重边界。
- 无法证明的个案一律 system_paused，不计为已补偿成功。
- 原解释与补充解释（correction payload + automatic_resolution.history）同时可追踪。

## R5 安全修复（commit `0303760`）

自动安全评审发现：`apply_automatic_review_resolution` 信任完全调用方可控的 resolution（含补偿 mutations）。当前无任何客户端路由可达该函数，但形状上存在未来误接风险。修复 = **引擎专属签名门禁**：resolution 必须携带 HMAC-SHA256 签名，覆盖规范化权威字段（review_request_id/status/source_action_id/source_receipt_hash/expected_current_state_version/mutations），密钥沿用 roll-receipt 同款域分离派生（ROLL_RECEIPT_SECRET/JWT_SECRET + dev-mode fallback）；未签名或签名后篡改 → `unverified_resolution` fail-closed，任何终态都不被采信。`sign_automatic_review_resolution()` 为引擎侧构造器 API（slice B 接线使用）。24 review tests 绿（新增测试断言未签名与篡改均被拒且零副作用）。
