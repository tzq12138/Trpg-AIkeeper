# 二、最核心的实现链路

代码里的主流程是：

```python
candidate = semantic_model.parse(utterance, safe_context)

grounded_candidate, ambiguities = grounder.ground(
    candidate,
    safe_context,
)

risk_level, handling = risk_policy.decide(
    grounded_candidate,
    ambiguities,
)

record = SemanticRecord(
    utterance=utterance,
    candidate=grounded_candidate,
    ambiguities=ambiguities,
    risk_level=risk_level,
    handling=handling,
)
```

这几个对象的职责完全分开：

|组件|负责什么|不能做什么|
|---|---|---|
|`SemanticModel`|从语言中提取候选语义|不能写状态、不能掷骰|
|`ViewerSafeGrounder`|将“守卫”“钥匙”“后门”等绑定到实体 ID|不能使用玩家不可见实体|
|`SemanticRiskPolicy`|判断讨论、澄清、确认或低风险执行|不决定规则成功失败|
|`SemanticCompiler`|生成已验证的 `ActionCommand`|不生成 `RuleResult`|
|`Transaction`|接收正式行动并保证幂等|不重新理解玩家语言|
|`RuleExecutor`|使用服务器角色值完成检定|不相信玩家自报数值|
|`StateService`|提交权威状态变化|不接受 AI 直接写入|

# 三、最重要的数据对象

## 1. 玩家原话

```python
class UtteranceEnvelope(BaseModel):
    utterance_id: str
    room_id: str
    speaker_character_id: str
    channel: Channel
    raw_text: str
    language: str = "zh-CN"
```

它保留：

```text
谁说的
在哪个房间
在哪个频道
原话是什么
```

后续即使 AI 理解错误，也能回到原始输入复核。

---

## 2. 安全语义上下文

```python
class SemanticContextSchema(BaseModel):
    room_id: str
    viewer_character_id: str
    visible_entities: list[VisibleEntity]
    available_frames: list[FrameType]
```

这里是非常重要的安全设计：

> **模型和实体绑定器只能获得该玩家当前有权知道的实体。**

例如玩家当前可见：

```json
[
  {
    "entity_id": "npc_guard",
    "kind": "npc",
    "label": "守卫"
  },
  {
    "entity_id": "loc_back_door",
    "kind": "location",
    "label": "后门"
  },
  {
    "entity_id": "item_letter",
    "kind": "item",
    "label": "信"
  }
]
```

如果模组中还有一个玩家尚未发现的：

```text
location:hidden_tunnel
```

它不会进入 `visible_entities`。

所以玩家说：

> “我看看有没有隐藏通道。”

系统可以保留描述：

```text
寻找可能存在的隐藏通道
```

但不能回应：

> “你是指北墙后的秘密通道吗？”

因为那会直接剧透。

---

## 3. 候选语义

```python
class SemanticCandidate(BaseModel):
    discourse_act: DiscourseAct
    commitment: Commitment
    macro_goal: str | None
    steps: list[SemanticStep]
    assumptions: list[str]
    parser_confidence: float
```

它只是 AI 的理解候选，不是正式行动。

---

## 4. 最终行动命令

```python
class ActionCommand(BaseModel):
    action_id: str
    idempotency_key: str
    room_id: str
    character_id: str
    source_utterance_id: str
    source_semantic_record_id: str
    macro_goal: str | None
    steps: list[ActionStep]
    status: Literal["confirmed"]
```

这个对象才会交给 `14-Transaction`。

而且它仍然不是：

```text
骰子结果
成功等级
状态变化
剧情事实
```

这些仍要经过：

```text
Transaction
→ RuleExecutor
→ StateService
→ Projection
→ Journal
```

# 四、示例一：建议不会被误执行

玩家输入：

> **“要不等守卫过去后，我从后门进去看看？”**

解析器识别出了三个语义步骤：

```text
1. 等待守卫经过
2. 从后门进入
3. 观察里面
```

但同时识别到：

```json
{
  "discourse_act": "proposal",
  "commitment": "proposal",
  "handling": "discussion_only"
}
```

玩家看到的结果：

> 我把这句话理解为队伍建议，不会执行行动。  
> 计划内容：等待守卫经过后，从后门进入并观察内部。

系统返回：

```json
{
  "handling": "discussion_only",
  "action": null
}
```

也就是说，即使系统完全理解了计划，也不会因为出现“进入”“观察”等动词就创建行动。

# 七、生产环境如何替换成真实 AI

示例中的 `DemoSemanticModel` 是离线规则解析器，只是为了让代码可以直接运行。

生产环境替换成：

```python
class AiGatewaySemanticModel:
    def __init__(self, gateway: AiGateway):
        self.gateway = gateway

    def parse(
        self,
        utterance: UtteranceEnvelope,
        context: SemanticContextSchema,
    ) -> SemanticCandidate:
        result = self.gateway.call(
            task="semantic_parse",
            schema_version="1.0.0",
            response_schema=SemanticCandidate.model_json_schema(),
            input={
                "utterance": utterance.model_dump(mode="json"),
                "semanticContext": context.model_dump(mode="json"),
            },
        )

        return SemanticCandidate.model_validate(result.typed_output)
```

重要的是模型调用时只给：

```text
玩家原话
当前玩家安全可见实体
当前允许的语义框架
必要的对话焦点
房间语义策略
```

不应该给：

```text
完整模组真相
全部隐藏 NPC
全部地图节点
其他玩家私密信息
数据库写入工具
RuleResult
State mutation 权限
```

# 八、真实系统还要再经过五层验证

模型返回结构后，至少继续检查：

```python
candidate = SemanticCandidate.model_validate(ai_output)

validate_frame_schema(candidate)
validate_entity_ids(candidate, viewer_safe_context)
validate_actor_permissions(candidate, current_character)
validate_room_preconditions(candidate, room_snapshot)
validate_action_risk(candidate, room_policy)
```

例如模型返回：

```json
{
  "frame": "UseItem",
  "itemRef": "item_secret_master_key"
}
```

但这个物品不在玩家安全上下文中，就必须拒绝：

```text
unknown_or_unauthorized_item
```

不能继续交给 Transaction。

# 九、与现有 01-24 模块怎么接

建议最终链路：

```text
16-Player Client
    提交 UtteranceEnvelope
        ↓
15-Projection / 21-Safety
    生成 SemanticContextSchema
        ↓
12-AI-Keeper
    生成 SemanticCandidate
        ↓
26-Semantic
    Grounding + Risk + Clarification + Confirmation
        ↓
14-Transaction
    ActionCommand 幂等入账
        ↓
04-Rule
    使用服务器权威技能和规则
        ↓
13-State
    提交世界状态
        ↓
15-Projection
    按角色视角安全投影
        ↓
11-Journal
    保存原话、语义合同、裁决和来源链
```

语音则是：

```text
20-Voice
TranscriptDraft
→ 玩家确认文字
→ UtteranceEnvelope
→ 同一 Semantic 链路
```

物品行动则是：

```text
Semantic Frame = UseItem / TransferItem
→ Item 系统验证物品
→ Transaction
→ Rule
→ State
```
