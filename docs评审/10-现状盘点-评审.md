# 10-现状盘点 评审报告

评审日期：2026-07-22
评审范围：`docs/10-现状盘点/` 全部 4 份 Markdown

## 1. 概述

**定位**：该文件夹应回答"项目现在在哪、缺什么、下一步先补什么"，是竞品分析、风险清单与工作区索引的混合体。

**文件清单**：

| 文件 | 日期标识 | 性质 |
|---|---|---|
| `2026-07-16-竞品双向分析与能力缺口.md` | 有（2026-07-16） | 竞品分析 + 优先级路线 |
| `工作区整理记录.md` | 无 | 一次性整理操作日志 |
| `当前项目状态与风险.md` | 无 | 代码/文档资产盘点 + 风险 |
| `最近更新文件索引.md` | 无 | 近期合并与工作区变动索引 |

**整体质量评分：C+**。竞品分析一份质量明显高出其余三份（约 B+），但三份"现状/索引"类文件无日期、引用路径大面积失效、相互矛盾，作为"现状盘点"的时效性与可信度不达标。

## 2. 主要问题

### P0-1：现状盘点文档的引用路径大面积失效，"现状"不可导航

- **问题描述**：`当前项目状态与风险.md`"已有文档资产"表列出的 6 份文档中，4 份路径已过期；竞品分析的"内部依据"也有 2 条失效。
- **证据**：
  - `当前项目状态与风险.md` 引用 `docs/KP_MCP_Design.md`、`docs/数据流.md`、`docs/数据流bug+思考.md`、`docs/规则导入.md`——实际均已移至 `docs/20-核心链路/`（`工作区整理记录.md` 自己记录了 soul.md 的迁移，却未同步修正本文档）。
  - 同文引用 `docs/TEST_COVERAGE.md`——实际位于 `docs/60-验收与测试报告/TEST_COVERAGE.md`。
  - `2026-07-16-竞品双向分析与能力缺口.md` 引用 `docs/深挖优势/第一条：AI 能长期记忆，但不篡改事实.md`——实际目录已改名为 `docs/25-深挖优势与设计原则/`，文件名也变为 `第1条：…`；引用 `docs/loop_runs/2026-07-15-yhdx-m0-mimo-browser-report.md`——实际位于 `docs/60-验收与测试报告/loop_runs/`。
- **影响**：现状盘点是后续执行（30-DeepSeek任务包）的上下文入口，路径失效意味着执行者拿到的"现状"是断链的；盘点文档自身的可信度也因此受损。
- **改进建议**：批量修正路径；在 docs/README 或 CI 加 Markdown 相对链接检查；文件迁移时同步全文检索替换引用。

### P0-2：时效性失控——4 份文件中 3 份无日期，却承载大量易腐信息

- **问题描述**：`工作区整理记录.md`、`当前项目状态与风险.md`、`最近更新文件索引.md` 均无日期、无版本、无作者，但内容全是易腐快照。
- **证据**：
  - `当前项目状态与风险.md`："执行前的 `git status --short` 显示当前工作区已有大量源码改动"——"执行前"无法对应到任何日期，评审时（07-22）无法判断该快照年龄。
  - `最近更新文件索引.md` 自称"本次新增索引文件，尚未提交"、"当前索引以 main 分支上最近两轮已合并内容为准（`0a0249d`、`5b860ef`）"——无日期佐证"最近"是哪段时间。
  - `工作区整理记录.md`："本轮整理结果"——"本轮"无定义。
- **影响**：现状盘点的核心价值是时效，无日期则无法判断"已过期"还是"仍有效"，后续读者只能全部存疑。
- **改进建议**：所有"现状/索引/记录"类文件强制头部加"快照日期 + 数据截止时间"；超过 N 天未刷新时在 docs/README 标灰或移入 90-归档。

### P1-3：竞品分析内部数字自相矛盾（两份 vs 三份黄金模组）

- **问题描述**：同一文档对 P0 关键交付物"黄金模组"的数量口径不一致。
- **证据**：`2026-07-16-竞品双向分析与能力缺口.md` P0 缺口表写"两份黄金模组；1 人和 4 人各完成…"，路线节写"固化两份受授权/原创黄金模组"；但 P1 缺口表"CoC 调查与恐怖专用模板"行写"…和三份原创黄金模组"。
- **影响**：P0 验收范围不清，"继续条件"无法判定是否达成。
- **改进建议**：统一为同一数字，并注明每份模组的验收矩阵（人数 × 链路）。

### P1-4：《最近更新文件索引》内部矛盾且混杂两种状态

- **问题描述**：(a) 对同一压缩包给出冲突结论；(b) "已合并基线"与"未提交工作区变动"两类异质信息混排，未声明哪类是当前事实源。
- **证据**：
  - "已移除文件"表称 `docs/50-AI-Keeper-Platform.7z`"历史压缩包已删，后续以真正目录为准"；但"当前工作区额外变动"表又记录 `docs/50-AI-Keeper-Platform.7z`"当前工作区再次出现压缩包文件，不应替代真实目录"和新增 zip——删除结论与再现事实并存，未给出处置动作（谁、何时删）。
  - 索引同时列"当前基线"（`0a0249d`、`5b860ef` 两次已合并 commit）和"当前工作区额外变动"（16 个未提交文件），并自述"回到 01-Room 评审时要注意不要和主线基线混看"——把防混淆责任推给读者而非文档结构。
- **影响**：索引的本职是消除歧义，实际制造了新的歧义。
- **改进建议**：拆成"已合并基线"与"在途变动"两节并分别标注截止 commit 与快照日期；压缩包问题给出明确处置项与 owner。

### P1-5：现状盘点之间、与验收报告之间互不呼应

- **问题描述**：三份现状文档各说各话，未形成结论闭环；与 `60-验收与测试报告/` 的最新证据未对齐。
- **证据**：
  - `当前项目状态与风险.md`"当前补漏方向"6 条（如"投影时序：涉及公共演出的私密状态变更不能提前剧透"）与竞品分析 P0 缺口（如"行动结果持续可见"）明显同源，但两份文档互不引用。
  - 竞品分析将"自然语言行动→预览→确认→确定性结算"标为"已验证"，依据是 07-15 的 loop_runs 报告；但 `60-验收与测试报告/` 已存在多份 07-19 验收文件（如 `260718_RUNTIME_ACCEPTANCE_2026-07-19.md`、`260718_COMPLETION_AUDIT_2026-07-19.md`），竞品分析（07-16）的结论未与更新证据核对。
- **影响**："现状"结论可能基于过期证据；风险清单与缺口清单重复建设。
- **改进建议**：竞品分析的"当前基线"表每行挂验收报告链接与日期；现状盘点文件夹内建立一份最小 README 说明三份文档的分工与刷新节奏。

### P2-6：指标大多不可测试

- **问题描述**：竞品分析的追踪指标与决策门缺乏数值门槛。
- **证据**："应持续追踪的竞争指标"表目标列几乎全是"持续下降/上升"（仅"必须为 0"和"60 秒内"可量化）；"继续条件"写"人工急救率、关键错误率和 AI 中断恢复率达到预设门槛"——门槛值全文未定义；P0 缺口的"成功指标"（完成率、行动卡死率、重连恢复时间）均无阈值。
- **影响**：决策门无法执行，"达到门槛再进 P1"沦为口号。
- **改进建议**：为每个继续条件补数值（如"4 人全流程人工急救 ≤ 2 次/场、重连恢复 ≤ 10s"）。

### P2-7：《工作区整理记录》是一次性日志却承担长期规范职能

- **问题描述**：该文件前半是某次整理的操作日志，后半"后续新增文件规则"实质是长期工作区规范。
- **证据**："后续新增文件规则"规定"新计划放入 docs/30-DeepSeek任务包/…运行日志不进入 Git"——这类规则应常驻 README/AGENTS.md，而不是埋在一份无日期的整理记录里。
- **影响**：规则随记录失去时效后被遗忘，新成员看不到。
- **改进建议**：规则段迁移至 docs/README.md 或 AGENTS.md，原文件标注日期后归档。

## 3. 一致性问题（与 PRDs、50-AI-Keeper-Platform、00-产品规范 对照）

1. **AI 供应商口径三处不一**：竞品分析称"MIMO 配置、文本叙事和动态提供方链已做浏览器验证"；`20-核心链路/KP_MCP_Design.md` §8.1 默认链为 `deepseek,mcp,local`；`60-验收与测试报告/` 中存在 `MCP_GPT54_叙事修复与切换报告_2026-07-10.md`。现状盘点未解释"当前生产供应商到底是谁"，其"已验证"结论对应的供应商可能与现行默认链不同。
2. **状态标记口径未与规范对齐**：竞品分析自定义"已验证 / 已实现待扩大验收 / 明确不做"三级标记，与 `00-产品规范/04-M0范围、里程碑与指标.md` 的 M0 范围口径、`50-AI-Keeper-Platform` 各模块 PRD 的功能状态之间没有对照表，读者无法互相映射（例如"防剧透与按视角投影：已实现/待扩大验收"对应 15-Projection 系统的哪些 PRD 条目）。
3. **"明确不做"清单与 50 平台模块树存在张力**：竞品分析将"内置语音/视频"列为明确不做，但 `50-AI-Keeper-Platform/20-Voice-Media语音与媒体系统` 仍在模块树中（索引文件也照常收录）。虽然可用"当前阶段不做 vs 平台终态"解释，但两份文档都未声明这一区分。
4. **Room 状态机口径**：`最近更新文件索引.md` 引用 `draft/lobby/active/paused/completed/archived` 与 `joined/pending_approval/left` 状态枚举，并列为"评审意见归档第 2 类"；该枚举应与 `00-产品规范/03-领域对象与唯一权威矩阵.md` 及 `50-.../01-Room团房间系统/PRD.md` 对齐——索引未做此确认，把"是否定义不清"留作开放问题。

## 4. 缺失项

- **无量化技术现状**：没有当前测试通过率/覆盖率数字（`当前项目状态与风险.md` 只说 TEST_COVERAGE "不能代表当前脏工作区"，但没给新数字）、无构建/部署环境现状、无数据库 schema 版本现状。
- **无进度与里程碑现状**：对照 `00-路线图` 和 `00-产品规范/04-M0范围`，当前处于哪个里程碑、偏差多少，无任何文件回答。
- **无数据资产现状**：已有剧本/黄金模组数量、授权状态（竞品分析要求"受授权/原创黄金模组"）无盘点。
- **无人员/协作现状**：`30-DeepSeek任务包` 的存在暗示人机协作流程，但现状盘点未覆盖任务分派与执行纪律的生效情况（`当前项目状态与风险.md` 列了纪律，但无"是否被遵守"的检查结论）。

## 5. 亮点

- 竞品分析的"方法与口径"声明克制严谨（"不将竞品未在官方资料中说明的功能直接判定为'没有'"），双向对比（缺口 + 反向取胜点）结构清晰，P0–P3 分层与决策门设计是可执行的优先级框架。
- "把文档能力当产品能力"（关键风险第 4 条）与 `当前项目状态与风险.md` 的"口径提醒"（"任何'已完成''已通过'结论都必须来自当批执行后的新测试输出"）是很好的工程纪律宣言。
- `最近更新文件索引.md` 的"收到评审意见后先按 6 类归档"（边界/状态机/权限/接口/验收/文案）是实用的评审分流框架。

## 6. 结论与行动建议

竞品分析可保留为战略参考；其余三份需要一次"时效性修复"才能继续承担现状盘点职能。

按优先级建议：

1. 【P0】修正全部失效引用路径（P0-1），并引入链接检查防止复发。
2. 【P0】为三份无日期文件补快照日期与数据截止时间；建立"现状类文件超过 14 天未刷新即标灰"的规则（P0-2）。
3. 【P1】统一黄金模组数量口径（P1-3）；拆分索引文件的基线/在途两节并对压缩包给出处置结论（P1-4）。
4. 【P1】竞品分析的"已验证"结论逐行挂 07-19 验收报告链接（P1-5）。
5. 【P2】为决策门补数值门槛（P2-6）；将工作区规则迁入长期文档（P2-7）。
