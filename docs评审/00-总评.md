## 二、跨文档四大系统性问题（比单点问题更致命）

### 1. 规范权威体系三面开战 —— P0
2026-07-15 生效的 normative 产品规范（ADR-002 PDF 不作验收前提 / ADR-003 文字唯一基线 / ADR-004 Stage 永远可选 / ADR-005 Host 废止 / ADR-006 仅 Engine 可写）与下游三套文档同时冲突：
- **PRDs**：README 自称"最终版本 v2.0"，以语音优先 + PDF 导入起点 + Stage 依赖为核心假设，31 份无一处引用规范；
- **50-AI-Keeper-Platform**：以 Host/owner_token 为一等角色、Host 可见隐藏全图、私密结果受 Host ACK 门控；
- **03 唯一权威矩阵**把事件/投影权威判给 Journal/Projection 等服务，与 ADR-006 字面冲突。

**后果**：按任何一套开发都会在验收时撞上另一套。这是全库第一优先级问题——需要先开一份 ADR 裁决"谁取代谁"，再谈其他修复。

### 2. 验收机制系统性失真 —— P0
三条独立证据链指向同一结论：**"通过"二字在当前文档库中不可信**。
- 50 平台 11 个子系统回执在自列一票否决项未闭环（Pipeline 先投影后落库、RAG 不按 visibility 过滤、ReleaseGate 仅内存）下仍判"通过"；
- 60-测试报告"全量通过"出现 1068/1151/1189/1194 等多个数字，无 commit 锚点；`TEST_COVERAGE.md` 宣称 30/31 PRD 完成，但 loop 结局全是显式 API 强收；
- 260718 全族报告验收的 PAO-FR 需求源文档根本不在库内，可追溯性断裂。

**建议**：验收回执引入"一票否决项未闭环禁止通过"的硬规则 + commit/环境锚点强制填写。

### 3. 影子协议与未收编文档 —— P0
正式协议体系（PRD-00 事件全集、产品规范）之外游离着多套"野生"契约：KP_MCP_Design 的 AI direct 免校验写状态通道、PAO DTO 体系（正式 PRD 零命中）、归档的 HOST_PROTOCOL_CONTRACT.md（自称单一事实源无废弃标注）、soul.md 生产 prompt 允许"AI 代骰"。任何一套都可能在实现层复活并绕过裁决与安全边界。

### 4. 安全与防剧透防线存在实锤缺口 —— P0
- 07-WorldBook 自评承认 `RAGStore.search()` 不按 visibility 过滤，玩家可经 `/api/rag/search` 命中剧本原文；
- M0 必验的 X-card/淡出/私密反馈/安全结束被 40-平台补全排到阶段 5 Batch 18；
- PRD-26 防剧透三档有名无实（ExposureState 无等级/阈值/更新规则）；
- Host 可见隐藏全图 + 私密结果 Host ACK 门控，与"Host 不是规范概念"根本冲突。

## 三、文档治理问题（普遍存在于各文件夹）

1. **命名与时间戳混乱**：`260718_` 前缀（应为 20260718 或 2026-07-18）、`plan~plan23` 无语义命名、大量文档无日期无版本无状态（路线图、3/4 现状盘点）。
2. **归档边界失守**：归档 zip 内含自称"当前有效设计基线"的文档，且与现役文件字节级相同（player 技术方案三处副本），必然漂移。
3. **半成品混入正式库**：《想到+待聊》（7 行）、含 sandbox 死链的聊天导出物留在 25-设计原则。
4. **设计与实现脱节**：设计前端存在 6 月 Stitch 体系与 7 月头脑风暴 Spec 两套矛盾基线，host 界面稿甚至违反 Spec 红线（大屏出现"掷骰 D100""推进剧情"按钮与精确 HP/SAN 数值）。

## 四、亮点（值得保留的做法）

- 00-产品规范的 ADR 制度、唯一权威矩阵的**思路**本身是正确方向（问题只在执行一致性）；
- PRDs 31 份模板骨架统一、README 索引含依赖图与已修正口径表，高于一般水平；
- PRD-19 断线重连 State Version Barrier、PRD-04 Watchdog 设计扎实；
- 25-设计原则的五条"AI 能…但不…"原则表述精准，是好的产品哲学（缺的是转化为可检查约束）。

## 六、总体结论

这是一套**思考深度远超治理水平**的文档库：产品哲学、ADR 制度、协议冻结意识都可圈可点，PRD 模板工程化程度高。但当前状态下它**不能作为开发的唯一事实源**——规范、PRD、平台施工图三套体系互相矛盾且互不引用，验收结论失真，影子协议游离在外。建议先完成"裁决冲突 → 修复验收机制 → 清剿影子协议"三件事，再进入下一轮开发，否则每一行代码都在为文档内战付利息。
